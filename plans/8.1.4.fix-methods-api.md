# 2. هدف

بازطراحی `Methods API` با اهداف زیر:

1. مصرف‌کننده مستقیماً Function Callback تعریف کند.
2. کلید public هر Method، کلید semantic مانند `CLICK` باشد.
3. نام implementation مانند `fn_onClickIcon` فقط در runtime/internal mapping استفاده شود.
4. پارامترهای `event`، `dataArgs` و `componentArgs` Type Safe باشند.
5. `this` در Function Callback به Component instance متصل شود.
6. `ClComponentBase.#getReadyComponentMethods` مسئول binding باشد.
7. Genericهای `CreateCategoryComponent` حفظ شوند.
8. تغییر نام implementation method باعث شکستن Public API نشود.
9. تعریف `componentArgs` و `dataArgs` در `Methods.ts` به عنوان source of truth حفظ شود.

---

# 3. قرارداد جدید API

مصرف‌کننده باید بتواند بنویسد:

```ts
{
    CLICK: function (event, dataArgs, componentArgs) {
        this.set(...);
    }
}
```

و نباید مجبور باشد نام runtime method را بداند:

```ts
{
    fn_onClickIcon: ...
}
```

Mapping داخلی:

```text
CLICK
 ↓
_COMPONENT_METHODS["CLICK"]
 ↓
destination
```

در این مدل، `_COMPONENT_METHODS` باید با **semantic keys** ساخته شده باشد.

---

# 4. Methods.ts

`Methods` سه مسئولیت دارد:

1. تعریف semantic method keys
2. نگهداری runtime method name
3. تعریف metadata مربوط به Component/Data Args

نمونه:

```ts
export const Methods = {
    CLICK: {
        name: "fn_onClickIcon",
        description: "Called when icon is clicked",

        args: {
            ICON: ComponentIconProps.prop_icon,
        },

        dataArgs: {} as const,
    },

    HOVER: {
        name: "fn_onHoverIcon",
        description: "Called when icon is hovered",

        args: {},

        dataArgs: {} as const,
    },

    BLUR: {
        name: "fn_onBlurIcon",
        description: "Called when icon loses focus",

        args: {},

        dataArgs: {} as const,
    },
} as const;
```

---

# 5. Source of Truth برای Args

`Methods.ts` باید source of truth مربوط به Method arguments باقی بماند.

از این metadata، typeهای مربوط به Component Args و Data Args استخراج شوند.

نمونه:

```ts
export type MethodsComponentArgs = {
    [K in keyof typeof Methods]: {
        [ArgKey in keyof typeof Methods[K]["args"]]:
            typeof Methods[K]["args"][ArgKey] extends {
                default: infer T
            }
                ? T
                : any;
    };
};
```

و:

```ts
export type MethodsDataArgs = {
    [K in keyof typeof Methods]:
        typeof Methods[K]["dataArgs"];
};
```

### نکته

اگر type مربوط به `prop`ها در معماری فعلی از قبل utility/type helper دارد، همان helper باید استفاده شود و منطق استخراج type نباید دوباره‌سازی شود.

همچنین در صورت امکان، `any` موجود در extraction باید در یک Phase بعدی با type-safe fallback جایگزین شود. استفاده از `any` در این قسمت نباید به callback API نشت کند.

---

# 6. Callback_ComponentMethod

نوع callback باید `this` را نیز مشخص کند.

```ts
export type Callback_ComponentMethod<
    TComponentArgs,
    TDataArgs,
    TThis = any
> = (
    this: TThis,
    event: Event,
    dataArgs: TDataArgs | null,
    componentArgs: TComponentArgs | null,
) => void;
```

### دلیل `TThis = any`

Default شدن `TThis` به `any` باعث می‌شود مصرف‌کنندگان فعلی که Generic مربوط به `this` را مشخص نمی‌کنند، دچار breaking change نشوند.

در Componentهای جدید، مقدار دقیق `TThis` باید به Component instance متصل شود.

---

# 7. Type Safety در MethodsConfigType

کلیدهای Public باید از:

```ts
keyof typeof Methods
```

استخراج شوند.

ساختار:

```ts
export type MethodsConfigType<
    TComponentArgs,
    TDataArgs,
    TThis = any
> = {
    [K in keyof typeof Methods]?:
        Callback_ComponentMethod<
            TComponentArgs[K],
            TDataArgs[K],
            TThis
        >;
};
```

در نتیجه API به شکل زیر خواهد بود:

```ts
{
    CLICK?: Callback_ComponentMethod<...>;
    HOVER?: Callback_ComponentMethod<...>;
    BLUR?: Callback_ComponentMethod<...>;
}
```

و نه:

```ts
{
    fn_onClickIcon?: ...
}
```

# 8. Semantic Key به عنوان Public API

اصل معماری:

```text
CLICK
HOVER
BLUR
```

Public API هستند.

در مقابل:

```text
fn_onClickIcon
fn_onHoverIcon
fn_onBlurIcon
```

implementation identifiers هستند.

مصرف‌کننده نباید به implementation identifiers وابسته باشد.

---

# 9. اصلاح #getReadyComponentMethods

در `ClComponentBase` نیازی به دسترسی مستقیم به `Methods` const نیست.

`_COMPONENT_METHODS` باید semantic keys را در اختیار داشته باشد.

بنابراین implementation:

```ts
for (const semanticKey in methods) {
    const fn = methods[semanticKey];

    if (typeof fn === "function") {
        const methodMeta =
            this._COMPONENT_METHODS[semanticKey];

        if (methodMeta) {
            methodMeta.destination = fn;
        }
    }
}
```

این implementation دو مزیت دارد:

1. مستقیماً با Public API کار می‌کند.
2. `ClComponentBase` به `Methods.ts` وابسته نمی‌شود.

---

# 10. مسئولیت `_COMPONENT_METHODS`

ساختار `_COMPONENT_METHODS` باید با semantic key قابل دسترسی باشد:

```ts
_COMPONENT_METHODS = {
    CLICK: {
        name: "fn_onClickIcon",
        destination: undefined,
    },

    HOVER: {
        name: "fn_onHoverIcon",
        destination: undefined,
    },

    BLUR: {
        name: "fn_onBlurIcon",
        destination: undefined,
    },
};
```

بنابراین:

```ts
this._COMPONENT_METHODS["CLICK"]
```

مستقیماً Method مربوط به `CLICK` را پیدا می‌کند.

`name` همچنان برای runtime/internal method identification نگهداری می‌شود.

# 11. Runtime Execution

در زمان execution:

```ts
destination.call(
    this,
    event,
    dataArgs,
    componentArgs
);
```

یا معادل موجود در `executeMethod`.

هدف این است که:

```ts
CLICK: function (
    event,
    dataArgs,
    componentArgs
) {
    this.set(...);
}
```

با:

```ts
this === Component instance
```

اجرا شود.

---

# 12. Arrow Function

این رفتار باید مستند و Type Contract آن مشخص باشد.

Function معمولی:

```ts
CLICK: function () {
    this.set(...);
}
```

از `.call(this, ...)` استفاده می‌کند و `this` آن قابل bind شدن است.

Arrow Function:

```ts
CLICK: () => {
    ...
}
```

`this` را از scope بیرونی می‌گیرد و `.call()` نمی‌تواند آن را تغییر دهد.

بنابراین:

> اگر callback به Component `this` نیاز دارد، باید از `function` استفاده شود.

Arrow function همچنان برای callbackهایی که به `this` نیاز ندارند مجاز است.

# 13. ComponentIcon Constructor

Constructor باید `MethodsConfigType` را دریافت کند و Genericهای Component-specific را حفظ کند.

به‌صورت مفهومی:

```ts
constructor(
    props: ComponentIconProps,
    methods?: MethodsConfigType<
        MethodsComponentArgs,
        MethodsDataArgs,
        ComponentIcon

```

ساختار دقیق Genericها باید با قرارداد فعلی `CreateCategoryComponent` منطبق شود و نباید architecture جدیدی خارج از scope این Plan ایجاد شود.

# 15. حذف Double Loop

Implementation قبلی:

```ts
for (...) {
    for (...) {
        ...
    }
}
```

حذف شود.

دلیل:

* `methodName` عملاً برای lookup لازم نیست.
* Public API key مستقیماً semantic key است.
* lookup باید O(n) و مستقیم باشد.
* mapping نباید با مقایسه stringهای semantic و runtime انجام شود.

---

# 16. چرا نام Runtime نباید Public شود؟

این API:

```ts
{
    fn_onClickIcon: callback
}
```

باعث coupling می‌شود.

در حالی که:

```ts
{
    CLICK: callback
}
```

Public contract را مستقل از implementation نگه می‌دارد.

در نتیجه تغییر:

```ts
name: "fn_onClickIcon"
```

به:

```ts
name: "handleIconClick"
```

نباید هیچ تغییری در مصرف‌کننده ایجاد کند.

# 17. Backward Compatibility

ساختار قدیمی:

```ts
{
    fn_onClickIcon: function (...) {}
}
```

به API جدید:

```ts
{
    CLICK: function (...) {}
}
```

تغییر می‌کند.

این یک API migration عمدی است.

Compatibility layer در این Plan اضافه نمی‌شود، مگر اینکه در بررسی compile مشخص شود مصرف‌کنندگان خارج از scope به API قدیمی وابسته‌اند.

در آن صورت compatibility باید به صورت migration step جداگانه تعریف شود.

# 20. Acceptance Criteria

Plan زمانی موفق است که تمام موارد زیر برقرار باشند:

### Public API

```ts
{
    CLICK: function (...) {},
    HOVER: function (...) {},
    BLUR: function (...) {}
}
```

معتبر باشد.

### Semantic Keys

Public API فقط بر اساس:

```text
CLICK
HOVER
BLUR
```

کار کند.

### Runtime Names

`fn_onClickIcon` و موارد مشابه فقط internal باشند.

### Type Safety

`dataArgs` و `componentArgs` از Genericهای Method مربوطه infer شوند.

### Callback this

در Function Callback:

```ts
function (...) {}
```

مقدار `this` برابر Component instance باشد.

### Runtime Binding

```text
methods.CLICK
    ↓
_COMPONENT_METHODS.CLICK.destination
```

به‌درستی bind شود.

### Execution

callback با:

```ts
fn.call(this, event, dataArgs, componentArgs)
```

اجرا شود.

### Refactor Safety

تغییر runtime method name نباید Public API را تغییر دهد.

### No New Any

هیچ `any` جدیدی در Public Callback API اضافه نشود.

# 21. تصمیم معماری نهایی

```text
                  Methods.ts
                     │
             ┌───────┴────────┐
             │                │
        semantic key       metadata
          CLICK              args
             │              dataArgs
             │              name
             ▼
     _COMPONENT_METHODS
             │
             │ destination
             ▼
      Consumer Callback
             │
             ▼
       executeMethod()
             │
             ▼
      fn.call(component)
```

اصل نهایی:

**Semantic Key متعلق به Public API است.**

**Runtime Name متعلق به Framework است.**

**Metadata متعلق به `Methods` است.**

**Callback متعلق به Consumer است.**

**Binding متعلق به `ClComponentBase` است.**

این تفکیک باید در تمام Componentهایی که از Methods استفاده می‌کنند قابل تعمیم باشد.
