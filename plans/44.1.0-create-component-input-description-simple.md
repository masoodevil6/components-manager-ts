# پلن 44.1.0 — ساخت `componentInputDescriptionSimple`

> **وضعیت:** پیاده‌سازی شد؛ `npm run build:app` موفق بود  
> **راهنما:** `documents/guides/component-create.md`  
> **الگوی معماری:** `componentInputSimple`  
> **دسته‌بندی:** `simples` موجود  
> **API پیشنهادی:** `UiCategory.UI.Simples.InputDescriptionSimple(config, methods, identity)`

## ۱. هدف و محدوده

یک کامپوننت ساده برای ورود متن چندخطی ایجاد شود. عنصر ورودی باید `<textarea>` بومی باشد و قرارداد مقدار، غیرفعال‌سازی، استایل، border و رویدادهای focus/change تا حد امکان با `ComponentInputSimple` هماهنگ بماند.

کامپوننت جدید است؛ در ساختار فعلی `src/framework/module_ui/module_components/lists` کامپوننتی با نام `ComponentInputDescriptionSimple` پیدا نشد. آن را به دسته‌بندی موجود `Simples` اضافه کن و دسته‌بندی تازه نساز. این پلن مهاجرت Legacy نیست و نباید رفتار `ComponentInputSimple` یا مصرف‌کنندگان فعلی آن را تغییر دهد. Label و validation در صورت نیاز مسئولیت کامپوننت‌های ترکیبی والد باقی می‌مانند.

## ۲. ساختار و قرارداد رندر

الگوی بیرونی از `ComponentStructureTrait` و الگوی فرم از `ComponentInputSimple` پیروی کند. چون `ComponentInputSimple` عنصر `<input>` می‌سازد، خود آن را به‌عنوان ورودی داخلی instantiate نکن؛ renderer جدید باید `<textarea>` را بسازد.

```text
COMPONENT
└── STRUCTURE
    └── FORM: part-input-description-simple-form
        └── ComponentBorder (قاب اصلی و مستقیم فرم)
            └── prop_content
                ├── TEXTAREA: part-input-description-simple-textarea
                └── CLEAR_ICON: part-input-description-simple-clear-icon
                    (با همان قرارداد پاک‌کردن مقدار در ComponentInputSimple)
```

- `ComponentBorder` فرزند مستقیم و قاب اصلی `FORM` باشد؛ دقیقاً مانند `ComponentInputSimple`، textarea باید در `prop_content` همین `ComponentBorder` رندر شود.
- خود textarea بیرون از `ComponentBorder`، کنار آن یا در یک border دوم قرار نگیرد. `ComponentBorder` مالک border، radius، پس‌زمینه و حالت focus است.
- آیکون پاک‌کردن نیز در صورت استفاده، در محتوای همین `ComponentBorder` و کنار textarea قرار بگیرد؛ border جداگانه و تکراری ساخته نشود.
- textarea تمام عرض قاب را بگیرد، مقدار observable را نمایش دهد و متن طولانی را در چند خط نگه دارد.
- ارتفاع تک‌خطی `ComponentInputSimple` به textarea تحمیل نشود. ارتفاع اولیه با ویژگی بومی `rows` تعیین شود و resize عمودی از طریق style قابل کنترل باشد.
- برای جلوگیری از تداخل متن با آیکون پاک‌کردن، فضای انتهایی textarea متناسب با `directionRtl` در نظر گرفته شود.
- رفتار border عادی، focus، radius، width و رنگ‌های آن از الگوی `ComponentInputSimple` گرفته شود و مقادیر size با `CoreConfig.Settings.SizeName.observable()` و `UtilStyle` محاسبه شوند.

## ۳. Props

Props پایهٔ `ComponentStructureTrait` ارث برسند و دوباره تعریف نشوند. قراردادهای مشترک با `ComponentInputSimple` تا حد ممکن هم‌نام بمانند تا استفاده در کامپوننت‌های فرم ساده باشد.

| Prop | نوع | پیش‌فرض پیشنهادی | کاربرد |
|---|---|---|---|
| `prop_inputName` | `string \| null` | `null` | نام فیلد؛ در صورت وجود، نام native textarea مطابق قرارداد فرم ساخته شود. |
| `prop_inputDisable` | `boolean` | `false` | غیرفعال‌کردن textarea و تعاملات وابسته. |
| `prop_inputValue` | `string \| null` | `null` | مقدار controlled متن چندخطی. |
| `prop_inputClass` | `string[]` | `['form-control']` | کلاس‌های textarea. |
| `prop_inputStyles` | `Record<string, string>` | `{}` | استایل‌های سفارشی textarea با merge واکنشی. |
| `prop_inputPlaceholder` | `string \| null` | `null` | متن راهنمای textarea. |
| `prop_inputRows` | `number` | `4` | تعداد سطرهای اولیه؛ مقدار نامعتبر یا کمتر از ۱ به ۱ محدود شود. |
| `prop_inputResize` | `'none' \| 'both' \| 'horizontal' \| 'vertical'` | `'vertical'` | سیاست resize بومی textarea. |
| `prop_inputBorderColor` | `string \| null` | `null` | رنگ border عادی؛ مقدار پیش‌فرض از الگوی InputSimple بیاید. |
| `prop_inputBorderColorFocus` | `string \| null` | `null` | رنگ border هنگام focus؛ مستقل از hover. |
| `prop_inputBorderWidth` | `UtilConst.Sizes` | `UtilConst.Sizes.M` | اندازهٔ border با تبدیل util. |
| `prop_inputBorderRadius` | `UtilConst.Sizes` | `UtilConst.Sizes.M` | اندازهٔ radius با تبدیل util. |
| `prop_inputBorderTopLeftRadiusHas` | `boolean` | `true` | فعال یا غیرفعال‌کردن radius گوشهٔ مربوط. |
| `prop_inputBorderTopRightRadiusHas` | `boolean` | `true` | فعال یا غیرفعال‌کردن radius گوشهٔ مربوط. |
| `prop_inputBorderBottomLeftRadiusHas` | `boolean` | `true` | فعال یا غیرفعال‌کردن radius گوشهٔ مربوط. |
| `prop_inputBorderBottomRightRadiusHas` | `boolean` | `true` | فعال یا غیرفعال‌کردن radius گوشهٔ مربوط. |
| `prop_inputBorderTopHas` | `boolean` | `true` | نمایش border بالایی. |
| `prop_inputBorderRightHas` | `boolean` | `true` | نمایش border سمت راست. |
| `prop_inputBorderBottomHas` | `boolean` | `true` | نمایش border پایینی. |
| `prop_inputBorderLeftHas` | `boolean` | `true` | نمایش border سمت چپ. |

برای حفظ هم‌خوانی API با InputSimple، clear icon در نسخهٔ اول حفظ شود و با `prop_inputDisable` رفتار غیرفعال داشته باشد. اگر حین بررسی implementation، الگوی فعلی InputSimple برای مقدار خالی یا دسترس‌پذیری مانع textarea شد، اصلاح باید محدود به همین کامپوننت باشد و در تصمیم‌های implementation ثبت شود.

همهٔ props با `Define_ComponentProp<T>` و metadata ترجمه‌شده از `Keys` تعریف شوند. `PropsType` و `PropsConfigType` با `ExtractPropsType` و `ExtractPropsConfigType` استخراج شوند. propهای مخصوص `<input>` مانند `prop_inputType`, `prop_inputMin` و `prop_inputMax` به این کامپوننت منتقل نشوند.

## ۴. Methods و رفتار مقدار

| Method | قرارداد |
|---|---|
| `INPUT_CHANGE` | پس از هر رویداد `input`، مقدار جدید در `prop_inputValue` ذخیره و سپس `VALUE` به callback داده شود. مقدار خالی مطابق InputSimple به `null` تبدیل شود. |
| `INPUT_FOCUS` | هنگام focus واقعی textarea، با مقدار فعلی `VALUE` اجرا شود. |
| `INPUT_BLUR` | هنگام blur واقعی textarea، با مقدار فعلی `VALUE` اجرا شود. |

- تغییر بیرونی prop مستقیم یا Observable باید مقدار native textarea را به‌روزرسانی کند.
- رویداد تایپ و پاک‌کردن مقدار هر کدام دقیقاً یک بار `INPUT_CHANGE` را اجرا کنند.
- در حالت disabled، textarea قابل تایپ نباشد و clear icon مقدار را تغییر ندهد.
- هیچ `input` بومی پنهان یا `ComponentInputSimple` موازی ساخته نشود.

## ۵. Schema و پیاده‌سازی Runtime

`COMPONENT` و `STRUCTURE` در ابتدای `Schemas` از `ComponentStructureTrait.schemas` گرفته شوند. schemaهای اختصاصی:

| Schema | Part | Props اصلی |
|---|---|---|
| `FORM` | `part-input-description-simple-form` | propهای border، radius و disabled |
| `TEXTAREA` | `part-input-description-simple-textarea` | name، disabled، value، class، styles، placeholder، rows و resize |
| `CLEAR_ICON` | `part-input-description-simple-clear-icon` | disabled و value |

- `Schemas.ts` فقط part و props مصرفی را تعریف کند؛ ساخت DOM و منطق مقدار در کلاس Runtime باشد.
- `ComponentInputDescriptionSimple.ts` یک `<textarea>` native با `CoreReactive.App` ایجاد کند و `input`, `focus`, `blur` را به Methods متصل کند.
- محاسبهٔ رنگ focus و انتقال تنظیمات border/radius به `ComponentBorder` مشابه `ComponentInputSimple` انجام شود.
- font-size و padding با utilهای موجود و `config.sizeName` محاسبه شوند. ارتفاع با `rows` مدیریت شود، نه height ثابت تک‌خطی.
- مقدار در DOM با property binding تنظیم شود، نه `innerHTML`.
- scope، listenerها، `ComponentBorder`, `ComponentIcon` و Step در `dispose()` آزاد شوند؛ dispose باید idempotent باشد.

## ۶. فایل‌ها و ثبت

```text
src/framework/module_ui/module_components/lists/componentInputDescriptionSimple/
├── Definition.ts
├── Props.ts
├── Schemas.ts
├── Methods.ts
├── Step.ts
├── ComponentInputDescriptionSimpleBase.ts
├── ComponentInputDescriptionSimple.ts
├── index.ts
└── examples/
    ├── Default.ts
    ├── Disabled.ts
    ├── CustomRows.ts
    └── index.ts

src/framework/module_ui/module_categories/lists/ui/simples/inputDescriptionSimple/
├── Definition.ts
└── index.ts
```

1. Definition یکتا با `id: "component_input_description_simple"`, `name: "componentInputDescriptionSimple"` و `version: "v1.0.0"` بساز.
2. Module component را در `module_ui/module_components/lists/index.ts` ثبت و از barrel عمومی lists export کن.
3. Category callable را زیر `UI.Simples.InputDescriptionSimple` اضافه کن؛ برای نوع props و methods از همان genericهای category در `simples/inputSimple/Definition.ts` استفاده کن.
4. کامپوننت را به فهرست اعضای Category موجود `Simples` اضافه و از barrel آن export کن؛ Category جدید نساز.
5. ثبت و نمایش از مسیر فعلی Category `Simples` انجام می‌شود و ساختار موجود آن حفظ می‌شود.
6. component، props، schemas، methods و مثال‌ها و نام/توضیحات Category جدید را در `Keys.ts`, `Fa.ts` و `En.ts` ثبت کن.
7. مثال پیش‌فرض باید با Category callable ساخته شود و `HTMLElement` برگرداند؛ هیچ import از Legacy در component یا مثال‌ها مجاز نیست.

## ۷. مثال‌ها

- **Default:** textarea controlled با placeholder و چند خط متن؛ تغییر مقدار در callback قابل مشاهده باشد.
- **Disabled:** مقدار موجود نمایش داده شود ولی ویرایش و پاک‌کردن ممکن نباشد.
- **CustomRows:** تعداد سطر متفاوت و resize عمودی برای نشان‌دادن تفاوت با ورودی تک‌خطی.

نام و توضیحات مثال‌ها از زبان‌های Fa/En خوانده شوند. در مثال‌ها `ComponentInputSimple` برای ورودی اصلی استفاده نشود.

## ۸. معیارهای پذیرش و بررسی

- `UiCategory.UI.Simples.InputDescriptionSimple` از ComponentManager resolve شود و صفحهٔ Components آن را زیر دسته‌بندی موجود `Simples` نشان دهد.
- DOM ورودی یک `<textarea>` باشد؛ `<input>` تک‌خطی رندر نشود.
- مقدار اولیه، تغییر prop/Observable، نام، placeholder، disabled و rows درست اعمال شوند.
- مقدار خالی و clear icon با قرارداد `null` و `INPUT_CHANGE` سازگار باشند و callback تکراری ایجاد نشود.
- focus/blur رنگ border را مانند الگوی InputSimple تغییر دهند؛ تنظیمات border و چهار radius از props پیروی کنند.
- متن چندخطی wrap شود و height ثابت تک‌خطی نگیرد؛ resize مطابق prop و ارتفاع rows کار کند.
- LTR/RTL، آیکون clear و padding متن با هم تداخل نداشته باشند.
- `dispose()` فرزندان، listenerها و Step را آزاد کند.
- مثال‌ها بدون `[object Object]` رندر شوند، `npm run build:app` موفق شود و `git diff --check` خطایی ندهد.

## ۹. خارج از محدوده

- Label و validation؛ این‌ها در کامپوننت والد ترکیب می‌شوند.
- autosize براساس طول متن؛ در نسخهٔ اول از native `rows` و resize استفاده شود.
- قابلیت toolbar، شمارندهٔ کاراکتر، rich text و markdown.
- تغییر در `ComponentInputSimple` یا تغییر مصرف‌کنندگان آن.
