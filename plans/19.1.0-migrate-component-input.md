# Plan 19.1.0 — انتقال ComponentInput به معماری جدید

> وضعیت: پیاده‌سازی و آزمون رفتاری انجام شد؛ ویژگی‌های label از طریق `ComponentLabelTrait` به کامپوننت مرجع افزوده شدند.
>
> منبع رفتار: `last/tools/components/inputs/ComponentInput.ts`.
>
> راهنمای معماری: `documents/guides/component-create.md`.
>
> مقصد: `src/framework/module_ui/module_components/lists/componentInput/` و API عمومی `UiCategory.UI.Inputs.Input(config, methods, identity)`.

## ۱. هدف و محدوده

کامپوننت ورودی Legacy را به ساختار declarative/runtime جدید منتقل کن. ورودی متنی کنترل‌شده، name/value/disabled، placeholder و type، آیکون اختیاری، دکمهٔ افزودن، رفتار focus/blur و تغییر مقدار، و نمایش اعتبارسنجی باید حفظ شوند. اندازه‌ها باید از `CoreConfig.Settings.SizeName` و utilهای سیستم محاسبه شوند؛ `prop_size` متعلق به Legacy است و نباید به API جدید منتقل شود.

در runtime جدید از `CoreComponents`، `CoreReactive`، `CoreObservable`، `CoreEvent`، `CoreConfig`، `UtilStyle` و componentهای جدید استفاده کن. import یا استفادهٔ اجرایی از `last/`، `ReactiveElement`، `Observable`، `ComponentBase`، `TOOLS`، `GOG_*` و componentهای Legacy ممنوع است.

این پلن انتقال خود `ComponentInput` و ثبت عمومی آن را پوشش می‌دهد. بازنویسی consumerهای قدیمی خارج از محدوده است؛ مصرف‌کنندگان را پیدا کن، سازگاری API آن‌ها را ثبت کن و فقط اصلاح لازم برای جلوگیری از شکست build را انجام بده.

## ۲. رفتار و API موجود در Legacy

کامپوننت از props پایهٔ component، structure، form-input، value و label استفاده می‌کند. در ساختار جدید، خود input باید حتماً با `ComponentInputSimple` جدید ساخته شود؛ ساخت `<input>` خام یا پیاده‌سازی دوبارهٔ رفتار input داخل `ComponentInput` مجاز نیست. `ComponentInputSimple` مقدار، نام، نوع، placeholder، disabled، class/styles و شعاع گوشه‌ها را دریافت می‌کند و مالک input واقعی، value binding و focus/blur است. آیکون اختیاری کنار آن قرار می‌گیرد و با کلیک روی آیکون focus به `ComponentInputSimple` منتقل می‌شود. رنگ border هنگام focus به `SECONDARY/GRADE_1` می‌رود و در blur به رنگ عادی بازمی‌گردد. در type عددی spinner پیش‌فرض مرورگر مخفی می‌شود.

دکمهٔ افزودن فقط وقتی `prop_btnAddStatus` فعال و ورودی enabled باشد نمایش داده می‌شود؛ عرض آن از `prop_btnAddWidth` می‌آید و کلیک آن callback جدا دارد. اعتبارسنجی فقط با `prop_hasRules` فعال می‌شود و تنظیمات absolute، rules و پیام‌ها به `ComponentValidate` داده می‌شوند. جزئیات بصری پس‌زمینه، radius، جهت RTL/LTR و اندازه‌ها از Legacy بازبینی و با utilهای جدید بازسازی شوند.

### ۲.۱. Props اختصاصی

Props ارثیِ form-input/value/label و `ComponentStructureTrait` را دوباره تعریف نکن. فهرست نهایی inherited props را از helperهای فعلی Core استخراج کن و نوع و رفتارشان را در پیاده‌سازی حفظ کن.

| Prop Legacy | نوع/پیش‌فرض Legacy | قرارداد مهاجرت |
|:---|:---|:---|
| `prop_title` | `string \| null`, پیش‌فرض `null` | برای عنوان مرتبط با اعتبارسنجی در Legacy استفاده شده؛ با `prop_labelTitle` ارثی اشتباه نشود. مصرف واقعی آن در validator بررسی شود. |
| `prop_backgroundColorForm` | string, `secondaryColor1` | پس‌زمینهٔ قاب فرم؛ روی border/content مناسب اعمال شود. |
| `prop_formBorderRadius` | سایز، `M` | شعاع قاب با `UtilStyle.Css_BorderRadius` و config سایز محاسبه شود؛ در صورت نیاز به حفظ prop، قرارداد Legacy ثبت شود. |
| `prop_colorIcon` | string, `""` | مصرف مؤثر در renderer بررسی شود؛ اگر واقعاً برای رنگ icon است، به رنگ آیکون جدید نگاشت شود. |
| `prop_size` | سایز، `M` | حذف شود؛ اندازه فقط از `CoreConfig.Settings.SizeName` خوانده شود. |
| `prop_inputClass` | `string[]`, `['form-control']` | classهای input حفظ شوند. |
| `prop_inputStyles` | `Record<string,string>`, `{}` | استایل سفارشی input با قاعدهٔ merge مشخص و واکنشی اعمال شود. |
| `prop_inputBorderColor` | string, `primaryColor1` | رنگ عادی border؛ به API Border/InputSimple نگاشت شود. |
| `prop_inputBorderColorFocus` | string, `secondaryColor1` | رنگ border هنگام focus؛ اتصال آن به focus state باید مستقل از hover باشد. |
| `prop_inputBorderWidth` | سایز، `M` | اگر در Legacy مؤثر است حفظ شود؛ مقدار CSS با `UtilStyle.Css_BorderWidth` و config جاری محاسبه شود. |
| `prop_inputBorderRadius` | سایز، `M` | اگر در Legacy مؤثر است حفظ شود و با radius فرم/گوشه‌های گروهی تداخل نکند. |
| `prop_type` | enum، `string` | enum جدید با مقادیر معتبر HTML: `string`, `number`, `email`, `password`, `tel`, `url`, `search`, `date`, `time`, `datetime-local`. مقدار `string` به `text` DOM نگاشت شود. |
| `prop_placeholder` | `string \| null`, `null` | به placeholder input نگاشت شود. |
| `prop_icon` | آیکون یا null، `null` | آیکون ورودی اختیاری؛ کلیک روی آن ورودی را focus کند. |
| `prop_btnAddStatus` | boolean, `false` | نمایش/عدم نمایش دکمهٔ افزودن؛ در disabled مخفی بماند. |
| `prop_btnAddWidth` | number, `120` | عرض دکمه برحسب px؛ فضای ورودی بر اساس آن کم شود. |
| `prop_btnAddIcon` | string, `"&plus;"` | Legacy در ساخت دکمهٔ فعلی آن را به Button نمی‌فرستد؛ پیش از تصمیم حذف، تمام مصرف‌ها و قصد API بررسی شود. |
| `prop_btnAddTitle` | string, `"add item"` | عنوان دکمهٔ افزودن. |
| `prop_btnAddClass` | `string[]`, `[]` | کلاس‌های اضافی دکمه؛ کلاس‌های پیش‌فرض Legacy نیز حفظ شوند. |
| `prop_btnColor` | نوع دکمه، `SUBMIT` | به semantic/variant متناظر Button جدید نگاشت شود؛ mapping مقادیر Legacy مستند شود. |
| `prop_hasRules` | boolean, `false` | validator فقط در حالت true ساخته/نمایش داده شود. |
| `prop_isAbsoluteRule` | boolean, `false` | به `ComponentValidate` جدید منتقل شود. |
| `prop_listRules` | آرایه، `[]` | قرارداد ruleها و نوع داده با Props کامپوننت Validate جدید تطبیق داده شود. |
| `prop_msgRules` | `Record<string,string> \| null`, `null` | پیام‌های سفارشی validation حفظ شوند. |

props پایه از `ComponentStructureTrait` به ارث برسند. props مقدار، نام، disabled و label از helperهای فرم جدید استفاده کنند؛ هر prop سفارشی با `Define_ComponentProp<T>`، metadata ترجمه‌شده از `Keys` و typeهای `ExtractPropsType` و `ExtractPropsConfigType` تعریف شود. nullable بودن و پیش‌فرض هر prop صریح باشد.

### ۲.۲. Methods

| Method جدید | نام Legacy | قرارداد پیشنهادی |
|:---|:---|:---|
| `INPUT_CHANGE` | `fn_onInputChange` | بعد از تایپ، مقدار جدید `VALUE` و DOM event به callback برسد؛ مقدار داخلی قبل از callback به‌روز باشد. |
| `INPUT_FOCUS` | `fn_onInputFocus` | هنگام focus واقعی input اجرا شود و مقدار جاری را در `VALUE` بدهد. |
| `INPUT_BLUR` | `fn_onInputBlur` | هنگام blur واقعی input اجرا شود و مقدار جاری را در `VALUE` بدهد. |
| `CLICK_BUTTON` | `fn_onClickButton` | با کلیک دکمهٔ افزودن اجرا شود؛ event و مقدار جاری در قرارداد callback مشخص باشند. |

metadata و `dataArgs` با نام‌گذاری استاندارد guide تعریف شوند و handlerها فقط از `executeMethod` عبور کنند. رفتار مقدار خالی (`null` یا `""`) با prop پایه و قرارداد `ComponentInputSimple` جدید یکسان و مستند شود؛ callbackها نباید دو بار برای یک رویداد اجرا شوند.

## ۳. Schemas و درخت DOM

`COMPONENT` و `STRUCTURE` از `ComponentStructureTrait.schemas` در ابتدای Schemas قرار گیرند. schemaهای اختصاصی پیشنهادی:

| Schema | part پیشنهادی | نقش |
|:---|:---|:---|
| `FORM` | `part-input-form` | ریشهٔ فرم و composition اصلی. |
| `INPUT` | `part-input-input` | renderer این part باید `ComponentInputSimple` جدید را instantiate کند و reactive props/methods ورودی را به آن forward کند؛ هیچ input خامی در `ComponentInput` ساخته نشود. |
| `ICON` | `part-input-icon` | آیکون اختیاری کنار ورودی و انتقال focus. |
| `BUTTON` | `part-input-button` | دکمهٔ افزودن شرطی. |
| `VALIDATE` | `part-input-validate` | نمایش شرطی `ComponentValidate` جدید. |

Schema فقط part و propهای مصرفی را تعریف کند؛ rendererها در `ComponentInput.ts` باشند. part ورودی باید از `UiCategory.UI.Simples.InputSimple` یا کلاس جدید `ComponentInputSimple` ساخته شود؛ API عمومی Category در composition ترجیح دارد. از `ComponentIcon`, `ComponentButton` و `ComponentValidate` جدید برای بخش‌های مکمل استفاده کن. `ComponentInputSimple` مالک input DOM، value binding، focus state و border/focus styling است؛ ComponentInput نباید یک input یا border هم‌پوشان برای همان فیلد بسازد. اگر wrapper بیرونی Legacy برای layout لازم است، فقط نقش container را داشته باشد و border قابل مشاهدهٔ تکراری نسازد.

## ۴. رفتار، اندازه و تعامل

- `prop_size` منتقل نشود. تمام font-size، padding، height، border-width، border-radius و icon sizing با `CoreConfig.Settings.SizeName.observable()` و `UtilStyle` محاسبه شوند.
- مقدار input controlled باشد؛ تغییر DOM، prop مقدار، فرم و callback در یک مسیر همگام شوند.
- name طبق رفتار Legacy با پسوند `[value]` ساخته شود؛ رفتار `name === null` با form helpers و فرم HTML بررسی شود.
- `prop_type === string` به `text` نگاشت شود و typeهای enum‌شده مستقیماً به DOM type معتبر تبدیل شوند.
- focus/blur را از callbackهای `ComponentInputSimple` جدید دریافت کن؛ input DOM جداگانه نساز. رنگ focus متعلق به border داخلی InputSimple است و با hover اشتباه نشود. disabled ظاهر و رفتار Legacy را حفظ کند و focus/clickهای غیرفعال callback نسازند.
- آیکون فقط در صورت وجود نمایش داده شود. کلیک آیکون input را focus کند و رویداد click والد را ناخواسته اجرا نکند.
- وجود دکمه به `prop_btnAddStatus && !disabled` وابسته باشد. محاسبهٔ عرض input با عرض button و وجود icon واکنشی باشد و در RTL/LTR از logical properties/config استفاده کند.
- validator فقط در صورت فعال‌بودن rules نمایش داده شود؛ `prop_title`, rules, messages, absolute mode و value به component جدید با قرارداد دقیق پاس شوند.
- استایل حذف spinner فقط برای `type=number` و با selector محدود به همین instance اعمال شود؛ ترجیحاً از API CSS/style موجود استفاده کن و global style تزریق نکن.
- `dispose()` منابع Step، listenerها، observableها و child componentهای ساخته‌شده را آزاد کند.

## ۶. وابستگی‌ها و مصرف‌کنندگان

- ورودی واقعی الزاماً `ComponentInputSimple` جدید باشد؛ از API عمومی `UiCategory.UI.Simples.InputSimple` یا کلاس آن استفاده کن و props/methods لازم را به‌صورت reactive forward کن. callbackهای آزمایشی/logging در مصرف‌کنندهٔ داخلی نباید باقی بمانند.
- آیکون از `ComponentIcon` جدید، دکمه از `ComponentButton` جدید و validation از `ComponentValidate` جدید استفاده کند.
- مصرف‌های `ComponentInput` در repo، Categoryهای inputs، bootstrap، manager و Examples جست‌وجو شوند. تغییر مصرف‌کنندگان Legacy خارج از این پلن است؛ هر نیاز سازگاری در گزارش اجرا ثبت شود.
- هیچ import runtime از `last/`، `tools/components` یا `core/ComponentBase` در مقصد باقی نماند.

## ۹. تصمیم‌های باز و ریسک‌ها

1. Legacy هم `prop_title` دارد و هم prop عنوان label را از ساختار پایه ارث می‌برد؛ renderer فعلی title سفارشی را به Validate می‌دهد، درحالی‌که Example عنوان label را مقداردهی می‌کند. این دو را یکی نکن؛ کاربرد فعال هرکدام و metadata آن را در مرحلهٔ بررسی مشخص کن.
2. `prop_btnAddIcon` در schema/config هست، اما renderer فعال دکمه آن را به `ComponentButtonSimple` نمی‌فرستد. پیش از افزودن یا حذف قابلیت، مصرف واقعی آن در کل repo بررسی شود؛ رفتار تازه بدون نیاز مصرف‌کننده نساز.
3. Legacy هم قاب بیرونی `ComponentBorder` دارد و هم `ComponentInputSimple` را داخل آن می‌سازد. نسخهٔ جدید باید همچنان `ComponentInputSimple` را برای ورودی واقعی به‌کار ببرد، اما border/focus نمایان را فقط یک‌بار اعمال کند؛ قاب اضافی Legacy را به wrapper/layout تبدیل کن یا حذفش کن.
4. Legacy handlerهای داخلی InputSimple فقط log می‌کردند. در نسخه جدید، callback عمومی `ComponentInput` مالک رویداد باشد و callback داخلی فرزند باعث duplicate notification نشود.
5. `prop_inputBorderColor`, focus color, width و radius در API Legacy تعریف شده‌اند؛ با renderer و مصرف‌کنندگان بررسی کن کدام‌یک واقعاً مؤثرند و compatibility را پیش از حذف حفظ کن.
