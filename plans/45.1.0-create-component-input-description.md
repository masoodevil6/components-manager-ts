# پلن 45.1.0 — ساخت `componentInputDescription`

> **وضعیت:** پیاده‌سازی شد  
> **دستهٔ ثبت:** `inputs` — عنوان فعلی `Input Components` / «کامپوننت‌های ورودی»  
> **API پیشنهادی:** `UiCategory.UI.Inputs.InputDescription(config, methods, identity)`  
> **راهنمای مبنا:** `documents/guides/component-create.md`

## ۱. هدف و محدوده

یک کامپوننت ترکیبی چندخطی به نام `ComponentInputDescription` ایجاد کن. ساختار کلی آن از `ComponentInput` الگو می‌گیرد، اما کنترل متن را حتماً با کامپوننت موجود `ComponentInputDescriptionSimple` بساز؛ textarea جدید یا نسخهٔ دوم آن در والد ایجاد نشود.

این والد مسئول اتصال label، مقدار و رویدادهای ورودی، و validation است. قاب و رفتار بومی textarea، از جمله clear، disabled، rows، resize و focus، مسئولیت `ComponentInputDescriptionSimple` باقی می‌ماند. کامپوننت ساده در دستهٔ موجود `Simples` ثبت شده است؛ کامپوننت ترکیبی جدید باید در دستهٔ موجود `inputs` با عنوان `Input Components` (در فارسی «کامپوننت‌های ورودی») قرار بگیرد. دسته‌بندی تازه نساز و رفتار `ComponentInput` یا `ComponentInputDescriptionSimple` را تغییر نده.

در بررسی فعلی سورس، `ComponentInputDescription` قدیمی برای انتقال پیدا نشد؛ بنابراین این پلن ساخت کامپوننت جدید با الگوی فعلی است، نه مهاجرت و تطبیق رفتار Legacy.

## ۲. ساختار و قرارداد رندر

```text
COMPONENT
└── STRUCTURE                         از ComponentStructureTrait
    ├── LABEL                         از ComponentLabelTrait
    ├── FORM: part-input-description-form
    │   └── DESCRIPTION: part-input-description-input
    │       └── UiCategory.UI.Simples.InputDescriptionSimple
    └── VALIDATE: part-input-description-validate
```

- `FORM` فقط wrapper ترکیبی والد باشد و child را با عرض کامل نمایش دهد؛ textarea یا `ComponentBorder` دومی نسازد.
- `DESCRIPTION` با `ComponentInputDescriptionSimple` ساخته شود. والد مقدار، نام، placeholder، disabled، rows، resize و تنظیمات ظاهری ورودی را به props متناظر فرزند نگاشت کند.
- label از `ComponentLabelTrait` ساخته شود. کلیک روی label باید textarea واقعی فرزند را focus کند.
- validation با `ComponentValidate` و قرارداد `ComponentInput` انجام شود و مقدار جاری والد را دریافت کند.
- `COMPONENT` و `STRUCTURE` طبق راهنما از `ComponentStructureTrait` به دست آیند؛ schemaهای والد نباید markup یا منطق رندر در خود داشته باشند.

## ۳. Props

Props با `Define_ComponentProp<T>` و ترجمه‌های `Keys` تعریف شوند. `PropsType` و `PropsConfigType` با helperهای `TypeHelpers` استخراج شوند. props مشترک label از `ComponentLabelTrait` ارث‌بری شوند و دوباره تعریف نشوند.

| Prop والد | نوع و پیش‌فرض پیشنهادی | نگاشت/کاربرد |
|---|---|---|
| `prop_name` | `string \| null`, `null` | نام textarea؛ با قرارداد نام‌گذاری `ComponentInput` سازگار باشد. |
| `prop_value` | `string \| null`, `null` | مقدار چندخطی کنترل‌شده و مقدار ورودی validation. |
| `prop_isDisable` | `boolean`, `false` | غیرفعال‌کردن textarea و رفتارهای وابسته. |
| `prop_placeholder` | `string \| null`, `null` | placeholder textarea. |
| `prop_rows` | `number`, `4` | تعداد سطرهای اولیه؛ به rows فرزند نگاشت و حداقل ۱ شود. |
| `prop_resize` | نوع resize پشتیبانی‌شده توسط فرزند, `vertical` | رفتار تغییر اندازهٔ بومی textarea. |
| `prop_inputClass` | `string[]`, `['form-control']` | کلاس‌های textarea. |
| `prop_inputStyles` | `Record<string, string>`, `{}` | استایل‌های سفارشی textarea. |
| `prop_inputBorderColor` و `prop_inputBorderColorFocus` | `string \| null`, `null` | رنگ قاب عادی و focus، طبق API فرزند. |
| `prop_inputBorderWidth` و `prop_inputBorderRadius` | `UtilConst.Sizes`, اندازهٔ پیش‌فرض متناظر با `ComponentInput` | نگاشت به فرزند و محاسبه با utilهای موجود. |
| `prop_backgroundColorForm` و `prop_formBorderRadius` | قرارداد موجود `ComponentInput` | تنظیم wrapper فرم؛ radius با `config.sizeName` محاسبه شود. |
| `prop_title`, `prop_hasRules`, `prop_isAbsoluteRule`, `prop_listRules`, `prop_msgRules` | قرارداد موجود `ComponentInput` | عنوان و تنظیمات validation. |

هیچ propی برای `type`، دکمهٔ افزودن یا آیکونِ متصل به ورودی اضافه نشود؛ این قابلیت‌ها در API فرزند چندخطی وجود ندارند و شاهدی برای نیاز آن‌ها در این کامپوننت نداریم. props چهار گوشه و لبهٔ border فرزند تنها در صورتی به والد افزوده شوند که لازم باشد رفتار ترکیبی مشخصی مانند اتصال یک کنترل کناری پیاده شود؛ در نسخهٔ اول، border مستقل فرزند حفظ شود.

## ۴. Methods و رفتار مقدار

قراردادهای والد از الگوی `ComponentInput` پیروی کنند:

| Method | رفتار |
|---|---|
| `INPUT_CHANGE` | مقدار جدید را در `prop_value` ثبت و `VALUE: string \| null` را یک‌بار به callback ارسال کند؛ مقدار خالی `null` باشد. |
| `INPUT_FOCUS` | رویداد focus واقعی textarea را با مقدار جاری به callback والد منتقل کند. |
| `INPUT_BLUR` | رویداد blur واقعی textarea را با مقدار جاری به callback والد منتقل کند. |

- رویدادهای child به همین سه method والد متصل شوند؛ برای هر تغییر، callback تکراری ساخته نشود.
- تغییر بیرونی `prop_value` یا Observable باید مقدار child را نیز به‌روز کند.
- validation مقدار تازهٔ textarea را ببیند، از جمله مقدار خالی.
- کلیک label باید عنصر `<textarea>` را پیدا کند و focus کند؛ selector ورودی تک‌خطی استفاده نشود.
- از `ComponentInputDescriptionSimple` یک instance مدیریت‌شده بساز و در `dispose()` آن، listenerها، scope و Step والد را به‌صورت idempotent آزاد کن.

## ۵. Schema و Runtime

در `Schemas.ts`، `COMPONENT` و `STRUCTURE` را در ابتدا از `ComponentStructureTrait.schemas` قرار بده و schemaهای label را از `ComponentLabelTrait.schemas` اضافه کن. schemaهای اختصاصی:

| Schema | Part | محتوای مسئول |
|---|---|---|
| `FORM` | `part-input-description-form` | wrapper و props ظاهری فرم |
| `DESCRIPTION` | `part-input-description-input` | جایگاه رندر `ComponentInputDescriptionSimple` |
| `VALIDATE` | `part-input-description-validate` | تنظیمات validation |

- `SchemasType` با `ExtractSchemasType<typeof Schemas>` تعریف شود.
- `Methods.ts` و `Step.ts` مطابق راهنما و الگوی `ComponentInput` باشند؛ Step به شکل factory ساخته و در `disposeStep()` آزاد شود.
- `ComponentInputDescriptionBase`، تعریف props/schema/methods و Definition را مطابق قرارداد فعلی Base بسازد و props مشترک label را با Trait وارد کند.
- `ComponentInputDescription.ts` routing مربوط به Traitها را از متدهای Trait انجام دهد و فقط schemaهای اختصاصی را به render methodهای خود هدایت کند.
- `ComponentValidate` مقدار والد را بگیرد و `prop_referenceComponent` به instance والد اشاره کند.
- تمام computedها با `CoreObservable.App.computed` و scope همان والد ساخته شوند؛ handler یا render در Schema قرار نگیرد.
- `ComponentInputDescriptionSimple` خودش border و textarea را می‌سازد؛ والد نباید آن را داخل border دیگری قرار دهد.

## ۷. مثال‌ها

- **Default:** متن چندخطی، label، placeholder و مشاهدهٔ callback تغییر مقدار.
- **Disabled:** مقدار موجود نمایش داده شود و ویرایش/پاک‌کردن غیرفعال باشد.
- **WithValidation:** قانون required روی مقدار چندخطی خالی و پر بررسی شود و پیام validation از `ComponentValidate` نمایش داده شود.
- مثال‌ها با callable عمومی `UiCategory.UI.Inputs.InputDescription(...)` ساخته شوند و `HTMLElement` برگردانند؛ در صورت استفاده از eventها، قرارداد موجود `MethodsConfigType` رعایت شود.

## ۸. معیارهای پذیرش و بررسی

- `UiCategory.UI.Inputs.InputDescription` از ComponentManager resolve شود و در صفحهٔ Components زیر دستهٔ موجود `inputs` با عنوان `Input Components` نمایش داده شود.
- DOM شامل یک `<textarea>` از فرزند `ComponentInputDescriptionSimple` باشد؛ textarea موازی یا border تکراری ساخته نشود.
- label، placeholder، مقدار اولیه، مقدار خالی، disabled، rows، resize و تغییر Observable درست به فرزند برسند.
- focus از label به textarea منتقل شود و رویدادهای change/focus/blur یک‌بار به والد برسند.
- validation برای مقدار خالی و مقدار واردشده، از `ComponentValidate` کار کند.
- LTR/RTL و اندازه‌های border/radius از قرارداد فرزند و `config.sizeName` پیروی کنند و برخورد متن با clear icon رخ ندهد.
- پس از dispose منابع child و والد آزاد شوند و `[object Object]` در DOM یا مثال‌ها دیده نشود.
- بررسی‌های نهایی: `npm run build:app` و `git diff --check`.

## ۹. خارج از محدوده

- تغییر در `ComponentInput`, `ComponentInputDescriptionSimple`, `ComponentValidate` یا `ComponentLabelTrait`، مگر رفع خطای واقعی و مستقیم ناشی از اتصال والد.
- افزودن toolbar، rich text، markdown، autosize، append button یا API جدید برای ویرایش متن.
- ایجاد دسته‌بندی تازه؛ دستهٔ ترکیبی موجود `inputs` (`Input Components`) و دستهٔ سادهٔ موجود `Simples` استفاده شوند.
- انتقال Legacy؛ در بررسی مخزن فعلی سورس قابل استنادی برای نسخهٔ قدیمی `ComponentInputDescription` پیدا نشد.
