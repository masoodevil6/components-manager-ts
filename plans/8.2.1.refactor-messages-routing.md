# Plan 8.2.1 — Refactor ComponentMessages renderManagerComponent

> **پیش‌نیاز:** Plan 8.2 (ساخت ComponentMessages)
> **هدف:** اصلاح الگوی `renderManagerComponent` در `ComponentMessages` برای توسعه‌پذیری بهتر

## مشکل

در پیاده‌سازی فعلی (Plan 8.2)، `renderManagerComponent` الگوی نامناسبی دارد:

```typescript
// ❌ مشکل‌دار — توسعه‌پذیر نیست
override renderManagerComponent(partName, attrsDefault, data, extra) {
    switch (partName) {
        case Schemas.MESSAGE.part:
            return this.renderContentComponent();  // ← کل ComponentStructure wrapper را می‌سازد!
        case Schemas.ICON.part:
            return this.renderCloseIcon(attrsDefault, data, extra);
        default:
            return super.renderManagerComponent(partName, attrsDefault, data, extra);
    }
}
```

**چرا بد است؟**
1. `MESSAGE.part` به `renderContentComponent()` می‌رود — این کل ComponentStructure wrapper را می‌سازد (لایه `<component-messages>` + `<section>`). ولی `executeSchemaPart` وقتی `MESSAGE.part` را صدا می‌زند، انتظار دارد مستقیم محتوای پیام‌ها را برگرداند، نه کل wrapper.
2. هر part جدید باید بداند کدام one به `renderContentComponent` می‌رود و کدام به متد مستقیم — این منطق پنهان و شکننده است.
3. در الگوی قدیمی (legacy)، هر part مستقیم به متد اختصاصی خودش routing می‌شد:
   ```typescript
   case MESSAGE: return this.template_render_messages(attrsDefault, data, extra);
   case ICON:    return this.componentFn_render_icon(attrsDefault, data, extra);
   ```

## راه‌حل — الگوی ترکیبی (Trait + per-part routing)

**اصل:** هر schema.part مستقیم به متد render اختصاصی خودش routing شود — بدون indirection.

`ComponentStructureTrait` همچنان برای ساخت wrapper پایه (در `renderContentComponent`) استفاده می‌شود — ولی `renderManagerComponent` نباید به `renderContentComponent` برگردد.

### ساختار Partها

ComponentMessages سه لایه part دارد:

| Part | Schema Key | متد render | کاربرد |
|:---|:---|:---|:---|
| `part-component` | COMPONENT (پایه) | `renderComponentSchema` (در ComponentStructure) | لایه خارجی `<component-messages>` |
| `part-component-structure` | STRUCTURE (پایه) | `renderStructureSchema` (در ComponentStructure) | لایه داخلی `<section>` با show/hide |
| `part-messages-message` | MESSAGE (اختصاصی) | `renderMessages` | رندر لیست پیام‌ها |
| `part-messages-icon` | ICON (اختصاصی) | `renderCloseIcon` | رندر آیکون بستن هر پیام |

**نکته:** COMPONENT و STRUCTURE از ComponentStructure به ارث می‌رسند (در `super.renderManagerComponent`). MESSAGE و ICON اختصاصی ComponentMessages هستند.

### جریان رندر صحیح

```
constructor → renderComponent(config, methods)
    → createComponentElement()
        → executeSchemaPart(firstSchema.part)  // ← اولین schema = MESSAGE
            → renderManagerComponent("part-messages-message", attrsDefault, data, extra)
                → this.renderMessages(attrsDefault, data, extra)  // ← مستقیم!

renderContentComponent()  // ← از Trait استفاده می‌کند
    → ComponentStructureTrait.renderContent(this, () => this.renderMessages())
        → ComponentStructure.create({ classList, prop_show, ..., content: () => this.renderMessages() })
            → renderComponentSchema → renderStructureSchema → renderContentComponent
                → content() = this.renderMessages()
```

**نکته کلیدی:** `renderMessages` هم در `renderManagerComponent` (برای executeSchemaPart مستقیم) و هم در `renderContentComponent` (به‌عنوان content callback برای Trait) استفاده می‌شود. این تضاد نیست — `renderMessages` یک متد pure است که `CoreReactive.App` برمی‌گرداند.

### تفاوت با قبل

| جنبه | قبل (Plan 8.2) | بعد (Plan 8.2.1) |
|:---|:---|:---|
| `MESSAGE.part` routing | `renderContentComponent()` (کل wrapper) | `renderMessages(attrsDefault, data, extra)` (مستقیم) |
| `ICON.part` routing | `renderCloseIcon(attrsDefault, data, extra)` | `renderCloseIcon(attrsDefault, data, extra)` (بدون تغییر — مستقیم) |
| `renderContentComponent` | `ComponentStructureTrait.renderContent(this, () => this.renderMessages())` | بدون تغییر — Trait همچنان استفاده می‌شود |
| توسعه‌پذیری | هر part جدید باید بداند کدام به `renderContentComponent` می‌رود | هر part مستقیم به متد خودش — الگوی یکنواخت |

### تغییر در renderCloseIcon — پارامترها از data

در الگوی جدید، `ICON.part` مستقیم از `renderManagerComponent` صدا زده می‌شود. در این حالت `data` شامل Observableهای مربوط به `Schemas.ICON.props` است:
- `prop_iconColor`
- `prop_type`

ولی `renderCloseIcon` در حال حاضر `(index, messageText, prop_type)` قبول می‌کند — این پارامترها از `data` قابل استخراج نیستند (index و messageText در data نیستند).

**راه‌حل:** `renderCloseIcon` باید دو حالت داشته باشد:

1. **از renderManagerComponent (ICON.part):** `data` شامل `prop_iconColor` و `prop_type` است. در این حالت، آیکون مستقیم با این props رندر می‌شود — بدون index/messageText (چون این part مستقل است).

2. **از renderSingleMessage:** `renderCloseIcon` با `(index, messageText, prop_type)` مستقیم صدا زده می‌شود.

**تصمیم:** `renderCloseIcon` به دو متد تقسیم شود:

- `renderCloseIcon(attrsDefault, data, extra)` — برای routing از `renderManagerComponent` (part مستقل)
- `renderCloseIconForMessage(index, messageText, prop_type)` — برای صدا زدن از داخل `renderSingleMessage`

#### بعد — renderCloseIcon (برای routing)

```typescript
protected renderCloseIcon(
    attrsDefault?: PartAttrDefault,
    data?:         Record<string, CoreObservable.App<any>>,
    extra?:        any,
): CoreReactive.App {

    const prop_iconColor = data?.["prop_iconColor"] ?? this._COMPONENT_PROPS_BIND.prop_iconColor;
    const prop_type      = data?.["prop_type"]      ?? this._COMPONENT_PROPS_BIND.prop_type;

    // رندر ComponentIcon برای بستن
    // در این حالت (part مستقل) index و messageText موجود نیستند
    // این part برای metadata و routing مستقل استفاده می‌شود
    const iconElement = UiCategory.UI.Simples.Icon(
        {
            prop_icon:      UiIcons.CreateIcon(UiIcons.Src.FileWindowClose.Definition, { size: 16 }),
            prop_iconClass: ["cursor-pointer"],
            prop_iconStyles: { "inset-inline-end": "5px", "top": "5px", "position": "absolute" },
        },
        {
            CLICK: (event: Event) => {
                event.preventDefault();
                this.executeMethod("CLOSE_MESSAGE", event, {
                    MESSAGE_INDEX: -1,
                    MESSAGE_TEXT:  "",
                    MESSAGE_TYPE:  prop_type.get(),
                });
            },
        },
    ).getElement();

    return CoreReactive.App.span({
        children: [iconElement],
    });
}
```

## نکات مهم

### چرا renderContentComponent تغییر نمی‌کند؟

`renderContentComponent` از `ComponentStructureTrait` استفاده می‌کند که wrapper پایه (`<component-messages>` + `<section>`) را می‌سازد. این wrapper شامل propهای پایه (classList, prop_show, structureClass, ...) است.

`renderMessages` فقط محتوای داخلی (لیست پیام‌ها) را رندر می‌کند — بدون wrapper.

این جداسازی صحیح است:
- **Trait** = wrapper (لایه خارجی)
- **renderMessages** = content (لایه داخلی)

### چرا ICON.part مستقل نگه داشته شد؟

هر schema.part یک مفهوم مستقل است. `ICON.part` نشان می‌دهد که ComponentMessages قابلیت رندر آیکون بستن دارد. این part:
1. در `Schemas.ICON.props` مشخص می‌کند چه propهایی برای icon نیاز است (`prop_iconColor`, `prop_type`)
2. در `renderManagerComponent` به `renderCloseIcon` routing می‌شود
3. ComponentManager می‌تواند از این metadata برای تحلیل استفاده کند

### الگوی کلی برای Componentهای آینده

این الگو برای تمام Componentهای آینده (Button, Input, etc.) قابل تعمیم است:

```typescript
override renderManagerComponent(partName, attrsDefault, data, extra) {
    switch (partName) {
        case Schemas.{PART_A}.part:  return this.render{PartA}(attrsDefault, data, extra);
        case Schemas.{PART_B}.part:  return this.render{PartB}(attrsDefault, data, extra);
        // ... هر part مستقیم به متد خودش
        default:                     return super.renderManagerComponent(partName, attrsDefault, data, extra);
    }
}
```
