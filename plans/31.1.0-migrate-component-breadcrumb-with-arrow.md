# پلن 31.1.0 — انتقال ComponentBreadcrumbWithArrow به ساختار جدید

> **وضعیت:** آمادهٔ پیاده‌سازی  
> **نسخهٔ پلن:** 31.1.0  
> **منبع Legacy:** `last/Older/components.js`، بخش 033-02، حدود خطوط 27256 تا 27830  
> **نمونهٔ Legacy:** `last/Older/index.html`، بخش Breadcrumb with arrow؛ همچنین مصرف‌کننده‌های قدیمی Table to Excel و Table to Print  
> **راهنما:** `documents/guides/component-create.md`  
> **مقصد پیشنهادی:** `src/framework/module_ui/module_components/lists/componentBreadcrumbWithArrow/`  
> **دسته‌بندی UI:** گروه موجود `Breadcrumb`  
> **API پیشنهادی:** `UiCategory.UI.Breadcrumb.BreadcrumbWithArrow(config, methods, identity)`

## 1. هدف و محدوده

`ComponentBreadcrumbWithArrow` از Legacy به قرارداد ComponentManager منتقل شود. این کامپوننت مسیر متنی/فلش‌دار `ComponentBreadcrumb` نیست: در نمایش عریض، مرحله‌ها به شکل قطعه‌های چندضلعی chevron با نشان مرحله و سایه نمایش داده می‌شوند؛ در نمایش باریک، مرحله‌ها به صورت دایره‌های متصل با عنوان و شماره یا تیک نمایش دارند.

کامپوننت جدید جدا از `ComponentBreadcrumb` باقی می‌ماند و در همان گروه UI یعنی `Breadcrumb` ثبت می‌شود. پیاده‌سازی جدید باید با SVG reactive خود Core ساخته شود؛ از `innerHTML`، `document.querySelector`، custom element سراسری و handler رشته‌ای Legacy استفاده نشود. ماژول عمومی `module_shapes` که در پلن 30.1.0 ایجاد شد اکنون بخش CSS دارد؛ در این پلن یک بخش مستقل `Svg` به همان ماژول افزوده می‌شود تا محاسبات و تبدیل‌های هندسی عمومی مورد نیاز SVG را فراهم کند. ساخت واقعی elementهای SVG همچنان با primitiveهای reactive Core مانند `svgPolygon`, `svgCircle`, `svgPath`, `svgText` و `svgG` انجام می‌شود.

**خارج از محدوده:** تغییر مصرف‌کننده‌های قدیمی Table to Excel/Print، تغییر رفتار مسیر‌یابی یا خودکار کردن انتخاب مرحله، و ادغام دو نوع Breadcrumb در یک کامپوننت.

## 2. شواهد و رفتار Legacy

- تعریف Base و کلاس اجرایی در `last/Older/components.js`، بخش 033-02 است. Schema اجرایی تنها یک بخش `part_breadcrumbs` دارد و همهٔ تنظیمات نمایشی را دریافت می‌کند.
- `prop_breadcrumbs` آرایه‌ای از شیء مرحله‌هاست؛ حداقل `title` برای نمایش لازم است. callback شیء کامل مرحله را دریافت می‌کند، نه فقط شناسه.
- در هر دو layout، وضعیت نمایشی از **اندیس صفرمبنا** محاسبه می‌شود: مرحله‌ای که `index <= prop_stepSelected` باشد فعال نمایش داده می‌شود. مقدار `id` برای رنگ فعال استفاده نمی‌شود. مقدار پیش‌فرض `prop_stepSelected` برابر `1` است؛ بنابراین در مقدار پیش‌فرض دو مرحلهٔ اول active هستند. این قرارداد در انتقال حفظ شود و با منطق انتخاب `ComponentBreadcrumb` که بر اساس id است یکی نشود.
- کلیک روی سطح مرحله، متن، دایره، تیک یا connector باید یک بار callback انتخاب را با event و همان شیء مرحله اجرا کند.
- handler داخلی `fn_onBackClick(event, stepData)` در واقع callback بیرونی `fn_callback(event, stepData)` را فراخوانی می‌کند. این کامپوننت دکمهٔ Back یا callback مستقل Back ندارد؛ نام داخلی Legacy نباید به API جدید منتقل شود.
- در layout باریک، دایره‌ها با یک خط اتصال افقی قرار می‌گیرند؛ عنوان مرحله بالای دایره است؛ مرحله‌های فعال fill فعال و تیک، و مرحله‌های غیرفعال شماره دارند.
- در layout عریض، هر مرحله یک Polygon اصلی و یک connector جداگانه (به‌جز آخرین مرحله) دارد. `prop_side`, `prop_length`, `prop_gap` و `prop_height` هندسه را تنظیم می‌کنند. Polygonها و نشانهٔ داخل مرحله سایه دارند و سطح چندضلعی نیز highlight داخلی دارد.
- breakpoint قدیمی با `tools_css.standardScreanWidth.m` برابر 768px است و از عرض پنجره خوانده می‌شود. در نسخهٔ جدید، layout بر اساس عرض واقعی container و `ResizeObserver` تعیین شود تا کامپوننت در containerهای باریک هم درست واکنش دهد؛ threshold پیش‌فرض 768px بماند.
- اندازهٔ SVG قدیمی `width: 100%` و `height: prop_height * 2.5` است. نسخهٔ جدید برای SVG، `viewBox` معتبر و اندازهٔ responsive بسازد و حالت صفر/یک مرحله را بدون تقسیم بر صفر مدیریت کند.
- فرمول mobile در Legacy مقدار `prop_marginMinPerent` را به شکل `(value / 10) * width` اعمال می‌کند که برای مقدار پیش‌فرض 10 فضای منفی ایجاد می‌کند. در نسخهٔ جدید این مقدار مطابق نام prop به‌عنوان درصد تفسیر شود: `width * value / 100`؛ مقدار در محدودهٔ معتبر clamp شود.
- `prop_gap` در Legacy برای فاصله/هم‌پوشانی connectorهای عریض مصرف می‌شود؛ جابه‌جایی hard-code شدهٔ `5 * index` نباید عیناً به‌عنوان API جدا منتقل شود. هندسه باید با `prop_gap` و جهت ساخته شود.
- مثال Legacy برای این کامپوننت `prop_size` هم ارسال می‌کند، اما این prop در Base یا renderer تعریف/مصرف نمی‌شود؛ به Props جدید منتقل نشود.
- مقادیر پیش‌فرض رنگ در `last/Older/tools.js` از `tools_const.styles.breadcrumbWithArrow` می‌آیند: پس‌زمینهٔ غیرفعال `primaryColor1`، متن غیرفعال `darkColor1`، پس‌زمینهٔ فعال `secondaryColor1`، متن فعال `shanColor1` و سایه `shadowColor2`.
- Legacy برای متن و تیک از انتخاب `prop_colorUnactive` در حالت active و `prop_colorActive` در حالت inactive استفاده می‌کند. این نگاشت نام‌گذاری‌شده وارونه به نظر می‌رسد؛ برای جلوگیری از تغییر پنهانی ظاهر، در پیاده‌سازی اولیه همان خروجی Legacy حفظ و این نکته در مثال/مستند رفتار ثبت شود. اگر قرار است معنی نام propها اصلاح شود، آن را به تغییر جداگانه تبدیل کنید.

### 3.1. گسترش `module_shapes` با بخش SVG

در `src/framework/module_util/module_shapes/` بخش‌های `Css` و `Svg` از هم جدا و از barrel عمومی صادر شوند. ساخت element، نصب event، دسترسی DOM یا import کردن `CoreReactive` وظیفهٔ Util نیست؛ متدهای `Svg` فقط ورودی‌های هندسی typed را به points/strings/مختصات تبدیل کنند و Component از نتیجه برای ساخت SVG reactive استفاده کند.

ساختار افزوده‌شونده:

```text
src/framework/module_util/module_shapes/
├── index.ts                         # export Css_Triangle و namespace Svg
├── methods/
│   ├── css/
│   │   ├── MTCssTriangle.ts         # انتقال helper CSS موجود به این بخش
│   │   └── index.ts                 # export متدهای ساخت شکل با CSS
│   ├── svg/
│   │   ├── MTSvgPolygonPointsToString.ts
│   │   ├── MTSvgPolygonVertexMean.ts
│   │   ├── MTSvgPolygonSliceClosed.ts
│   │   ├── MTSvgPointOffset.ts
│   │   └── index.ts                 # export متدهای هندسی SVG
│   └── index.ts                     # export عمومی بخش‌های Css و Svg
└── types/
    ├── css/
    │   ├── const/
    │   │   ├── TCTriangleDirection.ts
    │   │   └── index.ts
    │   ├── TShapeTriangle.ts
    │   └── index.ts
    ├── svg/
    │   ├── TSvgPoint.ts             # {x:number; y:number}
    │   ├── TSvgPolygon.ts           # آرایهٔ readonly از TSvgPoint
    │   └── index.ts
    └── index.ts
```

در این تغییر، `MTCssTriangle.ts` و typeهای triangle از مسیر فعلی خود به زیرپوشهٔ `css` منتقل شوند و importهای داخلی اصلاح شوند. نام و خروجی عمومی فعلی `UtilShape.Css_Triangle(...)` حفظ شود تا مصرف‌کننده‌های موجود نیازی به تغییر نداشته باشند. بخش `Css` برای شکل‌هایی است که با border/background/pseudo-elementهای CSS ساخته می‌شوند؛ بخش `Svg` برای محاسبات هندسی مورد نیاز SVG است.

API پیشنهادی:

```ts
UtilShape.Svg.PolygonPointsToString(points);
UtilShape.Svg.PolygonVertexMean(points);
UtilShape.Svg.PolygonSliceClosed(points, startIndex, count);
UtilShape.Svg.PointOffset(point, offsetX, offsetY);
```

قرارداد متدها:

- `PolygonPointsToString(points)`: نقاط typed را به مقدار SVG `points` مثل `"0,0 10,0 10,20"` تبدیل کند؛ ورودی را تغییر ندهد و برای آرایهٔ خالی رشتهٔ خالی برگرداند.
- `PolygonVertexMean(points)`: میانگین مختصات رأس‌ها را به `{x,y}` برگرداند. این دقیقاً قرارداد مرکز Legacy یعنی `getCenterPolygonElement` است (میانگین رأس‌ها، نه centroid سطح چندضلعی) تا محل متن و دایرهٔ تیک در انتقال جابه‌جا نشود. ورودی کمتر از یک رأس، نتیجهٔ امن/تهی برگرداند و NaN تولید نکند.
- `PolygonSliceClosed(points, startIndex, count)`: بازهٔ پیوستهٔ رأس‌ها را بدون mutation برگرداند و رأس اول بازه را برای بستن polygon در انتها تکرار کند؛ ورودی نامعتبر یا بازهٔ کمتر از سه نقطه، آرایهٔ خالی بدهد. این متد جایگزین محاسبهٔ DOMمحور `createShadowInsidePolygonElement` برای highlight داخلی است.
- `PointOffset(point, offsetX, offsetY)`: نقطهٔ جدید با جابه‌جایی عددی بسازد؛ برای جای‌گذاری عنوان/دایره/تیک نسبت به مرکز Polygon یا Circle استفاده شود و نقطهٔ ورودی را تغییر ندهد.
- متدها فقط دادهٔ SVG بسازند؛ selector، random ID، DOM element، filter element و handler در Utility ساخته نشود. شناسهٔ filter و خود SVG shape در scope هر Component ایجاد می‌شود.

`types/index.ts` typeهای `types/css` و `types/svg` را export کند. `methods/css/index.ts` متدهای CSS و `methods/svg/index.ts` متدهای SVG را صادر کنند؛ `methods/index.ts` هر دو را به صورت namespaceهای `Css` و `Svg` در دسترس قرار دهد و `module_shapes/index.ts` هم namespace جدید و هم alias سازگار `Css_Triangle` را نگه دارد. مسیرهای قابل استفاده شامل `UtilShape.Css.Triangle(...)`, alias موجود `UtilShape.Css_Triangle(...)` و `UtilShape.Svg.PolygonVertexMean(...)` باشند. تست‌های pure مربوط به این توابع در `tests/perf/module-shapes-svg.test.ts` اضافه شوند؛ تست helper فعلی CSS Triangle حفظ شود.

## 5. Props و Methods

Props جدید با `Define_ComponentProp<T>` تعریف شوند و name/description از Keys بیایند. برای سازگاری، نام Legacy شامل تایپ اشتباه `prop_marginMinPerent` در انتقال حفظ شود؛ نام اصلاح‌شدهٔ دیگری بدون نیاز مصرف‌کننده اضافه نشود.

| Prop | نوع | پیش‌فرض Legacy | کاربرد |
|---|---|---:|---|
| `prop_breadcrumbs` | آرایهٔ step object | `[]` | مرحله‌ها با حفظ فیلدهای اضافی ورودی؛ `title` برای نمایش |
| `prop_stepSelected` | `number` | `1` | آخرین اندیس فعال، با قرارداد `index <= value` |
| `prop_side` | `number` | `20` | عرض/عمق بخش مورب قطعه‌های desktop |
| `prop_length` | `number` | `120` | طول میانی قطعهٔ desktop |
| `prop_gap` | `number` | `6` | فاصله/برش اتصال بین قطعه‌های desktop |
| `prop_height` | `number` | `25` | ارتفاع پایهٔ هندسه؛ SVG حدود 2.5 برابر ارتفاع |
| `prop_marginMinPerent` | `number` | `10` | حداقل حاشیهٔ container به درصد؛ clamp برای جلوگیری از هندسهٔ منفی |
| `prop_unactiveBreadcrumb` | `string` | `primaryColor1` | پس‌زمینهٔ مرحلهٔ غیرفعال و segment مربوط |
| `prop_colorUnactive` | `string` | `darkColor1` | رنگ متن/تیک طبق نگاشت فعلی Legacy |
| `prop_activeBreadcrumb` | `string` | `secondaryColor1` | پس‌زمینهٔ مرحلهٔ فعال و segment مربوط |
| `prop_colorActive` | `string` | `shanColor1` | رنگ متن/تیک طبق نگاشت فعلی Legacy |
| `prop_colorShadow` | `string` | `shadowColor2` | رنگ سایهٔ شکل‌ها |

`Methods.ts` یک method عمومی تعریف کند:

- `SELECT_BREADCRUMB`: با کلیک/فعال‌سازی keyboard، `ITEM` شامل شیء کامل ورودی و event را به callback بدهد. همان شیء ورودی حفظ شود و از ساختن نسخهٔ ناقص `{id,title}` پرهیز شود.

نام Legacy `fn_callback` فقط به method جدید متصل شود. `fn_onBackClick` به‌عنوان API جدید تعریف نشود، چون رفتار آن در این کامپوننت انتخاب step است، نه بازگشت.

## 6. Schemas و رندر

- `COMPONENT` و `STRUCTURE` از `ComponentStructureTrait` گرفته شوند.
- `part-breadcrumb-with-arrow` ظرف responsive و بخش قابل دسترس SVG را مشخص کند.
- `part-breadcrumb-with-arrow-items` فهرست SVG مرحله‌ها را با `prop_breadcrumbs`, `prop_stepSelected`, ابعاد، حاشیه و رنگ‌ها بسازد.
- `part-breadcrumb-with-arrow-item` هر مرحله را به صورت `<g>`، شامل شکل زمینه، connector لازم، label و نشان check/number رندر کند. کل گروه یک `role="button"`, `tabindex="0"` و handler یکتا داشته باشد؛ Enter و Space همان callback click را اجرا کنند.
- `svgPolygon` با `points` پویا برای بدنهٔ chevron و connectorها استفاده شود. `svgCircle`, `svgLine`, `svgText` و `svgPath` برای حالت باریک و نشان‌های مرحله استفاده شوند.
- برای active بودن، رنگ پس‌زمینه طبق شرط Legacy تنظیم شود؛ متن/تیک نیز فعلاً از نگاشت Legacy پیروی کند. عنوان‌های خالی یا مرحلهٔ ناقص با fallback امن نمایش داده شوند.
- SVG و گروه‌ها `aria-label`/`aria-current` مناسب داشته باشند. در صورت استفاده از title برای دسترس‌پذیری، آن را از عنوان مرحله بگیرند.
- برای فهرست خالی، SVG با ابعاد معتبر ولی بدون تقسیم بر صفر رندر شود؛ برای یک مرحله connector تولید نشود.
- در حالت mobile، margin درصدی دو طرف از prop محاسبه شود، فضای باقی‌مانده بین گره‌ها توزیع شود، خط اتصال پشت دایره‌ها بماند، عنوان بالای دایره و شماره/تیک در مرکز آن باشد.
- در حالت desktop، عرض کل بر مبنای `3 * side + length` و تعداد مرحله‌ها محاسبه شود؛ margin مرکزی یا حداقل درصدی اعمال شود. اگر عرض کل از container بیشتر شد، خود نوار افقی scroll شود یا layout بدون فشرده‌شدن اندازه‌ها ادامه یابد.
- shapeها و متن‌ها با SVG attributes/styles ساخته شوند؛ از inline HTML رشته‌ای و `innerHTML` استفاده نشود.

| `fn_renderBreadCrumb_resize_isForPc` | generator هندسهٔ chevron | RTL-aware و بر اساس width واقعی container |
| `fn_renderBreadCrumb_resize_isForMobile` | generator هندسهٔ دایره/خط | حاشیهٔ درصدی به‌صورت اصلاح‌شده و بدون هندسهٔ منفی |

## 8. مثال‌ها و ثبت UI

- `Default`: چهار مرحله با `prop_stepSelected: 1` و callback انتخاب؛ ابعاد و رنگ پیش‌فرض سیستم.
- `Responsive`: همان داده با container قابل تغییر عرض، برای بررسی هر دو layout و resize؛ direction از تنظیم سیستم خوانده شود، نه hard-code در مثال.
- گروه `UiCategory.UI.Breadcrumb` هر دو callable مجزا را ارائه کند: `Breadcrumb(...)` و `BreadcrumbWithArrow(...)`.
- ComponentManager registry و صفحهٔ جزئیات از `Examples` همین component استفاده کنند؛ placeholder یا ثبت دسته‌بندی تکراری ساخته نشود.
- نمونه‌ها callback را به صورت function در Methods جدید ثبت کنند و در `render()` یک HTMLElement برگردانند.

## 9. معیارهای پذیرش و بررسی

1. کامپوننت با ComponentManager و از callable `UiCategory.UI.Breadcrumb.BreadcrumbWithArrow` ساخته شود.
2. حالت زیر و بالای breakpoint، بر اساس عرض container، layout mobile و desktop را تغییر دهد و ResizeObserver پس از dispose باقی نماند.
3. RTL و LTR ترتیب گره‌ها، جهت connectorها و هندسهٔ chevron را درست و آینه‌ای نمایش دهند.
4. active shading همچنان بر اساس اندیس صفرمبنا و شرط `index <= prop_stepSelected` باشد؛ callback شیء اصلی مرحله را بگیرد.
5. title، شماره، تیک، سایه، پس‌زمینه و رنگ‌های قابل تنظیم کار کنند.
6. حالت‌های صفر، یک، چند مرحله، حاشیهٔ صفر/بزرگ، عرض کم و `prop_stepSelected` خارج از محدوده بدون exception یا NaN رندر شوند.
7. keyboard activation (Enter/Space) و دسترس‌پذیری گروه مرحله کار کند.
8. هیچ custom tag سراسری، `innerHTML`, `document.querySelector`, handler رشته‌ای یا resize listener پاک‌نشده باقی نماند.
9. تست pure برای سه متد `UtilShape.Svg` و unit/integration test برای خروجی دو layout، هندسهٔ RTL/LTR، active index، callback و dispose/resize اضافه و اجرا شود.
10. `npm run build:app`, typecheck مرتبط و `git diff --check` اجرا شوند؛ خطاهای نامرتبط موجود پروژه جداگانه گزارش شوند.
