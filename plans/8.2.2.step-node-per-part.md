# Plan 8.2.2 — Step Node per Part برای ComponentMessages

> **پیش‌نیاز:** Plan 8.2.1 (Refactor ComponentMessages renderManagerComponent)
> **پایه:** Plan 5.10 (Add Step Node to ComponentStructure)
> **هدف:** هر Part در ComponentMessages یک Child Node در درخت Step داشته باشد

## هدف

در Plan 5.10، مفهوم `_COMPONENT_STEP` معرفی شد — یک درخت Workflow داخلی برای Component. ولی در پیاده‌سازی فعلی ComponentMessages، Step فقط یک child `close` دارد که هیچ ارتباطی با Partها ندارد.

این پلن تعریف می‌کند که **هر Part** یک **Child Node** در درخت Step داشته باشد — ساختار Step هماهنگ با Schemas.

## مشکل

در حال حاضر `MessagesStep` فقط یک child `close` دارد:

```typescript
// ❌ فعلی — هماهنگ با Schemas نیست
export const MessagesStep = CoreEvent.Step({
    children: {
        close: CoreEvent.Step({
            request:  CoreEvent.Request(),
            response: CoreEvent.Response({ value: "" }),
        }),
    }
});
```

ولی ComponentMessages دو Part اختصاصی دارد: `MESSAGE` و `ICON`. هر کدام باید Child Node خودش را در Step داشته باشد تا reactive elementهای داخل آن Part بتوانند به Step متصل شوند.

## راه‌حل — هر Part یک Child Node

### ساختار جدید Step

```typescript
// ✅ جدید — هماهنگ با Schemas
export const MessagesStep = CoreEvent.Step({
    children: {

        // Part MESSAGE — رندر لیست پیام‌ها
        message: CoreEvent.Step({
            request:  CoreEvent.Request(),
            response: CoreEvent.Response({ value: "" }),
        }),

        // Part ICON — رندر آیکون بستن
        icon: CoreEvent.Step({
            children: {
                close: CoreEvent.Step({
                    request:  CoreEvent.Request(),
                    response: CoreEvent.Response({ value: "" }),
                }),
            },
        }),
    }
});
```

### ساختار درخت

```
MessagesStep
    │
    ├── message (Part MESSAGE)
    │       request:  Request()
    │       response: Response({ value: "" })
    │
    └── icon (Part ICON)
            │
            └── close
                    request:  Request()
                    response: Response({ value: "" })
```

### هماهنگی با Schemas

| Schema Key | Part Name | Step Node | کاربرد |
|:---|:---|:---|:---|
| `MESSAGE` | `part-messages-message` | `MessagesStep.message` | رندر لیست پیام‌ها |
| `ICON` | `part-messages-icon` | `MessagesStep.icon` | رندر آیکون بستن |
| — | — | `MessagesStep.icon.close` | Request بستن پیام |

**نکته:** `close` زیر `icon` قرار دارد چون عملیات بستن از آیکون شروع می‌شود. این ساختار درختی امکان trace بهتری می‌دهد — می‌دانیم کدام Part درخواست را شروع کرده.

## اتصال Step به Reactive Elementها

طبق تصمیم، اتصال در **render متدها** انجام می‌شود — هر render متد Step مربوط به Part خودش را به reactive element متصل می‌کند.

### renderMessages — Part MESSAGE

```typescript
protected renderMessages(
    attrsDefault?: PartAttrDefault,
    data?: Record<string, CoreObservable.App<any>>,
    extra?: any,
): CoreReactive.App {

    // ... (همان کد فعلی)

    return CoreReactive.App.div({
        attrs: {
            ...attrsDefault,
        },
        unique: this._COMPONENT_STEP?.message ?? undefined,  // ← اتصال Step
        className: ["d-flex", "flex-column", "gap-2"],
        children: [
            messageItems,
        ],
    });
}
```

### renderCloseIcon — Part ICON

```typescript
protected renderCloseIcon(
    attrsDefault: PartAttrDefault,
    data: Record<string, CoreObservable.App<any>>,
    extra: any,
): CoreReactive.App {

    // ... (همان کد فعلی)

    const iconElement = UiCategory.UI.Simples.Icon(
        {
            prop_icon: UiIcons.CreateIcon(UiIcons.Src.FileWindowClose.Definition, {
                size: 16,
                primaryColor: CoreObservable.App.computed(/* ... */),
            }),
            prop_iconClass: ["cursor-pointer"],
            prop_iconStyles: { "inset-inline-end": "5px", "top": "5px", "position": "absolute" },
        },
        {
            CLICK: (event: Event) => {
                event.preventDefault();
                this.executeMethod("CLOSE_MESSAGE", event, {
                    MESSAGE_INDEX: extra?.index ?? undefined,
                    MESSAGE_TEXT:  extra?.messageText ?? undefined,
                    MESSAGE_TYPE:  prop_type.get(),
                });
            },
        },
        {
            // identity — اتصال آیکون به Step داخلی ComponentMessages
            unique: this._COMPONENT_STEP?.icon ?? undefined,  // ← اتصال Step
        },
    ).getElement();

    return CoreReactive.App.span({
        children: [iconElement],
    });
}
```

### renderSingleMessage — بدون اتصال مستقیم

`renderSingleMessage` خودش یک Part مستقل نیست — زیر Part MESSAGE است. پس Step مستقیم نمی‌گیرد. ولی آیکون بستن داخل آن از `renderCloseIcon` صدا زده می‌شود که Step را به `icon` متصل می‌کند.

### فایل ۲ — ComponentMessages.ts

#### تغییر ۱ — constructor باید Step را به super پاس دهد

در حال حاضر `ComponentMessages` از `ComponentMessagesBase` ارث می‌برد که از `CoreComponents.App` ارث می‌برد — نه `ComponentStructureBase`. پس `_COMPONENT_STEP` ندارد.

**مشکل:** `ComponentMessagesBase` از `CoreComponents.App` ارث می‌برد، نه `ComponentStructureBase`. پس فیلد `_COMPONENT_STEP` وجود ندارد.

**راه‌حل:** `_COMPONENT_STEP` را در `ComponentMessagesBase` اضافه کنیم (یا در `ComponentMessages` مستقیم).

```typescript
// ComponentMessagesBase.ts
protected _COMPONENT_STEP: CoreEvent.TStepInstance | null = null;

constructor(
    componentName: string = "messages",
    elId: string | null = null,
    identity?: Partial<ComponentIdentity>,
    step?: CoreEvent.TStepInstance,
) {
    super(componentName, elId);

    this._COMPONENT_UNIQUE = identity?.unique ?? null;
    this._COMPONENT_EMIT   = identity?.emit ?? null;
    this._COMPONENT_STEP   = step ?? null;
}
```

#### تغییر ۲ — ComponentMessages constructor باید MessagesStep را پاس دهد

```typescript
// ComponentMessages.ts
constructor(
    config?: Partial<StructurePropsType & PropsType>,
    methods?: MethodsConfigType<ComponentMessages>,
    identity?: {
        unique?: any;
        emit?: any;
        events?: Record<string, any> | null;
    },
) {
    super("messages", null, identity, MessagesStep);  // ← Step پاس داده می‌شود

    this.renderComponent(
        config as any,
        methods as any,
        identity?.events ?? null,
    );
}
```

## نکات مهم

### چرا `close` زیر `icon` قرار دارد؟

عملیات بستن از آیکون شروع می‌شود. پس `close` زیر `icon` قرار می‌گیرد — این ساختار درختی امکان trace بهتری می‌دهد:

```
MessagesStep.icon.close  ←  "بستن از Part ICON"
```

اگر `close` مستقل top-level بود، نمی‌دانستیم کدام Part درخواست را شروع کرده.

### چرا `_COMPONENT_STEP` در Base اضافه می‌شود؟

چون `ComponentMessagesBase` از `CoreComponents.App` ارث می‌برد (نه `ComponentStructureBase`). پس باید `_COMPONENT_STEP` را مستقیم در Base اضافه کنیم.

**آینده:** اگر تمام Componentها به این الگو نیاز دارند، می‌توان `_COMPONENT_STEP` را به `ClComponentBase` منتقل کرد. ولی فعلاً برای حفظ سازگاری، در Base اختصاصی هر Component نگه داشته می‌شود.

### هماهنگی با Plan 5.10

Plan 5.10 `_COMPONENT_STEP` را در `ComponentStructureBase` تعریف کرد. ولی ComponentMessages از `CoreComponents.App` ارث می‌برد (نه `ComponentStructureBase`). پس این پلن `_COMPONENT_STEP` را در `ComponentMessagesBase` مستقیم اضافه می‌کند — همان مفهوم، ولی در لایه متفاوت.

### الگوی کلی برای Componentهای آینده

این الگو برای تمام Componentهای آینده قابل تعمیم است:

```typescript
// Step.ts
export const {Component}Step = CoreEvent.Step({
    children: {
        {part_a}: CoreEvent.Step({ request, response }),
        {part_b}: CoreEvent.Step({
            children: {
                {sub_action}: CoreEvent.Step({ request, response }),
            },
        }),
    }
});

// {Component}Base.ts
protected _COMPONENT_STEP: CoreEvent.TStepInstance | null = null;

constructor(name, elId, identity?, step?) {
    super(name, elId);
    this._COMPONENT_STEP = step ?? null;
}

// {Component}.ts
constructor(config, methods, identity?) {
    super("{name}", null, identity, {Component}Step);
    this.renderComponent(config, methods, identity?.events);
}

// render{PartA}
return CoreReactive.App.div({
    unique: this._COMPONENT_STEP?.{part_a},
    ...
});
```
