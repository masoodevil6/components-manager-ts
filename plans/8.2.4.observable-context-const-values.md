# Plan 8.2.4 — افزودن `consts` پارامتر جدا از `context` در متدهای Observable

> **پیش‌نیاز:** Plan 8.2.3 (Fix executeMethod با Message ID)
> **هدف:** متدهای `for` و `forObject` یک پارامتر `consts` جدا از `context` داشته باشند برای مقادیر ثابت

## مشکل

در حال حاضر `CoreObservable.App.for` و `forObject` فقط `Record<string, ClObservable<any>>` در context قبول می‌کنند. ولی در `ComponentMessages` نیاز داریم مقادیر ثابت (مثل `randomId`) را هم پاس بدهیم.

اگر مقادیر ثابت را داخل `context` بگذاریم، مفهوم‌ها混 (mix) می‌شوند — `context` باید فقط Observable باشد (reactive) و `consts` فقط مقادیر ثابت (non-reactive).

## راه‌حل — پارامتر `consts` جدا

### امضای جدید `for`

```typescript
static for<T, TResult>(
    source: ClObservable<T[]>,
    mapper: (
        item: T,
        index: number,
        context: Record<string, any>,   // ← فقط Observable values (reactive)
        consts:  Record<string, any>,   // ← فقط const values (non-reactive)
    ) => TResult,
    context: Record<string, ClObservable<any>> = {},
    consts:  Record<string, any> = {},                           // ← جدید
    scope?:  Scope
): ClObservable<TResult[]>
```

### امضای جدید `forObject`

```typescript
static forObject<TObject, TResult>(
    source: ClObservable<TObject>,
    mapper: (
        key: keyof TObject,
        value: TObject[keyof TObject],
        index: number,
        context: Record<string, any>,   // ← فقط Observable values (reactive)
        consts:  Record<string, any>,   // ← فقط const values (non-reactive)
    ) => TResult,
    context: Record<string, ClObservable<any>> = {},
    consts:  Record<string, any> = {},                           // ← جدید
    scope?:  Scope
): ClObservable<TResult[]>
```

### جداسازی مفهوم‌ها

| پارامتر | نوع | رفتار | کاربرد |
|:---|:---|:---|:---|
| `context` | `Record<string, ClObservable<any>>` | **reactive** — در تغییر re-render می‌شود | `theme`, `locale`, `prop_type` |
| `consts` | `Record<string, any>` | **non-reactive** — ثابت در طول lifecycle | `randomId`, `componentName`, config flags |

## تغییرات

### فایل — `ClObservable.ts`

#### تغییر ۱ — `for` متد

##### قبل

```typescript
static for<T, TResult>(
    source: ClObservable<T[]>,
    mapper: (
        item: T,
        index: number,
        context: Record<string, any>
    ) => TResult,
    context: Record<string, ClObservable<any>> = {},
    scope?:  Scope
): ClObservable<TResult[]> {

    const getContextValues = () => {
        const result: Record<string, any> = {};
        Object.entries(context).forEach(([key, observable]) => {
            result[key] = observable.get();
        });
        return result;
    };

    const render = () => {
        const contextValues = getContextValues();
        return source.get().map((item, index) =>
            mapper(item, index, contextValues)
        );
    };

    // ...
}
```

## استفاده در ComponentMessages

بعد از این تغییر، `for` در `ComponentMessages` می‌تواند const values را در `consts` پاس بدهد:

```typescript
CoreObservable.App.for(
    prop_messages,
    (item, index, context, consts) => {
        const messageItem = item as MessageItem;

        return CoreReactive.App.section({
            attrs: {
                role: "alert",
                "data-id": consts.randomId,  // ← const value
            },
            // ...
            children: [
                CoreReactive.App.b({ children: [messageItem.text] }),
                this.renderManagerComponent(Schemas.ICON.part, attrsDefault, data, {
                    id:          consts.randomId,  // ← const value
                    index,
                    messageText: messageItem.text,
                }),
            ],
        });
    },
    {},  // ← context (Observable) — خالی
    {
        randomId: Math.random().toString(36).slice(2, 11)  // ← consts (non-reactive)
    },
    this.getScope()
);
```

### نکته مهم درباره randomId

`consts` در زمان ساخت `for` یک‌بار capture می‌شود و در re-render تغییر نمی‌کند. ولی `randomId` یک‌بار برای کل لیست تولید می‌شود — نه برای هر پیام.

اگر نیاز به id یکتا برای هر پیام داریم، باید از `messageItem.id` (که در constructor نرمال‌سازی شده) استفاده کنیم. `consts` برای مقادیر ثابت **سراسری** (یک مقدار برای کل لیست) استفاده شود.

## نکات مهم

### چرا `consts` جدا از `context`؟

| دلیل | توضیح |
|:---|:---|
| **جداسازی مفهوم** | `context` = reactive (Observable)، `consts` = non-reactive (ثابت) |
| **خوانایی** | مصرف‌کننده می‌داند کدام پارامتر reactive است و کدام ثابت |
| **Type safety** | `context` فقط `ClObservable` قبول می‌کند — خطای type در زمان compile |
| **Performance** | `consts` نیاز به subscribe ندارد — فقط یک‌بار capture می‌شود |

### ترتیب پارامترها

```
for(source, mapper, context, consts, scope)
                 ↑         ↑       ↑
                 reactive  ثابت    lifecycle
```

`context` قبل از `consts` چون reactive است و مهم‌تر — تغییر آن re-render می‌کند. `consts` بعد چون ثابت است و در lifecycle تغییر نمی‌کند.

### الگوی کلی برای متدهای آینده

هر متد Observable که context دارد، باید `consts` هم داشته باشد:

```typescript
static someMethod<T, TResult>(
    source: ClObservable<T>,
    mapper: (item: T, context: Record<string, any>, consts: Record<string, any>) => TResult,
    context: Record<string, ClObservable<any>> = {},
    consts:  Record<string, any> = {},
    scope?:  Scope
): ClObservable<TResult>
```
