# Plan 13.1.3 — اصلاح جای‌گذاری Tooltip Icon در ComponentLabel

> **پیش‌نیاز:** Plan 13.1.0 (ComponentLabel Migration), Plan 13.1.1 (Trait-Ready), Plan 13.1.2 (Tooltip/FloatMenu fixes)
> **هدف:** بازیابی رفتار legacy برای جای‌گذاری آیکون tooltip: آیکون باید `position: absolute` در انتهای label قرار بگیرد، وارد جریان متن نشود، و فلش popup دقیقاً به همان آیکون اشاره کند.
> **دامنه:** `src/framework/module_ui/module_components/lists/componentLabel/ComponentLabel.ts` و در صورت نیاز اصلاح محدود در `componentFloatMenu/ComponentFloatMenu.ts`
> **مرجع رفتار:** `last/tools/components/ComponentLabel.ts` و `last/tools/components/ComponentTooltipDescription.ts`

---

## ۱. شرح و انگیزه

### ۱.۱ وضعیت فعلی پس از 13.1.2

پس از جایگزینی tooltip ساده با `ComponentFloatMenu`، popup از نظر محتوا و show/hide بهتر شد، اما layout هنوز مطابق legacy نیست:

| بخش | وضعیت فعلی | مشکل |
|:---|:---|:---|
| `part-label-content` | `inline-flex` با children کنار هم | آیکون وارد flow متن شده و جلوی text قرار می‌گیرد |
| `part-label-content-tooltip` | یک child عادی کنار title | باید overlay/absolute باشد، نه بخشی از layout متن |
| `ComponentFloatMenu` selector | trigger داخل flow قرار می‌گیرد | در label باید در انتهای label absolute شود |
| arrow popup | با `prop_floatArrowPosition` محاسبه می‌شود | جهت کلی درست است، ولی anchor باید همان آیکون absolute باشد |

رفتار مشاهده‌شده: آیکون tooltip جلوی text می‌آید یا روی line/layout اثر می‌گذارد، درحالی‌که طبق طرح اصلی باید مثل یک affordance انتهایی روی label قرار بگیرد.

### ۱.۲ رفتار legacy

در legacy، `ComponentLabel` محتوای label را `position-relative` می‌کرد و title و tooltip را دو schema جدا نگه می‌داشت:

```typescript
return ReactiveElement.part("section", {
    styles: { cursor: "pointer" },
    className: ["position-relative"],
    children: [
        this.executeSchemaPart(BORDER_CONTENT_LABEL),
        this.executeSchemaPart(BORDER_CONTENT_TOOLTIP),
    ]
});
```

مرجع: `last/tools/components/ComponentLabel.ts`، متد `templateFn_render_borderContent`.

خود آیکون tooltip در legacy داخل `ComponentTooltipDescription` به‌صورت absolute تنظیم می‌شد:

```typescript
let styles = {top: "0"};
if (directionRtl) {
    styles["left"] = prop_iconPosition.get();
}
else {
    styles["right"] = prop_iconPosition.get();
}

return new ToolsComponents.ComponentIcon({
    prop_iconClass:  ["position-absolute"],
    prop_iconStyles: styles,
    prop_icon:       prop_icon,
});
```

مرجع: `last/tools/components/ComponentTooltipDescription.ts`، متد `templateFn_render_floatMenu_icon`.

### ۱.۳ semantic اصلی propها در legacy

| ComponentLabel prop | مقصد legacy | معنی واقعی |
|:---|:---|:---|
| `prop_labelTooltipIcon` | `prop_icon` در `ComponentTooltipDescription` | icon definition |
| `prop_labelTooltipDescription` | `prop_floatContent` در `ComponentFloatMenu` | متن popup |
| `prop_labelTooltipBackground` | `prop_floatBackground` | پس‌زمینه popup |
| `prop_labelTooltipColor` | `prop_floatBorderColor` | رنگ border دور popup، نه رنگ متن |
| `prop_labelTooltipPosition` | `prop_iconPosition` + `prop_floatArrowPosition` | فاصله آیکون از انتهای label و anchor فلش |
| `prop_labelTooltipDirection` | `prop_floatDirectionType` | جهت popup و arrow معکوس |

نکته مهم: `prop_labelTooltipPosition` در legacy فقط موقعیت popup نیست؛ هم **آیکون** را از انتهای label offset می‌کند و هم **فلش** را طوری محاسبه می‌کند که به آیکون برسد.

## ۲. هدف رفتاری 13.1.3

پس از اجرای این Plan باید این رفتارها برقرار باشند:

1. `part-label-content` مثل legacy `position-relative` باشد و وارد layout پیچیده‌ی inline-flex نشود.
2. `part-label-content-tooltip` خودش `position: absolute` داشته باشد.
3. بر اساس direction صفحه:
   - LTR → tooltip icon در انتهای راست label قرار بگیرد (`right: prop_labelTooltipPosition`).
   - RTL → tooltip icon در انتهای چپ label قرار بگیرد (`left: prop_labelTooltipPosition`).
4. آیکون tooltip جلوی متن قرار نگیرد و باعث line break نشود.
5. popup نسبت به همان آیکون باز شود و arrow به همان آیکون اشاره کند.
6. `prop_labelTooltipDirection` همچنان جهت popup را تعیین کند:
   - `BOTTOM` → popup زیر label/آیکون، فلش رو به بالا/به سمت آیکون.
   - `TOP` → popup بالای label/آیکون، فلش رو به پایین/به سمت آیکون.
7. `prop_labelTooltipBackground` و `prop_labelTooltipColor` semantic legacy را حفظ کنند.
8. رفتار hover و `CLICK` label خراب نشود.

## ۳. راهکار پیشنهادی

### ۳.۱ بازگرداندن `renderLabelContent` به layout legacy

تغییر قبلی `inline-flex` باید حذف شود. `part-label-content` نباید title و tooltip را کنار هم در flow بگذارد. باید همانند legacy فقط container نسبی باشد:

```typescript
return CoreReactive.App.section({
    attrs: {...attrsDefault},
    styles: {
        cursor: "pointer",
    },
    className: [
        "position-relative",
    ],
    children: [
        this.executeSchemaPart(Schemas.BORDER_CONTENT_TITLE.part),
        this.executeSchemaPart(Schemas.BORDER_CONTENT_TOOLTIP.part),
    ],
});
```

**دلیل:** tooltip باید overlay باشد، نه flex child.

### ۳.۲ absolute کردن `part-label-content-tooltip`

خود schema wrapper مربوط به tooltip باید absolute شود، نه اینکه فقط آیکون داخل آن absolute باشد. هدف این است که کل FloatMenu/selector در anchor انتهایی label بنشیند.

الگوی پیشنهادی:

```typescript
const tooltipAnchorStyles = CoreObservable.App.computed(
    (position, dirRtl) => ({
        position: "absolute",
        top:      "0",
        ...(dirRtl ? { left: position } : { right: position }),
    }),
    [prop_labelTooltipPosition, CoreConfig.Settings.DirectionRtl.observable()],
    this.getScope(),
);

return CoreReactive.App.section({
    attrs: {...attrsDefault},
    stylesBind: tooltipAnchorStyles,
    children: [tooltip],
});
```

اگر `CoreConfig.Settings.DirectionRtl.observable()` در API فعلی موجود نبود، باید ابتدا API صحیح direction را در `module_configs` پیدا کرد و بدون حدس جایگزین کرد.

### ۳.۳ FloatMenu selector باید inline/relative بماند، اما anchor اصلی wrapper باشد

در `ComponentLabel` هنگام ساخت `ComponentFloatMenu`:

```typescript
prop_selectorClass: ["position-relative"],
prop_selectorStyles: {},
```

selector نباید `w-100` بگیرد. اگر `ComponentFloatMenu` هنوز کلاس پیش‌فرض `d-block w-100 h-100` دارد، باید برای use-case label یا:

- در `ComponentLabel` با `prop_selectorClass` override شود، یا
- در `ComponentFloatMenu` کلاس ثابت به `d-inline-block` اصلاح شود، مشروط به اینکه مثال‌ها/مصرف‌های دیگر خراب نشوند.

تصمیم پیشنهادی: **در ComponentFloatMenu کلاس ثابت selector به `d-inline-block` تغییر کند** فقط اگر تست/نمونه‌ها نشان دهد مصرف‌های دیگر به full-width وابسته نیستند. در غیر این صورت، باید class ثابت حذف و full-width به default prop منتقل شود.

### ۳.۴ محاسبه arrowPosition مطابق legacy

legacy:

```typescript
prop_floatArrowPosition = SizeCalc(
    SizeUnit(100, PERCENT),
    MINUS,
    prop_iconPosition.get(),
    MINUS,
    SizeUnit(iconSize / 2, PEXEL)
)
```

در ساختار فعلی باید معادل CSS calc تولید شود:

```typescript
const arrowPosition = CoreObservable.App.computed(
    (sizeName, position) => UtilStyle.Css_SizeCalc(
        UtilStyle.Css_SizeUnit(100, UtilConst.Units.PERCENT),
        UtilConst.Operation.MINUS,
        position,
        UtilConst.Operation.MINUS,
        `calc(${UtilStyle.Css_IconSize(sizeName)} / 2)`,
    ),
    [CoreConfig.Settings.SizeName.observable(), prop_labelTooltipPosition],
    this.getScope(),
);
```

این مقدار باید به `prop_floatArrowPosition` داده شود.

### ۳.۵ محدود کردن تغییرات ComponentFloatMenu

`ComponentFloatMenu` پس از 13.1.2 اصلاح شده تا:

- popup همیشه در DOM ساخته شود وقتی `floatShowControlWithSelf=false`، تا `_BORDER_INSTANCE` موجود باشد.
- popup با `prop_show=false` شروع شود و hover آن را show کند.

این رفتار باید حفظ شود.

اما برای 13.1.3 باید بررسی شود که تغییر selector از `d-block w-100 h-100` به `d-inline-block` اثر جانبی ندارد. اگر اثر جانبی دارد، راه‌حل بهتر:

1. کلاس ثابت full-width از `renderSelector` حذف شود.
2. default `prop_selectorClass` در `Props.ts` برای FloatMenu روی `[]` بماند.
3. مصرف‌کننده‌هایی که full-width می‌خواهند خودشان `prop_selectorClass: ["d-block", "w-100", "h-100"]` بدهند.
4. `ComponentLabel` فقط `position-relative` بدهد.

## ۴. فازهای اجرایی

### فاز ۱ — بازگرداندن layout label به legacy

- حذف `display: inline-flex`, `alignItems`, `gap` از `renderLabelContent`.
- نگه‌داشتن `cursor: pointer` و `className: ["position-relative"]`.

### فاز ۲ — absolute positioning برای `part-label-content-tooltip`

- در `renderLabelTooltip` wrapper section را absolute کن.
- `top: 0` ثابت بماند.
- LTR/RTL را از تنظیمات واقعی پروژه بخوان.
- LTR: `right: prop_labelTooltipPosition`.
- RTL: `left: prop_labelTooltipPosition`.

### فاز ۳ — anchor کردن FloatMenu به آیکون

- `ComponentFloatMenu` داخل wrapper absolute باقی بماند.
- `prop_selectorClass: ["position-relative"]`.
- `prop_selectorStyles` فقط در صورت نیاز display/line-height را تنظیم کند.
- آیکون `ComponentIcon` با `prop_iconStyles: { top: "0" }` حفظ شود، اما دیگر خودش نباید مسئول left/right باشد؛ wrapper مسئول anchor است.

### فاز ۴ — arrowPosition مطابق legacy

- `prop_floatArrowPosition` از `100% - position - iconSize/2` تولید شود.
- در DOM نهایی باید CSS variable arrow شبیه این باشد:

```css
--arrow-left: calc(100% - 2.5% - calc(var(--iconSizeMedium) / 2));
```

یا معادل RTL/Direction بسته به رفتار `ComponentBorder`.

### فاز ۵ — بررسی/اصلاح محدود FloatMenu selector

- اگر selector هنوز باعث full-width یا line break شود:
  - کلاس ثابت `d-block w-100 h-100` حذف/اصلاح شود.
  - کم‌ریسک‌ترین گزینه: `d-inline-block` برای selector ثابت.
- قبل از تصمیم، مثال `componentFloatMenu/examples/Default.ts` و مصرف‌های `componentFloatMenu` جستجو شود.

### فاز ۶ — verification

حداقل تست‌های focused jsdom:

1. `part-label-content` نباید `display: inline-flex` داشته باشد.
2. `part-label-content-tooltip` باید `position: absolute` داشته باشد.
3. در LTR باید `right: <prop_labelTooltipPosition>` داشته باشد.
4. در RTL باید `left: <prop_labelTooltipPosition>` داشته باشد، اگر API تنظیم RTL در تست قابل کنترل است.
5. `component-floatmenu` باید داخل tooltip wrapper باشد.
6. `part-selector-position` باید بعد از اصلاح FloatMenu محتوا داشته باشد، نه خالی.
7. popup border باید ابتدا hidden باشد.
8. با `mouseenter` روی selector، popup border باید `show` شود.
9. arrow variable باید بر اساس `prop_labelTooltipPosition` و `iconSize` تنظیم شده باشد.
10. `CLICK` روی label content همچنان callback را اجرا کند.

در پایان:

```powershell
npx tsc --noEmit 2>&1 | findstr /C:"componentLabel\|componentFloatMenu"
```

خروجی بدون match با exit code 1 در `findstr` به معنی «هیچ خطایی در این دو فایل match نشده» است، نه الزاماً clean کامل کل repo.

## ۵. ریسک‌ها و کنترل‌ها

| ریسک | توضیح | کنترل |
|:---|:---|:---|
| شکستن مصرف‌های دیگر FloatMenu | تغییر selector از block/full-width به inline ممکن است روی کامپوننت‌های دیگر اثر بگذارد | قبل از تغییر global، مصرف‌ها و exampleها جستجو شوند |
| API نامشخص RTL | نباید `DirectionRtl.observable()` حدس زده شود | `module_configs` خوانده شود و API واقعی استفاده شود |
| arrow در RTL | `ComponentBorder` ممکن است arrow-left/right را خودش مدیریت کند | DOM/CSS variable در تست RTL بررسی شود |
| overlap متن طولانی با آیکون | چون آیکون absolute است، متن خیلی بلند ممکن است زیر آیکون برود | در صورت نیاز padding-inline-end/start متناسب با iconSize به content/title اضافه شود، ولی فقط بعد از مشاهده |
| popup clipping | popup داخل border label است | اگر clip شد، `overflow: visible` باید روی anchor/parent مناسب اضافه شود، نه بازگشت به CSS-only popup |

## ۶. معیار پذیرش

- آیکون tooltip در انتهای label قرار می‌گیرد و جلوی text نیست.
- آیکون باعث line break یا line دوم نمی‌شود.
- LTR/RTL در anchor آیکون رعایت می‌شود.
- popup با `prop_labelTooltipDirection` در جهت درست باز می‌شود.
- arrow به آیکون اشاره می‌کند.
- `prop_labelTooltipBackground` و `prop_labelTooltipColor` مثل legacy روی popup border اعمال می‌شوند.
- hover، initial hidden، و click callback بدون regression کار می‌کنند.
- هیچ تغییر unrelated در ComponentLabel/FloatMenu انجام نمی‌شود.
