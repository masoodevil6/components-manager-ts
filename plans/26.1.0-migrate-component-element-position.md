# پلن 26.1.0 — انتقال ComponentElementPosition به ساختار جدید

> **وضعیت:** پیشنهادی؛ پیاده‌سازی نشده
> **نسخه پلن:** 26.1.0
> **منبع Legacy:** last/tools/components/ComponentElementPosition.ts
> **راهنما:** documents/guides/component-create.md
> **مقصد:** src/framework/module_ui/module_components/lists/componentElementPosition/
> **API پیشنهادی:** UiCategory.UI.Positions.ElementPosition(config, methods, identity)

## 1. هدف و محدوده

کامپوننت عمومی موقعیت‌دهی را از ComponentBase قدیمی به ساختار declarative/runtime جدید منتقل کن. رفتار موجود شامل positionهای CSS، اندازه و مختصات، مختصات منطقی وابسته به جهت صفحه، transform، z-index، کلاس و style سفارشی، محتوای فرزند و callback کلیک باید حفظ شود.

این کامپوننت فقط یک wrapper موقعیت‌دهی است. منطق باز و بسته‌شدن منو، محاسبه موقعیت FloatMenu، محدودکردن popup به viewport یا رفتارهای ComponentPositionMenu و ComponentFloatMenu به آن منتقل نشود.

### وابستگی‌های Legacy که باید بدون تغییر باقی بمانند

جست‌وجوی repository نشان می‌دهد کامپوننت‌های زیر از نسخه Legacy استفاده می‌کنند:

- ComponentDraggableOrdersY
- ComponentInputCheckBox, ComponentInputColor, ComponentInputEmail, ComponentInputPassword, ComponentInputPhone, ComponentInputPrice, ComponentInputRadioBox, ComponentInputSize
- ComponentMouseScroller, ComponentSidebar, ComponentWebCode, ComponentWindow
- Positions/ComponentFloatMenu, simples/ComponentInputSimple, simples/ComponentSelectCustomSimple

این پلن مهاجرت مصرف‌کنندگان Legacy یا تغییر مسیر importهای آن‌ها را در بر نمی‌گیرد. کلاس Legacy تا زمان مهاجرت جداگانه‌ی مصرف‌کنندگان دست‌نخورده می‌ماند.

## 2. ساختار رندر مورد انتظار

ComponentElementPosition از ComponentStructureTrait استفاده می‌کند. زیر لایه‌های COMPONENT و STRUCTURE یک part با نام part-position رندر می‌شود و محتوای فرزند در آن قرار می‌گیرد. کامپوننت Label یا Form نیاز ندارد. عنصر نهایی همان یک section موقعیت‌دار است.

## 3. قرارداد Props و نگاشت Legacy

Props پایه‌ی ComponentStructureTrait دوباره تعریف نشوند. تمام propهای اختصاصی با Define_ComponentProp<T>, کلیدهای Keys, satisfies CoreComponents.ComponentProps, و helperهای ExtractPropsType و ExtractPropsConfigType تعریف شوند.

| Prop | قرارداد مورد انتظار |
|---|---|
| prop_content | محتوای فرزند را رندر کند؛ نوع دقیق ورودی با بررسی call siteهای Legacy و APIهای reactive موجود تثبیت شود. پشتیبانی از string و محتوای کامپوننتی ضروری است. |
| prop_positionClass | کلاس‌های عنصر موقعیت‌دار؛ مقدار پیش‌فرض معادل Legacy خالی/بدون کلاس باشد. شکل رشته، آرایه یا محتوای قدیمی class را با شواهد مصرف‌ها تعیین و در صورت نیاز normalize کن. |
| prop_positionStyles | Record<string, string> برای styleهای اضافه؛ پیش‌فرض {}. |
| prop_positionWidth | عرض CSS؛ پیش‌فرض 100%. |
| prop_positionHeight | ارتفاع CSS؛ پیش‌فرض null. |
| prop_positionBackgroundColor | رنگ پس‌زمینه؛ پیش‌فرض null. |
| prop_positionType | enum اختصاصی STATIC, FIX, RELATIVE, ABSOLUTE با پیش‌فرض ABSOLUTE. مقدار Legacy یعنی FIX = "fix" در CSS باید به position: fixed نگاشت شود؛ مقدار نامعتبر "fix" مستقیماً به مرورگر نرسد. |
| prop_positionTop, prop_positionBottom | مختصات فیزیکی بالا و پایین؛ پیش‌فرض null. |
| prop_positionLeft, prop_positionRight | مختصات فیزیکی چپ و راست؛ پیش‌فرض null و بر مختصات منطقی اولویت داشته باشند. |
| prop_positionStart, prop_positionEnd | مختصات منطقی؛ پیش‌فرض null و طبق CoreConfig.Settings.DirectionRtl به چپ/راست نگاشت شوند. |
| prop_positionTranslate | مقدار transform؛ پیش‌فرض null. سازگاری با نوع Legacy یعنی TranslateUnit را از روی مصرف‌کنندگان بررسی و به مقدار CSS قابل رندر تبدیل کن. |
| prop_positionZIndex | z-index عددی یا null؛ پیش‌فرض null. |

برای مقادیر CSS، الگوی سایر کامپوننت‌های جدید را رعایت کن و Observableها را در constructor/config بپذیر. در این کامپوننت اندازه‌ی سیستم یا prop_size جدید لازم نیست.

### اولویت مختصات

منطق Legacy عیناً حفظ شود:

- left اگر مقدار دارد، همان مقدار استفاده شود؛ در غیر این صورت در RTL از end و در LTR از start استفاده شود.
- right اگر مقدار دارد، همان مقدار استفاده شود؛ در غیر این صورت در RTL از start و در LTR از end استفاده شود.
- top و bottom مستقل از جهت اعمال شوند.
- مقدار null نباید به رشته‌ی "null" در CSS تبدیل شود یا مختصات قبلی را ناخواسته پاک کند؛ رفتار binding با runtime جدید بررسی شود.

## 4. Schema و رویداد

Schemas.ts شامل COMPONENT و STRUCTURE از ComponentStructureTrait.schemas و schema اختصاصی POSITION با part برابر part-position باشد. POSITION همه‌ی propهای اختصاصی موردنیاز را bind کند.

Schema فقط metadata و prop binding تعریف کند؛ rendering و منطق مختصات در کلاس runtime باشد.

در Methods.ts کلید عمومی CLICK حفظ شود و به runtime name قدیمی fn_onClick نگاشت شود. args و dataArgs طبق convention جدید و بدون payload اضافی تعریف شوند. رویداد DOM کلیک روی بخش موقعیت‌دار، preventDefault() را مطابق Legacy اجرا کند و callback را دقیقاً یک بار فراخوانی کند.

در Step.ts یک factory مستقل createElementPositionStep() با Step کلیک تعریف شود. هر نمونه Step جداگانه داشته باشد و Base، disposeStep() را فراهم کند.

## 7. زبان و Examples

برای نام/توضیح کامپوننت، propها، schema، متد و مثال‌ها کلیدهای ترجمه به Keys.ts اضافه و مقدارهای فارسی/انگلیسی در Fa.ts و En.ts ثبت شوند.

Examples با ComponentExample و تابع render() باشند و کامپوننت را از Category callable بسازند:

- Default: absolute positioning در والد position-relative.
- LogicalPosition: start/end با تغییر DirectionRtl و اولویت left/right فیزیکی.
- FixedOverlay: حالت Legacy FIX که باید CSS fixed تولید کند؛ z-index و اندازه نیز نمایش داده شوند.

Examples در registry به شکل satisfies Record<string, CoreComponents.ComponentExample> تعریف و از public index export شوند.

## 8. معیارهای پذیرش

1. رفتار اندازه، پس‌زمینه، کلاس، style سفارشی، transform و z-index مانند Legacy کار کند.
2. تغییر Observable هر prop پس از رندر، style متناظر را به‌روزرسانی کند.
3. جدول اولویت left/right و start/end برای هر دو جهت RTL/LTR دقیقاً رعایت شود.
4. FIX خروجی CSS معتبر position: fixed بدهد؛ STATIC، RELATIVE و ABSOLUTE نیز مقادیر معتبر CSS باشند.
5. کلیک روی content یا wrapper callback را طبق قرارداد اجرا کند؛ بدون callback هیچ خطایی رخ ندهد.
6. content رشته‌ای و content کامپوننتی بدون نمایش [object Object] رندر شوند.
7. کامپوننت در ComponentManager و Category دیده شود و Examples در TestsPage قابل نمایش باشند.
8. مصرف‌کنندگان Legacy فهرست‌شده در این پلن تغییر نکنند و هنوز به کلاس Legacy خود دسترسی داشته باشند.
9. npx tsc --noEmit، git diff --check و build موجود اجرا شوند؛ خطاهای پیشین repository از خطاهای این مهاجرت تفکیک شوند.
