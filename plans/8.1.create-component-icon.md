# Plan 8.1 — ساخت ComponentIcon

## هدف

ساخت `ComponentIcon` با معماری جدید — اولین Component واقعی.

`ComponentIcon` یک wrapper حول `UtilBrands.Icons` (خروجی `CreateIcon`) است که آن را در یک `<i>` با event handlerهای click/hover/blur قرار می‌دهد.

### چرا قبل از ComponentMessages؟

`ComponentMessages` برای آیکون بستن هر پیام به `ComponentIcon` وابسته است. پس اول `ComponentIcon` ساخته می‌شود.

---

## تحلیل Component قدیمی

### فایل منبع
`last/tools/components/ComponentIcon.ts`

### Props (۴ prop اختصاصی)

| Prop | Type | Default | کاربرد |
|:---|:---|:---|:---|
| `prop_icon` | `Icons \| null` | `null` | نمونه آیکون (خروجی CreateIcon) |
| `prop_iconTitle` | `string` | `""` | عنوان آیکون (tooltip) |
| `prop_iconClass` | `string[]` | `[]` | classهای اضافه |
| `prop_iconStyles` | `Record<string, string>` | `{}` | styleهای اضافه |

### Schemas (۱ part اختصاصی)

| Part | کاربرد |
|:---|:---|
| `part_icon` | رندر آیکون در `<i>` |

### Methods (۳ method)

| Method | کاربرد |
|:---|:---|
| `fn_onClickIcon` | کلیک روی آیکون |
| `fn_onHoverIcon` | mouseenter روی آیکون |
| `fn_onBlurIcon` | mouseleave روی آیکون |

### وابستگی‌ها

- `CreateIcon` — برای ساخت آیکون (در معماری جدید از `@/ui_icons`)
- `UtilBrands.Icons` — type آیکون
- `CoreReactive` — برای render

### فایل ۷ — ComponentIcon.ts

```typescript
import * as CoreReactive   from "@/core_reactive";
// --------------------------------
import {ComponentIconBase}  from "./ComponentIconBase";
import {IconStep}           from "./Step";
import {Schemas}            from "./Schemas";
import {PropsType}          from "./Props";
import {MethodsType}        from "./Methods";
import {ComponentIdentity}  from "@/core_components";


export class ComponentIcon extends ComponentIconBase {

    constructor(
        config:  PropsType,
        methods: MethodsType,
        identity?: Partial<ComponentIdentity>,
    ) {
        super("icon", null, identity, IconStep);
        this.renderComponent(config, methods);
    }


    override renderContentComponent(): CoreReactive.App {
        return this.renderIcon();
    }


    override renderManagerComponent(partName, attrsDefault, data, extra) {
        switch (partName) {
            case Schemas.ICON.part:  return this.renderIcon(attrsDefault, data);
            default:                 return super.renderManagerComponent(partName, attrsDefault, data, extra);
        }
    }


    protected renderIcon(attrsDefault?, data?): CoreReactive.App {

        const prop_icon       = data?.[Props.prop_icon.prop]       ?? this._COMPONENT_PROPS_BIND.prop_icon;
        const prop_iconTitle  = data?.[Props.prop_iconTitle.prop]  ?? this._COMPONENT_PROPS_BIND.prop_iconTitle;
        const prop_iconClass  = data?.[Props.prop_iconClass.prop]  ?? this._COMPONENT_PROPS_BIND.prop_iconClass;
        const prop_iconStyles = data?.[Props.prop_iconStyles.prop] ?? this._COMPONENT_PROPS_BIND.prop_iconStyles;

        return CoreReactive.App.create("i", {
            attrs: {
                ...attrsDefault,
            },
            attrsBind: {
                title: prop_iconTitle,
            },
            stylesBind: prop_iconStyles,
            classBind: [
                prop_iconClass,
            ],
            on: {
                click: (event: Event) => {
                    event.preventDefault();
                    this.executeMethod("CLICK", event, {});
                },
                mouseenter: (event: Event) => {
                    event.preventDefault();
                    this.executeMethod("HOVER", event, {});
                },
                mouseleave: (event: Event) => {
                    event.preventDefault();
                    this.executeMethod("BLUR", event, {});
                },
            },
            children: [
                prop_icon,
            ],
        });
    }

}
```

## نکات مهم

### prop_icon از نوع UtilBrands.Icons

در معماری جدید، `CreateIcon(definition, options)` خروجی `UtilBrands.Icons` می‌دهد — که در واقع یک `CoreReactive.App` (svg) با brand "icon" است.

این یعنی `prop_icon` مستقیماً در `children` قرار می‌گیرد — مثل پیاده‌سازی قدیمی.

### CoreReactive.App.create

در پیاده‌سازی قدیمی از `ReactiveElement.part("i", {...})` استفاده می‌شد. در معماری جدید معادل آن `CoreReactive.App.create("i", {...})` است (یا متد مشابه — باید بررسی شود).

### وابستگی به UiIcons

`ComponentIcon` به `@/ui_icons` فقط در Examples وابسته است — نه در خود کلاس. کلاس فقط `UtilBrands.Icons` را می‌گیرد (type).
