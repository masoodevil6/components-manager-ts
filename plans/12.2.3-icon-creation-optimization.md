### یافته‌های کلیدی

1. **State accumulation رد شد** — D1 (77ms) ≈ D6 (70ms)
2. **bottleneck اصلی: `cloneNode(true)`** — D7 = 49ms = **64% از کل زمان** (D1 = 77ms)
3. **wrapper creation ناچیز** — D8 = 1.83ms برای 100 wrapper
4. **patch برای آیکون‌های سبک 21-32% بهبود** — D2, D3, D4
5. **patch برای heaviest تفاوتی ندارد** — cloneNode روی 30 primitive همچنان bottleneck است
6. **Scaling خطی با complexity** — heaviest: 0.77 ms/icon, median: 0.09 ms/icon (8.5× اختلاف)

### ریشه bottleneck

در `MtCreateIcon.ts` تابع `createStaticIcon` (قبل از patch):

```
cache hit:
1. cached.svgElement.cloneNode(true)     ← 64% زمان (deep clone inner SVG, 30 primitives)
2. CoreReactive.App.svg({ attrs })       ← 2% زمان (wrapper + 6 event listeners + 3 observables)
3. while (cloned.firstChild)             ← 34% زمان (move 30 children)
     wrapper.element.appendChild(cloned.firstChild)
```

بعد از patch:

```
cache hit:
1. cached.svgElement.cloneNode(true)     ← bottleneck باقی‌مانده (cloneNode در jsdom)
2. CoreReactive.App.svg({ existingElement: cloned })  ← constructor روی cloned، صفر move
```

## ۳. راه‌حل پیاده‌سازی‌شده

### Strategy A: existingElement injection ✅

**تغییر ۱ — `ClReactiveElement.ts`:**
- `existingElement?: HTMLElement | SVGElement` به `Options` type اضافه شد
- constructor: اگه `existingElement` موجود باشد، از آن استفاده می‌کند به‌جای `createElementNS`
- event listenerها، hover/focus/active observables همه روی `this.element` (یعنی همان cloned SVG)
- `_applyOptions()` وقتی attrs/children/className نمی‌فرستیم، nothing apply می‌کند — overwrite نمی‌شود

**تغییر ۲ — `createStaticIcon` در `MtCreateIcon.ts`:**
- حذف `attrs` از `CoreReactive.App.svg()` call (cloned قبلاً همه را دارد)
- حذف `while (cloned.firstChild)` move loop
- پاس `existingElement: cloned` به `svg()`

**ساختار نهایی:**
```
ClReactiveElement
└── element = cloned SVG (با attrs + children)
    ├── path
    ├── path
    ├── circle
    └── ...
```

### Strategy B: Skip ClReactiveElement (رد شد)

D8 = 1.83ms/100 — overhead constructor فقط ۲٪ است. پیچیدگی API thin wrapper نمی‌ارزد.

### Strategy C: Cache innerHTML string (رد شد)

innerHTML copy 1.6× کندتر از cloneNode است.

- **behavioral tests 22/22 pass** — هیچ regression

### چه بهبود نکرد
- **scaling benchmark در jsdom:** نوسان شدید، بهبود قابل‌اعتماد دیده نشد
- **heaviest آیکون (score=30):** `cloneNode` روی 30 primitive همچنان bottleneck است

### bottleneck باقی‌مانده

`cloneNode(true)` روی SVG با 30 primitive = 0.49ms/icon در jsdom.
این **محدودیت jsdom** است — در browser واقعی `cloneNode` بسیار سریع‌تر است (native C++ implementation).

### توصیه

1. **patch را نگه داریم** — architecture بهتر، behavioral tests pass، diagnostic بهبود نشان داد
2. **بهینه‌سازی بیشتر در jsdom بازده ندارد** — bottleneck `cloneNode` است که خارج از کنترل ماست
3. **benchmark در browser واقعی** لازم است برای ارزیابی واقعی — jsdom data فقط برای regression detection مناسب است
4. **Strategy B پیچیدگی نمی‌ارزد** — overhead constructor فقط ۲٪ است
