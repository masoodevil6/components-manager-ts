# Plan 17.1.0 — انتقال ComponentInputSimple به معماری جدید

> وضعیت: اجراشده؛ کامپوننت، ثبت Category/Manager، ترجمه‌ها و تست رفتاری اضافه شده‌اند.
>
> منبع رفتار: `last/tools/components/simples/ComponentInputSimple.ts` و استفاده‌های آن در `last/tools/components/simples/ComponentSelectCustomSimple.ts`.
>
> راهنمای معماری: `documents/guides/component-create.md`.
>
> مقصد: `src/framework/module_ui/module_components/lists/componentInputSimple/` و دسترسی عمومی `UiCategory.UI.Simples.InputSimple(config, methods, identity)`.

## ۱. هدف و محدوده

کامپوننت قدیمی ورودی ساده را به ساختار declarative/runtime جدید منتقل کن. انتقال باید API ورودی، حالت مقدار و غیرفعال، رویدادهای تغییر/focus/blur، نمایش border و آیکون پاک‌کردن را حفظ کند. وابستگی runtime به `last/`، `ReactiveElement`، `Observable`، `ComponentBase` و `ToolsComponents` در مقصد مجاز نیست؛ از `CoreComponents`، `CoreReactive`، `CoreObservable`، تنظیمات سیستم و کامپوننت‌های جدید استفاده شود.

این پلن فقط انتقال `ComponentInputSimple` و ثبت آن در Manager و Category را پوشش می‌دهد. مهاجرت `ComponentSelectCustomSimple` و تغییر مصرف‌کنندگان قدیمی خارج از محدوده است؛ استفاده‌های موجود باید در بررسی سازگاری ثبت شوند.

## ۲. رفتار و API موجود در Legacy

ریشه با نام `input-simple` ساخته می‌شود و `renderContentComponent()` به `part_form` می‌رود. فرم از `ComponentBorder` جدیدِ آن دوره تشکیل شده و محتوایش input و آیکون پاک‌کردن است. هنگام focus رنگ border به `SECONDARY/GRADE_1` و در حالت عادی به `PRIMARY/GRADE_1` برمی‌گردد. پس‌زمینه در حالت disabled برابر `PRIMARY/GRADE_5` و در حالت عادی `SHAN/GRADE_1` است. آیکون پاک‌کردن فقط در حالت فعال نمایش داده می‌شود و با کلیک مقدار input را خالی می‌کند.

### ۲.۱. نگاشت props

| Prop قدیمی | نوع و پیش‌فرض | قرارداد جدید |
|:---|:---|:---|
| `prop_inputName` | `string \| null`, پیش‌فرض `null` | همان نام و نوع؛ مقدار `name` ورودی به شکل `${name}[value]` ساخته شود. وقتی null است رفتار مرورگر و قرارداد فعلی پروژه بررسی شود. |
| `prop_inputDisable` | `boolean`, پیش‌فرض `false` | همان نام و رفتار؛ input غیرفعال و آیکون پاک‌کردن مخفی شود. |
| `prop_inputValue` | `string \| null`, پیش‌فرض `null` | مقدار controlled؛ با تایپ به‌روز و `INPUT_CHANGE` اجرا شود. کلیک پاک‌کردن نیز مقدار و خود input را خالی کند. |
| `prop_inputClass` | `string[]`, پیش‌فرض `['form-control']` | کلاس‌های اضافی روی input؛ کلاس پیش‌فرض حفظ شود. |
| `prop_inputStyles` | `Record<string, string>`, پیش‌فرض `{}` | استایل‌های مصرف‌کننده روی input و با اولویت تعریف‌شده در پیاده‌سازی ادغام شود. |
| `prop_inputType` | enum، پیش‌فرض `string` | enum جدید `InputSimpleTypes` با مقادیر `string`, `number`, `email`, `password`, `tel`, `url`, `search`, `date`, `time`, `datetime-local`. |
| `prop_inputPlaceholder` | `string \| null`, پیش‌فرض `null` | همان قرارداد DOM input. |
| `prop_inputFor` | `string \| null`, پیش‌فرض `null` | نقش و محل اعمال آن را با semantics استاندارد HTML روشن کن؛ در Legacy به‌صورت `for` روی input نوشته می‌شود که برای input attribute استانداردی نیست. بدون تصمیم مستند، رفتار را بی‌صدا به label نسبت نده. |
| `prop_inputBorderTopLeftRadiusHas` | `boolean`, پیش‌فرض `true` | به prop متناظر `ComponentBorder` نگاشت شود. |
| `prop_inputBorderTopRightRadiusHas` | `boolean`, پیش‌فرض `true` | به prop متناظر `ComponentBorder` نگاشت شود. |
| `prop_inputBorderBottomLeftRadiusHas` | `boolean`, پیش‌فرض `true` | به prop متناظر `ComponentBorder` نگاشت شود. |
| `prop_inputBorderBottomRightRadiusHas` | `boolean`, پیش‌فرض `true` | به prop متناظر `ComponentBorder` نگاشت شود. |
| `prop_inputBorderTopHas` | `boolean`, پیش‌فرض `true` | به prop متناظر `ComponentBorder` نگاشت شود. |
| `prop_inputBorderRightHas` | `boolean`, پیش‌فرض `true` | به prop متناظر `ComponentBorder` نگاشت شود. |
| `prop_inputBorderBottomHas` | `boolean`, پیش‌فرض `true` | به prop متناظر `ComponentBorder` نگاشت شود. |
| `prop_inputBorderLeftHas` | `boolean`, پیش‌فرض `true` | به prop متناظر `ComponentBorder` نگاشت شود. |

Props پایه‌ی Component و Structure از `ComponentStructureTrait` دریافت شوند و دوباره تعریف نشوند. برای هر prop از `Define_ComponentProp<T>`، metadata ترجمه‌شده از `Keys`، و `PropsType`/`PropsConfigType` از `TypeHelpers` استفاده کن. نوع‌های null باید صریحاً nullable باشند.

### ۲.۲. نگاشت رویدادها

| نام عمومی پیشنهادی | نام Legacy | قرارداد |
|:---|:---|:---|
| `INPUT_CHANGE` | `fn_onInputChange` | با هر رویداد input، مقدار جاری از `prop_inputValue` و event به callback برسد. |
| `INPUT_FOCUS` | `fn_onInputFocus` | هنگام focus؛ مقدار جاری در dataArgs باشد. |
| `INPUT_BLUR` | `fn_onInputBlur` | هنگام blur؛ مقدار جاری در dataArgs باشد. |

در Legacy هر سه رویداد dataArg به نام `value` دارند. امضای جدید را با الگوی `Methods.ts` و `MethodsConfigType` بساز و نام قدیمی `fn_on...` را به‌عنوان نام metadata/سازگاری فقط در صورت پشتیبانی قرارداد فعلی نگه دار. callbackها باید از مسیر `executeMethod` اجرا شوند.

## ۳. Schemas و درخت DOM

در `Schemas.ts`، ابتدا `COMPONENT` و `STRUCTURE` را از `ComponentStructureTrait.schemas` قرار بده؛ سپس schemaهای اختصاصی را تعریف کن:

| Schema | part پیشنهادی | Props | نقش |
|:---|:---|:---|:---|
| `FORM` | `part-input-simple-form` | disabled، border sides و radius flags | قاب اصلی و composition محتوا |
| `INPUT` | `part-input-simple-input` | name، disabled، value، class، styles، type، placeholder، for | input واقعی |
| `CLEAR_ICON` | `part-input-simple-clear-icon` | disabled | آیکون پاک‌کردن و تعامل آن |

نام partهای Legacy (`part_form`, `part_form_input`, `part_form_iconClear`) در صورت نیاز به سازگاری DOM بررسی شود؛ نام schema جدید مطابق convention جدید و یکتا باشد. Rendering فقط در `ComponentInputSimple.ts` انجام شود و `Schemas.ts` حاوی renderer نباشد.

درخت مورد انتظار: `component-input-simple` → structure → form → `ComponentBorder` composition؛ داخل border input و clear icon باشند. Border باید focus را از input همان instance دریافت کند. اتکا به `this._ELEMENT_INPUT` قبل از ساخته‌شدن input یا اشتراک focus بین instanceها ممنوع است؛ ترتیب ساخت یا observable focus محلی را طوری طراحی کن که Border همواره به input همان instance متصل شود.

## ۴. قراردادهای اندازه، رنگ و تعامل

- اندازه‌های input (height، line-height، font-size و padding چهارطرفه) را از `CoreConfig.Settings.SizeName` و `UtilStyle` محاسبه کن؛ جدول دستی یا `prop_size` جدید نساز.
- جهت متن را از `CoreConfig.Settings.DirectionRtl` بگیر.
- رنگ border عادی `PRIMARY/GRADE_1` و هنگام focus `SECONDARY/GRADE_1` باشد؛ اگر Border جدید `prop_borderColor_hover` دارد، آن را با focus اشتباه نگیر و رفتار hover را جداگانه مشخص کن.
- پس‌زمینه‌ی فعال `SHAN/GRADE_1` و disabled `PRIMARY/GRADE_5` باشد، مگر قرارداد فعلی `ComponentBorder` برای disabled توضیح دیگری داشته باشد.
- focus و blur واقعی input حفظ شود؛ کلیک روی clear icon مقدار را null کند، input را همگام خالی کند و `INPUT_CHANGE` را فقط مطابق قرارداد Legacy فراخوانی کند.
- `inputType` فقط از مقادیر enum مجاز DOM استفاده کند.
- اگر clear icon با `ComponentIcon` و positioning ساخته می‌شود، APIهای جدید `UiCategory` را به‌کار ببر و برای هر instance childها و listenerها را در `dispose()` پاک‌سازی کن.

## ۸. ریسک‌ها و تصمیم‌های باز برای مرحله اجرا

1. `prop_inputFor` برای سازگاری با Legacy همچنان به‌صورت `for` روی input اعمال می‌شود؛ این attribute به‌تنهایی label association استاندارد ایجاد نمی‌کند و مصرف‌کننده‌ی فعلی آن استفاده نمی‌کند.
2. Legacy از `StyleValue.important()` برای رنگ border استفاده می‌کند؛ Border جدید رنگ فوکوس را با observable `prop_borderColor` کنترل می‌کند و نیازی به `important` ندارد.
3. `ComponentSelectCustomSimple` هنوز ComponentInputSimple قدیمی را instantiate می‌کند. با این پلن آن مصرف‌کننده مهاجرت نمی‌کند؛ حذف یا تعویض Legacy پیش از اجرای مستقل InputSimple انجام نشود.
4. آیکون پاک‌کردن مقدار را `null` می‌کند، درحالی‌که input DOM مقدار رشته‌ای است. observable، DOM و callback باید یک رفتار یکنواخت و مستند داشته باشند.
