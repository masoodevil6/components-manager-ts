# پلن 54.1.0 — نمودار سنجش مقدار و محدوده‌های عملکرد

> **وضعیت:** کامپوننت و اتصال اولیه پیاده‌سازی شده؛ بررسی ظاهری در مرورگر باقی است
> **دسته:** Chart Components → Monitor؛ مستقل از Progress
> **نام پیشنهادی:** `componentChartMetricGauge` و `UiCategory.UI.Charts.Monitor.Gauge`
> **راهنمای معماری:** `documents/guides/component-create.md`
> **نخستین کاربرد:** نمایش معیارهای صفحهٔ Performance در بخش Page overview

## ۱. هدف

یک کامپوننت عمومی برای نمایش **یک مقدار اندازه‌گیری‌شده در کنار مقیاس و محدوده‌های قابل تنظیم** ساخته شود. مصرف‌کننده بتواند برای هر مقدار مشخص کند چه بازه‌هایی «خوب»، «متوسط» و «نیازمند بررسی» هستند. جای مقدار روی نمودار و متن وضعیت باید خوانا باشند؛ نمایش فقط به رنگ وابسته نباشد.

فرض این پلن آن است که منظور از نمایش «اس‌پی‌جی» استفاده از **SVG** برای نمودار است. این کامپوننت نمایشگر مقدار است و با `ProgressLinear` تفاوت معنایی دارد: Progress پیشرفت انجام یک کار را نشان می‌دهد، در حالی که Gauge یک نتیجه را با مقیاس و محدوده‌های ارزیابی مقایسه می‌کند. خود کامپوننت اندازه‌گیری یا تصمیم‌گیری دربارهٔ خوب‌بودن عملکرد را بر عهده نمی‌گیرد.

## ۲. شکل پیشنهادی

نمای اولیه یک نوار افقی SVG با سه بخش و یک نشانگر مقدار است؛ متن واقعی و وضعیت کنار نمودار نیز به‌صورت HTML قابل انتخاب و خواندن باشد:

```text
DOM ready                            420 ms   خوب
0 ms       خوب          متوسط       نیازمند بررسی       1,500 ms
├───────────────┬──────────────┬────────────────────────┤
                ▲ مقدار اندازه‌گیری‌شده
```

اعداد نمودار بالا صرفاً برای نشان‌دادن شکل هستند و معیار پیشنهادی عملکرد پروژه محسوب نمی‌شوند. مقیاس هر سنجه مستقل است؛ قرار نیست میلی‌ثانیه، حجم و تعداد با هم جمع یا روی یک مقیاس مشترک مقایسه شوند. نمودار خطی در عرض کم قابل خواندن باقی بماند؛ نوع دایره‌ای، نمودار زمانی و مقایسهٔ چند اجرا در نسخهٔ اول خارج از محدوده‌اند.

## ۳. داده و قرارداد پیشنهادی

کامپوننت هر بار **یک سنجه** را نمایش می‌دهد و چیدمان چند نمودار به مصرف‌کننده واگذار می‌شود. این جداسازی استفاده از کامپوننت برای کاربردهای دیگر را نیز ممکن می‌کند.

```ts
type MetricBand = {
    id: string;
    label: string;       // متن توضیحی مصرف‌کننده
    from: number;        // شروع محدوده روی مقیاس
    to: number;          // پایان محدوده روی مقیاس
    color?: string;      // رنگ اختیاری، با پیش‌فرض توکن‌های پروژه
};

UiCategory.UI.Charts.Monitor.Gauge({
    prop_title: "DOM ready",
    prop_value: 420,
    prop_unit: "ms",
    prop_min: 0,
    prop_max: 1500,
    prop_bands: [
        {id: "good", label: "Good", from: 0, to: 500},
        {id: "moderate", label: "Moderate", from: 500, to: 1000},
        {id: "poor", label: "Needs attention", from: 1000, to: 1500},
    ],
});
```

این ورودی‌ها فقط مثال هستند. API به عدد و واحد مشخص محدود نیست و باید با `Observable`ها و تنظیمات واکنشی فریم‌ورک کار کند.

| ورودی | نوع و رفتار پیشنهادی |
|---|---|
| `prop_title` | عنوان سنجه |
| `prop_value` | `number \| null`؛ مقدار واقعی یا نبود داده |
| `prop_unit` | واحد نمایشی، مانند `ms`، `KiB` یا تعداد |
| `prop_min` / `prop_max` | دو انتهای مقیاس نمایشی، با `min < max` |
| `prop_bands` | فهرست مرتب محدوده‌های غیرهم‌پوشان با عنوان، بازه و رنگ اختیاری |
| `prop_valueText` | متن قالب‌بندی‌شدهٔ اختیاری، بدون تغییر مقدار عددی محاسبات |
| `prop_unavailableText` | پیام مقدار ناموجود؛ با پیش‌فرض قابل ترجمه |
| `prop_chartClass` / `prop_chartStyles` | شخصی‌سازی طبق الگوهای فریم‌ورک |

### قواعد ارزیابی و مقیاس

- برای مرز مشترک، بازه‌ها به شکل `[from, to)` هستند و **آخرین بازه انتهای خودش را هم شامل می‌شود**؛ بنابراین یک مقدار مرزی دقیقاً به یک دسته تعلق می‌گیرد.
- از ترتیب یا نام «good» به‌تنهایی نتیجه‌گیری نشود: مقدار سنجه ممکن است هرچه بیشتر یا هرچه کمتر بهتر باشد. مصرف‌کننده محدوده و عنوان را مشخص می‌کند و نمودار طبق همان بازهٔ منطبق نمایش می‌دهد.
- برای مقدار خارج از مقیاس، عدد واقعی حفظ شود، نشانگر به نزدیک‌ترین لبه محدود شود و متن «خارج از مقیاس» نشان داده شود. وضعیت فقط با بازه‌های تعریف‌شده تعیین شود؛ برش نشانگر نباید به معنای تغییر داده باشد.
- `null`، `NaN` یا مقدار غیرمتناهی، و نیز مقیاس نامعتبر، به حالت «داده ناموجود / تنظیمات نامعتبر» بروند و نشانگر یا رتبهٔ جعلی تولید نکنند. برای بازه‌های تکراری، هم‌پوشان، وارونه، غیرمتناهی یا خارج از مقیاس، خطای پیکربندی روشن ارائه شود؛ در حالت تولید نمودار ارزیابی گمراه‌کننده نشان ندهد.
- محدوده‌ها می‌توانند کل مقیاس را پوشش ندهند. اگر مقدار در یک فاصلهٔ بدون محدوده باشد، مقدار و نشانگر نمایش داده شوند ولی وضعیت «بدون دسته‌بندی» باشد.
- بدون محدوده‌های معتبر و آگاهانه، فقط مقدار خام و وضعیت «بدون معیار ارزیابی» نمایش داده شود؛ رنگ یا عنوان خوب/بد نباید حدس زده شود.

## ۴. کاربرد در Page overview

صفحه برای چهار سنجهٔ موجود، چهار نمونه از همین کامپوننت را با مقدار، واحد، مقیاس و محدوده‌های مستقل فراهم می‌کند:

| سنجه | دادهٔ فعلی پروژه | واحد | ملاحظات |
|---|---|---|---|
| DOM ready | `domContentLoadedEventEnd` | `ms` | از زمان آغاز navigation سند iframe؛ خود آن لزوماً آماده‌شدن کامل رابط نیست |
| Page load | `loadEventEnd` | `ms` | زمان پایان رویداد load سند iframe |
| Transferred | مجموع `transferSize` گزارش‌شده برای navigation و منابع | `KiB` | داده می‌تواند به علت کش یا محدودیت منابع ناقص باشد |
| Resources | تعداد entryهای resource | تعداد | تعداد entry است، نه الزاماً تعداد درخواست‌های شبکه |

صفحه باید **پروفایل آستانهٔ مستقل و قابل تنظیم برای هر سنجه** داشته باشد. تا وقتی آستانه‌ای برای یک سنجه تعریف و فعال نشده است، رتبه‌ای نمایش داده نشود. در نسخهٔ اول صرفاً سازوکار دریافت تنظیمات در کنترلر طراحی شود؛ ساخت تنظیم‌گر و ذخیره‌سازی دائمی یا مقایسهٔ خودکار با baseline می‌تواند مرحلهٔ بعد باشد. هیچ عددی به عنوان استاندارد همگانی برای هر چهار سنجه در هستهٔ کامپوننت ثابت نشود.

حجم صفر به‌تنهایی اثبات انتقال صفر نیست: دادهٔ کش‌شده، اندازهٔ گزارش‌نشده یا منابع با محدودیت دسترسی می‌توانند باعث صفر شدن بعضی `transferSize`ها شوند. صفحه باید میزان پوشش داده را مشخص کند و وقتی قابل اتکا نیست، از دادن برچسب خوب/بد خودداری کند. برای نبود زمان load یا resource timing هم وضعیت «ناموجود» نشان داده شود، نه صفر.

## ۵. معماری فریم‌ورک و SVG

- ساخت مجموعهٔ استاندارد فایل‌ها در `src/framework/module_ui/module_components/lists/componentChartMetricGauge/`: `Definition.ts`، `Props.ts`، `Schemas.ts`، `Methods.ts`، Base، Component، `examples/` و `index.ts`؛ ساخت Step فقط مطابق نیاز و قرارداد پروژه، بدون event تصنعی.
- ثبت کامپوننت در دستهٔ Monitor زیر Charts، درخت عمومی، ComponentManager، ترجمه‌های فارسی و انگلیسی، metadata و مثال‌ها.
- Schemaهای پیشنهادی: `ROOT`، `HEADER`، `CHART`، `BANDS`، `MARKER` و `LEGEND`. از `ComponentStructureTrait`، Observable و Scope پروژه استفاده شود؛ به‌رسانی داده موجب بازساخت کل کامپوننت نشود.
- نمودار با `svg` و namespace صحیح، `viewBox` و عرض واکنش‌گرا ساخته شود. مقیاس خطی و مختصات در یک تابع محضِ مستقل محاسبه شوند. متن مقدار، وضعیت و محدوده‌ها در HTML موجود باشند تا نتیجه در نبود SVG یا فناوری کمکی قابل فهم باشد.
- رنگ و اندازه با token و util پروژه سازگار باشند. در RTL ترتیب برچسب‌ها و جهت متن با تنظیمات پروژه هماهنگ باشد؛ جهت محور و معنای حداقل/حداکثر صریح و ثابت تعریف شود، نه اینکه داده به‌طور ناخواسته وارونه شود.
- برای دسترس‌پذیری از متن عنوان، مقدار، واحد، وضعیت و شرح محدوده استفاده شود. اگر semantics بومی `meter` یا نقش ARIA استفاده می‌شود، نقش انتخاب‌شده با مقیاس واقعی و حالت بدون داده سازگار باشد؛ ارزیابی نباید صرفاً با رنگ منتقل شود. انیمیشن اختیاری، کوتاه و مطابق `prefers-reduced-motion` باشد.
- نمونه‌ها: مقدار داخل هر محدوده، مقدار مرزی، خارج از مقیاس، دادهٔ ناموجود، جهت خوب‌بودن معکوس، بازهٔ فاقد طبقه‌بندی، دادهٔ واکنشی و RTL.

## ۶. مراحل اجرا

1. نهایی‌کردن شکل خطی SVG، نام دسته و قرارداد آستانه با استفاده از این پلن.
2. پیاده‌سازی محاسبهٔ بازه، محدودسازی نشانگر و اعتبارسنجی به شکل مستقل از DOM.
3. ساخت کامپوننت عمومی، SVG واکنش‌گرا، ترجمه‌ها، مثال‌ها، ثبت دسته و خروجی عمومی.
4. افزودن پروفایل ارزیابی قابل تزریق به صفحهٔ Performance و نمایش چهار نمونه. در نبود پروفایل، نمایش مقدار خام بدون رتبه.
5. بررسی سناریوهای iframe با دادهٔ واقعی، cached، اطلاعات محدود و ناموجود؛ حفظ نمایش Resource breakdown موجود.
6. پس از تأیید رفتار، بررسی ظاهری مرورگر در اندازه‌های مختلف و هر دو جهت، و ثبت نتیجه در پلن.

## ۷. تست‌ها و معیار پذیرش

- تست تابع محض برای هر بازه، دو سر مقیاس، مرزهای مشترک، gap، خروج از مقیاس، محدوده‌های معکوس و هم‌پوشان، `null` و اعداد غیرمتناهی.
- تست واکنش‌پذیری مقدار و تنظیمات، متن و نقش دسترس‌پذیر، نمایش مقدار واقعی خارج از مقیاس، پاک‌سازی scope، و جدابودن داده‌های نمونه‌ها.
- تست صفحه برای هر چهار سنجه، آستانهٔ تعریف‌نشده، مقدار ناموجود و transfer با پوشش ناقص؛ تأیید اینکه هیچ رتبهٔ ساختگی نمایش داده نمی‌شود.
- بررسی مرورگر واقعی برای SVG، تغییر عرض، مقیاس کوچک، RTL/LTR، تم و کاهش حرکت؛ تست DOM شبیه‌سازی‌شده به‌تنهایی چیدمان و رسم را اثبات نمی‌کند.

معیار پایان: چهار مقدار واقعی صفحه، در صورت وجود تنظیمات معتبر و دادهٔ کافی، به‌شکل مستقل و با وضعیت قابل توضیح نمایش داده شوند؛ در غیر این صورت مقدار خام یا علت نبود داده بدون قضاوت نادرست دیده شود.
