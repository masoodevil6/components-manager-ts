> وضعیت اجرا: کامپوننت، ثبت Category/Manager، زبان‌ها و تست‌های رفتاری پیاده‌سازی شدند؛ بررسی بصری در TestsPage هنوز انجام نشده است.

## ۱. وضعیت Legacy و وابستگی‌ها

`ComponentTimerDown` قدیمی یک تایمر قابل راه‌اندازی با **زمان پایان مطلق بر حسب میلی‌ثانیه از epoch** است. نمای آن از بخش فرم، tooltip اختیاری، نمایش چهار رقم دقیقه/ثانیه، متن وضعیت و دکمه‌ی درخواست مجدد تشکیل می‌شود. state از شش Observable برای ارقام، وضعیت پایان و متن و یک interval تشکیل شده است. پس از پایان، ارقام به `--:--` تبدیل و دکمه‌ی retry نمایش داده می‌شود. retry فقط callback مصرف‌کننده را فراخوانی می‌کند؛ شروع دوباره‌ی شمارش بر عهده‌ی مصرف‌کننده است.

| موضوع | Legacy | مقصد و تصمیم |
|:---|:---|:---|
| Root | `super("timer-down", null)`، `renderContentComponent()` → `part_form` | `Definition` با `component_timer_down`/`componentTimerDown`، tag `timer-down` و routing پایه‌ی Trait |
| Props | ۱۱ prop اختصاصی + propهای Component/Structure | یازده `Define_ComponentProp<T>`؛ هفت prop پایه از `ComponentStructureTrait.props` |
| Schema | پنج part: `part_form`, `part_tooltip`, `part_timer`, `part_text`, `part_text_button` | دو schema پایه‌ی Trait در ابتدا، سپس پنج schema فقط metadata |
| Template | `BODY` با reference به `prop_description` | حذف؛ `renderContentComponent` و rendererهای part جای آن |
| Methods | `fn_onClickRetry` و `fn_onFinishTimer` بدون dataArgs/componentArgs | `CLICK_RETRY` و `FINISH_TIMER` در `Methods.ts` |
| Tooltip | `ComponentTooltipDescription` قدیمی | `UiCategory.UI.Positions.Tooltip` جدید پس از بررسی API نمایش شرطی |
| Retry | `ComponentButton` قدیمی | `UiCategory.UI.Simples.Button` جدید؛ method `CLICK` به `CLICK_RETRY` وصل شود |
| زمان‌بندی | `call_startCountdown(timeUnixEnd)`؛ `setInterval(..., 1000)` | حفظ API ورودی timestamp میلی‌ثانیه؛ محاسبه از `Date.now()` در هر tick و cleanup کامل |

`last/tools/components/index.ts` export قدیمی تایمر را کامنت کرده است. مسیر جدید هیچ runtime import از `last/`، `ToolsComponents`، `ReactiveElement` یا `Observable` قدیمی نداشته باشد. وابستگی‌های Button و Tooltip جدید در `src/` موجودند. اگر `ComponentTooltip` برای icon legacy سازگار نیست، mapping `UiIcons.IIconDefinition` را بررسی و آزمایش کنید؛ از object آیکون قدیمی در prop جدید استفاده نشود.

متن‌های پیش‌فرض قدیمی: فارسی «تا ارسال مجدد کد»، «کد منقضی شده است»، «ارسال مجدد»؛ انگلیسی `Until resend code`, `The code has been deprecated`, `Retry`. این متن‌ها داده‌ی قابل override کامپوننت‌اند؛ metadata `Keys` جداگانه در `Keys.ts`, `Fa.ts`, `En.ts` برای نام/توضیح component، props، schemas، methods و examples اضافه شود. `Props.ts` فقط propهای اختصاصی را تعریف کند و typeها با `ExtractPropsType`/`ExtractPropsConfigType` استخراج شوند. `satisfies CoreComponents.ComponentProps` و نوع generic صریح برای `Define_ComponentProp<T>` رعایت شود.

## ۳. نگاشت Schema و Rendering

| Schema جدید | part قدیمی | مسئولیت renderer |
|:---|:---|:---|
| `COMPONENT`, `STRUCTURE` | لایه‌های پایه | **دو ورودی اول** از `ComponentStructureTrait.schemas`؛ route با `ComponentStructureTrait.renderComponentSchema` و `renderStructureSchema` |
| `FORM` | `part_form` | پوسته‌ی ظاهری، رنگ زمینه، جهت و فرزندان `TOOLTIP`, `TIMER`, `TEXT` |
| `TOOLTIP` | `part_tooltip` | tooltip شرطی بر اساس `prop_description`؛ icon و جای‌گیری سازگار با RTL/LTR |
| `TIMER` | `part_timer` | `MM:SS` چهار رقم، رنگ‌ها و افکت پالس یک‌ثانیه‌ای در زمان فعال؛ اندازه و جهت LTR ارقام |
| `TEXT` | `part_text` | متن وضعیت از `prop_langSelected`/`prop_langs`، جداکننده و `TEXT_BUTTON` شرطی هنگام پایان؛ وابسته به `prop_show_options` |
| `TEXT_BUTTON` | `part_text_button` | عنوان retry زبان جاری و ارسال `CLICK_RETRY` از Button جدید |

Schema صرفاً `part/props/name/description` را نگه دارد؛ state، handler، renderer و style پویا در `ComponentTimerDown.ts` باشند. از `this._COMPONENT_PROPS_BIND` با `data?.["prop_..."] ?? bind.prop_...` و `CoreObservable.App.computed/conditionWhen` برای تغییرات بعدی استفاده شود. تصمیم layout responsive قدیمی (`col-md-1`, `col-md-4`, `col-12`) و RTL در مثال بصری سنجیده شود. افکت با CSS scoped به instance یا property اختصاصی پیاده شود تا دو تایمر با هم تداخل نکنند؛ حذف افکت هنگام پایان/‌dispose بررسی شود.

فهرست `props` هر schema از Legacy: `FORM` ← `prop_backgroundColor_body`, `prop_size`؛ `TOOLTIP` ← `prop_tooltipIcon`, `prop_description`, `prop_backgroundColor_body`, `prop_size`؛ `TIMER` ← `prop_size`, `prop_backgroundColor_timer`, `prop_backgroundColor_timerEffect`, `prop_color_timer`, `prop_show_options`؛ `TEXT` ← `prop_size`, `prop_color_description`, `prop_langSelected`, `prop_langs`, `prop_show_options`؛ `TEXT_BUTTON` ← `prop_size`, `prop_langSelected`, `prop_langs`. هر ورودی به entry از `Props.ts` اشاره کند.

## ۴. API، state و چرخه‌ی عمر

```typescript
call_startCountdown(timeUnixEnd: number): void; // Date.now() + durationMs
```

- در ابتدا، بدون فراخوانی start، نمایش `--:--` و متن خالی است و دکمه‌ی retry دیده نمی‌شود؛ این همان state اولیه‌ی Legacy است.
- start، interval قبلی را متوقف، وضعیت پایان را false، زمان پایان جدید را ثبت و نمایش را همان لحظه از اختلاف `timeUnixEnd - Date.now()` به‌روز کند؛ سپس tick هر ثانیه از clock واقعی محاسبه شود تا drift انباشته نشود.
- اگر زمان پایان در حال حاضر گذشته یا برابر با `Date.now()` است، همان لحظه به `--:--` و متن پایان برود و `FINISH_TIMER` **یک بار** اجرا شود؛ برای آن start، interval جدید ساخته نشود. این اصلاح صریح لبه‌ی Legacy است که پایان زمان گذشته را تا tick بعدی عقب می‌انداخت.
- نمایش `MM:SS` با صفر پیشرو؛ برای زمان بیشتر از ۵۹ دقیقه، تصمیم نمایش دقیقه‌ی کل به‌جای wrap ساعتِ نسخه‌ی قدیم در تست ثبت شود. داده‌ی نامعتبر (`NaN`, بی‌نهایت) interval نسازد.
- پایان یک run، interval را پاک و فقط یک `FINISH_TIMER` اجرا کند؛ شروع دوباره، run قبلی را لغو کند. `CLICK_RETRY` فقط از click دکمه اجرا شود و به‌طور خودکار تایمر را آغاز نکند.
- `dispose()` interval، منابع reactive/child در اختیار کامپوننت و `disposeStep()` را پاک کند. callback پایان بعد از dispose نباید اجرا شود. Step با factory `createTimerDownStep()` در constructor هر instance ساخته شود.

## ۵. فایل‌ها و ترتیب اجرا مطابق راهنما

```text
src/framework/module_ui/module_components/lists/componentTimerDown/
├── Definition.ts
├── Props.ts
├── Schemas.ts
├── Methods.ts
├── Step.ts
├── ComponentTimerDownBase.ts
├── ComponentTimerDown.ts
├── index.ts
└── examples/
    ├── Default.ts
    └── index.ts
```

1. `Definition.ts` (`id: "component_timer_down"`, `name: "componentTimerDown"`, `version: "v1.0.0"`)، یازده prop، هفت schema و دو method declarative ساخته شوند. `Methods.ts` با `ExtractMethodsType`, `ExtractMethodsConfigType` و نام‌های `fn_onClickRetry` / `fn_onFinishTimer`؛ `Step.ts` factory، نه singleton.
2. `ComponentTimerDownBase.ts` از `CoreComponents.App` ارث ببرد؛ `ComponentStructureTrait.props/schemas` و `Props/Schemas/Methods` را در چهار فیلد قراردادی ثبت کند و `disposeStep()` داشته باشد.
3. `ComponentTimerDown.ts` با constructor `(config?, methods?, identity?)`، `renderContentComponent`، route کامل در `renderManagerComponent` (دو case پایه با Trait، پنج case اختصاصی)، state و `call_startCountdown` ساخته شود. هر instance فقط یک interval فعال داشته باشد؛ `dispose()` آن را ببندد.
4. Button و Tooltip با Category callable ساخته شوند، `getElement()` به children داده شود، callback `CLICK` دکمه به `executeMethod("CLICK_RETRY", ...)` متصل شود. متن retry از prop زبان به‌شکل reactive تغییر کند.
5. `examples/Default.ts` با `render(): HTMLElement` و `examples/index.ts` ساخته شوند؛ مثال timer یک دقیقه‌ای و callback retry با restart ارائه کند. هر timeout کمکی مثال هنگام dispose مدیریت شود.
6. `componentTimerDown/index.ts`، `src/framework/module_ui/module_components/lists/index.ts` (export و `CoreComponents.ComponentManager.register({ ..., examples })`) به‌روزرسانی شوند. در Category، `module_categories/lists/ui/contents/timerDown/{Definition.ts,index.ts}`، `contents/index.ts` و `contents/Definition.ts` افزوده شوند؛ API نهایی `UiCategory.UI.Contents.TimerDown(config, methods, identity)` instance برگرداند.
