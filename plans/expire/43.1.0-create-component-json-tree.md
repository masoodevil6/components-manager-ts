# پلن 43.1.0 — ساخت `componentJsonTree`

> **وضعیت:** Implemented  
> **راهنما:** `documents/guides/component-create.md`  
> **کامپوننت:** `componentJsonTree`  
> **دسته‌بندی:** `tools → dataType`  
> **API پیشنهادی:** `UiCategory.UI.Tools.DataType.JsonTree(config, methods, identity)`

## ۱. هدف و محدوده

هدف اصلی `componentJsonTree` نمایش مناسب و حرفه‌ای درخت JSON است؛ نه صرفاً تبدیل آبجکت به چند ردیف بازوبسته‌شونده. خروجی باید ساختار، نوع و مقدار داده را با سلسله‌مراتب بصری روشن، رنگ‌بندی خوانا، کنترل‌های قابل‌فهم و پیمایش مناسب برای داده‌های کوچک و بزرگ نشان دهد. کامپوننت viewer است و داده را تغییر نمی‌دهد.

دسته‌بندی `tools → dataType` برای نمایش ساخت‌یافتهٔ داده در نظر گرفته شده است. این شاخه در Categoryهای فعلی `tools` وجود ندارد و باید همراه این کامپوننت ساخته و به درخت `Tools` اضافه شود. کامپوننت به `ComponentCodeMirror` و `ComponentConsole` وابسته نمی‌شود و می‌تواند مستقلاً برای مشاهدهٔ responseها، تنظیمات و نمونه‌های JSON استفاده شود.

ورودی `prop_data` مقدار JSON از نوع `null`, `boolean`, `number`, `string`, آرایه یا آبجکت ساده است. رشتهٔ JSON به‌صورت خودکار parse نمی‌شود؛ رشتهٔ ورودی یک مقدار متنی است. تبدیل متن JSON به مقدار باید پیش از ارسال به کامپوننت انجام شود.

## ۲. قرارداد رفتاری و ارائهٔ بصری

- هر node در یک ردیف منظم نمایش داده شود: toggle، key یا array index، جداکنندهٔ `:`, سپس مقدار یا خلاصهٔ شاخه.
- object و array با نشانگر نوع و شمار property/item نمایش داده شوند؛ حالت بسته preview کوتاه مانند `{…}` یا `[…]` داشته باشد و حالت باز childها را زیر والد نشان دهد.
- نوع‌های string، number، boolean و null با رنگ معنایی متفاوت اما برگرفته از tokenهای موجود پروژه مشخص شوند. key، punctuation و value از نظر رنگ و وزن بصری قابل تفکیک باشند.
- رشته‌ها با قواعد JSON quote/escape شوند؛ رشتهٔ خالی، مقدار null، boolean و عدد صفر نمایش مبهم یا خالی نداشته باشند.
- indentation هر عمق یکنواخت باشد و یک راهنمای بصری ظریف برای سلسله‌مراتب داشته باشد؛ ردیف hover و keyboard focus واضح و هماهنگ با theme باشند.
- ردیف‌ها در عرض والد بمانند؛ key/value بسیار بلند به‌شکل کنترل‌شده wrap شوند و horizontal overflow ناخواسته نسازند.
- object/array خالی به‌صورت `{}` و `[]` نمایش داده شوند؛ null ریشه و حالت بدون داده از حالت بارگذاری یا خطا تفکیک شوند.
- هر node بازشدنی با button دسترس‌پذیر، `aria-expanded`, نام قابل‌فهم و آیکون chevron پروژه باز/بسته شود؛ رفتار با mouse و keyboard یکسان باشد.
- toolbar شامل جست‌وجوی اختیاری، بازکردن/بستن همهٔ شاخه‌ها و کپی JSON کامل باشد. جست‌وجو key و مقدارهای primitive را بیابد، nodeهای مطابق را برجسته کند و ancestorهای لازم را برای دیدن نتیجه باز کند.
- بازکردن/بستن همه به سقف‌های `prop_maxDepth` و `prop_maxNodes` احترام بگذارد و رابط را با دادهٔ بزرگ قفل نکند.
- عمق اولیه با `prop_initialExpandDepth` کنترل شود؛ تغییر مقدار داده، expansion state را بر اساس pathهای موجود حفظ کند و state مربوط به pathهای حذف‌شده را پاک کند.
- تغییر `prop_data` یا مقدار observable آن، درخت را دوباره نمایش دهد. برای تغییرات in-place، مصرف‌کننده باید observable را به‌روزرسانی کند یا مقدار جدید بفرستد.
- traversal با `prop_maxDepth` و `prop_maxNodes` محدود شود؛ محدودشدن داده با نشانگر/پیام truncation داخل شاخه مشخص باشد.
- رنگ، فاصله، radius و اندازه از utilها و tokenهای پروژه و `config.sizeName` استفاده کنند؛ ظاهر بیرونی با `ComponentBorder` قابل مدیریت باشد.
- هیچ ورودی با `innerHTML` تفسیر نشود؛ key و valueها به‌صورت متن امن render شوند.

## ۳. نوع داده و Props

`JsonValue` در `Types.ts` تعریف شود و فقط انواع استاندارد JSON را بپذیرد:

```ts
export type JsonValue =
    | null
    | boolean
    | number
    | string
    | JsonValue[]
    | {[key: string]: JsonValue};
```

Props اختصاصی:

| Prop | نوع | پیش‌فرض | کاربرد |
|---|---|---|---|
| `prop_data` | `JsonValue \| undefined \| CoreObservable.App<JsonValue \| undefined>` | `undefined` | داده‌ای که به درخت تبدیل می‌شود؛ `undefined` یعنی ورودی تعیین نشده و `null` یک مقدار JSON معتبر است. |
| `prop_initialExpandDepth` | `number` | `1` | حداکثر عمقی که هنگام render اولیه باز است؛ مقدار منفی به صفر محدود شود. |
| `prop_maxDepth` | `number` | `20` | حداکثر عمق پیمایش؛ مقدار نامعتبر به مقدار امن محدود شود. |
| `prop_maxNodes` | `number` | `1000` | سقف تعداد گره‌های renderشده برای محدودکردن داده‌های بزرگ. |
| `prop_showSearch` | `boolean` | `true` | نمایش جست‌وجوی key و مقدارها در toolbar. |
| `prop_showExpandControls` | `boolean` | `true` | نمایش کنترل‌های بازکردن/بستن شاخه‌ها در toolbar. |
| `prop_showCopyButton` | `boolean` | `true` | نمایش یا مخفی‌کردن کنترل کپی JSON. |
| `prop_searchPlaceholder` | `string \| CoreObservable.App<string>` | متن ترجمه‌شده | placeholder فیلد جست‌وجو. |
| `prop_emptyText` | `string \| CoreObservable.App<string>` | متن ترجمه‌شده | متن حالت خالی. |

Props مربوط به پوستهٔ `ComponentBorder` با aliasهای `prop_componentBorder*` در اختیار والد باشند. نام، نوع و default هر alias از `ComponentBorder/Props.ts` گرفته شود؛ منبع دوم برای همان default ساخته نشود. `prop_data` و سایر Props با `Define_ComponentProp<T>` تعریف و نوع config با `ExtractPropsConfigType` استخراج شود.

## ۴. Methods عمومی

- `NODE_TOGGLE`: هنگام باز یا بسته‌شدن یک object/array اجرا شود و `PATH`, `KEY`, `EXPANDED` و `KIND` را در `dataArgs` ارائه کند. `PATH` باید برای کلیدهای تو‌در‌تو و index آرایه یکتا و قابل‌تشخیص باشد.
- `SEARCH_CHANGE`: بعد از تغییر query جست‌وجو اجرا شود و `QUERY` را ارائه کند.
- `EXPAND_ALL` و `COLLAPSE_ALL`: بعد از اجرای کنترل toolbar اجرا شوند و تعداد nodeهای تغییر وضعیت‌یافته را در `dataArgs` بدهند.
- `COPY`: بعد از کپی موفق اجرا شود و متن JSON را در `dataArgs` بدهد. در شکست کپی، موفقیت گزارش نشود.

کامپوننت هیچ methodی برای تغییر داده ندارد؛ state باز/بسته‌شدن گره‌ها state نمایشی داخلی است.

## ۵. Schema و ساختار

ساختار از `ComponentStructureTrait` ارث ببرد. نخستین المنت محتوایی کامپوننت `ComponentBorder` باشد و toolbar و درخت در محتوای آن قرار بگیرند.

```text
COMPONENT
STRUCTURE
ROOT: part-json-tree
└── ComponentBorder (پوستهٔ اصلی)
    └── CONTENT: part-json-tree-content
        ├── TOOLBAR: part-json-tree-toolbar
        │   ├── SEARCH: part-json-tree-search (شرطی)
        │   ├── EXPAND_CONTROLS: part-json-tree-expand-controls (شرطی)
        │   └── COPY_BUTTON: part-json-tree-copy-button (شرطی)
        └── TREE: part-json-tree-root
            └── NODE: part-json-tree-node (تکرارشونده و بازگشتی)
                ├── TOGGLE: part-json-tree-node-toggle (برای object/array)
                ├── KEY: part-json-tree-node-key (برای property/index)
                ├── SEPARATOR: part-json-tree-node-separator
                ├── VALUE: part-json-tree-node-value (با کلاس نوع JSON)
                ├── SUMMARY: part-json-tree-node-summary (برای شاخهٔ بسته)
                └── CHILDREN: part-json-tree-node-children (شرطی)
```

- `Schemas.ts` فقط partها و Props متناظر را اعلام کند؛ traversal داده و ساخت childها در کلاس runtime بماند.
- کلاس runtime داده را به nodeهای قابل render تبدیل کند، depth و max node limit را اعمال کند و state باز/بسته را بر اساس path نگه دارد.
- گره‌های فرزند با یک تابع runtime بازگشتی render شوند. Schema نباید به کلاس Component وابسته شود.
- کنترل‌های toolbar از `ComponentInputSimple`, `ComponentButton` و `ComponentIcon` ساخته شوند؛ هر کنترل بر اساس prop مربوطه شرطی باشد.
- کنترل باز/بسته‌شدن node با button و `ComponentIcon` مناسب ساخته شود؛ از `details/summary` پیش‌فرض مرورگر استفاده نشود تا ظاهر و keyboard behavior یکپارچه بماند.
- برای انواع JSON کلاس/part اختصاصی یا style binding مبتنی بر token داشته باشیم؛ رنگ‌ها در theme روشن و تیره خوانا بمانند و کنتراست حفظ شود.
- `ComponentBorder` از Props والد تغذیه شود؛ محتوای آن عرض کامل بگیرد، nodeها در عرض والد بمانند و متن بلند wrap شود.
- subscriptionها و handlerهای ساخته‌شده در scope همان instance ثبت و در `dispose()` آزاد شوند.

```text
src/framework/module_ui/module_components/lists/componentJsonTree/
├── Definition.ts

├── Props.ts
├── Schemas.ts

├── ComponentJsonTreeBase.ts

└── examples/
    ├── Default.ts

    ├── SearchAndControls.ts

src/framework/module_ui/module_categories/lists/ui/tools/dataType/jsonTree/

```

- `Definition.ts`: شناسهٔ یکتای `component_json_tree`، نام `componentJsonTree` و نسخهٔ `v1.0.0` داشته باشد.
- `ComponentJsonTreeBase.ts`: الگوی Base کامپوننت‌های جدید را رعایت کند و `ComponentStructureTrait`، Props، Schemas و Methods را متصل کند.
- `ComponentJsonTree.ts`: render درخت، syntax-aware value rows، جست‌وجو، expansion controls، toggle state، کپی و cleanup را پیاده‌سازی کند.
- `Step.ts`: مطابق راهنما تعریف شود؛ اگر workflow اختصاصی نیاز نیست، Step خالی/حداقلی موجود در الگوی جاری استفاده شود و event behavior در آن قرار نگیرد.
- `index.ts`: فقط API عمومی کامپوننت، typeهای عمومی و Examples را export کند.

## ۷. ثبت و دسترسی

1. `componentJsonTree` در `module_ui/module_components/lists/index.ts` export و در `ComponentManager` با Definition، Props، Schemas، Methods، Examples و constructor ثبت شود.
2. Category جدید `dataType` به‌عنوان فرزند `tools` ساخته شود و callable عمومی زیر را ارائه دهد:

   ```ts
   UiCategory.UI.Tools.DataType.JsonTree({prop_data: data});
   ```

3. Definition و barrelهای `dataType` و `tools` ساخته شوند؛ این شاخه در ساختار Categoryها نمایش داده شود.
4. مسیر صفحهٔ Components برابر `tools → dataType` باشد و `.info`/metadata از `CreateCategoryComponent` بیاید.

## ۸. Examples

- **Default:** نمونهٔ polished شامل object، آرایه و همهٔ نوع‌های primitive با hierarchy، type colors و وضعیت‌های باز/بسته.
- **Nested:** دادهٔ چندسطحی برای نمایش indentation، guideهای عمق، preview شاخه و کنترل اولیهٔ بازشدن.
- **SearchAndControls:** دادهٔ بزرگ‌تر برای نشان‌دادن جست‌وجو، برجسته‌سازی نتیجه، expand/collapse و کپی.
- یک مثال تغییر `prop_data` پس از تعامل داشته باشد تا به‌روزرسانی reactive قابل مشاهده باشد.

همهٔ مثال‌ها از `ComponentExample` و Category callable ساخته شوند؛ متن نام و توضیحات از زبان‌های Fa/En بیاید.

## ۹. ترجمه‌ها

در `Keys.ts`, `En.ts` و `Fa.ts` کلیدهای نام و توضیحات برای category/component و موارد زیر افزوده شوند:

- Props: data، initialExpandDepth، maxDepth، maxNodes، showSearch، showExpandControls، showCopyButton، searchPlaceholder و emptyText
- Schemas/parts: root، toolbar، search، expand controls، tree، node و copy button
- Methods: nodeToggle، searchChange، expandAll، collapseAll و copy
- متن empty، truncation، search placeholder/no results، expand/collapse و copy success/failure
- مثال‌های Default، Nested و SearchAndControls

## ۱۰. معیارهای پذیرش

- `UiCategory.UI.Tools.DataType.JsonTree` در registry و صفحهٔ Components قابل دسترسی باشد.
- primitive، object، array، null و مقدارهای خالی بدون exception نمایش داده شوند.
- hierarchy، indentation، object/array preview و رنگ معنایی نوع‌های JSON در theme روشن و تیره خوانا و یکپارچه باشند.
- گره‌های تو‌در‌تو با کنترل دسترس‌پذیر باز و بسته شوند و `NODE_TOGGLE` اطلاعات مسیر صحیح بدهد.
- جست‌وجو نتایج key/value را برجسته کند و شاخه‌های ancestor نتیجه را قابل‌دیدن سازد؛ expand/collapse همه وضعیت nodeها را درست عوض کند.
- محدودیت depth و node count رعایت و truncation به کاربر مشخص شود.
- تغییر `prop_data` در مقدار مستقیم و Observable به render تازه منجر شود.
- کپی، در صورت فعال‌بودن، JSON معتبر و مرتب را منتقل کند و خطا را بی‌صدا موفق تلقی نکند.
- ورودی به‌صورت متن امن render شود و HTML اجرا نشود.
- در `dispose()` listener و subscription باقی نماند.
- مثال‌ها بدون `[object Object]` نمایش داده شوند و `npm run build:app` موفق باشد.

## ۱۱. خارج از محدودهٔ نسخهٔ اول

- ویرایش، حذف یا افزودن property/item از UI.
- parse خودکار رشته‌های متنی به JSON.
- پشتیبانی از انواع غیر JSON مانند `Date`, `Map`, `Set`, `BigInt`, function و ارجاع‌های چرخه‌ای.
- ویرایش inline، افزودن یا حذف property/item.
- diff دو نسخهٔ JSON.
- تغییر رفتار `ComponentConsole` یا `ComponentCodeMirror`؛ اتصال به این کامپوننت‌ها می‌تواند در پلن جدا انجام شود.
