# PLAN: افزودن Unique Identity به Component

## هدف

هر instance از Component باید یک `unique` داشته باشد تا بتواند در آینده به‌عنوان یک **Step / Node در Workflow** شناسایی و مدیریت شود.

---

## 1. محل Unique

`unique` نباید داخل `ComponentProps` یا `ComponentMethods` قرار بگیرد.

ساختار Constructor به شکل زیر باشد:

```ts
new ComponentButton(
    props,
    methods,
    componentArgs
)
```

و `unique` داخل `componentArgs` قرار بگیرد:

```ts
{
    unique?: string;
}
```

---

## 2. مثال استفاده

نمونه فعلی:

```ts
static override renderExampleComponent(): HTMLElement {
    return new ComponentButton(
        <ComponentButtonPropsType>{
            classList: ["col-md-3", "col-12", "border", "p-2"],
            prop_btnTitle: "asd",
            prop_type: "submit",
            prop_btnBorderRadius: SIZES.DEFAULT,
            prop_btnBorderRadiusStartTop: SIZES.M,
            prop_btnBorderRadiusEndTop: SIZES.XXL,
            prop_btnBorderRadiusStartBottom: SIZES.XXL,
            prop_btnBorderRadiusEndBottom: SIZES.M,
            prop_btnIcon: "icon-name",
        },
        <ComponentButtonMethodsType>{
            fn_onClickButton: function (event, dataArgs, componentArgs) {
                alert("asd");
            }
        },
        {
            unique: "submit-button"
        }
    ).getElement();
}
```

---

## 3. تغییر Component Base

در `ClComponentBase` یا abstraction مناسب Component:

* `componentArgs` اضافه شود.
* `unique` از آن دریافت شود.
* Unique برای instance قابل دسترسی باشد.
* Component در زمان ایجاد instance دارای identity مشخص باشد.

مثلاً:

```ts
component.getUnique()
```

یا یک API معادل که با معماری فعلی Framework سازگار باشد.

---

## 4. تولید خودکار Unique

اگر `unique` توسط مصرف‌کننده مشخص نشود، Framework باید بتواند یک مقدار unique تولید کند.

مثال:

```ts
new ComponentButton(props, methods)
```

نباید باعث شود Component بدون identity باشد.

اما مقدار تولیدشده باید فقط در صورت نبود `unique` صریح استفاده شود.

---

## 5. قوانین

### MUST

* هر Component instance باید یک `unique` داشته باشد.
* `unique` بخشی از Identity Component است.
* `unique` نباید بخشی از UI Props باشد.
* `unique` نباید بخشی از Methods باشد.

### SHOULD

* Developer بتواند `unique` مشخص کند.
* Framework در صورت عدم تعیین `unique` مقدار تولید کند.

---

## 6. Workflow Compatibility

در این مرحله فقط زیرساخت Identity ایجاد شود.

فعلاً:

* Workflow ساخته نشود.
* Step جدید طراحی نشود.
* Event system تغییر نکند.
* رفتار Component تغییر نکند.

هدف فعلی فقط این است که:

```text
Component Instance
       │
       └── unique
              │
              ▼
        Future Workflow Step
```

در آینده Workflow بتواند Component را بر اساس `unique` شناسایی کند.

---

## 7. Guide Update

در Guide سطح Component نیز مفهوم جدید ثبت شود:

```text
Component
├── Identity
│   └── unique
├── Pattern
├── Schema
├── Methods
└── Templates
```

تعریف:

> `unique` شناسه یکتای instance کامپوننت است و برای شناسایی آن در سیستم‌های خارجی مانند Workflow استفاده می‌شود.

## 8. محدودیت

در این مرحله فقط موارد لازم برای اضافه شدن `unique` تغییر کند.

### ممنوع:

* تغییر معماری Workflow
* ساخت Workflow
* تغییر Event System
* تغییر APIهای غیرمرتبط
* Refactor گسترده
* تغییر Props فعلی Componentها
