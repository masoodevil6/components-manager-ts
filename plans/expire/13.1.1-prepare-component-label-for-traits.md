### ۱.۲ انحراف باقی‌مانده — ریشه مشکل

`renderContentComponent` فعلی Label (ComponentLabel.ts:82-102):

```typescript
override renderContentComponent(attrsDefault, data, extra) {
    const bind = this._COMPONENT_PROPS_BIND;
    const prop_labelShow = data?.["prop_labelShow"] ?? bind.prop_labelShow;

    // Legacy behavior: prop_labelShow=false → label رندر نشود
    const show = CoreObservable.App.computed(
        (show) => show ? this.renderLabelBorder(attrsDefault, data, extra) : null,
        [prop_labelShow],
        this.getScope(),
    );

    return CoreReactive.App.section({
        attrs: {...attrsDefault},
        children: [show],
    });
}
```

**سه مشکل:**

1. **نقض قرارداد ۱۱.۲ §۲.۵:** `renderContentComponent` باید فقط `executeSchemaPart(Schemas.BORDER.part)` برگرداند (مثل ComponentBorder.ts:78-84). هر منطق اضافه = انحراف از قرارداد.

2. **Dual-Path رندر BORDER:** `renderLabelBorder` از دو مسیر قابل رسیدن است:
   - مسیر A (استاندارد): `COMPONENT → STRUCTURE (Trait) → renderContentComponent → renderLabelBorder مستقیم` — بدون عبور از `renderManagerComponent`
   - مسیر B: `executeSchemaPart(Schemas.BORDER.part)` → `renderManagerComponent("part-label-border")` → `renderLabelBorder`
   
   نتیجه: مسیر A از `renderManagerComponent` عبور نمی‌کند؛ یعنی هر intercept آینده روی schema BORDER (logging در Console Inspector — Plan 8.2.9، اجرای schema-level events، ...) در مسیر A دور زده می‌شود.

3. **شخصی‌سازی show/hide بیرون از لایه STRUCTURE:** `prop_labelShow` در یک `section` دستی پردازش می‌شود، در حالی که لایه `STRUCTURE` (Trait) خودش `prop_show` + `mapBoolean("show", "d-none")` دارد. Label این مکانیزم پایه را بای‌پس کرده است.

### ۱.۳ چرا این Plan لازم است؟

- Trait-Ready بودن یعنی: هر مصرف‌کننده‌ای که قرارداد ۱۱.۲ را می‌شناسد (Trait حال یا آینده — Console Inspector، Schema Tracker، Test Harness) بتواند روی رفتار استاندارد حساب کند.
- Label اولین کامپوننتی است که «Composition روی کامپوننت مهاجرت‌شده دیگر» (Border) را دارد؛ این Plan الگوی صحیح ترکیب STRUCTURE-first + Composition را مستند و اعمال می‌کند تا کامپوننت‌های بعدی (PositionMenu و...) از همین الگو پیروی کنند.

override renderContentComponent(
    attrsDefault: PartAttrDefault,
    data:         Record<string, CoreObservable.App<any>>,

    return this.executeSchemaPart(Schemas.BORDER.part, {});

- عبور `attrsDefault`/`data` دیگر لازم نیست — `executeSchemaPart` خودش data part را می‌سازد (الگوی Border).
- امضای override ثابت می‌ماند (هماهنگ با Trait.renderStructureSchema:165 که آن را صدا می‌زند).

### ۲.۲ انتقال منطق prop_labelShow به BORDER Schema (فاز ۲)

رفتار Legacy «prop_labelShow=false → label رندر نشود» حفظ می‌شود، اما در **نقطه درست**: داخل `renderLabelBorder` — نه در لایه ساختاری:

```typescript
protected renderLabelBorder(
    attrsDefault?: PartAttrDefault,
    data?:         Record<string, CoreObservable.App<any>>,
    extra?:        any,
): CoreReactive.App {

    const bind = this._COMPONENT_PROPS_BIND;

    const prop_labelShow      = data?.["prop_labelShow"]      ?? bind.prop_labelShow;
    const prop_labelBackground = data?.["prop_labelBackground"] ?? bind.prop_labelBackground;
    const prop_labelRadius     = data?.["prop_labelRadius"]     ?? bind.prop_labelRadius;
    const prop_labelMinWidth   = data?.["prop_labelMinWidth"]   ?? bind.prop_labelMinWidth;

    // Plan 13.1.1 — منطق show منتقل‌شده از renderContentComponent (بدون تغییر رفتار)
    const borderElement = CoreObservable.App.computed(
        (show) => show ? this.buildBorderElement(data, { labelBackground, labelRadius, labelMinWidth }) : null,
        [prop_labelShow],
        this.getScope(),
    );

    return CoreReactive.App.span({
        children: [borderElement],
    });
}
```

**تفکیک مسئولیت:**

| متد | مسئولیت |
|:---|:---|
| `renderLabelBorder` | رندر Part BORDER — ورود به schema، اعمال شرط show، wrapper span |
| `buildBorderElement` (private، جدید) | ساخت Composition Border (کد فعلی خطوط ۱۵۹-۱۹۱ بدون تغییر رفتار) |

> **چرا شرط show در BORDER و نه STRUCTURE؟**
> - `prop_labelShow` prop اختصاصی Label است (در Schemas.BORDER.props ثبت شده — Schemas.ts:34) و معنایش «نمایش کل label» است، نه «نمایش لایه ساختاری».
> - `prop_show` ساختاری (Trait STRUCTURE) جریان خودش را دارد و با آن دست نمی‌زنیم.
> - این‌طوری مسیر B (`executeSchemaPart("part-label-border")`) هم دقیقاً همان شرط را اعمال می‌کند — **رفتار واحد در هر دو مسیر**.

### ۲.۳ حذف انحراف‌های باقی‌مانده در ROUTING (فاز ۳ — بازبینی)

Routing فعلی (ComponentLabel.ts:116-133) از نظر استاندارد درست است و **تغییر نمی‌کند**؛ فقط کامنت‌های Plan 13.1.0 به‌روزرسانی می‌شوند تا dual-path حذف‌شده را منعکس کنند. به‌علاوه:

- کامنت `Plan 11.2 — renderContentComponent` بالای متد (خط ۷۷-۸۱) با متن Plan 13.1.1 جایگزین می‌شود.
- کامنت «Plan 13.1.0» سرصفحه کلاس — بند «الگوی تقسیم‌بندی متدها» با یک خط: «renderContentComponent = executeSchemaPart(BORDER) — قرارداد 11.2 §۲.۵ (Plan 13.1.1)» تکمیل می‌شود.
