# Plan 20.1.0 — انتقال ComponentInputPassword به ساختار جدید

> **وضعیت:** پیاده‌سازی شد  
> **منبع رفتار قدیمی:** `last/tools/components/ComponentInputPassword.ts`  
> **راهنمای معماری:** `documents/guides/component-create.md`  
> **نمونه‌های مرجع جدید:** `componentInput` و پلن `19.1.0-migrate-component-input.md`  
> **مقصد:** `src/framework/module_ui/module_components/lists/componentInputPassword/`  
> **API موردنظر:** `UiCategory.UI.Inputs.InputPassword(config, methods, identity)`

## 1. هدف و محدوده

انتقال `ComponentInputPassword` از معماری Legacy به ساختار declarative/runtime جدید. رفتار عمومی ورودی رمز، مقدار کنترل‌شده، نام فیلد، disabled، placeholder، آیکون اختیاری ابتدای ورودی، پاک‌کردن مقدار، نمایش/پنهان‌کردن رمز، رویدادهای ورودی و اعتبارسنجی حفظ شود.

الزامات معماری:

- ساخت input خام در `ComponentInputPassword` ممنوع است؛ input واقعی را فقط `ComponentInputSimple` بسازد.
- برای label از `ComponentLabelTrait`، props و schema آن استفاده شود؛ label با کلیک input را focus کند.
- برای اندازه‌ها از `CoreConfig.Settings.SizeName.observable()` و `UtilStyle` استفاده شود. `prop_size` از API جدید حذف شود.
- برای آیکون‌ها از `ComponentIcon` و برای اعتبارسنجی از `ComponentValidate` استفاده شود.
- هیچ import یا اجرای Legacy از `last/`، `Observable` قدیمی، `ReactiveElement`، `ComponentBase`، `TOOLS` یا `GOG_*` وارد ساختار جدید نشود.
- ظاهر ورودی، border/focus، گوشه‌ها و فاصله‌ی آیکون‌ها از مسیر `ComponentInputSimple` و config سیستم مدیریت شود؛ border دومی روی input ساخته نشود.

## 2. رفتار قدیمی و قرارداد انتقال

کامپوننت قدیمی از props پایه‌ی Component، Structure، FormInput، Value و Label به‌علاوه‌ی props اختصاصی استفاده می‌کند. input آن با تغییر وضعیت visibility بین `password` و `text` جابه‌جا می‌شود. آیکون `prop_icon` اختیاری است و کلیک روی آن ورودی را focus می‌کند. آیکون clear و آیکون نمایش رمز در حالت disabled پنهان می‌شوند. clear مقدار را خالی می‌کند و focus را به input برمی‌گرداند. validator با rules و پیام‌های داده‌شده فعال می‌شود.

در ساختار جدید، هر کنترل جانبی باید فقط یک بار رندر شود. `ComponentInputSimple` مالک input، مقدار، clear، focus/blur و border است؛ `ComponentInputPassword` مالک visibility، آیکون آغازین، composition، label و validation باقی می‌ماند. چون clear داخلی `ComponentInputSimple` مقدار خالی را به‌شکل `null` گزارش می‌کند، adapter کامپوننت رمز آن را برای قرارداد قدیمی به `""` تبدیل و از همان مسیر `INPUT_CHANGE` منتشر کند.

## 3. Props و سازگاری

### 3.1 Props حفظ‌شونده

| Prop | قرارداد جدید |
|---|---|
| `prop_name` | نام فیلد به `ComponentInputSimple` منتقل شود؛ پسوند `[value]` مطابق قرارداد آن کامپوننت اعمال شود. |
| `prop_value` | مقدار کنترل‌شده‌ی رمز؛ مقدار ورودی، clear و callback همگام باشند. مقدار خالی در API عمومی `""` باشد. |
| `prop_isDisable` | input و کنترل‌های تعاملی را غیرفعال کند؛ clear و visibility در حالت disabled قابل کلیک/نمایش نباشند. |
| `prop_title` | عنوان مستقل validation؛ با `prop_labelTitle` یکی فرض نشود. |
| `prop_backgroundColorForm` | پس‌زمینه‌ی wrapper فرم؛ مقدار پیش‌فرض `var(--secondaryColor1)`. |
| `prop_formBorderRadius` | در صورت حفظ، مقدار radius با `UtilStyle.Css_BorderRadius` و config اندازه تبدیل شود. |
| `prop_colorIcon` | رنگ آیکون‌های آغازین و visibility؛ مقدار پیش‌فرض و fallback مطابق رفتار فعلی ثبت شود. |
| `prop_inputClass` | کلاس‌های سفارشی input به `ComponentInputSimple` منتقل شوند. |
| `prop_inputStyles` | استایل‌های سفارشی input با sizing پایه merge شوند؛ استایل سفارشی نباید ابعاد محاسبه‌شده‌ی layout را ناخواسته خراب کند. |
| `prop_placeholder` | placeholder به `ComponentInputSimple` منتقل شود. |
| `prop_icon` | descriptor آیکون اختیاری آغازین؛ نبود آن نباید فضای آیکون رزرو کند. |
| `prop_hasRules`، `prop_isAbsoluteRule`، `prop_listRules`، `prop_msgRules` | تنظیمات validator حفظ شوند و validation فقط با rules معتبر و فعال رندر شود. |

### 3.2 Props حذف‌شونده یا بازنگری‌شونده

- `prop_size` حذف شود؛ تمام اندازه‌ها از `CoreConfig.Settings.SizeName` بیایند.
- `prop_inputBorderWidth` و `prop_inputBorderRadius` که اندازه‌های Legacy هستند به اندازه‌ی استاندارد config/util منتقل شوند و به‌عنوان ورودی مستقل جدید باقی نمانند.
- رنگ عادی و focus با رفتار پیش‌فرض `ComponentInputSimple` برابر `PRIMARY/GRADE_1` و `SECONDARY/GRADE_1` است. اگر props رنگ Legacy در API جدید حفظ می‌شوند، `ComponentInputSimple` باید قابلیت اختیاری برای دریافت رنگ عادی و focus از parent داشته باشد؛ رنگ را با استایل inline روی input بدون border اعمال نکنید.
- هر prop دیگری که فقط در Legacy تعریف شده ولی مصرف واقعی ندارد، با جست‌وجوی مصرف‌ها تعیین تکلیف و در جدول migration مستند شود؛ حذف خاموش و بی‌دلیل انجام نشود.

`PropsType` و `PropsConfigType` با `ExtractPropsType` و `ExtractPropsConfigType` تعریف شوند و typeهای `ComponentLabelTrait` در API به‌صورت اشتراکی لحاظ شوند. props خود Trait دوباره تعریف نشوند.

## 4. Methods

| Method جدید | نام Legacy | رفتار مورد انتظار |
|---|---|---|
| `INPUT_CHANGE` | `fn_onInput` | پس از تغییر مقدار، `VALUE` به‌روز و یک بار منتشر شود؛ clear مقدار `""` منتشر کند. |
| `INPUT_FOCUS` | `fn_onFocus` | هنگام focus واقعی input، مقدار جاری ارسال شود. |
| `INPUT_BLUR` | `fn_onBlur` | هنگام blur واقعی input، مقدار جاری ارسال شود. |
| `VISIT` یا `TOGGLE_VISIBILITY` | `fn_onVisit` | با کلیک آیکون، نوع ورودی بین `password` و `text` عوض شود؛ callback یک بار اجرا شود. |

از قرارداد استاندارد `Methods.ts` استفاده شود: method name، description از `Keys`، args مبتنی بر propهای واقعی و typeهای استخراج‌شده. امضای callback با سایر کامپوننت‌های جدید یکسان باشد. کلیک روی آیکون آغازین فقط focus کند و رویداد visibility یا value را اجرا نکند. کلیک clear نباید callback ورودی را دوبار اجرا کند.

## 5. Schemas و درخت composition

`COMPONENT` و `STRUCTURE` از `ComponentStructureTrait.schemas` بیایند؛ `LABEL` از `ComponentLabelTrait.schemas` استفاده کند. schema فقط part، props، name و description را تعریف کند.

| Schema | Part پیشنهادی | مسئولیت |
|---|---|---|
| `LABEL` | trait label | label و tooltip؛ کلیک label input را focus کند. |
| `FORM` | `part-input-password-form` | wrapper و ترتیب composition؛ پس‌زمینه و radius فرم. |
| `ICON` | `part-input-password-icon` | فرزند مستقیم اول فرم؛ آیکون اختیاری آغازین و focus کردن input. |
| `INPUT` | `part-input-password-input` | instantiate کردن `ComponentInputSimple`؛ هیچ input خامی اینجا ساخته نشود. |
| `ICON_VISIBILITY` | `part-input-password-icon-visibility` | فرزند مستقیم سوم فرم؛ `ComponentIcon` با آیکون eye/eye-off و تغییر نوع password/text. |
| `VALIDATE` | `part-input-password-validate` | رندر شرطی `ComponentValidate`. |

درخت composition باید دقیقاً مانند `ComponentInput` باشد؛ سه جزء فرم فرزند مستقیم `part-input-password-form` هستند و wrapper جداگانه برای جایگاه آیکون‌ها ساخته نشود:

```text
ComponentInputPassword
├── 1. ComponentLabelTrait label
├── part-input-password-form
│   ├── 2.1 ComponentIcon (اختیاری؛ آیکون آغازین)
│   ├── 2.2 ComponentInputSimple (input + clear داخلی)
│   └── 2.3 ComponentIcon (آیکون نمایش/پنهان‌کردن رمز)
└── 3. ComponentValidate (شرطی)
```

Schema `ICON_VISIBILITY` باید فقط componentIcon سوم را route کند؛ state visibility در `ComponentInputPassword` بماند و به `ComponentInputSimple` فقط نوع reactive ورودی را بدهد. وجود آیکون آغازین شرطی است، اما جایگاه آن در ترتیب composition ثابت می‌ماند.

### 5.1 چیدمان و اندازه‌ها

- فرم بر اساس جهت `CoreConfig.Settings.DirectionRtl.observable()` بچیند؛ در RTL/LTR آیکون آغازین و visibility در سمت درست باشند.
- clear داخلی `ComponentInputSimple` در انتهای inline ناحیه‌ی خودش قرار دارد؛ `ComponentInputSimple` باید با عرض محاسبه‌شده‌ی باقی‌مانده رندر شود و آیکون سوم به‌عنوان فرزند بعدی فرم فضای مستقل داشته باشد تا روی clear نیفتد.
- فضای متن input با وجود آیکون آغازین و دو کنترل انتهایی کافی بماند؛ در نبود آیکون آغازین، فضای خالی مربوط حذف شود.
- ارتفاع و عرض wrapperهای آیکون با `UtilStyle` و `sizeName` جاری محاسبه شوند؛ مقدارهای ثابت Legacy مثل `35px`، `40px`، `20pt` یا `prop_size` مستقیماً منتقل نشوند.
- در حالت disabled کنترل clear و visibility مخفی یا غیرقابل تعامل باشند؛ input disabled و استایل/پس‌زمینه‌ی disabled مطابق `ComponentInputSimple` باقی بماند.

## 6. ComponentInputSimple و value bridge

`renderInput` باید یک نمونه‌ی `ComponentInputSimple.Component` بسازد و آن را در فیلد child نگه دارد. این نمونه باید موارد زیر را دریافت کند:

- `prop_inputName`, `prop_inputValue`, `prop_inputDisable`, `prop_inputPlaceholder`, `prop_inputClass`, `prop_inputStyles`.
- نوع ورودی reactive که بر اساس observable visibility فقط `password` یا `text` باشد.
- گوشه‌های border متناسب با وجود leading/visibility accessories و جهت RTL/LTR تنظیم شوند؛ border، focus border و sizing به `ComponentInputSimple` واگذار شوند.
- `INPUT_CHANGE`, `INPUT_FOCUS`, `INPUT_BLUR` از child به methodهای عمومی این کامپوننت bridge شوند. مقدار `null` حاصل از clear به `""` برای قرارداد `ComponentInputPassword` تبدیل شود.
- componentIcon سوم visibility را toggle کند و پس از تغییر observable، input را focus کند؛ کلیک componentIcon اول و label نیز فقط input را focus کنند.

از query سراسری `document.querySelector` یا idهای تصادفی Legacy برای پیدا کردن input استفاده نشود. مرجع DOM فقط از child نگه‌داری‌شده‌ی `ComponentInputSimple` گرفته شود.

## 7. Step، lifecycle و فایل‌ها

پوشه‌ی مقصد طبق راهنما این فایل‌ها را داشته باشد:

```text
componentInputPassword/
├── Definition.ts
├── Props.ts
├── Schemas.ts
├── Methods.ts
├── Step.ts
├── ComponentInputPasswordBase.ts
├── ComponentInputPassword.ts
├── index.ts
└── examples/
    ├── Default.ts
    ├── Visibility.ts
    ├── Validation.ts
    └── index.ts
```

- `Definition.ts`: شناسه‌ی یکتا مانند `component_input_password`، نام `componentInputPassword` و نسخه‌ی `v1.0.0`.
- `Step.ts`: گره‌های component و partها برای label، form، icon اول، input، icon سوم و validate؛ identity و eventها از الگوی جدید پیروی کنند.
- Base: ارث‌بری از `CoreComponents.App` با genericهای props/schema/methods؛ props و schemas پایه از `ComponentStructureTrait` و `ComponentLabelTrait` ترکیب شوند.
- Runtime: constructor استاندارد `(config, methods, identity)`، dispatch بر اساس schema، نگهداری childها و `dispose()` idempotent. هنگام dispose، `ComponentInputSimple`، ComponentLabel و سایر childها و scope پاک شوند.
- `index.ts`: exportهای public از جمله `Component`, `Props`, `Schemas`, `Methods`, `Definition`, example registry و typeهای عمومی.

## 10. آزمون و معیار پذیرش

1. `UiCategory.UI.Inputs.InputPassword` ساخته و یک input واقعی از نوع `password` تولید کند؛ هیچ input دوم یا خامی در parent ساخته نشود.
2. تغییر value از DOM به `prop_value` و `INPUT_CHANGE` برسد؛ مقدار اولیه‌ی observable نیز در input نمایش داده شود.
3. clear مقدار را به `""` برگرداند، یک `INPUT_CHANGE` منتشر کند و input را focus کند.
4. visibility بین `password` و `text` جابه‌جا شود و مقدار input از بین نرود؛ callback toggle یک بار اجرا شود.
5. focus و blur واقعی یک بار callback مناسب با مقدار جاری اجرا کنند؛ کلیک label و leading icon فقط focus کنند.
6. در disabled، input غیرفعال باشد و clear/visibility عمل نکنند؛ تغییر prop در runtime نیز UI را به‌روز کند.
7. با و بدون leading icon، clear و visibility روی هم نیفتند؛ چیدمان در LTR و RTL درست باشد و اندازه‌ها با تغییر config `sizeName` واکنش نشان دهند.
8. border عادی و focus، radius، placeholder، class و custom styles مطابق props پشتیبانی‌شده بررسی شوند.
9. validator در نبود rules رندر نشود و در حضور rules، value، پیام‌ها، عنوان و حالت absolute را درست دریافت کند.
10. پس از `dispose()` listener، child یا animation/resource باقی نماند و فراخوانی تکراری dispose خطا ندهد.
11. تست‌های هدفمند و TypeScript اجرا شوند؛ `git diff --check` بدون خطا باشد.

## 11. موارد خارج از محدوده

- تغییر رفتار عمومی `ComponentInputSimple`، جز افزودن capability اختیاری و backward-compatible برای انتقال رنگ border عادی/focus در صورتی که حفظ customization Legacy لازم باشد.

- ساخت input یا border دوم برای دور زدن محدودیت‌های `ComponentInputSimple`.
