# Plan 9.1 — ComponentIcon Migration به الگوی Plan 8.2.7/8.2.10

> **پیش‌نیاز:** Plan 8.2.7 (SubEvent), Plan 8.2.10 (Component Wrapper Layer)
> **هدف:** به‌روزرسانی ComponentIcon موجود به الگوی رسمی ComponentMessagesBase (Plan 8.2.7)

`ComponentIcon` از قبل در معماری جدید پیاده‌سازی شده است (Declarative Layer + Composition با Trait + Examples + Category). ولی هنوز با الگوی رسمی `Plan 8.2.7` (که در `ComponentMessagesBase` پیاده‌سازی شده) مطابقت ندارد.

## ۲. هدف

`ComponentIcon` باید دقیقاً همان الگوی `ComponentMessagesBase` / `ComponentMessages` را دنبال کند — با تفاوت‌های اختصاصی Icon (بدون Per-Message Scope، چون Icon فرزندان dynamic ندارد).

### ۲.۱ الگوی مرجع

```text
ComponentMessagesBase (الگوی کامل Plan 8.2.7)
  ├── _COMPONENT_STEP field
  ├── constructor(componentName, elId, identity?, step?)
  ├── CoreEvent.SubEvent در constructor
  └── identity management

ComponentMessages (الگوی کامل Plan 8.2.7)
  ├── constructor با Step در constructor
  ├── super(name, null, identity, step)
  ├── dispose() → this.disposeStep()
  └── renderContentComponent از Trait
```

## ۳. مراحل اجرا

### Phase ۱ — `Step.ts` — factory function

`IconStep` از ثابت به factory function تبدیل شود — هر Instance Step مستقل.

```typescript
// قبل:
export const IconStep = CoreEvent.Step({ ... });

// بعد:
export function createIconStep() {
    return CoreEvent.Step({
        children: {
            click: CoreEvent.Step({
                request:  CoreEvent.Request(),
                response: CoreEvent.Response({ value: "" }),
            }),
            hover: CoreEvent.Step({
                request:  CoreEvent.Request(),
                response: CoreEvent.Response({ value: "" }),
            }),
            blur: CoreEvent.Step({
                request:  CoreEvent.Request(),
                response: CoreEvent.Response({ value: "" }),
            }),
        }
    });
}
```

**دلیل:** هر Instance ComponentIcon باید Step مستقل داشته باشد — نه shared const.
اگر `IconStep` ثابت باشد، همه Instanceها یک Step دارند → تداخل در registerEmit.

### Phase ۲ — `ComponentIconBase.ts` — constructor + _COMPONENT_STEP + SubEvent

الگوی `ComponentMessagesBase` اعمال شود:

```typescript
import * as CoreComponents   from "@/core_components";
import * as CoreEvent        from "@/core_event";
// --------------------------------
import {ComponentStructureTrait} from "../../traits/componentStructureTrait";
// --------------------------------
import {Props,     PropsType}     from "./Props";
import {Schemas,   SchemasType}   from "./Schemas";
import {Methods,   MethodsType}   from "./Methods";
import {Definition}               from "./Definition";


export class ComponentIconBase extends CoreComponents.App<
    PropsType & Record<string, any>,
    SchemasType,
    any,
    MethodsType
> {

    /**
     * Step Node — درخت Workflow داخلی ComponentIcon
     */
    protected _COMPONENT_STEP: CoreEvent.TStepInstance<any> | null = null;


    /**
     * constructor (Plan 8.2.7)
     *
     * @param componentName — نام Component (default: "icon")
     * @param elId          — شناسه المان (default: null)
     * @param identity      — بیرونی { unique?, emit?, events? }
     * @param step          — داخلی (Workflow خاص این Component)
     */
    constructor(
        componentName: string = "icon",
        elId: string | null   = null,
        identity?: {
            unique?: CoreEvent.TStepRef | null;
            emit?:   CoreEvent.TEmitHandler | null;
            events?: Record<string, any> | null;
        },
        step?: CoreEvent.TStepInstance<any>,
    ) {
        super(componentName, elId);

        this._COMPONENT_UNIQUE = identity?.unique ?? null;
        this._COMPONENT_EMIT   = identity?.emit ?? null;

        this._COMPONENT_STEP   = step ?? null;

        // Plan 8.2.7 — SubEvent
        if (step && identity?.unique) {
            CoreEvent.SubEvent(identity.unique, componentName, step);
        }
    }

    protected _COMPONENT_DEFINITION = Definition;

    protected _COMPONENT_PATTERN = CoreComponents.DefineProp<PropsType & Record<string, any>>({
        ...ComponentStructureTrait.props,
        ...Props,
    } as any);

    protected _COMPONENT_SCHEMA = CoreComponents.DefineSchema<SchemasType, PropsType & Record<string, any>>({
        ...Schemas,
    } as any);

    protected _COMPONENT_METHODS = CoreComponents.DefineMethod<MethodsType, PropsType & Record<string, any>>({
        ...Methods,
    } as any);
}
```

### Phase ۳ — `ComponentIcon.ts` — constructor + dispose + renderIcon با unique

```typescript
export class ComponentIcon extends ComponentIconBase {

    constructor(
        config?:  Partial<StructurePropsType & IconPropsType>,
        methods?: MethodsConfigType<ComponentIcon>,
        identity?: {
            unique?: any;
            emit?:   any;
            events?: Record<string, any> | null;
        },
    ) {
        // Plan 8.2.7 — Step داخلی در constructor ساخته می‌شود
        const step = createIconStep();

        super("icon", null, identity, step);

        this.renderComponent(
            config as any,
            methods as any,
            identity?.events ?? null,
        );
    }


    /* ---------------------------------------------
       Plan 8.2.7 — Component Disposal

       Contract:
         ComponentIcon.dispose()
            ↓
         disposeStep()              ← CoreEvent.dispose بازگشتی
            ↓
         internal Step disposed     ← click/hover/blur از رجیستری
            ↓
         SubEvent relationship disposed  ← از parent قطع می‌شود
            ↓
         registry cleaned           ← emits Map پاک می‌شود
    --------------------------------------------- */
    dispose(): void {
        this.disposeStep();
    }


    /* ---------------------------------------------
       Plan 8.2.10 — renderContentComponent از Trait
    --------------------------------------------- */
    override renderContentComponent(): CoreReactive.App {
        return ComponentStructureTrait.renderContent(
            this,
            () => this.renderIcon(),
        );
    }


    /* ---------------------------------------------
       renderManagerComponent — Routing
    --------------------------------------------- */
    override renderManagerComponent(
        partName:     string,
        attrsDefault: PartAttrDefault,
        data:         Record<string, CoreObservable.App<any>>,
        extra:        any,
    ): CoreReactive.App {

        switch (partName) {
            case Schemas.ICON.part:
                return this.renderContentComponent();
            default:
                return super.renderManagerComponent(partName, attrsDefault, data, extra);
        }
    }


    /* ---------------------------------------------
       renderIcon — رندر Part ICON
       Plan 8.2.7 — unique از _COMPONENT_STEP متصل شود

       click / hover / blur (نکته ۵):
         click    ← Event Engine endpoint (unique روی <i>)
         hover    ← DOM → Method API (بدون unique)
         blur     ← DOM → Method API (بدون unique)

         Stepهای hover/blur برای آینده نگه داشته شده‌اند.
    --------------------------------------------- */
    protected renderIcon(
        attrsDefault?: PartAttrDefault,
        data?:         Record<string, CoreObservable.App<any>>,
    ): CoreReactive.App {

        const prop_icon       = data?.["prop_icon"]       ?? this._COMPONENT_PROPS_BIND.prop_icon;
        const prop_iconTitle  = data?.["prop_iconTitle"]  ?? this._COMPONENT_PROPS_BIND.prop_iconTitle;
        const prop_iconClass  = data?.["prop_iconClass"]  ?? this._COMPONENT_PROPS_BIND.prop_iconClass;
        const prop_iconStyles = data?.["prop_iconStyles"] ?? this._COMPONENT_PROPS_BIND.prop_iconStyles;

        return CoreReactive.App.i({
            attrs: {
                ...attrsDefault,
            },
            attrsBind: {
                title: prop_iconTitle,
            },
            stylesBind: prop_iconStyles,
            classBind: [
                prop_iconClass,
            ],
            // Plan 8.2.7 — اتصال Step به reactiveElement
            // فقط click به‌عنوان Event Engine endpoint (نکته ۵)
            unique: this._COMPONENT_STEP?.click,
            emit: (request) => {
                return { value: prop_icon.get(), valid: true };
            },
            on: {
                click: (event: Event) => {
                    event.preventDefault();
                    this.executeMethod("CLICK", event, {});
                },
                // hover/blur: DOM → Method API (بدون Event Engine routing)
                mouseenter: (event: Event) => {
                    event.preventDefault();
                    this.executeMethod("HOVER", event, {});
                },
                mouseleave: (event: Event) => {
                    event.preventDefault();
                    this.executeMethod("BLUR", event, {});
                },
            },
            children: [
                prop_icon,
            ],
        });
    }
}
```

## ۵.۱. SubEvent — تفکیک External Identity از Internal Step

> **اصلاح Plan (نکته ۳):** نباید این برداشت ایجاد شود که SubEvent خودش parent identity است.

```text
identity.unique          ← External Event Endpoint (از سمت والد)
    ↓
CoreEvent.SubEvent(identity.unique, "icon", step)
    ↓
step                     ← Internal Component Event Tree (click/hover/blur)
```

| مفهوم | جهت | مالکیت |
|:---|:---|:---|
| `identity.unique` | **بیرونی** — والد به این Component | والد تعریف می‌کند |
| `step` | **داخلی** — این Component به فرزندانش | Component خودش می‌سازد |
| `SubEvent` | **رابط** — بین این دو | Component در constructor صدا می‌زند |

> **SubEvent رابطه است، نه identity.** SubEvent به external identity متصل می‌شود،
> نه اینکه خودش parent identity باشد.

## ۵.۲. emit Contract — تطبیق با ComponentMessages

> **اصلاح Plan (نکته ۴):** آیا emit همیشه باید وجود داشته باشد؟

بررسی `ComponentMessages`:

| المان | unique | emit | دلیل |
|:---|:---|:---|:---|
| Container (root `<div>`) | ❌ ندارد | ❌ ندارد | UI wrapper — Event endpoint نیست |
| Message section (dynamic child) | ✅ `scope.body` | ✅ همیشه | Event endpoint — close action |

**قرارداد Messages:** emit فقط روی **Event endpointها** ثبت می‌شود — همیشه present،
نه مشروط به external identity.

**اعمال روی ComponentIcon:**

المان `<i>` در ComponentIcon یک **Event endpoint** است (click/hover/blur روی آن رخ می‌دهد).
مثل message section در Messages، نه مثل container.

بنابراین:

```typescript
// ✅ درست — <i> همیشه unique + emit دارد (مثل message section)
return CoreReactive.App.i({
    unique: this._COMPONENT_STEP?.click,
    emit: (request) => {
        return { value: prop_icon.get(), valid: true };
    },
    on: { click, mouseenter, mouseleave },
    ...
});
```

> **نتیجه:** Plan فعلی (emit همیشه present) با قرارداد Messages **سازگار است**.
> هیچ تغییری لازم نیست — فقط مستند شد.

## ۵.۳. click / hover / blur — تفکیک Event Engine از Method API

> **اصلاح Plan (نکته ۵):** صریح کردن اینکه کدام event وارد Event Engine می‌شود.

Step structure:

```text
IconStep
├── click    ← Event Engine endpoint (unique روی <i>)
├── hover    ← ساختار Step وجود دارد ولی DOM routing از Method API
└── blur     ← ساختار Step وجود دارد ولی DOM routing از Method API
```

| Event | DOM → Routing | Event Engine | Step child |
|:---|:---|:---|:---|
| `click` | `on.click` → `executeMethod("CLICK")` | ✅ `unique: step.click` | ✅ |
| `mouseenter` | `on.mouseenter` → `executeMethod("HOVER")` | ❌ (بدون unique) | ✅ (ساختار) |
| `mouseleave` | `on.mouseleave` → `executeMethod("BLUR")` | ❌ (بدون unique) | ✅ (ساختار) |

> **دلیل:** click یک **action** است (ارتباط با والد از طریق Event Engine).
> hover/blur **UI feedback** هستند (فقط Method API کافی است).
>
> Stepهای hover/blur برای **آینده** نگه داشته شده‌اند — اگر بعداً نیاز به
> Event Engine routing شد، فقط `unique` اضافه می‌شود.
>
> **این distinction باید در `component-create.md` هم مستند شود.**

### ۶.۱ Event Identity Contract (اصلاح شده)

> **نکته مهم:** «Event identity نباید تغییر کند» جمله‌ای مبهم بود — اصلاح شد.

تفکیک دقیق:

```text
Step Structure     ≠  Step Identity
Step Identity      ≠  Step Instance
```

سلسله:

```text
Component Instance
    ↓
Step Instance        ← هر ComponentIcon یک Step Instance مستقل
    ↓
Step Identity        ← CoreEvent.Step() در زمان ساخت unique مستقل ایجاد می‌کند
```

قرارداد:

- ✅ هر ComponentIcon Instance باید **Step Instance مستقل** داشته باشد
- ✅ Step Instance نباید بین ComponentIconها shared باشد
- ✅ Step Identity باید در طول lifecycle همان ComponentIcon **پایدار** بماند
- ✅ Step Identity نباید بین Icon Instanceها shared باشد

> **تغییر از Plan قبلی:** با تبدیل `IconStep` (ثابت) به `createIconStep()` (factory)،
> هر Instance Step Identity مستقل می‌گیرد. این **تغییر مطلوب** است، نه invariant.

### ۶.۲. Event Scope Ownership

هر ComponentIcon **مالک** Step Instance خودش است:

```text
ComponentIcon
    owns
      ↓
ComponentIcon Step
    owns
      ↓
click / hover / blur
```

قرارداد:

- ❌ ComponentIcon A نباید Step متعلق به B را dispose کند
- ❌ ComponentIcon B نباید Step متعلق به A را reuse کند
- ✅ disposal یک Component فقط باید Event resources متعلق به همان Component را آزاد کند

> این بعداً برای lifecycle و dynamic componentها خیلی مهم می‌شود.
