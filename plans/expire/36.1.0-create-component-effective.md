# پلن 36.1.0 — ایجاد `componentEffective`

> **وضعیت:** پیاده‌سازی انجام شد؛ build برنامه موفق است. Typecheck کامل مخزن با خطاهای موجود در فایل‌های دیگر متوقف می‌شود.
> **راهنما:** `documents/guides/component-create.md`
> **کامپوننت جدید:** `src/framework/module_ui/module_components/lists/componentEffective/`
> **دسته‌بندی:** `effects`
> **کامپوننت پایهٔ نمایش:** `componentBorder`

## 1. هدف و محدوده

کامپوننت `componentEffective` یک wrapper برای نمایش `componentBorder` با کنترل والد بر وضعیت نمایش و افکت‌های ورود و خروج است. والد بتواند نمایش یا پنهان‌شدن را با Prop تغییر دهد، برای ورود و خروج mode جداگانه تعیین کند و تنظیمات ظاهری و محتوایی `componentBorder` را نیز از طریق Props خود `componentEffective` کنترل کند.

این کامپوننت منطق محتوای داخل Border را تغییر نمی‌دهد؛ افکت روی کل Border و محتوای آن اعمال می‌شود.

## 2. نیازمندی‌های رفتاری

- مقدار `prop_isVisible` از والد تعیین کند که Border نمایش داده شود یا پنهان.
- mode ورود و خروج مستقل باشند تا والد بتواند برای ظاهرشدن و ناپدیدشدن رفتارهای متفاوت انتخاب کند.
- modeهای اولیه شامل `none`، `fade`، `slide` و `scale` باشند. مقادیر enum و نتیجهٔ بصری هر mode در `Props.ts` و ترجمه‌ها/مثال‌ها مستند شوند.
- مدت ورود و خروج به‌صورت جداگانه قابل تنظیم باشد؛ زمان‌ها برحسب میلی‌ثانیه باشند.
- در خروج انیمیشنی، Border تا پایان مدت خروج در DOM بماند و سپس پنهان شود. اگر پیش از پایان خروج دوباره `prop_isVisible` فعال شد، زمان‌سنج قبلی لغو شود تا Border ناخواسته پنهان نشود.
- در ورود، ابتدا حالت شروع mode اعمال و سپس حالت نمایان اجرا شود تا transition در اولین فریم از دست نرود.
- مقدار اولیهٔ `prop_isVisible: false` نباید یک فلاش لحظه‌ای از Border ایجاد کند.
- تغییر Props مربوط به `componentBorder` به Border داخلی برسد، بدون آنکه API خود `componentBorder` تغییر کند.
- چیدمان و جهت افکت‌های جهتی از جهت منطقی و تنظیمات RTL/LTR سیستم پیروی کند.

## 3. قرارداد API

### Props افکت

Props زیر در `Props.ts` تعریف شوند:

| Prop | نوع پیشنهادی | پیش‌فرض | کاربرد |
|---|---|---|---|
| `prop_isVisible` | `boolean` | `true` | وضعیت نمایش که والد کنترل می‌کند |
| `prop_showMode` | enum اختصاصی | `fade` | mode ورود Border |
| `prop_hideMode` | enum اختصاصی | `fade` | mode خروج Border |
| `prop_showDuration` | `number` | `200` | مدت ورود برحسب میلی‌ثانیه |
| `prop_hideDuration` | `number` | `200` | مدت خروج برحسب میلی‌ثانیه |
| `prop_easing` | `string` | `"ease"` | تابع زمان‌بندی transition |

Enumهای mode در ماژول تعریف شوند و فقط مقادیر پشتیبانی‌شده را بپذیرند. برای مقدار mode ناشناخته، رفتار امن `none` در نظر گرفته شود.

### Props عبوری `componentBorder`

- Props عمومی `componentBorder` که برای محتوا، رنگ متن و پس‌زمینه، رنگ و نوع Border، opacity، کلاس و style، فلش، عرض، حداقل عرض، گوشه‌ها و ضلع‌های Border استفاده می‌شوند، از والد `componentEffective` قابل تنظیم باشند.
- نام، نوع و مقدار پیش‌فرض هر Prop عبوری با قرارداد متناظر `componentBorder` سازگار بماند؛ wrapper مقدارها را به نمونهٔ داخلی `componentBorder` منتقل کند.
- `prop_content` همان محتوای داخلی Border باشد و افکت روی کل Border اعمال شود.
- Propهای افکت با Propهای عبوری Border تداخل نام نداشته باشند.
- فهرست Props عبوری هنگام پیاده‌سازی با `componentBorder/Props.ts` تطبیق داده شود تا گزینه‌ای از API عمومی آن جا نماند؛ نیازی به تغییر رفتار یا API خود `componentBorder` نیست.

نام و توضیح Props جدید با `Define_ComponentProp` و کلیدهای زبان سیستم تعریف شوند. نوع‌های `PropsType` و `PropsConfigType` با helperهای پروژه استخراج شوند.

## 4. معماری و Schema

الگوی فایل‌ها و چرخهٔ عمر از `component-create.md` پیروی کند. `COMPONENT` و `STRUCTURE` از `ComponentStructureTrait.schemas` و در ابتدای Schemaها استفاده شوند.

```text
COMPONENT
STRUCTURE
ROOT: part-effective
└── BORDER: part-effective-border
    └── componentBorder
```

- `ROOT` مسئول نگهداری state افکت، اعمال حالت شروع/پایان و زمان‌بندی خروج باشد.
- `BORDER` محل رندر `componentBorder` داخلی و دریافت همهٔ Props عبوری آن باشد.
- کلاس‌ها یا styleهای افکت روی wrapper پیرامونی Border اعمال شوند تا styleهای `prop_borderStyles` والد ناخواسته بازنویسی نشوند.
- Schemaها فقط Partها و Props وابسته را تعریف کنند؛ منطق انتخاب mode و گذارهای نمایش در `ComponentEffective.ts` بماند.
- هر timer یا listener در `dispose` پاک‌سازی شود.

## 5. ساختار فایل‌ها

```text
src/framework/module_ui/module_components/lists/componentEffective/
├── Definition.ts
├── Props.ts
├── Schemas.ts
├── Methods.ts
├── Step.ts
├── ComponentEffectiveBase.ts
├── ComponentEffective.ts
├── index.ts
└── examples/
    ├── Default.ts
    ├── SeparateShowHideModes.ts
    └── index.ts
```

- `Definition.ts`: شناسهٔ `component_effective`، نام `componentEffective` و نسخهٔ آغازین `v1.0.0`.
- `ComponentEffectiveBase.ts`: اتصال Core و typeهای Props، Schemas و Methods مطابق الگوی کامپوننت‌های جدید.
- `ComponentEffective.ts`: ساخت `componentBorder`، انتقال Props و مدیریت گذارهای visible/hidden و cleanup.
- `Default.ts`: نمونهٔ ساده با fade.
- `SeparateShowHideModes.ts`: نمونه‌ای که والد visibility را تغییر می‌دهد و mode یا مدت ورود و خروج متفاوت تعیین می‌کند؛ تنظیمات Border هم از والد داده شود.
- `Methods.ts` و `Step.ts` با الگوی راهنما حفظ شوند. Method رویدادی جدید فقط در صورت نیاز واقعی به callback از والد اضافه شود؛ تغییر `prop_isVisible` به‌تنهایی callback اجباری ندارد.

## 6. ثبت Component و دسته‌بندی `effects`

1. ماژول `componentEffective` را در `src/framework/module_ui/module_components/lists/index.ts` import، در ComponentManager ثبت و در namespace عمومی Lists export کن.
2. چون درخت فعلی UI دسته‌بندی `effects` ندارد، شاخهٔ آن را ایجاد کن:

   ```text
   src/framework/module_ui/module_categories/lists/ui/effects/
   ├── Definition.ts
   ├── index.ts
   └── effective/
       ├── Definition.ts
       └── index.ts
   ```

3. در `ui/effects/Definition.ts` دسته‌ای با شناسهٔ `effects` بساز و `Effective` را در `components` قرار بده.
4. `Effects` را از `ui/index.ts` export کن. Category callable کامپوننت از `CreateCategoryComponent` و الگوی گروه‌های موجود استفاده کند.
5. در `Keys.ts` کلیدهای نام و توضیح دستهٔ effects و کامپوننت، Props، Schemaها و مثال‌ها را تعریف و ترجمه‌های انگلیسی و فارسی را در `En.ts` و `Fa.ts` اضافه کن.

## 7. بررسی و پذیرش

- `npm run build:app` بدون خطای TypeScript یا build اجرا شود.
- در مثال‌ها، همهٔ modeها برای ورود و خروج قابل مشاهده و مدت هرکدام مستقل باشد.
- تغییر `prop_isVisible` از والد، Border را وارد یا خارج کند؛ اجرای سریع show/hide پشت‌سرهم timer کهنه‌ای باقی نگذارد.
- شروع با حالت hidden فلاش نداشته باشد و mode `none` فوراً وضعیت نهایی را اعمال کند.
- Props عبوری مانند `prop_content`, `prop_borderColor`, `prop_contentBackgroundColor`, `prop_borderStyles`, `prop_width` و تنظیمات radius/sides به `componentBorder` داخلی برسند.
- تغییرات Props عبوری، mode یا visibility، API یا رفتار `componentBorder` را تغییر ندهند.
- category در فهرست UI با مسیر `effects` و مثال‌های Component در صفحهٔ نمایش کامپوننت‌ها قابل دسترسی باشند.
- حالت‌های RTL/LTR و پاک‌سازی timer هنگام dispose بررسی شوند.
