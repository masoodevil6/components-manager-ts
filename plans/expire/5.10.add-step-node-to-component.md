# Plan 5.10 — افزودن Step Node به ComponentStructure برای جریان داخلی Component

## هدف

هر Component یک `CoreEvent.Step` داخلی داشته باشد که جریان Workflow اختصاصی‌اش را کنترل می‌کند.

این Step در constructor به ComponentStructure (پدر) پاس داده می‌شود تا نگه دارد.
در متدهای schema/render به هر reactiveElement / child Component متصل می‌شود.

---

## دو مفهوم جدا

| مفهوم | جهت | کاربرد |
|-------|------|--------|
| `identity` (unique, emit, events) | **بیرونی** — والد به این Component | والد جریان خودش را اعمال می‌کند |
| `step` | **داخلی** — این Component به فرزندهایش | Component جریان داخلی خودش را کنترل می‌کند |

مثال:
```
ComponentForm (Step: FormStep)
    │
    ├── ComponentButton (identity.unique = FormStep.submit)  ← بیرونی
    │       │
    │       └── Step: ButtonStep  ← داخلی
    │               │
    │               ├── click: Step({ request, response })
    │               └── ...
    │
    └── ComponentInput (identity.unique = FormStep.name)     ← بیرونی
            │
            └── Step: InputStep  ← داخلی
                    │
                    ├── change: Step({ request, response })
                    └── ...
```

## معماری هدف

### Constructor

```ts
class ComponentStructure<
    TProp, TSchemas, TMethods, TIdentity
> extends CoreComponents.App<...> {

    /**
     * Step Node — درخت Workflow داخلی Component
     * فرزند در constructor از طریق super پاس می‌دهد.
     * در متدهای schema/render به reactiveElementها متصل می‌شود.
     */
    protected _COMPONENT_STEP: CoreEvent.TStepInstance | null = null;

    constructor(
        componentName: string = "structure",
        elId: string | null   = null,
        identity?: Partial<TIdentity>,        // بیرونی — والد به این Component
        step?:    CoreEvent.TStepInstance,    // داخلی — این Component به فرزندهایش
    ) {
        super(componentName, elId);

        this._COMPONENT_UNIQUE = identity?.unique ?? null;
        this._COMPONENT_EMIT   = identity?.emit ?? null;
        this._COMPONENT_EVENTS = identity?.events ?? null;

        this._COMPONENT_STEP   = step ?? null;
    }
}
```

### تعریف Step در فرزند

```ts
// ButtonStep.ts (در پوشه ComponentButton)
import * as CoreEvent from "@/core_event";

export const ButtonStep = CoreEvent.Step({
    children: {
        click: CoreEvent.Step({
            request:  CoreEvent.Request(),
            response: CoreEvent.Response({ value: "" })
        }),
    }
});

// ComponentButton.ts
class ComponentButton extends ComponentButtonBase {

    constructor(
        config:  ButtonPropsType,
        methods: ButtonMethodsType,
        identity?: Partial<ButtonIdentity>,
    ) {
        super("button", null, identity, ButtonStep);  // ← Step پاس داده می‌شود
        this.renderComponent(config, methods);
    }

    override renderContentComponent() {
        return CoreReactive.App.button({
            unique: this._COMPONENT_STEP!.click,  // ← اتصال به Step داخلی
            emit:   (request) => { ... },
            on: {
                click: (e, event) => {
                    event!.request(
                        CoreEvent.requestMap([
                            [this._COMPONENT_STEP!.click, { action: "validate" }]
                        ]),
                        this._COMPONENT_STEP!.click
                    );
                }
            }
        });
    }
}
```

### استفاده در متدهای schema/render

در `renderComponentSchema` یا `renderStructureSchema` یا `renderContentComponent`:

```ts
protected renderComponentSchema(attrsDefault, data) {
    return CoreReactive.App.component(
        this._COMPONENT_NAME,
        {
            ...
            children: [
                // اتصال به Step داخلی — اگر وجود دارد
                ...(this._COMPONENT_STEP ? [
                    CoreReactive.App.attr("data-step", this._COMPONENT_STEP.unique)
                ] : []),
                this.executeSchemaPart(Schemas.STRUCTURE.part),
            ],
        }
    );
}
```

## فایل‌های تغییر

### ۱. ComponentStructure.ts

- import `CoreEvent`
- افزودن field `protected _COMPONENT_STEP: CoreEvent.TStepInstance | null = null`
- افزودن پارامتر چهارم `step?` به constructor
- set کردن `this._COMPONENT_STEP = step ?? null`

### ۲. ExampleRenderer (به‌روزرسانی)

Example معمولاً Step ندارد (چون Step در تعریف کلاس ثابت است، نه در Example).
پس ExampleRenderer فقط `identity` را پاس می‌دهد، `step` نه.

## نکات مهم

### چرا Step در constructor پاس داده می‌شود؟

چون:
1. Step در تعریف کلاس فرزند ثابت است (مثل `ButtonStep`)
2. فرزند در constructor از طریق `super(..., ButtonStep)` به ComponentStructure می‌دهد
3. ComponentStructure نگه می‌دارد تا در متدهای render در دسترس باشد

### چرا `_COMPONENT_STEP` و `_COMPONENT_UNIQUE` جدا هستند؟

- `_COMPONENT_STEP` = درخت Workflow **داخلی** Component (ثابت، در تعریف کلاس)
- `_COMPONENT_UNIQUE` = هویت Instance در درخت Workflow **والد** (متغیر، در constructor از بیرون)

### چرا `null` default؟

چون ComponentStructure خودش Step ندارد — فقط فرزندها تعریف می‌کنند.
