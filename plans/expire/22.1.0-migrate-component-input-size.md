# پلن 22.1.0 — انتقال `ComponentInputSize` به ساختار جدید

> **وضعیت:** پیاده‌سازی انجام شد؛ آزمون Vitest به‌دلیل محدودیت اجرای `esbuild` در محیط فعلی اجرا نشد.  
> **منبع Legacy:** `last/tools/components/ComponentInputSize.ts`  
> **راهنمای معماری:** `documents/guides/component-create.md`  
> **الگوهای جدید:** `componentInput`، `componentInputPassword` و `componentInputSimple`  
> **مقصد:** `src/framework/module_ui/module_components/lists/componentInputSize/`  
> **API موردنظر:** `UiCategory.UI.Inputs.InputSize(config, methods, identity)`

## 1. هدف و محدوده

انتقال ورودی عددی Legacy به معماری declarative/runtime جدید. باید ورودی عددی، آیکون ورودی اختیاری، کنترل‌های کاهش/افزایش، مقدار کنترل‌شده، محدودیت‌های min/max، disabled، clear، focus/blur/input callbacks و validation حفظ شوند.

درخت composition موردنظر:

```text
ComponentInputSize
├── 1. ComponentLabelTrait
├── 2. part-input-size-form
│   ├── ComponentBorder (قاب فرم و layout)
│   │   ├── 2.1 ComponentIcon (اختیاری؛ آیکون آغازین)
│   │   ├── 2.2 ComponentInputSimple (type=number؛ clear داخلی)
│   │   ├── 2.3 ComponentButton (کاهش مقدار)
│   │   └── 2.4 ComponentButton (افزایش مقدار)
│   └── 3. ComponentValidate (خواهر قاب فرم)
└── (همه‌ی اندازه‌ها از config سیستم)
```

ساخت input خام، دکمه‌ی HTML خام، clear icon جداگانه، یا border تکراری در `ComponentInputSize` مجاز نیست. خود `ComponentInputSimple` مالک input DOM، مقدار و clear داخلی است؛ `ComponentButton` برای دو کنترل +/- و `ComponentIcon` برای آیکون اختیاری استفاده شود. از الگوی label و value bridge در `ComponentInput` و `ComponentInputPassword` استفاده شود.

## 2. رفتار Legacy و قرارداد عددی جدید

- نوع ورودی همیشه `number` است؛ `min` و `max` در صورت تعریف به DOM input هم منتقل می‌شوند.
- دکمه‌های کاهش و افزایش فقط در حالت enabled دیده و فعال باشند.
- کلیک کاهش/افزایش مقدار را یک واحد کم/زیاد کند، از محدوده‌ی min/max بیرون نرود و مقدار نهایی را از مسیر واحد `INPUT_CHANGE` منتشر کند.
- در مقدار خالی، افزایش مقدار را به `min` در صورت وجود، و در غیر این صورت به `0` برساند. رفتار کاهش مقدار خالی باید صریحاً `0` یا `min` را مطابق منطق مشترک clamp انتخاب کند؛ پیشنهاد این پلن: مبنای کاهش هم `min ?? 0` باشد و بعد clamp اعمال شود، تا نتیجه deterministic باشد.
- در تایپ دستی مقدار عددی parse شود؛ مقدار نامعتبر یا خالی باید طبق قرارداد `ComponentInputSimple` و prop مقدار (`number | null`) مدیریت شود. مقدار خالی را به صفر تبدیل نکن مگر این‌که API موجود آن را الزام کند.
- مقدار هنگام blur و ورود دستی با min/max clamp شود؛ input DOM و prop کنترل‌شده همگام بمانند.
- قاعده‌ی clamp استاندارد باشد: `min` و `max` مستقل قابل اعمال باشند؛ اگر هر دو هستند و `min > max`، از رفتار ناسازگار جلوگیری و حالت را مشخص/معتبرسازی کن (ترجیحاً propها را بدون قید اضافی نگه دار ولی clamp را با بازه‌ی معتبر انجام بده و وضعیت نامعتبر را مستند کن).
- کلیک آیکون آغازین و label input را focus کند. دکمه‌های +/- پس از تغییر مقدار input را focus نکنند مگر رفتار موردنیاز ComponentInputSimple چنین باشد.
- `prop_hasRules` پیش‌فرض Legacy برابر false است؛ validator فقط در صورت فعال‌بودن و وجود rules معتبر نمایش یابد. حالت disabled validator را مخفی کند.
- `prop_title` عنوان validator است و از عنوان label جدا می‌ماند.

## 3. Props و سازگاری

Props پایه‌ی component، structure، value و label از الگوی Traits و قرارداد جدید گرفته شوند؛ آن‌ها را در Props اختصاصی دوباره تعریف نکن. برای props اختصاصی از `Define_ComponentProp<T>`، کلیدهای ترجمه‌شده‌ی `Keys`، `satisfies CoreComponents.ComponentProps`، `ExtractPropsType` و `ExtractPropsConfigType` استفاده شود.

| Prop Legacy | قرارداد جدید |
|---|---|
| `prop_name`, `prop_value`, `prop_isDisable` | از props پایه استفاده شود. مقدار جدید عددی (`number \| null`) باشد؛ در صورت ناسازگاری نوع inherited فعلی، adapter کنترل‌شده بساز و نوع عمومی را با شواهد مصرف‌کنندگان تعیین کن. |
| `prop_labelTitle` و props Label | از `ComponentLabelTrait` بیایند؛ label با کلیک input را focus کند. |
| `prop_title` | حفظ به‌عنوان عنوان ComponentValidate، مستقل از label. |
| `prop_backgroundColorForm` | حفظ با پیش‌فرض `var(--secondaryColor1)` و اعمال روی قاب فرم مناسب. |
| `prop_formBorderRadius` | در صورت حفظ API، radius با `UtilStyle.Css_BorderRadius` و `CoreConfig.Settings.SizeName` تعیین شود؛ اندازه‌ی hardcode منتقل نشود. |
| `prop_colorIcon` | حفظ در صورت مصرف واقعی؛ رنگ از utilهای رنگ و fallback استاندارد سیستم استفاده کند. |
| `prop_size` | حذف از API جدید؛ sizing از `CoreConfig.Settings.SizeName.observable()` و utilها بیاید. |
| `prop_inputClass`, `prop_inputStyles` | به `ComponentInputSimple` منتقل شوند؛ sizing پایه و custom style ترتیب merge روشن داشته باشند. |
| `prop_inputBorderColor`, `prop_inputBorderColorFocus` | بررسی compatibility؛ در صورت حفظ، فقط از قابلیت استاندارد/افزوده‌شده‌ی InputSimple/Border استفاده شود، نه استایل border موازی روی input. پیش‌فرض focus مطابق استاندارد `SECONDARY/GRADE_1`. |
| `prop_inputBorderWidth`, `prop_inputBorderRadius` | اندازه‌های Legacy به API جدید منتقل نشوند؛ border width و radius از config سیستم و utilها بیایند. |
| `prop_placeholder` | به `ComponentInputSimple.prop_inputPlaceholder` نگاشت شود. |
| `prop_icon` | آیکون اختیاری آغازین، از نوع descriptor جدید `UiIcons.IIconDefinition \| null`؛ در نبود آیکون فضای خالی نسازد. |
| `prop_buttonsWidth` | حفظ، default برابر `45px` مطابق Legacy؛ هر دو دکمه عرض یکسان بگیرند و ورودی بر اساس دو عرض و اندازه‌ی آیکون محاسبه شود. |
| `prop_iconPositive`, `prop_iconNegetive` | نام Legacy اشتباه/ناسازگار است؛ مصرف واقعی repo بررسی شود. در API جدید نام‌گذاری درست و مستقل مثل `prop_iconIncrement` و `prop_iconDecrement` پیشنهاد می‌شود؛ در صورت حفظ نام قدیمی، deprecated/compat mapping روشن باشد. مقدار پیش‌فرض از آیکون‌های مثبت/منفی جدید باشد. |
| `prop_min`, `prop_max` | حفظ به شکل `number \| null`؛ به attrs min/max در InputSimple و منطق clamp پاس شوند. |
| `prop_hasRules`, `prop_isAbsoluteRule`, `prop_listRules`, `prop_msgRules` | حفظ؛ نوع rule با `ValidatorRule[]` و API جدید ComponentValidate هماهنگ شود. پیش‌فرض `hasRules=false`, `isAbsoluteRule=true`, rules خالی و messages null مطابق Legacy. |

پیش از حذف یا rename هر prop، مصرف‌های `ComponentInputSize` در repo بررسی شوند. نیاز compatibility مصرف‌کنندگان مستند شود؛ خارج از محدوده بازنویسی کامل Legacy callerها است. props inherited Label از Trait گرفته شوند و دوباره تعریف نشوند.

## 4. Methods

Methods با metadata ترجمه‌شده و typeهای استخراج‌شده از `TypeHelpers` تعریف شوند. `VALUE`, `MIN`, `MAX` باید مقدار واقعی رویداد را بازتاب دهند، نه صرفاً defaultهای config.

| Method جدید | نام Legacy | قرارداد |
|---|---|---|
| `INPUT_CHANGE` | `fn_onInputChange` | پس از تایپ، clear یا کلیک +/-، مقدار نهایی کنترل‌شده را یک‌بار همراه min/max جاری منتشر کند. |
| `INPUT_FOCUS` | `fn_onInputFocus` | هنگام focus واقعی InputSimple با مقدار/min/max فعلی اجرا شود. |
| `INPUT_BLUR` | `fn_onInputBlur` | هنگام blur واقعی، پس از اعمال سیاست clamp، مقدار/min/max نهایی ارسال شود. |

اگر داده‌های method در Legacy با نام‌های lowercase (`value`, `min`, `max`) تعریف شده‌اند، API جدید کلیدهای semantic typed (`VALUE`, `MIN`, `MAX`) داشته باشد و compatibility در اجرای callback واضح باشد. دو دکمه callback عمومی مجزایی ندارند؛ تغییر مقدارشان از `INPUT_CHANGE` عبور کند. از callback دوباره‌کاری بین parent و InputSimple جلوگیری شود.

## 5. Schemas و composition

`COMPONENT` و `STRUCTURE` از `ComponentStructureTrait.schemas` و schemaهای label از `ComponentLabelTrait.schemas` بیایند. schema فقط metadata و props را تعریف کند.

| Schema | Part پیشنهادی | مسئولیت |
|---|---|---|
| `FORM` | `part-input-size-form` | wrapper فرم، ساخت border/container و چیدن فرزندان. |
| `ICON` | `part-input-size-icon` | آیکون آغازین اختیاری با focus action. |
| `INPUT` | `part-input-size-input` | ساخت `ComponentInputSimple` با `type=number` و min/max. |
| `BUTTON_DECREMENT` | `part-input-size-button-decrement` | `ComponentButton` برای کاهش مقدار. |
| `BUTTON_INCREMENT` | `part-input-size-button-increment` | `ComponentButton` برای افزایش مقدار. |
| `VALIDATE` | `part-input-size-validate` | `ComponentValidate` شرطی و خواهر container فرم. |

درخت DOM داخل فرم باید `Icon? → InputSimple → Decrement → Increment` باشد، مطابق ترتیب/سمت طراحی Legacy و جهت سیستم. اگر clear داخلی InputSimple حفظ می‌شود، در محل مستقل خودش داخل InputSimple بماند و با دو دکمه تداخل نکند؛ در صورت نیاز `prop_inputStyles` یا layout child برای فضای دو دکمه تنظیم شود.

## 6. Runtime و رفتار دکمه‌ها

- فرم با `ComponentBorder` جدید یا container ساده و بدون border تکراری ساخته شود؛ در Legacy قاب border دور group است، پس border فقط یک‌بار دیده شود.
- `ComponentInputSimple` با `prop_inputType=NUMBER`، `prop_inputName`, value, disabled, placeholder, class و styles ساخته شود.
- `min` و `max` از props reactive گرفته شوند و به `min`/`max` input forward شوند. اگر InputSimple در حال حاضر attrs سفارشی min/max ندارد، قابلیت typed اختیاری آن را اضافه کن یا راه استاندارد attribute binding موجود را به‌کار ببر.
- کسر عرض: `100% - (buttonsWidth × 2) - iconBoxWidth` در حضور آیکون؛ iconBoxWidth با `UtilStyle` و `sizeName` جاری محاسبه شود. دکمه‌ها و input در flex قرار گیرند تا float و عرض‌های Legacy ثابت حذف شوند.
- گوشه‌های border با وجود آیکون و دو دکمه و `DirectionRtl` درست تنظیم شوند؛ هر ضلع فقط در صورت مجاورت کنترل، با چهار props استاندارد radius `ComponentInputSimple` صفر شود.
- دکمه‌ها از `ComponentButton` جدید با `type=button`، عرض `prop_buttonsWidth`, ارتفاع util-based و آیکون‌های پیش‌فرض جدید ساخته شوند. در disabled، دکمه‌ها مخفی/غیرفعال باشند و هیچ mutation رخ ندهد.
- الگوریتم افزایش/کاهش یک تابع مشترک عددی داشته باشد: خواندن مقدار جاری، تعیین مقدار پایه در حالت خالی، اعمال step یک واحد، clamp با min/max، ثبت prop و `_CURRENT_VALUE` و انتشار یک `INPUT_CHANGE`.
- تغییر prop value از بیرون باید value input و validator را sync کند. اشتراک observable در dispose آزاد شود.
- Label و آیکون ورودی فقط child input واقعی را focus کنند؛ query سراسری document استفاده نشود.
- border/focus رنگ و سایز را `ComponentInputSimple`/`ComponentBorder` جدید مدیریت کنند. اندازه‌ها با `SizeName` config و utilها باشند، نه `prop_size` یا px ثابت برای height/padding.
- spinner مرورگر برای input number فقط در صورت حفظ نیاز بصری Legacy، با selector محدود به instance پنهان شود؛ CSS global نساز.

## 7. Validation

- validator فقط وقتی enabled، `prop_hasRules` درست و rules معتبر/غیرخالی هستند رندر شود.
- `prop_listRules`, `prop_msgRules`, `prop_isAbsoluteRule`, `prop_title` و مقدار کنونی به `ComponentValidate` منتقل شوند.
- در صورت ضرورت قاعده‌ی عددی اجباری، از validator رسمی موجود استفاده کن؛ پلن رفتار تازه‌ای مثل اجباری‌بودن خودکار اضافه نمی‌کند چون Legacy فقط rules مصرف‌کننده را عبور می‌داد.
- مقدار null/خالی validator را به‌عنوان خالی ببیند؛ مقدار عددی clamp‌شده پس از کلیک/blur باید منعکس شود.

## 9. Examples

- `Default`: مقدار کنترل‌شده، label، placeholder و دو دکمه‌ی +/-.
- `WithBounds`: min/max و آزمون مرزهای increment/decrement و تایپ دستی.

- مثال‌ها نباید `prop_size`، icon generator Legacy یا ruleهای خام `_is_number` را مصرف کنند؛ از `UtilValidators` رسمی استفاده شود.

## 10. معیارهای پذیرش و آزمون

1. `UiCategory.UI.Inputs.InputSize` در Category و ComponentManager ثبت شده باشد.
2. composition شامل Label اختیاری، فرم با ComponentInputSimple و دو ComponentButton، و Validate در جای درست باشد؛ فقط یک input DOM وجود داشته باشد.
3. input نوع number، name، value، disabled، placeholder، min و max را درست دریافت کند.
4. مقدار اولیه‌ی بیرونی، تایپ دستی، clear و observable updates همگام باشند.
5. increment/decrement مقدار را یک واحد تغییر دهند، هرگز از min/max عبور نکنند، و هر رویداد دقیقاً یک `INPUT_CHANGE` بدهد.
6. مقدار خالی، min-only، max-only، min/max هر دو و bounds نامعتبر رفتار مستند و قابل پیش‌بینی داشته باشند.
7. focus/blur واقعی فقط یک‌بار callback بدهند؛ blur مقدار را با سیاست clamp sync کند.
8. آیکون اختیاری فقط در صورت وجود فضا بگیرد و کلیک آن input را focus کند.
9. disabled همه‌ی راه‌های تغییر را متوقف کند؛ دکمه‌ها callback/change ایجاد نکنند.
10. گوشه‌ها و layout در LTR/RTL، با/بدون آیکون و هنگام تغییر reactive config درست باشند؛ clear و دکمه‌ها overlap نداشته باشند.
11. validator خاموش/روشن، title، messages، rules و value جاری را درست منعکس کند.
12. اندازه‌ها با `CoreConfig.Settings.SizeName`/`UtilStyle` به‌روز شوند و API جدید `prop_size` نداشته باشد.
13. `dispose()` امن، idempotent و کامل باشد؛ childها، subscriptions، scope و Step آزاد شوند.
14. تست‌های رفتاری، TypeScript هدفمند و `git diff --check` موفق باشند.
