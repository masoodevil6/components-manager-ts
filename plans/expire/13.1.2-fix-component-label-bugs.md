## ۱. شرح و انگیزه

### ۱.۱ وضعیت فعلی

ComponentLabel پس از Plan 13.1.0 (مهاجرت) و 13.1.1 (Trait-Ready) از نظر معماری استاندارد است، اما **۳ باگ بحرانی** و **۲ انحراف معماری** باقی مانده که در runtime رخ می‌دهند:

| # | نوع | شدت | شرح |
|:---:|:---|:---:|:---|
| ۱ | باگ | 🔴 بحرانی | Tooltip **هرگز رندر نمی‌شود** — پارامتر `show` در computed بدون observable است |
| ۲ | باگ | 🔴 بحرانی | CSS tooltip **هرگز تزریق نمی‌شود** — `getTooltipCssCustom` تعریف شده ولی صدا زده نمی‌شود |

### ۱.۲ ریشه باگ‌های بحرانی

#### باگ ۱ — Tooltip هرگز رندر نمی‌شود

`renderLabelTooltip` (ComponentLabel.ts:333-376):

```typescript
const tooltip = CoreObservable.App.computed(
    (desc, icon, bg, color, pos, dir, show) => {   // ← ۷ پارامتر
        if (!show || desc == null) return null;     // ← show همیشه undefined
        ...
    },
    [
        prop_labelTooltipIcon,         // ← ۱: icon (نه desc!)
        prop_labelTooltipDescription,  // ← ۲: desc (نه icon!)
        prop_labelTooltipBackground,
        prop_labelTooltipColor,
        prop_labelTooltipPosition,
        prop_labelTooltipDirection,
        // ← پارامتر ۷ (show): هیچ observable‌ای موجود نیست
    ],
    this.getScope(),
);
```

**سه مشکل:**

1. **`desc` و `icon` جابجا شده‌اند** — dependency array `[prop_labelTooltipIcon, prop_labelTooltipDescription, ...]` دارد، ولی callback `(desc, icon, ...)` انتظار دارد description اول باشد. نتیجه: `desc` = آیکون، `icon` = توضیحات.

2. **`show` بدون observable** — callback ۷ پارامتر دارد ولی dependency array ۶ observable دارد. `show` همیشه `undefined` است.

3. **`!show` همیشه `true`** — چون `show` همیشه `undefined` است، `!show` همیشه `true` است و `if (!show || desc == null) return null` همیشه `null` برمی‌گرداند. **Tooltip هرگز رندر نمی‌شود.**

#### باگ ۲ — CSS tooltip هرگز تزریق نمی‌شود

`getTooltipCssCustom` (ComponentLabel.ts:390-417) CSS rules برای `:hover` popup می‌سازد:

```css
#selector .component-label-tooltip-popup { display: none; ... }
#selector .component-label-tooltip:hover .component-label-tooltip-popup { display: inline-block; }
```

ولی این متد **هیچ‌جا صدا زده نمی‌شود**. در `ComponentBorder`، الگوی مرجع `getArrowCssCustom` در `renderBorder` از طریق `stylesCustom` تزریق می‌شود:

```typescript
// ComponentBorder.ts:154
stylesCustom: this.getArrowCssCustom(attrsDefault?.id),
```

در `ComponentLabel`، `renderLabelTooltip` یا `renderLabelContent` باید همین کار را بکنند، ولی نمی‌کنند. نتیجه: حتی اگر tooltip رندر شود، popup همیشه `display: none` می‌ماند چون CSS rule وجود ندارد.

#### باگ ۳ — خطای TypeScript در buildBorderElement

`buildBorderElement` (ComponentLabel.ts:203):

```typescript
return UiCategory.UI.Contents.Border(
    {...} as any,
    {...},
    {...},
).getElement();   // ← HTMLElement | ClReactiveElement
```

تابع `buildBorderElement` خروجی `CoreReactive.App` (=`ClReactiveElement`) دارد، ولی `.getElement()` خروجی `HTMLElement | ClReactiveElement` برمی‌گرداند. TypeScript خطا می‌دهد:

```
error TS2322: Type 'HTMLElement | ClReactiveElement' is not assignable to type 'ClReactiveElement'.
```

### ۱.۳ انحراف‌های معماری

#### انحراف ۴ — span اضافی در BORDER

`renderLabelBorder` (ComponentLabel.ts:168-170) خروجی را در یک `span` wrapper می‌پیچد:

```typescript
return CoreReactive.App.span({
    children: [borderElement],   // ← borderElement یا Border composition یا null
});
```

این span برای شرط `prop_labelShow` اضافه شده — وقتی `show=false`، `children: [null]` می‌شود و یک span خالی رندر می‌شود. ولی:

- **DOM اضافی**: `<span data-part-name="part-label-border"><component-border>...</component-border></span>` — span دور component-border.
- **رفتار متفاوت از Legacy**: در Legacy، `prop_labelShow=false` → کل label رندر نمی‌شد. در اینجا یک span خالی رندر می‌شود.
- **الگوی مرجع نقض می‌شود**: `ComponentBorder.renderBorder` مستقیم `section` برمی‌گرداند، نه wrapper دور آن.

#### انحراف ۵ — ارجاع اشتباه در Plan 13.1.0

Plan 13.1.0 بخش ۱.۳ می‌گوید:

> Composition با `UiCategory.UI.Simples.Border`

ولی Border در `UiCategory.UI.Contents.Border` ثبت شده (نه `Simples`). کد فعلی (ComponentLabel.ts:203) مسیر درست را استفاده می‌کند (`UiCategory.UI.Contents.Border`)، ولی پلن مستندات اشتباه دارد.

## ۲. راهکار

### ۲.۱ رفع باگ ۱ — Tooltip parameter mismatch (فاز ۱)

دو تغییر:

**الف) ترتیب dependency array با callback هم‌تراز شود:**

```typescript
// قبل (اشتباه):
[
    prop_labelTooltipIcon,          // → desc (اشتباه!)
    prop_labelTooltipDescription,    // → icon (اشتباه!)
    ...
]

// بعد (صحیح):
[
    prop_labelTooltipDescription,    // → desc ✓
    prop_labelTooltipIcon,           // → icon ✓
    ...
]
```

**ب) پارامتر `show` حذف شود:**

`show` برای بررسی `prop_labelShow` اضافه شده بود، ولی این بررسی **اضافی** است — `prop_labelShow` در `renderLabelBorder` اعمال می‌شود و اگر `false` باشد، کل Border (شامل tooltip) رندر نمی‌شود. شرط `show` در tooltip redundant است.

```typescript
// قبل:
(desc, icon, bg, color, pos, dir, show) => {
    if (!show || desc == null) return null;
    ...
}

// بعد:
(desc, icon, bg, color, pos, dir) => {
    if (desc == null) return null;
    ...
}
```

### ۲.۲ رفع باگ ۲ — تزریق CSS tooltip (فاز ۲)

CSS tooltip باید در نقطه درست رندر تزریق شود. دو گزینه:

| گزینه | نقطه تزریق | مزیت | معیوب |
|:---|:---|:---|:---|
| A | `renderLabelContent` (BORDER_CONTENT) | CSS نزدیک popup | CSS حتی وقتی tooltip null هم تزریق می‌شود |
| B | `renderLabelTooltip` (BORDER_CONTENT_TOOLTIP) | CSS فقط وقتی tooltip رندر می‌شود | نیاز به `attrsDefault?.id` |

**تصمیم: گزینه B** — CSS فقط وقتی tooltip واقعاً رندر می‌شود تزریق شود. `renderLabelTooltip` یک `section` برمی‌گرداند که `stylesCustom` روی آن اعمال می‌شود:

```typescript
return CoreReactive.App.section({
    attrs: {...attrsDefault},
    stylesCustom: this.getTooltipCssCustom(attrsDefault?.id),
    children: [tooltip],
});
```

> **نکته:** `getTooltipCssCustom` از `this.getPartId(Schemas.BORDER_CONTENT_TOOLTIP.part)` برای selector استفاده می‌کند. `attrsDefault?.id` باید همان part ID باشد که توسط `executeSchemaPart` تزریق می‌شود. اگر `attrsDefault?.id` نبود، fallback به `getPartId` استفاده می‌شود (همان رفتار فعلی).

### ۲.۳ رفع باگ ۳ — خطای TypeScript (فاز ۳)

دو گزینه:

| گزینه | راه‌حل | مزیت | معیوب |
|:---|:---|:---|:---|
| A | `as CoreReactive.App` cast | ساده | type safety کاهش می‌یابد |
| B | خروجی تابع را `HTMLElement \| ClReactiveElement` بپذیریم و در caller cast کنیم | دقیق‌تر | نیاز به تغییر امضا |

**تصمیم: گزینه A** — `as CoreReactive.App` cast، هم‌تراز با الگوی پروژه (`as any` روی config Border در همان تابع). خطای `.getElement()` خروجی union است که در همه composition‌ها وجود دارد و cast استاندارد است.

```typescript
return UiCategory.UI.Contents.Border(
    {...} as any,
    {...},
    {...},
).getElement() as CoreReactive.App;
```

### ۲.۴ انحراف ۴ — span اضافی در BORDER (حذف نشد — مستندسازی)

> **تصمیم نهایی:** حذف span wrapper در فاز اجرا انجام **نشده** است.

**دلیل:** `CoreObservable.App.computed` خروجی `ClObservable<ClReactiveElement | null>` برمی‌گرداند، نه `ClReactiveElement`. متد `renderLabelBorder` امضا `CoreReactive.App` (=`ClReactiveElement`) دارد. computed مستقیم قابل برگرداندن نیست — یک wrapper element لازم است تا observable را به‌عنوان children میزبانی کند.

```typescript
// اجرا شده (نهایی):
const borderElement = CoreObservable.App.computed(...);  // ClObservable
return CoreReactive.App.span({
    children: [borderElement],   // span observable را میزبانی می‌کند
});
```

**وضعیت:** span wrapper حفظ شد. این یک محدودیت API است، نه انحراف معماری. کامنت‌ها به‌روزرسانی شدند تا دلیل wrapper را توضیح دهند.

### ۲.۵ رفع انحراف ۵ — مستندات Plan 13.1.0 (فاز ۵)

کامنت‌های ComponentLabel.ts و (در صورت نیاز) Plan 13.1.0 به‌روزرسانی شوند:
- ارجاع `UiCategory.UI.Simples.Border` → `UiCategory.UI.Contents.Border`
- افزودن ارجاع Plan 13.1.2 به سرصفحه کلاس

### فاز ۴ — حذف span اضافی

**فایل:** `ComponentLabel.ts` — متد `renderLabelBorder` (خطوط ۱۵۷-۱۷۱)

تغییر: مستقیم computed برگردانده شود، نه wrapper در span:

```typescript
protected renderLabelBorder(
    attrsDefault?: PartAttrDefault,
    data?:         Record<string, CoreObservable.App<any>>,
    extra?:        any,
): CoreReactive.App {

    const bind = this._COMPONENT_PROPS_BIND;

    const prop_labelShow        = data?.["prop_labelShow"]        ?? bind.prop_labelShow;
    const prop_labelBackground  = data?.["prop_labelBackground"]  ?? bind.prop_labelBackground;
    const prop_labelRadius      = data?.["prop_labelRadius"]      ?? bind.prop_labelRadius;
    const prop_labelMinWidth    = data?.["prop_labelMinWidth"]    ?? bind.prop_labelMinWidth;

    // Plan 13.1.2 — span wrapper حذف شد؛ computed مستقیم برگردانده می‌شود
    // (هم‌تراز با الگوی ComponentBorder.renderBorder)
    return CoreObservable.App.computed(
        (show) => show ? this.buildBorderElement(data, {
            labelBackground: prop_labelBackground,
            labelRadius:     prop_labelRadius,
            labelMinWidth:   prop_labelMinWidth,
        }) : null,
        [prop_labelShow],
        this.getScope(),
    );
}
```
