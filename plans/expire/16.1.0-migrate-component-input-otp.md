# Plan 16.1.0 — انتقال ComponentInputOtp به معماری جدید

> وضعیت: اجراشده؛ کامپوننت، Category، مثال و تست‌های رفتاری پیاده‌سازی شده‌اند.
>
> منبع رفتار: `last/tools/components/ComponentInputOtp.ts`؛ راهنمای معماری: `documents/guides/component-create.md`؛ نمونه‌های فعلی: `componentLabel/` و `componentInputCheckBox/` در `src/framework/module_ui/module_components/lists/`.
>
> مقصد: `src/framework/module_ui/module_components/lists/componentInputOtp/` و دسترسی عمومی `UiCategory.UI.Inputs.InputOtp(...)`.

## ۱. دامنه و پیش‌نیاز

هدف، بازیابی رفتار قابل مشاهده‌ی OTP قدیمی در قرارداد جدید `Definition / Props / Schemas / Methods / Step / Base / Component / Examples / Category` است. فایل قدیمی کپی یا در مسیر جدید import نشود. `ComponentStructureTrait` دو schema پایه‌ی `COMPONENT` و `STRUCTURE` را فراهم می‌کند؛ `part_structure` قدیمی یک part **داخلی OTP** است و نباید با `STRUCTURE` پایه هم‌نام شود.

**پیش‌نیاز Plan 15.1.0 انجام شده است:** `ComponentTimerDown` جدید در `UiCategory.UI.Contents.TimerDown` ثبت شده و API آن timestamp میلی‌ثانیه‌ای می‌گیرد. OTP امضای قدیمی `call_startCountdown(minutes)` را حفظ می‌کند و تبدیل دقیقه به timestamp را در مرز فراخوانی تایمر انجام می‌دهد. وابستگی runtime به ماژول `last/` وجود ندارد.

`componentLabel/` مهاجرت شده و می‌تواند برای label استفاده شود؛ سازگاری API آن، نمایش متن و اتصال `for` به اولین input را پیش از انتخاب composition بررسی کنید. `prop_size` در API جدید OTP حذف می‌شود؛ اندازه‌ی خانه‌ها و label فقط از تنظیم سراسری اندازه‌ی سیستم (`CoreConfig.Settings.SizeName`) گرفته شود و با تغییر آن به‌روز بماند. این prop از Props و schemaهای OTP عبور داده نشود. اجزای فرزند مستقل، مانند TimerDown، تنظیم اندازه‌ی خودشان را طبق قرارداد داخلی‌شان دریافت می‌کنند.

## ۲. موجودی دقیق Legacy

| مورد | قرارداد و رفتار قدیمی | مقصد پیشنهادی |
|:---|:---|:---|
| ریشه | `super("input-otp", null)`؛ `renderContentComponent()` به `part_structure` می‌رود | شناسه‌ی `component_input_otp` و tag `input-otp` در کلاس جدید؛ schemaهای پایه در ابتدای `Schemas` |
| Props | پنج prop اختصاصی، علاوه بر propهای پایه‌ی Component/Structure | چهار prop اختصاصی در `Props.ts` (`prop_size` طبق تصمیم محصول حذف شده)، پایه‌ها از Trait |
| Parts | `part_structure`, `part_value`, `part_elements`, `part_label`, `part_inputs`, `part_timerDown` | شش schema اختصاصی؛ `OTP_STRUCTURE` برای جلوگیری از برخورد با schema پایه |
| Template | `BODY` با reference به `prop_input` | حذف؛ part و render در قرارداد جدید جای Template قدیمی را می‌گیرند |
| Methods | `fn_onGetNewToken`, `fn_onFinishToken`, `fn_onChange` با args خالی | کلیدهای `GET_NEW_TOKEN`, `FINISH_TOKEN`, `CHANGE` در `Methods.ts` |
| State | `_OTP_VALUE: Observable<string>` و `_OTP_TIMER` | `CoreObservable.App<string>` و instance تایمر جدید یا controller معادل؛ پاک‌سازی در `dispose()` |
| API عمومی | `call_startCountdown(durationForEnd)` با ورودی **دقیقه** و `call_getValue(): string` | حفظ امضا و واحد دقیقه؛ تبدیل به timestamp بر حسب میلی‌ثانیه فقط در مرز تایمر |

### نگاشت Props

| Prop | نوع و default قدیمی | قرارداد پیشنهادی جدید |
|:---|:---|:---|
| `prop_size` | مقدار `SIZES.M` | حذف از API جدید؛ اندازه‌ی ورودی و label فقط از تنظیم سراسری `CoreConfig.Settings.SizeName` خوانده شود |
| `prop_name` | `string`, مقدار `"otp"` | `string`, مقدار `"otp"`؛ در نام‌گذاری/id ورودی‌ها و اولین label |
| `prop_input` | `string \| null`, مقدار `null` | `string \| null`, مقدار `null`؛ در متن label (مثلاً شماره/ایمیل مقصد) |
| `prop_langs` | `Record<string, any>` با `_title_otp_description` و `_tooltip_otp_description` | نوع مشخص با همین دو کلید و defaultهای معادل؛ متن سفارشی مصرف‌کننده حفظ شود |
| `prop_length` | `number`, مقدار `6` | `number`, مقدار `6`؛ تعداد خانه‌ها؛ اعتبارسنجی مقدار صحیح مثبت هنگام ساخت/تغییر |

برای هر prop از `Define_ComponentProp<T>` با `name` و `description` از `Keys.category.components.inputOtp.props.*` استفاده شود. `PropsType` و `PropsConfigType` از `TypeHelpers` استخراج شوند. متن‌های default در `prop_langs` بخشی از رفتار قبلی‌اند؛ متن پیش‌فرض فارسی عنوان «کد برای شماره/ایمیل زیر ارسال شد» و tooltip پیش‌فرض `null` است. `Keys/Fa/En` برای metadata کامپوننت، props، schemas، methods و examples تکمیل شوند؛ ترجمه‌ی metadata جایگزین متن سفارشی `prop_langs` نشود.

### نگاشت Parts و وابستگی داده

| کلید جدید | part قدیمی | وظیفه |
|:---|:---|:---|
| `OTP_STRUCTURE` | `part_structure` | wrapper نسبی OTP؛ children: `VALUE`, `ELEMENTS` |
| `VALUE` | `part_value` | input مخفی با نام یکتای `input_otp_value_<instance>` و value واکنش‌گرای `_OTP_VALUE` |
| `ELEMENTS` | `part_elements` | container شامل `LABEL`, `INPUTS`, `TIMER_DOWN` |
| `LABEL` | `part_label` | توضیح و `prop_input`، label متصل به اولین input؛ props: `prop_name`, `prop_input`, `prop_langs`؛ اندازه از تنظیم سراسری سیستم |
| `INPUTS` | `part_inputs` | `prop_length` خانه‌ی تک‌کاراکتری و navigation؛ props: `prop_name`, `prop_length`؛ اندازه از تنظیم سراسری سیستم |
| `TIMER_DOWN` | `part_timerDown` | شرح tooltip و تعامل retry/finish؛ props: `prop_langs`؛ در صورت نیاز TimerDown اندازه را از تنظیم سراسری خودش می‌گیرد |

`Schemas.ts` فقط metadata (`part`, `props`, `name`, `description`) دارد. `COMPONENT` و `STRUCTURE` از `ComponentStructureTrait.schemas` **دو ورودی اول** باشند؛ rendering همه‌ی شش part در `ComponentInputOtp.ts` انجام شود. برای idهای خانه از شناسه‌ی یکتای instance و index با separator روشن استفاده کنید تا دو OTP در یک صفحه به هم برخورد نکنند. اگر `prop_name` یا `prop_length` هنگام اجرا تغییر می‌کند، render/focus/value دوباره همگام شوند و listener یا node قدیمی باقی نماند.

## ۳. قرارداد رفتار قابل حفظ

1. هر خانه حداکثر یک کاراکتر دارد. پس از ورود مقدار، focus به خانه‌ی بعدی می‌رود؛ Backspace روی خانه‌ی خالی به خانه‌ی قبلی می‌رود. رفتار قدیمی هنگام focus مقدار همان خانه را پاک می‌کند. خواندن همه‌ی خانه‌ها `_OTP_VALUE` و hidden input را به‌روز کرده و `CHANGE` را اجرا می‌کند؛ کد ترکیبی با `call_getValue()` در دسترس است.
2. متن label از `_title_otp_description` و `prop_input` ساخته می‌شود و به **اولین** خانه اشاره می‌کند. متن از ورودی مصرف‌کننده با ساخت HTML ناامن وارد نشود؛ برای متن عادی node متنی/children واکنش‌گرا استفاده شود.
3. `call_startCountdown(minutes)` پایان را با `Date.now() + minutes * 60_000` تعیین می‌کند. پایان شمارش دقیقاً یک بار `FINISH_TOKEN` را اعلام کند؛ retry در child به `GET_NEW_TOKEN` در OTP وصل شود. شروع مجدد، تایمر قبلی را لغو کند؛ timer/interval/subscription در `dispose()` پاک شود.
4. `CHANGE` با هر به‌روزرسانی ترکیب کد فراخوانی می‌شود؛ `GET_NEW_TOKEN` با retry و `FINISH_TOKEN` با پایان شمارش. امضای callback جدید از `MethodsConfigType` پیروی کند و مسیرهای قدیمی `fn_on...` به‌عنوان نام metadata قابل شناسایی بمانند.
5. دکمه‌ها، focus و تایمر در چند instance مستقل عمل کنند. paste چندرقمی، تصفیه‌ی ورودی غیرعددی و اعلان خودکار تکمیل کد در Legacy قرارداد مشخصی ندارند؛ اگر مطلوب باشند، پس از حفظ رفتار پایه با تصمیم جداگانه و تست افزوده شوند.

## ۴. فایل‌ها و ترتیب پیاده‌سازی

1. **وابستگی و زبان:** خروجی Plan 15.1.0 و API `ComponentTimerDown` جدید بررسی شد؛ `Keys.ts`, `Fa.ts`, `En.ts` برای `inputOtp` تکمیل شدند.
2. **Declarative:** `Definition.ts` با `id: "component_input_otp"`, `name: "componentInputOtp"`, `version: "v1.0.0"`؛ `Props.ts` با چهار prop؛ `Schemas.ts` با دو schema پایه و شش part؛ `Methods.ts` با سه method و args مشخص؛ `Step.ts` به‌شکل `createInputOtpStep()` برای رویدادهای داخلی هر instance.
3. **Runtime:** `ComponentInputOtpBase.ts` طبق الگوی `componentLabel/ComponentLabelBase.ts`، با ثبت Trait و `disposeStep()`؛ `ComponentInputOtp.ts` با constructor `(config?, methods?, identity?)`، `renderContentComponent()`, route در `renderManagerComponent()`، state، event handlers و API عمومی. از `CoreReactive.App` و `CoreObservable.App` استفاده شود، نه `ReactiveElement/Observable` قدیمی؛ از `data?.[key] ?? bind.[key]` برای binding schema استفاده شود.
4. **Composition و چرخه‌عمر:** label از Category جدید (در صورت سازگاری API) و تایمر از `UiCategory.UI.Contents.TimerDown` ساخته شود؛ listener سراسری فقط در صورت ضرورت و همراه با cleanup. اتصال Step در constructor، نه هنگام render؛ cleanup child و Step در `dispose()`.
5. **Public API و مثال:** `componentInputOtp/index.ts`, `examples/Default.ts`, `examples/index.ts` با `render(): HTMLElement`؛ مثال دارای شش خانه، مقصد قابل نمایش، callback تغییر، retry و شمارش کوتاه. `src/framework/module_ui/module_components/lists/index.ts` برای export و `CoreComponents.ComponentManager.register({ ..., examples })` به‌روز شود.
6. **Category:** پوشه‌ی `src/framework/module_ui/module_categories/lists/ui/inputs/inputOtp/` با `Definition.ts` و `index.ts` بر مبنای `inputCheckBox/`؛ export در `inputs/index.ts` و افزودن به `inputs/Definition.ts`. امضای callable instance بازگرداند: `UiCategory.UI.Inputs.InputOtp(config, methods, identity)`.

## ۶. ریسک‌های مشخص

| ریسک | اقدام در اجرا |
|:---|:---|
| تفاوت واحد API تایمر | تبدیل دقیقه به timestamp در مرز OTP انجام شده و با تست زمان‌دار بررسی شده است |
| برخورد `part_structure` قدیمی با `STRUCTURE` Trait | نام کلید `OTP_STRUCTURE` با حفظ part اختصاصی قدیمی یا نام part یکتا؛ route پایه جداگانه |
| render مجدد هنگام تغییر `prop_length` | همگام‌سازی خانه‌ها، value و focus؛ حذف listener/child قبلی |
| ناسازگاری `ComponentLabel` با label واقعی HTML | بررسی DOM و API؛ در صورت نیاز `<label for=...>` واکنش‌گرا در خود OTP |
| تایمر و timeout مثال پس از dispose | timeout مثال و timer instance را پاک کنید؛ callback پایان بیش از یک بار اجرا نشود |

مرجع اصلی در زمان اجرا همچنان `documents/guides/component-create.md` است؛ الگوی اجرایی فایل‌ها، exportها و registration باید با ساختار فعلی repository تطبیق داده شود.
