> **مرجع:** `src/framework/module_ui/module_components/lists/componentStructure/` — کلاس پایه و الگوی صحیح

## ۱. شرح قانون و مشکل

### ۱.۱ قانون

هر Component در معماری جدید باید **دو Schema پایه** به‌عنوان اولین ورودی‌های `_COMPONENT_SCHEMA` داشته باشد:

| ترتیب | Schema | Part | وظیفه |
|:---:|:---|:---|:---|
| ۱ | `COMPONENT` | `part-component` | لایه خارجی `<component-{name}>` با RTL + classList + styles |
| ۲ | `STRUCTURE` | `part-component-structure` | لایه داخلی `<section>` با show/hide + structureClass + structureStyles |
| ۳+ | Schemaهای اختصاصی | `part-{name}` | محتوای اختصاصی Component |

### ۱.۲ چرا؟

`ClComponentBase.createComponentElement()` اولین Schema از `_COMPONENT_SCHEMA` را به‌عنوان **Root Part** رندر می‌کند:

```typescript
// ClComponentBase.ts:206
const firstSchema = Object.values(this._COMPONENT_SCHEMA)[0];
const rootPartName = firstSchema?.part;
this._COMPONENT_CONTENT = this.executeSchemaPart(rootPartName);
```

اگر اولین Schema `STRUCTURE` (یا `COMPONENT`) باشد، Component با لایه ساختار پایه شروع می‌شود و محتوای اختصاصی درون آن قرار می‌گیرد.

### ۱.۳ مشکل فعلی

در تمام Componentهای مهاجرت‌شده، Schema پایه (`COMPONENT` + `STRUCTURE`) **وجود ندارد**. اولین Schema همیشه Schema اختصاصی Component است:

| Component | اولین Schema فعلی | اولین Schema موردنظر |
|:---|:---|:---|
| `ComponentButton` | `BUTTON` (part-button) | `COMPONENT` → `STRUCTURE` → `BUTTON` → ... |
| `ComponentBorder` | `BORDER` (part-border) | `COMPONENT` → `STRUCTURE` → `BORDER` |
| `ComponentIcon` | `ICON` (part-icon) | `COMPONENT` → `STRUCTURE` → `ICON` |
| `ComponentMessages` | `MESSAGE` (part-messages-message) | `COMPONENT` → `STRUCTURE` → `MESSAGE` → `ICON` |
| `ComponentFloatMenu` | `SELECTOR` (part-selector) | `COMPONENT` → `STRUCTURE` → `SELECTOR` → ... |

**نتیجه:** `renderContentComponent()` که `ComponentStructureTrait.renderContent()` را صدا می‌زند، **هرگز در جریان اصلی رندر فراخوانی نمی‌شود**. Component مستقیم به محتوای اختصاصی رندر می‌شود، بدون لایه `<component-{name}>` و `<section>`.

### ۱.۴ Evidence از کد

#### ComponentButton — جریان فعلی (ناقص):
```
createComponentElement()
  → firstSchema = BUTTON (part-button)
  → executeSchemaPart("part-button")
  → renderManagerComponent("part-button")
  → renderButton()                    ← مستقیم، بدون لایه ساختار
```

#### ComponentStructure — جریان صحیح:
```
createComponentElement()
  → firstSchema = COMPONENT (part-component)
  → executeSchemaPart("part-component")
  → renderManagerComponent("part-component")
  → renderComponentSchema()           ← <component-{name}> با RTL + classList
  → children: [executeSchemaPart("part-component-structure")]
    → renderManagerComponent("part-component-structure")
    → renderStructureSchema()         ← <section> با show/hide
    → children: [renderContentComponent()]
      → renderContentComponent()      ← محتوای اختصاصی
```

## ۲. راهکار

### ۲.۱ افزودن Schema پایه به ComponentStructureTrait

`ComponentStructureTrait` در حال حاضر فقط `props` و `renderContent` ارائه می‌دهد. باید `schemas` را هم اضافه کند تا Componentها بتوانند آن را import و merge کنند.

#### تغییر `ComponentStructureTrait/Trait.ts`:

```typescript
import {Schemas as StructureSchemas} from "../../lists/componentStructure/Schemas";

export const ComponentStructureTrait = {
    props: StructureProps,
    schemas: StructureSchemas,          // ← NEW
    renderContent(component, content) { ... },
};
```

### ۲.۲ افزودن Schema پایه به Schemas.ts هر Component

هر Component باید `COMPONENT` و `STRUCTURE` را از `ComponentStructureTrait.schemas` import کرده و به‌عنوان **اولین ورودی‌ها** در `Schemas` خود قرار دهد.

#### الگوی صحیح (مثال ComponentButton):

```typescript
import {ComponentStructureTrait} from "../../traits/componentStructureTrait";

export const Schemas = {
    // --- Schema پایه (الزامی — اولین ورودی) ---
    COMPONENT: ComponentStructureTrait.schemas.COMPONENT,
    STRUCTURE: ComponentStructureTrait.schemas.STRUCTURE,

    // --- Schema اختصاصی ---
    BUTTON:      { part: "part-button", ... },
    BUTTON_TITLE: { part: "part-button-title", ... },
    BUTTON_ICON:  { part: "part-button-icon", ... },
    WRAPPER:      { part: "part-button-wrapper", ... },
} satisfies CoreComponents.ComponentSchemas;
```

### ۲.۳ تغییر renderManagerComponent در هر Component

هر Component باید در `renderManagerComponent` دو case جدید برای `COMPONENT` و `STRUCTURE` اضافه کند:

```typescript
override renderManagerComponent(partName, attrsDefault, data, extra) {
    switch (partName) {
        // --- Schema پایه ---
        case ComponentStructureTrait.schemas.COMPONENT.part:
            return this.renderComponentSchema(attrsDefault, data);
        case ComponentStructureTrait.schemas.STRUCTURE.part:
            return this.renderStructureSchema(attrsDefault, data);

        // --- Schema اختصاصی ---
        case Schemas.BUTTON.part:
            return this.renderButton(attrsDefault, data, extra);
        ...
        default:
            return super.renderManagerComponent(partName, attrsDefault, data, extra);
    }
}
```

### ۲.۴ متدهای renderComponentSchema و renderStructureSchema

این متدها می‌توانند از `ComponentStructure` کپی شوند یا از طریق یک Helper مشترک ارائه شوند. دو گزینه:

#### گزینه A — کپی مستقیم در هر Component (ساده‌تر، تکراری):
هر Component متدهای `renderComponentSchema` و `renderStructureSchema` را مستقیم پیاده‌سازی می‌کند (کپی از `ComponentStructure.ts`).

#### گزینه B — افزودن به ComponentStructureTrait (تمیزتر، DRY):
`ComponentStructureTrait` متدهای `renderComponentSchema` و `renderStructureSchema` را به‌عنوان helper ارائه می‌دهد:

```typescript
export const ComponentStructureTrait = {
    props: StructureProps,
    schemas: StructureSchemas,
    renderContent(component, content) { ... },
    renderComponentSchema(component, attrsDefault, data) { ... },  // ← NEW
    renderStructureSchema(component, attrsDefault, data) { ... },  // ← NEW
};
```

**پیشنهاد:** گزینه B — جلوگیری از تکرار و حفظ DRY.

### ۲.۵ تغییر renderContentComponent

با افزودن Schema پایه، `renderContentComponent` دیگر نباید `ComponentStructureTrait.renderContent()` را صدا بزند (چون لایه ساختار از طریق Schema رندر می‌شود). به‌جای آن، مستقیم محتوای اختصاصی Component را رندر می‌کند:

#### قبل (ناقص):
```typescript
override renderContentComponent() {
    return ComponentStructureTrait.renderContent(
        this,
        () => this.executeSchemaPart(Schemas.BUTTON.part, {}),
    );
}
```

#### بعد (صحیح):
```typescript
override renderContentComponent() {
    return this.executeSchemaPart(Schemas.BUTTON.part, {});
}
```

## ۶. نکات و ملاحظات

### ۶.۱ ترتیب Object Keys در JavaScript

`Object.values()` ترتیب insertion را حفظ می‌کند. بنابراین `COMPONENT` باید **قبل از** سایر Schemaها در `Schemas` object literal نوشته شود.

### ۶.۲ Type Safety

`SchemasType` با `ExtractSchemasType<typeof Schemas>` استخراج می‌شود. افزودن `COMPONENT` و `STRUCTURE` به `Schemas` باعث گسترش `SchemasType` می‌شود. این باید در `_COMPONENT_SCHEMA` در Base class هم منعکس شود.

### ۶.۳ ComponentStructureTrait.renderContent — Deprecation

متد `renderContent` در Trait بعد از این Plan **منسوخ** (deprecated) می‌شود. تمام Componentها به‌جای استفاده از آن، از `schemas` + `renderComponentSchema` + `renderStructureSchema` استفاده می‌کنند.

### ۶.۴ ComponentStructure خودش

`ComponentStructure` خودش نیازی به تغییر ندارد — او قبلاً `COMPONENT` و `STRUCTURE` را به‌عنوان Schema اول دارد. این Plan فقط فرزندهای composition-based را اصلاح می‌کند.

### ۶.۵ Base Classها

`ComponentButtonBase`, `ComponentBorderBase`, و غیره در حال حاضر `ComponentStructureTrait.props` را در `_COMPONENT_PATTERN` merge می‌کنند. این درست است و باقی می‌ماند. تغییر فقط در `_COMPONENT_SCHEMA` است که باید `ComponentStructureTrait.schemas` را هم merge کند:

```typescript
protected _COMPONENT_SCHEMA = CoreComponents.DefineSchema({
    ...ComponentStructureTrait.schemas,   // ← NEW
    ...Schemas,
} as any);
```
