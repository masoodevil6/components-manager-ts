# پلن 37.1.0 — ایجاد `componentCodeMirror`

> **وضعیت:** آمادهٔ پیاده‌سازی  
> **راهنما:** `documents/guides/component-create.md`  
> **کامپوننت جدید:** `src/framework/module_ui/module_components/lists/componentCodeMirror/`  
> **دسته‌بندی:** `tools → code`  
> **بسته‌های موجود:** `codemirror`، `@codemirror/lang-html`، `@codemirror/lang-javascript`

## 1. هدف و محدوده

ساخت کامپوننت `componentCodeMirror` برای ویرایش و نمایش کد HTML و JavaScript، با API و چرخهٔ عمر کامپوننت‌های جدید پروژه.

این کامپوننت کد را به‌عنوان متن نمایش می‌دهد و اجرا یا به‌صورت صفحهٔ HTML رندر نمی‌کند. برای پشتیبانی از نمایش فقط‌خواندنی، Prop مربوط به read-only قابل تنظیم است.

بسته‌های اصلی CodeMirror و زبان‌های HTML و JavaScript در `package.json` و `package-lock.json` ثبت شده‌اند. اگر پیاده‌سازی برای `EditorState` و `Compartment` از `@codemirror/state` مستقیماً import کند، آن را نیز به‌عنوان dependency مستقیم ثبت کند؛ استفاده از dependency ترانزیتی بدون ثبت مستقیم انجام نشود.

## 2. نیازمندی‌های رفتاری

- زبان اولیه HTML باشد و امکان انتخاب HTML یا JavaScript از طریق Prop فراهم شود.
- تغییر زبان پس از ساخته‌شدن کامپوننت، extension زبان را با `Compartment` بازپیکربندی کند؛ `EditorView` دوباره ساخته نشود و selection/cursor بی‌دلیل از دست نرود.
- مقدار کد از `prop_value` دریافت شود. تغییر کد در ادیتور، مقدار Prop را به‌روز و رویداد `CHANGE` را فقط برای تغییر واقعی سند صادر کند.
- تغییر بیرونی `prop_value` به ادیتور منتقل شود. مقدار یکسان دوباره dispatch نشود تا حلقهٔ به‌روزرسانی و جابه‌جایی cursor ایجاد نکند.
- `prop_isReadOnly` هم ویرایش تعاملی را ببندد و هم وضعیت read-only خود CodeMirror را تنظیم کند؛ تغییر آن بدون بازسازی EditorView اعمال شود.
- placeholder اختیاری باشد و line wrapping از طریق Prop قابل کنترل باشد.
- ارتفاع قابل تنظیم باشد و مقدار پیش‌فرض آن با `config.sizeName` و توابع `UtilStyle` محاسبه شود؛ ارتفاع سفارشی در صورت تعیین والد اعمال شود.
- ساختار CodeMirror فقط یک بار برای هر نمونه ایجاد شود. هنگام `dispose`، `EditorView.destroy()` اجرا و هر listener، scope و Step متعلق به کامپوننت پاک‌سازی شود.
- تغییرات reactive مانند value، زبان و read-only فقط state یا extension ادیتور را به‌روز کنند و DOM ادیتور را دوباره نسازند.
- کد HTML به‌عنوان متن باقی بماند؛ هیچ کدی اجرا نشود و هیچ HTML ورودی با `innerHTML` تزریق نشود.

## 3. قرارداد API

### Enum زبان

در `Props.ts` تعریف شود:

```typescript
export enum CodeMirrorLanguage {
    HTML = "html",
    JAVASCRIPT = "javascript",
}
```

برای HTML از `html()` در `@codemirror/lang-html` و برای JavaScript از `javascript()` در `@codemirror/lang-javascript` استفاده شود.

### Props

| Prop | نوع | پیش‌فرض | کاربرد |
|---|---|---|---|
| `prop_value` | `string` | `""` | متن کد و مقدار reactive ادیتور |
| `prop_language` | `CodeMirrorLanguage` | `HTML` | زبان syntax highlighting و parser |
| `prop_isReadOnly` | `boolean` | `false` | تعیین حالت ویرایش یا نمایش |
| `prop_placeholder` | `string \| null` | `null` | متن راهنمای سند خالی |
| `prop_lineWrapping` | `boolean` | `true` | شکستن خط‌های طولانی |
| `prop_editorHeight` | `string \| null` | `null` | ارتفاع اختیاری با مقدار CSS؛ مقدار پیش‌فرض از اندازهٔ سیستم محاسبه شود |

Props با `Define_ComponentProp<T>` تعریف شوند و نام و توضیحشان از `Keys` ترجمه شوند. نوع‌های `PropsType` و `PropsConfigType` با helperهای پروژه استخراج شوند. Propهای پایهٔ `ComponentStructureTrait` نیز حفظ شوند.

### Method

- `CHANGE` با نام runtime برابر `fn_onChange` تعریف شود.
- هنگام تغییر سند، مقدار جدید کد و زبان جاری در payload callback در دسترس باشد.
- تغییر زبان، read-only یا تنظیمات ظاهری نباید `CHANGE` را اجرا کند.

## 4. معماری و Schema

از ساختار فایل‌ها، `ComponentStructureTrait`، `ComponentManager`، `Step` و `ComponentExample` در راهنمای رسمی پیروی شود.

```text
COMPONENT
STRUCTURE
ROOT: part-code-mirror
└── EDITOR: part-code-mirror-editor
    └── CodeMirror EditorView mount host
```

- `COMPONENT` و `STRUCTURE` از `ComponentStructureTrait.schemas` و در ابتدای Schema قرار گیرند.
- `ROOT` پوستهٔ کامپوننت را تعریف کند و Props مربوط به ساختار را بپذیرد.
- `EDITOR` میزبان پایدار DOM برای `EditorView` باشد و Props اختصاصی ادیتور را ثبت کند.
- Schema فقط Part و Props را تعریف کند؛ ساخت EditorView، اتصال listenerها و تغییر state در کلاس کامپوننت انجام شود.
- برای border و ظاهر پوسته از `componentBorder` استفاده شود. رنگ، border width، border radius، font size و line height با توکن‌های رنگ و `UtilStyle` محاسبه شوند.
- `.cm-editor` و `.cm-scroller` عرض کامل host را بگیرند؛ ارتفاع، scroll داخلی، focus و line wrapping با اندازهٔ والد سازگار باشند.
- نمونهٔ ادیتور فقط در همان نمونهٔ کامپوننت نگهداری شود؛ state یا EditorView بین نمونه‌ها اشتراکی نباشد.

## 5. ساختار فایل‌ها

```text
src/framework/module_ui/module_components/lists/componentCodeMirror/
├── Definition.ts
├── Props.ts
├── Schemas.ts
├── Methods.ts
├── Step.ts
├── ComponentCodeMirrorBase.ts
├── ComponentCodeMirror.ts
├── index.ts
└── examples/
    ├── Default.ts
    ├── JavaScript.ts
    ├── ReadOnly.ts
    └── index.ts
```

- `Definition.ts`: شناسهٔ `component_code_mirror`، نام `componentCodeMirror` و نسخهٔ آغازین `v1.0.0`.
- `Props.ts`: Enum زبان و Props عمومی بالا.
- `Schemas.ts`: Schemaهای پایه و `ROOT` و `EDITOR`.
- `Methods.ts`: قرارداد رویداد `CHANGE`.
- `Step.ts`: factory مرحلهٔ اصلی و مرحلهٔ تغییر کد مطابق الگوی کامپوننت‌های جدید.
- `ComponentCodeMirrorBase.ts`: ترکیب Props، Schemas و Methods با Core و `ComponentStructureTrait`.
- `ComponentCodeMirror.ts`: ساخت و نگهداری EditorView، به‌روزرسانی reactive، composition با `componentBorder` و پاک‌سازی.
- `Default.ts`: نمونهٔ ویرایش HTML با callback تغییر کد.
- `JavaScript.ts`: نمونهٔ JavaScript قابل ویرایش.
- `ReadOnly.ts`: نمایش HTML یا JavaScript بدون امکان ویرایش.
- `index.ts`: export عمومی Component، Base، Definition، Props، نوع‌ها، Schemas، Methods، Step و Examples.

## 6. ثبت کامپوننت در دسته‌بندی `tools → code`

1. در `src/framework/module_ui/module_components/lists/index.ts`، کامپوننت را export و در `CoreComponents.ComponentManager.register` با Definition، Props، Schemas، Methods، Examples و constructor ثبت کن.
2. شاخهٔ دسته‌بندی زیر را ایجاد کن:

   ```text
   src/framework/module_ui/module_categories/lists/ui/tools/
   ├── Definition.ts
   ├── index.ts
   └── code/
       ├── Definition.ts
       ├── index.ts
       └── codeMirror/
           ├── Definition.ts
           └── index.ts
   ```

3. Category ریشهٔ `tools` با شناسهٔ `tools` و Category فرزند `code` با شناسهٔ `code` تعریف شود؛ کامپوننت `CodeMirror` در بخش `components` دستهٔ `code` ثبت شود.
4. در `ui/tools/code/codeMirror/Definition.ts` API callable با `.info` از `CreateCategoryComponent` و `UIComponents.Lists.ComponentCodeMirror` ساخته شود.
5. `Tools` از `src/framework/module_ui/module_categories/lists/ui/index.ts` و `Code` از `ui/tools/index.ts` export شود.
6. برای نام و توضیحات دسته‌های `tools` و `code` و کامپوننت، Props، Schemaها، Method و مثال‌ها، کلیدهای `Keys.ts` و ترجمه‌های `En.ts` و `Fa.ts` اضافه شوند.
7. API callable در نمونه‌ها از مسیر `UiCategory.UI.Tools.Code.CodeMirror(...)` استفاده کند.

## 7. مثال‌ها و مستندسازی

- مثال پیش‌فرض HTML، کد اولیه، زبان و callback تغییر را نشان دهد.
- مثال JavaScript، language selection و line wrapping را نشان دهد.
- مثال ReadOnly ثابت کند که کد قابل مشاهده و انتخاب است ولی قابل ویرایش نیست.
- Examples از `ComponentExample` با تابع `render()` استفاده کنند تا در صفحهٔ تست خودکار پروژه نمایش داده شوند.
- نام و توضیح هر Example در کلیدهای ترجمه ثبت شود.

## 8. بررسی و پذیرش

- `npm run build:app` بعد از پیاده‌سازی موفق شود؛ در صورت خطای محیطی، خطای مستقل از کامپوننت از خطای کامپوننت تفکیک و گزارش شود.
- Category مسیر `tools → code` در فیلتر و صفحهٔ جزئیات `componentCodeMirror` قابل مشاهده باشد.
- Exampleها در صفحهٔ تست خودکار render شوند و خطای `[object Object]` یا host خالی نداشته باشند.
- حالت HTML، JavaScript، placeholder، line wrapping و ارتفاع سفارشی کار کنند.
- `CHANGE` فقط پس از ویرایش سند اجرا شود و مقدار جدید را به والد برساند؛ تغییر مقدار از والد نیز در ادیتور ظاهر شود.
- جابه‌جایی زبان و read-only، EditorView را بازسازی نکند و selection/cursor را در تغییرات غیرمرتبط بی‌دلیل از بین نبرد.
- read-only با تایپ و paste قابل دور زدن نباشد.
- ساخت چند نمونه، هر EditorView را مستقل نگه دارد.
- پس از `dispose`، EditorView و منابع وابسته پاک‌سازی شوند.
- هیچ HTML یا JavaScript ورودی اجرا نشود.
