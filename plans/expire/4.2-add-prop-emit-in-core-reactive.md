# Clarification: ReactiveElement `emit` Contract

## 1. مفهوم `emit`

در معماری CoreEvents، property به نام `emit` در `ClReactiveElement` یک event emitter معمولی نیست.

`emit` در واقع **نقطه‌ی دریافت و اجرای Request برای Step متصل به ReactiveElement** است.

رابطه:

```text
CoreEvents.Step
      │
      │ unique
      ▼
ReactiveElement
      │
      │ emit
      ▼
Request Handler
      │
      ▼
Response
```

بنابراین `emit` نباید با `on` اشتباه گرفته شود.

---

# 2. تفاوت `on` و `emit`

`on` مربوط به Eventهای DOM است:

```ts
const button = ClReactiveElement.button({

    on: {

        click: (e, event) => {

            // DOM Event
        }

    }

});
```

اما `emit` مربوط به **CoreEvents Request** است:

```ts
const input = ClReactiveElement.input({

    unique: User.info.name,

    emit: request => {

        // CoreEvents Request

        return {
            value: "Mehdi",
            valid: true
        };

    }

});
```

پس:

```text
on
↓
DOM Event

emit
↓
CoreEvents Request
```

---

# 3. `emit` نباید Event تولید کند

نام `emit` ممکن است باعث سوءبرداشت شود.

در این معماری:

```ts
emit: request => {}
```

به معنی:

> «هرگاه CoreEvents یک Request برای Step این Element دریافت کرد، این callback را اجرا کن.»

نه:

> «این Element یک Event منتشر می‌کند.»

بنابراین اگر نام API هنوز قابل تغییر است، این رفتار باید به عنوان قرارداد اصلی مستند شود.

---

# 4. نقش `unique`

ReactiveElement با property زیر به یک Step متصل می‌شود:

```ts
unique: User.info.name
```

یعنی:

```text
User.info.name
      │
      ▼
CoreEvents.Step
      │
      │ unique
      ▼
ReactiveElement.input
```

CoreEvents می‌تواند با استفاده از همین Step تشخیص دهد Request مربوط به کدام ReactiveElement است.

---

# 5. مثال واقعی

تعریف Workflow:

```ts
const User = CoreEvents.Step({

    children: {

        info: CoreEvents.Step({

            children: {

                name: CoreEvents.Step({
                    request: CoreEvents.Request(),
                    response: CoreEvents.Response()
                }),

                family: CoreEvents.Step({
                    request: CoreEvents.Request(),
                    response: CoreEvents.Response()
                }),

                submit: CoreEvents.Step({
                    request: CoreEvents.Request(),
                    response: CoreEvents.Response()
                })

            }

        })

    }

});
```

ReactiveElementها:

```ts
const nameInput = ClReactiveElement.input({

    unique: User.info.name,

    emit: request => {

        if (request.action === "validate") {

            const value =
                nameInput.getElement().value;

            return {
                value,
                valid: value.trim().length > 0
            };

        }

    }

});
```

و:

```ts
const familyInput = ClReactiveElement.input({

    unique: User.info.family,

    emit: request => {

        if (request.action === "validate") {

            const value =
                familyInput.getElement().value;

            return {
                value,
                valid: value.trim().length > 0
            };

        }

    }

});
```

---

# 6. ارسال Request توسط Button

Button به Step خودش متصل است:

```ts
const submitButton = ClReactiveElement.button({

    unique: User.info.submit,

    children: "Save",

    on: {

        click: (e, event) => {

            return event.request({

                [User.info.name]: {
                    action: "validate"
                },

                [User.info.family]: {
                    action: "validate"
                }

            });

        }

    }

});
```

در اینجا Button مستقیماً `nameInput` یا `familyInput` را نمی‌شناسد.

فقط Stepهای موردنظر را Target می‌کند.

---

# 7. CoreEvents چه اتفاقی می‌اندازد؟

وقتی:

```ts
event.request({

    [User.info.name]: {
        action: "validate"
    },

    [User.info.family]: {
        action: "validate"
    }

});
```

اجرا می‌شود، CoreEvents باید:

```text
Request
   │
   ├── Target: User.info.name
   │
   └── Target: User.info.family
```

را resolve کند.

سپس:

```text
User.info.name
       │
       ▼
nameInput.emit(request)
```

و:

```text
User.info.family
       │
       ▼
familyInput.emit(request)
```

را اجرا کند.

---

# 8. `emit` Response تولید می‌کند

خروجی callback `emit` باید Response مربوط به Request باشد.

مثلاً:

```ts
emit: request => {

    return {
        value: "Mehdi",
        valid: true
    };

}
```

CoreEvents باید این نتیجه را به Request مربوطه نسبت دهد.

در نتیجه:

```text
Request #100
   │
   ├── name
   │    └── Response #101
   │
   └── family
        └── Response #102
```

---

# 9. Response به Request کننده برمی‌گردد

در Button:

```ts
on: {

    click: (e, event) => {

        const response = event.request({

            [User.info.name]: {
                action: "validate"
            },

            [User.info.family]: {
                action: "validate"
            }

        });

        return response;

    }

}
```

بنابراین:

```text
Button
  │
  │ request
  ▼
CoreEvents
  │
  ├──→ name.emit()
  │       │
  │       └── response
  │
  └──→ family.emit()
          │
          └── response
  │
  ▼
Button
```

---

# 10. نکته مهم: `emit` متعلق به Element است، نه Step

`Step` تعریف می‌کند:

```text
چه چیزی وجود دارد؟
چه Requestای قبول می‌کند؟
چه Responseای تولید می‌کند؟
```

ReactiveElement مشخص می‌کند:

```text
این Step در UI چگونه اجرا می‌شود؟
```

بنابراین:

```text
CoreEvents.Step
       │
       │ Contract
       ▼
ReactiveElement
       │
       │ emit
       ▼
Runtime implementation
```

این separation باید حفظ شود.

---

# 11. یک Step می‌تواند بدون ReactiveElement وجود داشته باشد

مثلاً:

```ts
const info = CoreEvents.Step({

    children: {

        name: CoreEvents.Step(...),

        family: CoreEvents.Step(...)

    }

});
```

این Step ممکن است هیچ:

```ts
unique
```

متصل به ReactiveElement نداشته باشد.

پس CoreEvents نباید فرض کند هر Step دارای `emit` است.

---

# 12. یک ReactiveElement می‌تواند فقط یک `unique` داشته باشد

نمونه:

```ts
ClReactiveElement.input({

    unique: User.info.name,

    emit: request => {

        ...

    }

});
```

`unique` مشخص می‌کند Request به کدام Step مربوط است.

`emit` implementation اجرای Request در آن Element است.

---

# 13. مدل نهایی

مدل اصلی سیستم باید این باشد:

```text
                 CoreEvents
                     │
                  Request
                     │
                     ▼
                 Target Step
                     │
                     │ unique
                     ▼
              ReactiveElement
                     │
                   emit
                     │
                     ▼
                 Response
                     │
                     ▼
                 CoreEvents
                     │
                     ▼
              Request Sender
```

و برای چند Target:

```text
                     Request
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
       Step A        Step B        Step C
          │             │             │
        emit           emit           emit
          │             │             │
          ▼             ▼             ▼
      Response       Response       Response
          └─────────────┼─────────────┘
                        ▼
                  Request Sender
```

---

# 14. اصل بسیار مهم برای Implementation

در implementation این اشتباه انجام نشود:

```ts
emit: EventEmitter
```

یا:

```ts
emit: Observable
```

یا:

```ts
emit: (...events) => {}
```

`emit` باید یک **Request Handler** باشد.

مفهوم صحیح:

```ts
emit?: (
    request: CoreEvents.RuntimeRequest
) => CoreEvents.RuntimeResponse | any;
```

نوع دقیق باید با طراحی نهایی Request/Response هماهنگ شود.

---

# 15. خلاصه قرارداد

```text
on
│
└── DOM → ReactiveElement

unique
│
└── ReactiveElement → CoreEvents.Step

request()
│
└── Sender → Target Steps

emit
│
└── Target ReactiveElement ← Request

return
│
└── emit → Response

response
│
└── Target Step → Request Sender
```

پس در این معماری:

> **`on` رفتار DOM را دریافت می‌کند، `request()` ارتباط CoreEvents را آغاز می‌کند، `unique` مسیر Request را مشخص می‌کند، و `emit` نقطه‌ای است که ReactiveElement Request را اجرا کرده و Response تولید می‌کند.**
