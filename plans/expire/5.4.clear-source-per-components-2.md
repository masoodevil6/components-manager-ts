# ComponentStructure Architecture Refactoring Plan

> **Scope:** تثبیت معماری `ComponentStructure` و استانداردسازی ارتباط بین `Definition`، `Props`، `Schemas`، `SchemaHandlers` و Runtime
>
> **Guide Path:**
> `D:\projects\components\master\documents\guides\Basic`

---

## 1. هدف

هدف این Phase، تثبیت قرارداد معماری Component قبل از شروع توسعه Componentهای واقعی مانند `ComponentButton` است.

معماری هدف باید مسئولیت‌های زیر را از یکدیگر جدا کند:

```text
Definition   → هویت و شناسنامه Component
Props        → ورودی‌های Component
Schemas      → تعریف ساختار UI
SchemaHandler → رفتار و Rendering Schema
Methods      → رفتار قابل تزریق Component
Runtime      → اجرای Component
```

اصل کلیدی:

> **Schema باید Declarative باشد و Handler باید Behavioral باشد.**

بنابراین منطق Rendering نباید مستقیماً داخل `Schemas.ts` قرار گیرد.

# 2. معماری هدف

```text
                    Component
                       │
       ┌───────────────┼────────────────┐
       ▼               ▼                ▼
  Definition         Props           Methods
       │
       ▼
    Schemas
       │
       ▼
 Schema Handler
       │
       ▼
    Runtime
```

مسئولیت هر بخش:

| بخش                  | مسئولیت                                          |
| -------------------- | ------------------------------------------------ |
| `Definition`         | هویت، نام، نسخه و اطلاعات قابل شناسایی Component |
| `Props`              | تعریف ورودی‌ها و مقادیر پیش‌فرض                  |
| `Schemas`            | تعریف Parts و ساختار UI                          |
| `SchemaHandlers`     | رفتار و Rendering هر Schema                      |
| `Methods`            | Callbackها و رفتار قابل تزریق توسط مصرف‌کننده    |
| `ComponentStructure` | ترکیب قراردادهای بالا در Runtime                 |

# 3. Definition

## مسئولیت

`Definition.ts` فقط شناسنامه Component است.

نمونه خروجی:

```ts
import * as UiComponents from "@/ui_components";

export const Definition = {
    id: "component_structure",
    name: "componentStructure",
    version: "1.0.0",
} satisfies UiComponents.Basic.Types.ComponentDefinition;
```

## قوانین

* `id` باید unique و پایدار باشد.
* `Definition` نباید مسئول Rendering باشد.
* `Definition` نباید به Runtime وابسته باشد.
* `Definition` باید بدون ساخت Instance قابل دسترسی باشد.
* در آینده `Definition` ورودی `ComponentManager` خواهد بود.
* در این Phase ساخت `ComponentManager` انجام نمی‌شود.

# 5. Methods

`ComponentStructure` پایه در حال حاضر Method اختصاصی ندارد.

بنابراین:

```ts
export const Methods = {} as const;
```

و:

```ts
export type MethodsType = {
    [K in keyof typeof Methods]:
        (event: Event, dataArgs: any, componentArgs: any) => void
};
```

## نکته معماری مهم

`SchemaHandler` و `Component Method` دو مفهوم متفاوت هستند.

```text
SchemaHandler
    ↓
رفتار داخلی Framework
```

در مقابل:

```text
Component Method
    ↓
رفتار قابل استفاده یا تزریق توسط مصرف‌کننده
```

مثلاً:

```ts
fn_onClickButton()
```

یک Component Method است.

در حالی که:

```ts
SchemaHandler.render()
```

رفتار داخلی Rendering است.

این دو نباید در یک سیستم قرار بگیرند.

# 9. SchemaHandlers

فایل جدید ایجاد شود:

```text
componentStructure/
└── SchemaHandlers.ts
```

این فایل Rendering مربوط به Schemaهای پایه را نگهداری می‌کند.

ساختار پیشنهادی:

```ts
export const SchemaHandlers = {

    COMPONENT: {

        render(context) {

            const rtl =
                CoreConfigs.Settings.DirectionRtl.observable();

            const classList =
                context.data?.classList ??
                new CoreObservable.App([]);

            const styles =
                context.data?.styles ??
                new CoreObservable.App({});

            return CoreReactive.App.component(
                context.component._COMPONENT_NAME,
                {
                    attrs: {
                        ...context.attrsDefault,
                    },

                    classBind: [
                        classList,
                    ],

                    stylesBind: {
                        direction:
                            rtl.mapBoolean("rtl", "ltr"),

                        styles,
                    },

                    children: [
                        context.component.executeSchemaPart(
                            Schemas.STRUCTURE.part
                        ),
                    ],
                }
            );
        },
    },

    STRUCTURE: {

        render(context) {

            const prop_show =
                context.data?.prop_show ??
                new CoreObservable.App(true);

            const prop_structureClass =
                context.data?.prop_structureClass ??
                new CoreObservable.App([]);

            const prop_structureStyles =
                context.data?.prop_structureStyles ??
                new CoreObservable.App({});

            return CoreReactive.App.part(
                "section",
                {
                    classBind: [
                        prop_structureClass,
                        prop_show.mapBoolean(
                            "show",
                            "d-none"
                        ),
                    ],

                    attrs: {
                        ...context.attrsDefault,
                    },

                    stylesBind: {
                        prop_structureStyles,
                    },

                    children: [
                        context.component
                            .renderContentComponent(),
                    ],
                }
            );
        },
    },

};
```

> این کد یک نمونه معماری است. Signature نهایی `context` باید بر اساس Core واقعی پروژه تنظیم شود.

# 13. ComponentStructure

`ComponentStructure` باید Runtime پایه همه Componentها باشد.

خروجی مورد انتظار:

```ts
export class ComponentStructure<
    TProp extends Record<string, any> = PropsType,
    TSchemas = SchemasType,
    TMethods extends Record<string, any> = MethodsType
> extends CoreComponents.App<
    TProp,
    TSchemas,
    any,
    TMethods
> {

    constructor(
        componentName: string = "structure",
        elId: string | null = null,
    ) {
        super(componentName, elId);
    }

    _COMPONENT_PATTERN =
        CoreComponents.DefineProp<TProp>({
            ...Props,
        } as any);

    _COMPONENT_SCHEMA =
        CoreComponents.DefineSchema<TSchemas, TProp>({
            COMPONENT: {
                part: Schemas.COMPONENT.part,
                props: (Schemas.COMPONENT.props ?? []) as any,
            },

            STRUCTURE: {
                part: Schemas.STRUCTURE.part,
                props: (Schemas.STRUCTURE.props ?? []) as any,
            },

        } as any);

    _COMPONENT_METHODS =
        CoreComponents.DefineMethod<TMethods, TProp>({
            ...Methods,
        } as any);

}
```

## ComponentStructure نباید شامل این موارد باشد

```text
renderManagerComponent()
renderComponentLayer()
renderStructureLayer()
Schema Rendering Logic
if/switch برای انتخاب Schema
```
