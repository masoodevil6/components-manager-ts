# پلن 42.1.0 — ساخت `componentEffectChange`

> **وضعیت:** Draft — آماده‌ی بازبینی پیش از implementation  
> **راهنما:** `documents/guides/component-create.md`  
> **نام کامپوننت:** `componentEffectChange`  
> **دسته‌بندی:** `effects`  
> **مسیر مصرف:** `UiCategory.UI.Effects.EffectChange(config, methods, identity)`

## ۱. هدف و محدوده

`componentEffectChange` محتوای فعلی خود را نگه می‌دارد و هنگام جایگزین‌شدن محتوا، تغییر را با transition نمایش می‌دهد. کاربردهای اصلی آن تغییر صفحه یا بخش صفحه و جابه‌جایی اسلایدهاست.

این کامپوننت با `componentEffective` تفاوت دارد: `componentEffective` نمایش یا پنهان‌شدن یک محتوای ثابت را کنترل می‌کند؛ `componentEffectChange` جایگزینی یک محتوا با محتوای دیگر را متحرک می‌کند. این کامپوننت وضعیت route، انتخاب اسلاید یا منطق بارگذاری محتوا را مدیریت نمی‌کند؛ والد محتوای تازه را به آن می‌دهد.

کامپوننت باید بتواند هر محتوای reactive یا DOM قابل‌نمایش را در بر بگیرد و به ظاهر `ComponentBorder` وابسته نباشد. در صورت نیاز، مصرف‌کننده می‌تواند خودش `ComponentBorder` را داخل محتوای ورودی قرار دهد.

## ۲. قرارداد رفتاری

- نمایش اولیه بدون انیمیشن انجام شود تا هنگام mount فلش یا حرکت ناخواسته دیده نشود.
- وقتی مقدار `prop_content` عوض شد، محتوای قبلی و جدید با ترتیب خروج/ورود مشخص transition شوند.
- transitionهای اولیه شامل `none`، `fade`، `slide` و `scale` باشند.
- در حالت `slide` جهت حرکت با `prop_changeDirection` تعیین شود. جهت‌های `forward` و `backward` با `config.directionRtl` سازگار باشند تا برای صفحه و slider قابل استفاده باشند.
- اگر تغییر دیگری هنگام transition برسد، transition قبلی لغو شود و آخرین محتوا نمایش داده شود؛ callback یا timer قدیمی نباید محتوای تازه‌تر را بازنویسی کند.
- ارتفاع wrapper هنگام transition حفظ شود یا بر اساس اندازه‌ی محتوای ورودی به‌روز شود تا صفحه نپرد؛ پس از پایان، ارتفاع به حالت طبیعی محتوا بازگردد.
- انیمیشن نباید focus، event handler یا DOM state محتوای فعال را با clone کردن DOM از بین ببرد. childهای جایگزین‌شده و منابع متعلق به آن‌ها طبق قرارداد component lifecycle آزاد شوند.
- در `prefers-reduced-motion: reduce` انیمیشن با مدت صفر اجرا شود، اگر `prop_respectReducedMotion` فعال باشد.
- پس از `dispose()` هیچ timer، animation frame یا listener مربوط به transition فعال نماند.

## ۳. API پیشنهادی

### Props اختصاصی

| Prop | نوع | پیش‌فرض | کاربرد |
|---|---|---|---|
| `prop_content` | محتوای قابل‌رندر (`CoreReactive.App`، `HTMLElement`، رشته یا `null`) | `null` | محتوای فعلی؛ تغییر این مقدار trigger اصلی transition است. |
| `prop_mode` | `EffectChangeMode` | `FADE` | نوع انیمیشن: `NONE`, `FADE`, `SLIDE`, `SCALE`. |
| `prop_changeDirection` | `EffectChangeDirection` | `FORWARD` | جهت منطقی حرکت برای `SLIDE`: `FORWARD` یا `BACKWARD`. |
| `prop_duration` | `number` | `300` | مدت transition برحسب میلی‌ثانیه؛ مقدار نامعتبر یا منفی به صفر محدود شود. |
| `prop_easing` | `string` | `"ease-in-out"` | تابع timing انیمیشن CSS. |
| `prop_respectReducedMotion` | `boolean` | `true` | کاهش یا حذف حرکت بر اساس تنظیم سیستم‌عامل کاربر. |

`EffectChangeMode` و `EffectChangeDirection` در `Props.ts` تعریف و از `index.ts` صادر شوند. مقدار ناشناخته باید به رفتار امن `NONE` تبدیل شود. Props عمومی `ComponentStructure` نیز طبق راهنما به ارث برسند.

### Methods

- `TRANSITION_START`: هنگام آغاز transition واقعی اجرا شود.
- `TRANSITION_END`: پس از نمایش محتوای جدید اجرا شود.
- هر دو callback، در صورت نیاز مصرف‌کننده، کلید قبلی و جدید محتوا و جهت تغییر را در `dataArgs` دریافت کنند. نمایش اولیه و mode برابر `NONE` نباید transition مصنوعی ایجاد کنند.

## ۴. معماری و Schema

کامپوننت از `ComponentStructureTrait` برای schemaهای پایه استفاده کند. ریشه یک wrapper پایدار باشد تا اندازه و موقعیت transition در تغییر محتوا کنترل شود؛ محتوای ورودی در slot داخلی آن رندر شود.

```text
COMPONENT
STRUCTURE
ROOT: part-effect-change
└── CONTENT: part-effect-change-content
    └── prop_content
```

- `Schemas.ts` فقط partها و Props متناظر را تعریف کند.
- state، تعویض child، زمان‌بندی transition و cleanup در `ComponentEffectChange.ts` بماند.
- برای ساخت و اتصال داخلی، از قرارداد `CoreEvent.Step` و `Component...Base` مطابق راهنما استفاده شود؛ اگر workflow اختصاصی لازم نیست، Step خالی باقی بماند.
- wrapper اندازه‌ی محتوا را در زمان لازم اندازه‌گیری کند؛ برای transitionهای هم‌پوشان از clone کردن DOM استفاده نشود.
- اندازه‌گیری و styleهای inline فقط روی wrapper/slot transition اعمال شوند تا styleهای داخلی محتوای مصرف‌کننده بازنویسی نشوند.

## ۶. ثبت در ComponentManager و دسته‌بندی UI

1. component در `module_ui/module_components/lists/index.ts` ثبت، export و در `ComponentManager` اضافه شود.
2. در `ui/effects/effectChange/Definition.ts` از `CreateCategoryComponent` استفاده شود و API callable زیر ارائه شود:

   ```ts
   UiCategory.UI.Effects.EffectChange({
       prop_content: currentPage,
       prop_mode: EffectChangeMode.SLIDE,
       prop_changeDirection: EffectChangeDirection.FORWARD,
   });
   ```

3. `EffectChange` به `ui/effects/Definition.ts` و barrelهای لازم اضافه شود؛ category فعلی `effects` حفظ و شامل هر دو `Effective` و `EffectChange` شود.
4. Props، schemaها، methods و exampleها در ComponentManager قابل مشاهده باشند و مسیر category صفحه‌ی Components برابر `effects` باشد.

## ۷. مثال‌ها

- **Default:** تعویض دو متن/بخش با fade و بدون نمایش انیمیشن در mount اولیه.
- **PageChange:** دکمه‌های بعدی/قبلی محتوای صفحه را عوض کنند؛ جهت forward/backward و RTL قابل مشاهده باشد.
- **Slider:** چند اسلاید با کنترل قبلی/بعدی جایگزین شوند؛ در زمان تغییر سریع، آخرین اسلاید انتخاب‌شده باقی بماند.
- در دست‌کم یک مثال `prefers-reduced-motion` یا `prop_respectReducedMotion` نشان داده شود.

تمام مثال‌ها از `ComponentExample` و callable category ساخته شوند و نام و توضیح ترجمه‌شده داشته باشند.

## ۹. معیارهای پذیرش

- مسیر `UiCategory.UI.Effects.EffectChange` و صفحه‌ی Components، component را زیر دسته‌ی `effects` نشان دهند.
- مقدار اولیه‌ی محتوا بدون transition ناخواسته رندر شود.
- تغییر محتوا در هر چهار mode نتیجه‌ی قابل‌مشاهده و مطابق مدت/easing داشته باشد.
- جهت slide در forward/backward و RTL/LTR درست باشد.
- تغییرهای پیاپی transitionهای قدیمی را لغو و آخرین محتوا را حفظ کنند.
- اندازه‌ی صفحه هنگام تعویض محتوا بی‌دلیل فرو نریزد یا پرش نکند.
- تنظیم reduced motion رعایت و cleanup در `dispose()` کامل باشد.
- مثال‌های page change و slider از یک API مشترک استفاده کنند و منطق navigation در خود کامپوننت قرار نگیرد.
- `npm run build:app` موفق باشد و خطای type مربوط به فایل‌های تازه یا ثبت category وجود نداشته باشد.

## ۱۰. خارج از محدوده

- مدیریت route، تاریخچه‌ی مرورگر یا بارگذاری صفحه.
- نگهداری state اسلایدر، autoplay، pagination و کنترل‌های next/previous در خود `componentEffectChange`.
- تغییر رفتار یا API کامپوننت‌های `ComponentPage`, `ComponentEffective`, `ComponentTabs` یا `ComponentBorder`.
- کتابخانه‌ی انیمیشن خارجی؛ transition با CSS و API موجود پروژه پیاده‌سازی شود.
