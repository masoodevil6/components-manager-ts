# پلن 41.1.0 — ساخت `componentConsole`

> **وضعیت:** Draft — آمادهٔ پیاده‌سازی پس از بازبینی قرارداد API  
> **نسخهٔ پلن درخواستی:** 40.1.0؛ این شماره قبلاً برای `ComponentIframe` استفاده و اجرا شده است، بنابراین این پلن با شمارهٔ بعدی ثبت می‌شود.  
> **راهنما:** `documents/guides/component-create.md`  
> **کامپوننت:** `componentConsole`  
> **دسته‌بندی:** `tools → code`  
> **API پیشنهادی:** `UiCategory.UI.Tools.Code.Console(config, methods, identity)`

## 1. هدف و محدوده

ساخت یک کامپوننت کنسول برای نمایش خروجی اجرای کد، با رفتار آشنای کنسول مرورگر: پیام‌های دارای سطح اهمیت، مقدارهای ساخت‌یافته و قابل بازکردن، خطاها همراه stack، پاک‌کردن خروجی و پیمایش خودکار به پیام تازه.

کامپوننت باید به‌تنهایی نیز قابل استفاده باشد و در `ComponentCodeMirror` جایگزین خروجی متنی سادهٔ اجرای کد شود. اجرای کد همچنان در iframe ایزولهٔ فعلی `ComponentCodeMirror` انجام می‌شود؛ کنسول فقط پیام‌های اجرای آن را دریافت و نمایش می‌دهد.

در این نسخه ورودی فرمان برای اجرای expression در کنسول ساخته نمی‌شود. اجرای برنامه از دکمهٔ Run خود CodeMirror انجام می‌گیرد و این کامپوننت مسئول تجربهٔ خروجی و خطا است.

## 2. رفتار مورد انتظار

- سطوح پیام: `log`, `info`, `warn`, `error`, `debug` و پیام نتیجهٔ اجرای عبارت.
- چند آرگومان هر فراخوانی کنسول به‌صورت یک پیام مرتب نمایش داده شوند.
- رشته، عدد، boolean، `null`، `undefined`، `BigInt`، `Symbol`، تابع، آرایه، شیء و `Error` با نمایش قابل تشخیص ارائه شوند.
- شیء و آرایه درختی و بازوبسته‌شدنی باشند؛ مقادیر تو‌در‌تو نیز قابل پیمایش باشند.
- خطای اجرای کد، پیام خطا و stack را در سطح `error` نمایش دهد.
- دکمهٔ پاک‌کردن، خروجی فعلی را حذف کند.
- تعداد خروجی‌ها سقف قابل تنظیم داشته باشد تا اجرای طولانی حافظه و DOM را بی‌حد افزایش ندهد.
- هنگام ورود پیام جدید، اگر کاربر نزدیک انتهای فهرست باشد به انتها حرکت کند؛ اگر کاربر در حال بررسی پیام‌های قبلی است، موقعیتش حفظ شود.
- نمونه‌های بصری با تنظیمات رنگ و اندازهٔ سیستم و `ComponentBorder` ساخته شوند.

## 3. قرارداد داده و Props

نوع‌های عمومی در فایل مستقل `Types.ts` تعریف و از `index.ts` صادر شوند.

```ts
export type ConsoleLevel = "log" | "info" | "warn" | "error" | "debug" | "result";

export type ConsoleValue =
    | {type: "primitive"; value: string | number | boolean | null; display: string}
    | {type: "undefined"; display: "undefined"}
    | {type: "bigint" | "symbol" | "function"; display: string}
    | {type: "error"; name: string; message: string; stack?: string}
    | {type: "array" | "object"; display: string; entries: Array<{key: string; value: ConsoleValue}>; truncated?: boolean};

export type ConsoleEntry = {
    id: string;
    level: ConsoleLevel;
    timestamp: number;
    values: ConsoleValue[];
    source?: string;
};
```

قرارداد Props اولیه:

| Prop | نوع | پیش‌فرض | کاربرد |
|---|---|---|---|
| `prop_entries` | `ConsoleEntry[]` | `[]` | پیام‌های کنسول؛ باید مقدار reactive را از قرارداد عادی Component نیز بپذیرد. |
| `prop_maxEntries` | `number` | `500` | بیشترین تعداد پیام نگهداری‌شده؛ ورودی نامعتبر به مقدار امن محدود شود. |
| `prop_autoScroll` | `boolean` | `true` | پیمایش هوشمند به انتها هنگام دریافت پیام جدید. |
| `prop_showTimestamp` | `boolean` | `true` | نمایش زمان ثبت پیام. |
| `prop_showLevelFilter` | `boolean` | `true` | نمایش فیلتر سطح‌های پیام. |
| `prop_placeholder` | `string \| null` | `null` | متن محلی‌سازی‌شده برای حالت بدون پیام. |
| `prop_componentBorder*` | alias از Props موجود `ComponentBorder` | پیش‌فرض مرجع | کنترل Border ریشه از والد، با همان نام‌گذاری و قرارداد `ComponentWidget`. |

هر prop با `Define_ComponentProp<T>`، نوع استخراج‌شده با `ExtractPropsType` و `ExtractPropsConfigType`، و نام/توضیح ترجمه‌شده تعریف شود. برای aliasهای Border از خود `ComponentBorder/Props` الگو گرفته شود؛ defaultهای موازی و ناسازگار تعریف نشوند.

## 4. Methods و رخدادهای عمومی

- `CLEAR`: پس از فشردن دکمهٔ پاک‌کردن اجرا شود تا مصرف‌کننده بتواند از پاک‌شدن خروجی مطلع شود.
- `ENTRY`: هنگام رسیدن پیام جدید اجرا شود و `ENTRY` و سطح آن را در `dataArgs` ارائه کند.
- `FILTER_CHANGE`: هنگام تغییر فیلتر سطح پیام اجرا شود.

افزودن پیام از طریق تغییر `prop_entries` انجام شود؛ قرارداد callbackها برای command داخلیِ افزودن پیام استفاده نشود. در اتصال CodeMirror، observable متعلق به همان نمونه به‌روزرسانی شود.

## 5. Schema و ساختار Component

اولین المنت رندرشدهٔ `componentConsole` باید خود `ComponentBorder` باشد. هیچ wrapper یا ناحیهٔ toolbar نباید پیش از آن در DOM قرار بگیرد. کل محتوای کنسول، شامل toolbar و خروجی، به‌عنوان `prop_content` به همان Border داده شود. تنظیمات Border باید از والد `componentConsole` با Props عمومی `prop_componentBorder*` قابل کنترل باشند و نوع/default هر alias از Props مرجع `ComponentBorder` گرفته شود.

```text
COMPONENT
STRUCTURE
ROOT: ComponentBorder (اولین المنت DOM و پوستهٔ اصلی)
└── prop_content: part-console
    ├── TOOLBAR: part-console-toolbar
    │   ├── CLEAR_BUTTON: part-console-clear-button
    │   └── LEVEL_FILTERS: part-console-level-filters
    └── OUTPUT: part-console-output
        └── ENTRIES: part-console-entries
            └── ENTRY: part-console-entry
                ├── META: part-console-entry-meta
                └── VALUES: part-console-entry-values
                    └── VALUE: part-console-value
                        └── DETAILS: part-console-value-details
```

- `Schemas.ts` فقط Partها و Props متناظر را معرفی کند؛ ساخت DOM، نگهداری state، ثبت listener و تبدیل payload در کلاس Component بماند.
- `ComponentBorder` نخستین المنت و ریشهٔ واقعی باشد؛ `part-console` و تمام محتوای داخلی آن فقط در `ComponentBorder.prop_content` سوار شوند.
- همهٔ Props عمومی Border با aliasهای `prop_componentBorder*` در `ComponentConsole/Props.ts` ثبت و از والد قابل تنظیم باشند؛ نوع و default از `ComponentBorder/Props.ts` گرفته شود.
- ناحیهٔ خروجی scroll داخلی و دارای `min-height: 0` باشد تا در والدهای با اندازهٔ محدود درست کار کند.
- ردیف پیام با سطح پیام رنگ/نشانگر مشخص داشته باشد؛ رنگ‌ها از توکن‌های سیستم و `UtilStyle` بیایند.
- اشیای تو‌در‌تو در عناصر قابل دسترس با `button`, `aria-expanded` و کلیدهای صفحه‌کلید باز و بسته شوند.
- متن پیام و نمایش مقدار primitive با `textContent`/متن reactive ساخته شود؛ دادهٔ ورودی با `innerHTML` تفسیر نشود.

## 6. مرز Serialization و امنیت اتصال iframe

کد اجراشده در iframe باید خروجی را به‌صورت پیام ساخت‌یافته به صفحهٔ میزبان بفرستد؛ خروجی در DOM کنسول با دستکاری HTML خام درج نشود.

- Bridge فقط متدهای `console.log/info/warn/error/debug` را در محیط اجرای iframe گردآوری کند و payload هر بار را به رکورد امن `ConsoleEntry` تبدیل کند.
- serializer باید چرخهٔ ارجاع را تشخیص دهد، عمق و تعداد کلیدها را محدود کند و برای مقادیر غیرقابل‌سریال‌سازی نمایش جایگزین مشخص بسازد.
- `Error` به `name`, `message`, `stack` تبدیل شود؛ `BigInt`, `Symbol` و function نیز نباید باعث شکست serialization شوند.
- پیام دریافتی در میزبان فقط وقتی پذیرفته شود که `event.source` همان `contentWindow` iframe فعال باشد و شناسهٔ نشست جاری در payload با نشست اجرا برابر باشد.
- با اجرای دوباره، پیام‌های نشست قدیمی نادیده گرفته شوند؛ با `dispose()` همهٔ listenerها، iframeها و منابع هر نمونه پاک شوند.
- iframe همچنان sandbox شده بماند و دسترسی same-origin به صفحهٔ میزبان نگیرد. این ارتباط مجوزی برای ارسال داده یا HTML اجرایی از iframe به صفحهٔ اصلی ایجاد نکند.
- خطای parse/runtime یا `window.onerror`/`unhandledrejection` به رکورد سطح `error` تبدیل شود؛ جزئیات خطا نیز در صفحهٔ میزبان به شکل متن امن نمایش یابد.

## 7. اتصال به `ComponentCodeMirror`

- در حالت `prop_canRun = false` هیچ ComponentConsole یا ناحیهٔ خروجی ساخته نشود.
- در حالت `prop_canRun = true` پنل اجرای فعلی CodeMirror حفظ شود؛ محتوای خروجی `<pre>` با `ComponentConsole` جایگزین شود.
- انتخاب Run در `ComponentMenuMore` خروجی قبلی را طبق رفتار تعیین‌شده در implementation پاک کند، نشست جدید بسازد و اجرای تازه را به همان کنسول متصل کند.
- در چیدمان افقی و عمودی، نسبت‌های ۵۰/۵۰ موجود میان ویرایشگر و خروجی حفظ شوند؛ تغییر جهت و borderهای فعلی CodeMirror خراب نشوند.
- پایان اجرای کد، خالی بودن خروجی را به شکل قابل فهم نمایش دهد و از باقی‌ماندن listener یا iframe اجرای قبلی جلوگیری شود.
- `ComponentCodeMirror` فقط از API و نوع عمومی `ComponentConsole` استفاده کند؛ ComponentConsole نباید به CodeMirror وابسته شود.

```text

```

1. `Definition.ts` از `CoreComponents.ComponentDefinition` استفاده کند و `id: "component_console"`, `name: "componentConsole"`, `version: "v1.0.0"` داشته باشد.
2. `ComponentConsoleBase.ts` از Base استاندارد، `ComponentStructureTrait`، Props، Schemas و Methods ارث ببرد.
3. `ComponentConsole.ts` ابتدا `ComponentBorder` ریشه را بسازد، محتوای console را به `prop_content` آن بدهد و aliasهای Border را از Props والد به آن منتقل کند. کلاس، state پیام‌ها، serialization، clear/filter/scroll behavior و DOM disclosure را مدیریت کند؛ listenerها به scope همان instance وابسته باشند.
4. `Step.ts` و `Methods.ts` طبق الگوی Componentهای فعلی ساخته شوند؛ در صورت نیازنبودن workflow اختصاصی، Step مصنوعی اضافه نشود.
5. کامپوننت در `module_components/lists/index.ts` ثبت و export شود و Definition، Props، Schemas، Methods و Examples در ComponentManager ثبت شوند.
6. Category فرزند `code` با API callable `UiCategory.UI.Tools.Code.Console(...)` ساخته و از barrelهای مربوط صادر شود.
7. ترجمه‌های Category، Component، Props، Schema، Methods و Examples در `module_categories/languages/Keys.ts`, `En.ts`, `Fa.ts` تکمیل شوند.
8. `ComponentCodeMirror` به ComponentConsole متصل شود؛ سایر رفتارهای اجرای کد و تنظیمات فعلی CodeMirror خارج از این تغییر باقی بمانند.

## 9. Examples

- **Default:** خروجی خالی و سپس چند پیام `log`, `info`, `warn`, `error` با timestamp.
- **Levels:** فیلتر سطح پیام و پاک‌کردن کنسول.
- **Objects:** مقادیر primitive، آرایه، شیء تو‌در‌تو، مقدارهای خاص و `Error` با stack.
- **CodeMirror run:** نمونهٔ `ComponentCodeMirror` با `prop_canRun = true`, اجرای JavaScript دارای چند سطح log، مقدار object و خطای runtime؛ نتیجه باید در ComponentConsole قابل مشاهده و بازکردن باشد.

همهٔ مثال‌ها از `ComponentExample` و callable Category ساخته شوند و متن نام/توضیح‌شان از `Keys` بیاید.

## 10. معیارهای پذیرش

- مسیر `UiCategory.UI.Tools.Code.Console` در رجیستری و صفحهٔ Components قابل دسترسی باشد.
- ورود پیام جدید با ترتیب، سطح، timestamp و چند مقدار حفظ شود.
- فیلتر سطح، clear، محدودیت تعداد رکورد و auto-scroll مطابق Props کار کنند.
- object و array بدون خطای circular data باز و بسته شوند؛ `Error` پیام و stack خود را نشان دهد.
- مقدارهای ورودی به‌عنوان HTML اجرا نشوند.
- CodeMirror در هر دو چیدمان افقی/عمودی خروجی Console را در نیمهٔ اختصاص‌یافته نشان دهد و اجرای مجدد پیام‌های اجرای پیشین را طبق رفتار تعیین‌شده مدیریت کند.
- پیام‌های اجرای قبلی پس از اجرای جدید یا `dispose()` وارد نمونهٔ فعال نشوند.
- `dispose()` listenerهای `message`, handlerهای DOM و child componentها را آزاد کند.
- ترجمه‌های Fa/En موجود باشند، مثال‌ها بدون `[object Object]` render شوند و `npm run build:app` موفق باشد.

## 11. خارج از محدودهٔ نسخهٔ اول

- اجرای دستورهای تایپ‌شده در prompt کنسول.
- ابزارهای کامل DevTools مانند Network, Sources, breakpoints, live object references و profiler.
- دسترسی کنسول به context صفحهٔ میزبان یا دستکاری DOM بیرونی iframe.
- ذخیرهٔ پایدار پیام‌ها پس از بستن صفحه.
