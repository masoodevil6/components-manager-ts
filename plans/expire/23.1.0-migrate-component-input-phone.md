# پلن 23.1.0 — انتقال `ComponentInputPhone` به ساختار جدید

> **وضعیت:** پیاده‌سازی شد؛ اجرای build در محیط فعلی با `spawn EPERM` متوقف شد.  
> **نسخه:** 23.1.0  
> **منبع Legacy:** `last/tools/components/ComponentInputPhone.ts`  
> **راهنما:** `documents/guides/component-create.md`  
> **الگوهای معماری:** `componentInput`، `componentInputEmail`، `componentInputPassword` و `componentSelectCustomSimple`  
> **مقصد:** `src/framework/module_ui/module_components/lists/componentInputPhone/`  
> **API نهایی:** `UiCategory.UI.Inputs.InputPhone(config, methods, identity)`

## 1. هدف و محدوده

انتقال ورودی تلفن Legacy به ساختار declarative/runtime جدید و حفظ رفتار انتخاب کشور، انتخاب شهر، ورود شماره، label، اعتبارسنجی، غیرفعال‌سازی و callbackها. خود کامپوننت نباید DOM خام برای input یا select بسازد؛ برای فیلد شماره از `ComponentInputSimple` و برای انتخاب‌های کشور و شهر از `ComponentSelectCustomSimple` استفاده شود.

ساختار مورد انتظار:

```text
ComponentInputPhone
├── 1. ComponentLabelTrait
├── 2. part-input-phone-form
│   ├── 2.1 ComponentIcon (اختیاری؛ آیکون تلفن)
│   ├── 2.2 ComponentSelectCustomSimple (کشور، اختیاری)
│   ├── 2.3 ComponentSelectCustomSimple (شهر، اختیاری)
│   └── 2.4 ComponentInputSimple (شماره تلفن، type=tel)
└── 3. ComponentValidate (شرطی)
```

کشور و شهر هر کدام به‌صورت مستقل اختیاری هستند. اگر یکی غیرفعال باشد، فضا و عنصر آن نیز از فرم حذف شود. ترتیب اجزا باید مطابق ساختار Legacy و جهت سیستم حفظ شود.

## 2. بررسی رفتار و سازگاری Legacy

- مقدار پیش‌فرض `prop_value` رشته خالی است؛ مقدار `null` در مرز `ComponentInputSimple` به `""` تبدیل شود.
- `prop_countryOptions` و `prop_cityOptions` در Legacy شامل گزینه‌هایی با `id`, `name`, `code` هستند؛ گزینه‌های `ComponentSelectCustomSimple` از `id`, `name`, `prefix` استفاده می‌کنند. adapter باید `code` را به `prefix` نگاشت کند، بدون تغییر API ورودی Phone.
- گزینه‌های شهر دارای `countryId` هستند. فهرست نمایشی شهرها باید بر اساس کشور انتخاب‌شده فیلتر شود؛ انتخاب کشور، انتخاب شهر و شماره را مطابق Legacy پاک کند.
- مقدارهای country و city ممکن است در Legacy عدد یا رشته باشند. مقایسه و نگاشت option باید مقدارها را بدون خطای نوع مدیریت کند و callback مقدار را با قرارداد جدید مستندشده تحویل دهد.
- انتخاب شهر مقدار شماره را پاک می‌کند؛ انتخاب کشور مقدار شهر و شماره را پاک می‌کند. هر تغییر باید state داخلی، props کنترل‌شده و event args را همگام نگه دارد.
- disabled باید روی هر دو selector و ورودی شماره اعمال شود. انتخاب پنهان یا غیرفعال نباید event انتخاب صادر کند.
- label از `ComponentLabelTrait` ساخته شود و کلیک آن input شماره را focus کند. `prop_title` مستقل از عنوان label، برای validator باقی بماند.
- validator فقط وقتی نمایش داده شود که `prop_hasRules` فعال و rules معتبر/غیرخالی باشند؛ در حالت disabled نمایش داده نشود.
- sizing از `CoreConfig.Settings.SizeName` و utilهای استاندارد گرفته شود؛ `prop_size` Legacy حذف شود.
- مقدار پیش‌فرض‌های Legacy حفظ شوند: country/city selectors روشن، عرض‌های انتخابگر و select، پس‌زمینه فرم، آیکون تلفن، placeholder، قواعد validation و مقدارهای نمونه. مقادیر اندازه‌ای که باید تابع config سیستم باشند hardcode نشوند.

## 3. Props و قرارداد مهاجرت

Props مشترک component، structure، value و label از قراردادها/traitهای موجود ارث برسند و در Props محلی دوباره تعریف نشوند. برای props اختصاصی از `Define_ComponentProp<T>`، کلیدهای ترجمه `Keys`، `satisfies CoreComponents.ComponentProps` و type helperهای `ExtractPropsType` و `ExtractPropsConfigType` استفاده شود.

| Legacy | تصمیم ساختار جدید |
|---|---|
| `prop_name`, `prop_value`, `prop_isDisable` | از props پایه مناسب استفاده و به `ComponentInputSimple` منتقل شوند؛ `prop_value` رشته‌ای باقی بماند. |
| props label | از `ComponentLabelTrait`؛ بدون تعریف تکراری. |
| `prop_title` | حفظ شود و فقط به عنوان validator برسد، نه label. |
| `prop_countryHas`, `prop_cityHas` | حفظ به‌عنوان flagهای نمایش selector؛ پیش‌فرض مطابق Legacy. |
| `prop_countryWidth`, `prop_cityWidth`, `prop_selectWidth` | حفظ در صورت استفاده واقعی Legacy؛ واحد و محل اعمال width در طرح مشخص شود. اندازه‌های وابسته به config با util محاسبه شوند. |
| `prop_countryOptions`, `prop_cityOptions` | ورودی Legacy با `id/name/code` پذیرفته شود؛ در runtime به گزینه‌های `id/name/prefix` تبدیل گردد. نوع داده مشخص تعریف شود، از `any[]` پرهیز شود. |
| `prop_countryValue`, `prop_cityValue` | حفظ به‌عنوان انتخاب‌های کنترل‌شده؛ مقادیر پس از انتخاب در state و prop همگام شوند. |
| `prop_placeholder` | به `ComponentInputSimple.prop_inputPlaceholder` نگاشت شود. |
| `prop_backgroundColorForm`, `prop_formBorderRadius` | پس از بررسی مصرف واقعی حفظ شوند؛ radius با `UtilStyle` و `SizeName` سیستم تعیین شود. |
| `prop_colorIcon`, `prop_icon` | آیکون اختیاری و قابل جایگزینی باقی بماند؛ مقدار پیش‌فرض آیکون تلفن جدید از `UiIcons` باشد و رنگ با utilهای رنگ تنظیم شود. |
| `prop_size` | از API جدید حذف؛ config اندازه سیستم مرجع باشد. |
| `prop_labelClass` | بررسی شود که معادل معتبر Trait دارد؛ در غیر این صورت مهاجرت/حذف مستند شود و prop بی‌مصرف منتقل نشود. |
| `prop_inputClass`, `prop_inputStyles` | به `ComponentInputSimple` منتقل شوند؛ استایل پایه و سفارشی با ترتیب مشخص merge شوند. |
| `prop_inputBorderColor`, `prop_inputBorderColorFocus`, `prop_inputBorderWidth`, `prop_inputBorderRadius` | سازگاری مصرف‌کنندگان بررسی شود؛ رنگ‌ها فقط از API پشتیبانی‌شده‌ی childها، و اندازه‌های border از util/config سیستم بیایند. border موازی روی input نسازید. |
| `prop_hasRules`, `prop_isAbsoluteRule`, `prop_listRules`, `prop_msgRules` | حفظ و به `ComponentValidate` نگاشت شوند؛ نوع rules با validatorهای جدید هماهنگ باشد. |

هر prop قدیمی پیش از حذف یا تغییر نام با `rg` در repo جست‌وجو شود. هدف مهاجرت حفظ API مورد استفاده است؛ تغییر ناسازگار باید در پلن/مثال صریح باشد.

## 4. Methods و رویدادها

تعریف‌ها در `Methods.ts` باید metadata ترجمه‌شده و آرگومان‌های typed داشته باشند. قرارداد فعلی Legacy برای هر رویداد country، city و value جاری را ارائه می‌کند.

| Method جدید | قرارداد |
|---|---|
| `SELECT_COUNTRY_CHANGE` | پس از ثبت کشور جدید و پاک‌کردن city/value، یک بار اجرا شود؛ آرگومان‌های `COUNTRY`, `CITY`, `VALUE` مقادیر نهایی را منعکس کنند. |
| `SELECT_CITY_CHANGE` | پس از ثبت شهر جدید و پاک‌کردن value، یک بار اجرا شود؛ آرگومان‌های `COUNTRY`, `CITY`, `VALUE` مقدارهای نهایی باشند. |
| `INPUT_CHANGE` | پس از تایپ یا clear داخلی `ComponentInputSimple` یک بار اجرا شود؛ country/city جاری و value نهایی را بدهد. |
| `INPUT_FOCUS` | فقط در focus واقعی input شماره اجرا شود و country/city/value جاری را بدهد. |
| `INPUT_BLUR` | فقط در blur واقعی input شماره اجرا شود و country/city/value جاری را بدهد. |

برای انتخاب‌ها از event استاندارد `ComponentSelectCustomSimple` استفاده شود؛ callback دستی موازی که همان تغییر را دوباره emit کند نسازید. تغییر controlled props باید از subscription/observableهای موجود پیروی کند و در `dispose()` پاک‌سازی شود.

## 5. Schemas و مسئولیت هر بخش

`COMPONENT` و `STRUCTURE` از `ComponentStructureTrait` و `LABEL` از `ComponentLabelTrait` بیایند. Schemaها declarative باقی بمانند و فقط metadata و prop binding را تعریف کنند.

| Schema | Part پیشنهادی | مسئولیت |
|---|---|---|
| `FORM` | `part-input-phone-form` | wrapper فرم و ترتیب چهار فرزند؛ layout و استایل فرم. |
| `ICON` | `part-input-phone-icon` | آیکون اختیاری تلفن؛ کلیک روی آن input را focus کند. |
| `COUNTRY_SELECT` | `part-input-phone-country-select` | selector کشور با گزینه‌های map‌شده و مقدار انتخاب‌شده. |
| `CITY_SELECT` | `part-input-phone-city-select` | selector شهر؛ گزینه‌ها با کشور انتخاب‌شده فیلتر شوند. |
| `INPUT` | `part-input-phone-input` | `ComponentInputSimple` با نوع تلفن, placeholder, disabled و مقدار رشته‌ای. |
| `VALIDATE` | `part-input-phone-validate` | ساخت `ComponentValidate` فقط در وضعیت معتبر و فعال. |

هر part باید فقط props لازم خود را فهرست کند. layout باید با LTR/RTL سیستم سازگار بماند و از wrapper، border یا selector خام موازی اجتناب کند.

## 7. Runtime، state و پاک‌سازی

- Component نهایی از Base جدید و `createInputPhoneStep()` استفاده کند؛ constructor طبق الگوهای جدید `config`, `methods`, `identity` را بپذیرد.
- برای مقدارهای observable، مقدار جاری در initialization خوانده و subscriptionها با تغییر بیرونی همگام شوند؛ از loop بین `set()` و subscription جلوگیری شود.
- گزینه‌های map‌شده و گزینه‌های شهر فیلترشده باید reactive به تغییر options/country باشند.
- childهای ساخته‌شده در آرایه‌ای نگهداری و هنگام dispose آزاد شوند؛ subscriptionها، scope و event step نیز پاک شوند.
- selectorها و input از طریق reference childها کنترل شوند؛ از `document.querySelector` و selectorهای سراسری استفاده نشود.
- UI در نبود کشور یا شهر، نبودن گزینه‌ها، مقدار انتخاب‌شده‌ی نامعتبر، disabled و RTL/LTR بدون exception رندر شود.

## 8. Example و معیار پذیرش

Example پیش‌فرض از نمونه‌ی Legacy الهام بگیرد اما با API جدید ساخته شود: کشورها و شهرها با `id/name/code`، مقدارهای انتخاب‌شده، شماره، label، placeholder، validation و callbackهای نمونه. حداقل یک مثال دیگر حالت بدون selector کشور یا شهر را نشان دهد، اگر API آن را پشتیبانی می‌کند.

پلن زمانی کامل است که:

1. فرم تنها یک بار و با ترتیب آیکون، کشور، شهر، شماره رندر شود؛ selectorهای خام Legacy دیگر تولید نشوند.
2. انتخاب کشور، شهر و شماره مطابق قواعد پاک‌سازی بالا عمل کند و callback هر تغییر فقط یک بار فراخوانی شود.
3. تغییر controlled values/options از بیرون در UI دیده شود و گزینه‌های شهر با کشور جاری هماهنگ بمانند.
4. input به‌صورت `tel` و با clear داخلی، disabled، focus/blur و placeholder کار کند.
5. label روی input فوکوس کند و validator فقط در وضعیت معتبر نمایش داده شود.
6. اندازه‌ها از config سیستم بیایند؛ رفتار در LTR و RTL و با country/city selectorهای خاموش بررسی شود.
7. metadata و انواع جدید کامل باشند و example از مسیر TestsPage/ComponentManager قابل مشاهده باشد.
8. `git diff --check`، typecheck هدفمند و تست‌های موجود/مرتبط اجرا شوند؛ محدودیت اجرای تست‌ها در صورت بروز مستند شود.

## 9. خارج از محدوده

- بازنویسی مصرف‌کنندگان Legacy در کل پروژه.
- تغییر قواعد کسب‌وکار کشور/شهر، افزودن منبع داده‌ی شبکه‌ای یا پیاده‌سازی جست‌وجوی جدید.
- تغییر قرارداد عمومی callbackها بدون شواهد مصرف و ثبت دلیل سازگاری.
- دست‌کاری سایر inputها یا تغییر رفتار عمومی `ComponentSelectCustomSimple`، مگر آنکه مانع مستقیم و مستند این مهاجرت باشد.

## 10. گزارش اجرا

- ساختار component، props، schemas، methods، Step، examples و API عمومی پیاده‌سازی و در `ComponentManager` و دسته‌ی Inputs ثبت شد.
- گزینه‌های Legacy با `{id, name, code}` به ساختار selector جدید نگاشت شدند؛ شهرها با کشور انتخاب‌شده فیلتر می‌شوند.
- typecheck سراسری خطاهای ازپیش‌موجود در فایل‌های Legacy و بخش‌های نامرتبط گزارش می‌کند؛ خطایی از فایل‌های جدید Phone یا registration آن دیده نشد.
- `git diff --check` گذشت. `npm run build` به‌دلیل محدودیت اجرای فرایند esbuild در محیط (`spawn EPERM`) کامل نشد.
