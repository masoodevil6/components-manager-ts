# پلن 51.1.0 — ساخت `ComponentCardRowInfo` از `ComponentCardInfo` قدیمی

> **وضعیت:** اجراشده؛ تست هدفمند و بررسی نوع انجام شد  
> **دامنه:** انتقال رفتار Legacy به معماری فعلی Componentها  
> **منبع Legacy:** `last/Older/components.js`، کلاس `ComponentCardInfo` و Base آن  
> **راهنمای مبنا:** `documents/guides/component-create.md`  
> **دستهٔ ثبت پیشنهادی:** `UI.Contents` — Content Components، در کنار `ComponentCardViewInfo`  
> **API عمومی پیشنهادی:** `UiCategory.UI.Contents.CardRowInfo(config, methods, identity)`

## ۱. هدف و محدوده

کامپوننت Legacy با نام `ComponentCardInfo` به کامپوننت جدید `ComponentCardRowInfo` منتقل شود. خروجی، یک قاب اطلاعاتی با محتوای اصلی و یک `ComponentMenuMore` اختیاری برای گزینه‌های عملیاتی است. منو در گوشهٔ بالای کارت قرار می‌گیرد، در حالت عادی کم‌رنگ است و با hover کارت واضح می‌شود. ردیف HTML دست‌ساز و دکمه‌های مستقل Legacy در نسخهٔ جدید ساخته نمی‌شوند.

این کامپوننت از نظر کاربرد به `ComponentCardViewInfo` نزدیک است، اما جایگزین آن نیست: `CardViewInfo` کارت سادهٔ عنوان/محتواست؛ `CardRowInfo` علاوه بر محتوا، نوار گزینه‌های قابل‌کلیک و callback دارد.

این پلن فقط مهاجرت را مشخص می‌کند. فایل Legacy و رفتار مصرف‌کننده‌های فعلی در این مرحله تغییر نمی‌کنند؛ سازگاری مستقیم با `window.ComponentCardInfo` خارج از محدوده است. مهاجرت مصرف‌کننده‌های قدیمی می‌تواند مرحلهٔ جداگانه‌ای باشد.

## ۲. برداشت از پیاده‌سازی Legacy

`ComponentCardInfoBase` در حدود خطوط 3167 تا 3265 این props را تعریف می‌کند:

| Legacy prop | مقدار پیش‌فرض | نقش |
|---|---|---|
| `prop_size` | اندازهٔ `m` سیستم قدیمی | اندازه‌ای که به renderer گزینه‌ها داده می‌شود |
| `prop_borderClass` | `border rounded shadow-sm` | کلاس‌های قاب |
| `prop_borderStyles` | `{}` | styleهای قاب |
| `prop_body` | `null` | محتوای بدنه؛ پیاده‌سازی جدید از prop صریح استفاده می‌کند |
| `prop_options` | `null` | فهرست گزینه‌ها؛ در نسخهٔ جدید به آیتم‌های `ComponentMenuMore` تبدیل می‌شود |
| `prop_optionsOpacity` | `45` | opacity اولیهٔ نوار گزینه‌ها بر حسب درصد |
| `prop_backgroundOptions` | مقدار theme قدیمی | پس‌زمینهٔ نوار |
| `prop_backgroundOptionItem` | مقدار theme قدیمی | پس‌زمینهٔ هر گزینه |
| `prop_colorItem` | مقدار theme قدیمی | رنگ محتوای گزینه |
| `prop_backgroundOptionHover` | مقدار theme قدیمی | پس‌زمینهٔ گزینه هنگام hover |
| `prop_colorHover` | مقدار theme قدیمی | رنگ گزینه هنگام hover |

هر گزینه در Legacy شیئی با `attrs.title`, `attrs.name`, `attrs.id` و `html` است. `html` می‌تواند رشته باشد یا تابعی که `size` و `color` می‌گیرد. کلیک از `fn_callback(event, name, id)` عبور می‌کند؛ شناسهٔ رشته‌ای به‌صورت ضمنی با `parseInt` تبدیل می‌شود. این شکل داده type-safe نیست و شرط `typeof fn_callback != null` نیز وجود callback را درست بررسی نمی‌کند؛ API جدید باید قرارداد روشنی داشته باشد.

رندر قدیمی از `ComponentBorder` استفاده می‌کند، برای body فاصلهٔ بالایی را با `getHeightSize() + 10` و style درون‌خطی می‌سازد، نوار را با `position-absolute` و `right/left` وابسته به RTL قرار می‌دهد و روی بدنه `overflow: hidden` می‌گذارد. مقدار پیش‌فرض opacity در prop برابر 45 است، ولی renderer در نبود مقدار مقدار 20 را به کار می‌برد؛ پیاده‌سازی جدید باید یک مقدار واحد داشته باشد.

## ۳. قرارداد رفتاری پیشنهادی

- قاب با `ComponentBorder` ساخته شود و کلاس و style قاب از props دریافت شود.
- `prop_body` محتوای اصلی را نگه دارد؛ برای body، slot نام‌گذاری‌شده تعریف نمی‌شود. رشته، HTMLElement، reactive content و Component باید فقط از مسیرهای پشتیبانی‌شدهٔ framework رندر شوند؛ string به‌عنوان HTML خام تزریق نشود.
- گزینه‌ها با `ComponentMenuMore` رندر شوند و فقط وقتی `prop_options` غیرخالی است منو ساخته شود. از `prop_orientation: HORIZONTAL`، `prop_isFullWidth: false`، `prop_direction: AUTO` و `prop_menuBorder: false` استفاده شود؛ `prop_items` همان فهرست `MenuMoreEntry` باشد. منو در گوشهٔ بالای inline-end کارت جای بگیرد و از `float-start` یا مختصات ثابت چپ/راست استفاده نشود.
- `prop_optionsOpacity` در بازهٔ 0 تا 100 تعریف شود و مقدار پیش‌فرض واحد آن 45 بماند. opacity ریشهٔ منو از این مقدار به 1 با hover کارت تغییر کند؛ position و opacity با style واکنشی scoped روی `ComponentMenuMore` تنظیم شوند. رنگ منو و hover از props استاندارد خود `ComponentMenuMore` استفاده کنند.
- شکل دادهٔ گزینه‌ها با قرارداد `MenuMoreEntry`/`MenuMoreItem` هماهنگ باشد: `attrs.title` به `title`، `attrs.name` به `action` و `attrs.id` به `id` تبدیل شود. چون `MenuMoreItem.id` رشته‌ای است، شناسه در مرز مهاجرت با `String(id)` تبدیل شود و هیچ `parseInt` معکوسی انجام نشود. `html` خام یا renderer تابعی Legacy مستقیماً به منو منتقل نشود؛ محتوای گزینه با `title` و در صورت نیاز `icon` نمایش داده شود.
- برای منوی شناور، فضای لازم در بدنه فقط وقتی گزینه‌ای نمایش داده می‌شود رزرو شود. مقدار فاصله باید بر اساس `config.sizeName` و توابع `UtilStyle` محاسبه شود؛ ارتفاع پیکسلی و `+ 10px` ثابت وارد نشود.
- محتوای فرزند نباید به‌خاطر قاب یا body بریده شود؛ پیش‌فرض `overflow` باید اجازه دهد محتواهای شناور مانند menuهای فرزند بیرون از کارت دیده شوند.
- آیتم‌های منو عنوان/نام دسترس‌پذیر داشته باشند. رویداد `SELECT_ITEM` از `ComponentMenuMore` به Method استاندارد `SELECT_OPTION` نگاشت شود و item بدون تبدیل ناخواسته تحویل داده شود.
- هر child Component که در body رندر می‌شود با نام پایدار زیر workflow والد ثبت و در dispose جدا شود. منوی گزینه‌ها با نام پایدار `optionsMenu` ثبت شود.

## ۴. API پیشنهادی

### Props

| Prop | نوع و پیش‌فرض | نگاشت/کاربرد |
|---|---|---|
| `prop_borderClass` | `string[]` / `['border', 'rounded', 'shadow-sm']` | کلاس‌های قاب |
| `prop_borderStyles` | `Record<string, string>` / `{}` | styleهای قاب |
| `prop_body` | `CoreReactive.App`، `CoreObservable.App`، `Node`، `string`، Component یا `null` / `null` | محتوای قاب؛ در نبود مقدار بدنه خالی می‌ماند |
| `prop_options` | `MenuMoreEntry[]` / `[]` | ورودی‌های `ComponentMenuMore`؛ در نبود آیتم منو رندر نشود |
| `prop_optionsOpacity` | `number` / `45` | opacity عادی، محدودشده به بازهٔ 0 تا 100 |
| `prop_menuBackgroundColor` | `string` / مقدار پیش‌فرض `ComponentMenuMore` | به `ComponentMenuMore.prop_menuBackgroundColor` داده شود |
| `prop_itemBackgroundColorHover` | `string` / مقدار پیش‌فرض `ComponentMenuMore` | به `ComponentMenuMore.prop_itemBackgroundColorHover` داده شود |

همهٔ props با `Define_ComponentProp<T>` تعریف شوند و `PropsType` و `PropsConfigType` از `TypeHelpers` استخراج شوند. props قدیمی `prop_backgroundOptions` و `prop_backgroundOptionHover` به‌ترتیب به `prop_menuBackgroundColor` و `prop_itemBackgroundColorHover` نگاشت شوند. `prop_size` و props قدیمی `prop_backgroundOptionItem`، `prop_colorItem` و `prop_colorHover` به API جدید منتقل نشوند؛ ظاهر آیتم‌ها از palette استاندارد `ComponentMenuMore` پیروی کند. اگر برای کنترل style یا فاصله prop تازه‌ای لازم شد، تنها با نیاز روشن و مقدار پیش‌فرض خنثی اضافه شود؛ props پایهٔ `ComponentStructure` تکرار نشوند.

نوع آیتم از API عمومی `ComponentMenuMore` استفاده کند و type محلی موازی ساخته نشود:

```typescript
import type {MenuMoreEntry, MenuMoreItem} from "../componentMenuMore/Props";
```

آیتمی مثل `{id: "edit", title: "Edit", icon: UiIcons.Src.FilesEdit.Definition, action: "edit"}` مستقیماً به `ComponentMenuMore` داده شود. `MenuMoreItem` handler داخلی مستقلی از CardRowInfo دریافت نکند؛ کلیک از Method کامپوننت والد عبور کند. HTML خام یا callback renderer قدیمی `html(size, color)` پشتیبانی نشود.

### Method و workflow

- Method عمومی `SELECT_OPTION` با آرگومان `{ITEM: MenuMoreItem}` تعریف شود و `ComponentMenuMore` از طریق `SELECT_ITEM` به آن متصل شود.
- `ITEM.id` و `ITEM.action` بدون تبدیل یا دست‌کاری به فراخواننده برسند؛ `MenuMoreItem.id` رشته‌ای است.
- Step از factory مستقل instance ساخته شود و endpoint کلیک گزینه را ثبت کند.
- `ComponentBorder` و خود `ComponentMenuMore` به‌ترتیب با کلیدهای `border` و `optionsMenu` زیر workflow والد ثبت شوند. Component قرارگرفته در `prop_body` به‌عنوان فرزند خود Border در workflow ثبت می‌شود؛ حذف منو یا render مجدد باید workflow قبلی را detach و dispose کند. آیتم‌های داخلی MenuMore child کامپوننت CardRowInfo محسوب نمی‌شوند.

## ۵. ساختار رندر

```text
COMPONENT / STRUCTURE            از ComponentStructureTrait
└── CARD: part-card-row-info
    ├── BORDER                   ComponentBorder child
    │   └── CONTENT              prop_body
    ├── ComponentMenuMore        فقط با گزینه
    └── workflow children        border و optionsMenu در صورت وجود
```

- `Schemas.ts` فقط part، props و metadata ترجمه را ثبت کند؛ ساخت DOM و handler در آن قرار نگیرد.
- `COMPONENT` و `STRUCTURE` از `ComponentStructureTrait.schemas` بیایند و در `renderManagerComponent` به Trait واگذار شوند.
- قاب از `ComponentBorder` و نوار گزینه‌ها از API عمومی `ComponentMenuMore` ساخته شود؛ دکمهٔ دست‌ساز برای هر option نسازیم. دستکاری مستقیم DOM داخلی یا query selector سراسری ممنوع باشد.
- جای‌گذاری و opacity منو از طریق styleهای ریشهٔ `ComponentMenuMore` و Observableهای scoped تنظیم شوند؛ styleهای لازم با `UtilStyle` و تنظیمات سیستم محاسبه شوند. هیچ `<style>` داینامیک متکی به id تصادفی یا listener مستقیم خارج از lifecycle اضافه نشود.
- وقتی `prop_options` تغییر می‌کند، `prop_items` منو با مقدار جاری هماهنگ شود؛ خالی‌شدن فهرست باید منو را حذف و workflow child با نام `optionsMenu` را پاک کند.

## ۷. مثال‌های لازم

1. **Default:** قاب پیش‌فرض با محتوای ساده و بدون نوار گزینه‌ها.
2. **With options:** چند `MenuMoreItem` دارای icon/title/id، نمایش opacity عادی و hover، و دریافت item انتخاب‌شده با `SELECT_OPTION`.
3. **Custom content:** body شامل یک Component واقعی برای نمایش اتصال workflow فرزند و امکان قرارگیری محتوای شناور.

هر Example مطابق راهنما `ComponentExample` با `render(): HTMLElement` باشد و از Category عمومی یا instance Component استفاده کند؛ مثال‌ها نباید کلاس Legacy را فراخوانی کنند.

## ۸. اعتبارسنجی و آزمون‌های پذیرش

- تست رندر پیش‌فرض قاب، body و عدم رندر نوار خالی.
- تست منو: `ComponentMenuMore` با جهت افقی، عرض محتوایی و آیتم‌های داده‌شده رندر شود؛ آیتم انتخاب‌شده با `id` و `action` اصلی از `SELECT_OPTION` دریافت شود.
- تست hover کارت: opacity منو از مقدار اولیه به حالت کامل تغییر کند و رنگ‌های منو و hover از props استاندارد `ComponentMenuMore` بیایند.
- تست RTL/LTR: نوار در سمت inline-end قرار بگیرد و ترتیب آیتم‌ها قابل‌پیش‌بینی باشد.
- تست تغییر واکنشی props شامل body، options و opacity پس از رندر؛ خالی‌کردن options منو را حذف کند.
- تست محتوای string/HTMLElement/Reactive/Component طبق قرارداد content؛ متن escape شود و Component child در workflow زیرمجموعهٔ Border ثبت شود.
- تست حذف منو و `dispose()` برای اطمینان از پاک‌شدن child، listener و Step مرتبط.
- اجرای type-check، تست‌های هدفمند کامپوننت، تست workflow composition و build طبق وضعیت پروژه.

## ۹. معیار پایان

پلن زمانی کامل است که `ComponentCardRowInfo` از طریق `UI.Contents.CardRowInfo` در دسترس باشد، قاب را با `ComponentBorder` و گزینه‌ها را با `ComponentMenuMore` بسازد، item انتخاب‌شده را از Method type-safe ارسال کند، children واقعی را در workflow والد ثبت و در dispose پاک‌سازی کند، و مثال‌ها و ترجمه‌های فارسی/انگلیسی داشته باشد. رفتار مهم Legacy حفظ شود، اما HTML خام، ردیف دکمه‌های دست‌ساز، callback پراکنده، padding پیکسلی، parse عددی ناخواسته و دسترسی مستقیم به DOM به قرارداد جدید منتقل نشوند.

## ۱۰. خارج از محدوده

- حذف یا بازنویسی `ComponentCardInfo` در `last/Older/components.js`.
- تغییر خودکار همهٔ مصرف‌کننده‌های Legacy یا فراهم‌کردن alias عمومی `ComponentCardInfo`.
- بازطراحی `ComponentCardViewInfo` یا یکپارچه‌سازی اجباری دو کامپوننت.
- پشتیبانی از renderer تابعی arbitrary برای هر option؛ محتوای ویژه باید به icon یا Component صریح تبدیل شود.
