# پلن 32.1.0 — انتقال BreadcrumbShadow به ساختار جدید

> **وضعیت:** پیاده‌سازی شد؛ اجرای build به‌دلیل محدودیت spawn محیط تأیید نشده است  
> **نسخهٔ پلن:** 32.1.0  
> **منبع Legacy:** `last/Older/components.js`، کلاس `ComponentPageHeaderBase` و `ComponentPageHeader`، به‌ویژه بخش‌های `part_form_title`, `part_form_title_nav`, `part_form_title_txt` در حدود خطوط 28300 تا 28740  
> **نمونهٔ خروجی ارائه‌شده:** header با عنوان «Page Title Sample» و دو آیتم nav با نام‌های `b` و `a`  
> **راهنما:** `documents/guides/component-create.md`  
> **مقصد پیشنهادی:** `src/framework/module_ui/module_components/lists/componentBreadcrumbShadow/`  
> **دسته‌بندی UI:** گروه موجود `UiCategory.UI.Breadcrumb`  
> **API پیشنهادی:** `UiCategory.UI.Breadcrumb.BreadcrumbShadow(config, methods, identity)`

## 1. هدف و محدوده

بخش عنوان و navigation نواری `ComponentPageHeader` قدیمی به یک کامپوننت مستقل با نام **BreadcrumbShadow** منتقل شود. ظاهر اصلی شامل عنوان صفحه، یک نوار آیتم‌های ناوبری با دو لایهٔ مثلثی در لبهٔ هر آیتم، رنگ متن/زمینهٔ قابل تنظیم و پنهان‌شدن navigation در نمایشگر باریک است.

این پلن فقط بخش عنوان صفحه را منتقل می‌کند؛ بخش‌های برگشت (`part_form_back`), گزینه‌ها (`part_form_options`) و آیکون‌های header جزو `ComponentPageHeader` قدیمی هستند و در این کامپوننت جدید ساخته نمی‌شوند. BreadcrumbShadow با `ComponentBreadcrumb` و `ComponentBreadcrumbWithArrow` هم‌زمان قابل استفاده خواهد بود و در گروه موجود `Breadcrumb` ثبت می‌شود.

رندر جدید باید با Schema و `CoreReactive` انجام شود. برای فلش‌های CSS از API عمومی `UtilShape.Css.Triangle(...)` که در پلن 30.1.0 اضافه شده استفاده شود؛ تولید CSS مختص هر آیتم باید scoped و بر اساس اندازه، رنگ و جهت سیستم باشد. از HTML رشته‌ای، `innerHTML`، handler رشته‌ای و شناسه‌های DOM سراسری استفاده نشود.

## 2. شواهد و رفتار Legacy

- کلاس اصلی در `last/Older/components.js` با نام `ComponentPageHeader` تعریف شده است. ورودی‌های بخش هدف عبارت‌اند از `prop_pageTitle`, `prop_pageNav`, `prop_colorNav`, `prop_backgroundColorNav`, `prop_colorHeader`, `prop_size` و `prop_hasIconBack`.
- بخش عنوان والد `part_form_title` عرض `60%` دارد. Legacy برای آن float را براساس `directionRtl` تعیین می‌کند و در صورت `prop_hasIconBack` یک جداکنندهٔ یک‌پیکسلی سفید در سمت داخلی عنوان می‌گذارد. این prop در کامپوننت مستقل فقط برای حفظ جداکنندهٔ اختیاری عنوان نگه داشته شود؛ خود دکمهٔ برگشت منتقل نمی‌شود.
- `part_form_title_nav` در عرض حداکثر `768px` مخفی است. آیتم‌ها ارتفاع و line-height برابر اندازهٔ محاسبه‌شده از `prop_size`، اندازهٔ فونت متناسب با همان size، cursor قابل کلیک و دو لایهٔ مثلثی دارند: لایهٔ بیرونی با رنگ متن و لایهٔ داخلی با رنگ زمینه.
- آیتم nav قدیمی اطلاعات را از `prop_pageNav` می‌گیرد و callback را با `event` و `attrs.name` به `fn_onclickItemNav` می‌فرستد. در نمونهٔ ارائه‌شده، شناسه‌ها `b` و `a` هستند. API جدید باید شناسه را به شکل صریح `name` در هر item تعریف کند.
- Renderer قدیمی محتوای آیتم را از فیلد `html` به‌صورت HTML خام قرار می‌دهد؛ در نمونه‌های مصرف‌کنندهٔ موجود نیز `prop_pageNav` گاهی فقط `title` دارد، در حالی که renderer انتظار `html` دارد. API جدید این ابهام را برطرف کند: عنوان متنی با `title` نمایش داده شود و از پذیرش/تزریق HTML خام خودداری شود.
- حلقهٔ Legacy از `length` تا صفر حرکت می‌کند و ترتیب خروجی را معکوس می‌کند؛ مقدار مرزی صفر نیز یک عضو نامعتبر را بررسی می‌کند. ترتیب API جدید باید روشن و پایدار باشد: ترتیب ورودی نمایش داده شود، مگر آنکه مصرف‌کننده صریحاً آرایه را برعکس ارسال کند.
- `part_form_title_txt` عنوان را در همان نوار نمایش می‌دهد، ارتفاع و line-height را از `prop_size` می‌گیرد، و در حضور nav به اندازهٔ `elHeight + 10px` از سمت داخلی فاصله می‌گیرد. سمت float و margin باید از `CoreConfig.Settings.DirectionRtl` پیروی کنند.
- snippet پیوست‌شده یک خروجی LTR-ثابت با `float:right`, `border-right`, `margin-right`, و فلش‌های سمت چپ نشان می‌دهد؛ منبع کامل Legacy این مقادیر را با `directionRtl` آینه می‌کند. در انتقال، تنظیم جهت سیستم مرجع باشد تا هر دو RTL و LTR پشتیبانی شوند.
- `prop_size` در Legacy پیش‌فرض `tools_css.standardSizes.xl.name` دارد. در ساختار جدید همچنان از `CoreConfig.Settings.SizeName` و `UtilStyle` استفاده شود؛ اندازهٔ سیستم مبنای ابعاد باشد و نیازی به مقادیر ثابت `30px`, `14px`, `45px` در CSS جدید نباشد.

## 5. Props و Methods

Props با `Define_ComponentProp<T>` و typeهای استخراج‌شدهٔ `ExtractPropsType` و `ExtractPropsConfigType` تعریف شوند. ترجمهٔ metadata از `Keys` بیاید.

| Prop | نوع | پیش‌فرض پیشنهادی | کاربرد |
|---|---|---|---|
| `prop_pageTitle` | `string` | `""` | عنوان اصلی صفحه؛ به‌صورت متن نمایش داده شود. |
| `prop_pageNav` | `BreadcrumbShadowItem[]` | `[]` | آیتم‌های navigation به ترتیب نمایش؛ هر عضو `{name, title}` دارد. |
| `prop_colorNav` | `string` | رنگ تیرهٔ متن از توکن‌های سیستم | رنگ متن آیتم‌های navigation و لایهٔ بیرونی مثلث. |
| `prop_backgroundColorNav` | `string` | رنگ روشن/سطح از توکن‌های سیستم | زمینهٔ آیتم و لایهٔ داخلی مثلث. |
| `prop_colorHeader` | `string` | رنگ متن header از توکن‌های سیستم | رنگ عنوان صفحه. |
| `prop_size` | `UtilConst.SizeName` یا type استاندارد اندازهٔ پروژه | `CoreConfig.Settings.SizeName` | اندازهٔ ارتفاع، padding و فونت؛ وجود prop فقط برای سازگاری/override باشد. |
| `prop_hasDivider` | `boolean` | `false` | نمایش جداکنندهٔ سمت داخلی بخش عنوان؛ جایگزین معنایی `prop_hasIconBack` قدیمی، بدون رندر دکمهٔ back. |
| `prop_widthTitle` | `string` | `"60%"` | سهم عنوان از عرض header؛ مقدار Legacy. |
| `prop_hideNavigationBelow` | `number` | `768` | breakpoint مخفی‌شدن نوار nav؛ مقدار Legacy. |

**تصمیم سازگاری:** چون این کامپوننت جدید و مستقل است، نام‌های `prop_pageTitle` و `prop_pageNav` برای هم‌راستایی با Legacy حفظ شوند؛ `prop_hasIconBack` به نام هدف‌محور `prop_hasDivider` تغییر کند تا وابستگی ساختگی به دکمهٔ منتقل‌نشده ایجاد نشود. ابعاد padding مثل `45px` و `10px` از `UtilStyle`/`sizeName` ساخته شوند و prop اضافی برای این اعداد اضافه نشود.

ساختار item:

```ts
export type BreadcrumbShadowItem = {
    name: string;
    title: string;
};
```

`Methods.ts` متد زیر را ارائه کند:

- `SELECT_ITEM`: ورودی شامل `event`, `name` و `item` اصلی باشد؛ به callback ثبت‌شده در `MethodsConfigType` تحویل داده شود. هیچ item جدید ناقصی ساخته نشود.

## 6. Schemas و رندر

- `COMPONENT` و `STRUCTURE` از `ComponentStructureTrait` دریافت شوند.
- `part-breadcrumb-shadow` نوار اصلی و زمینهٔ آن را رندر کند. ارتفاع/line-height بر اساس `prop_size` و توکن‌های Util باشد.
- `part-breadcrumb-shadow-title` والد عنوان و nav را در یک ردیف نگه دارد؛ سهم پیش‌فرض title برابر 60% باشد و separator اختیاری فقط با `prop_hasDivider` رندر شود.
- `part-breadcrumb-shadow-title-text` عنوان را با `<b>` یا عنصر متنی مناسب نمایش دهد؛ سمت float و فاصله‌گذاری بر اساس direction باشد. اگر عنوان خالی است، ساختار بدون متن اضافی حفظ شود.
- `part-breadcrumb-shadow-navigation` فقط وقتی آرایه nav خالی نیست رندر شود و در عرض برابر/کمتر از breakpoint مخفی شود.
- `part-breadcrumb-shadow-navigation-item` هر آیتم را با زمینه، رنگ متن، ابعاد، cursor و دو لایه مثلث بسازد. pseudo-element `before` و `after` از `UtilShape.Css.Triangle` بیایند؛ اولی رنگ مرزی/متن و دومی رنگ زمینه دارد تا لایهٔ زیرین به شکل shadow/rim دیده شود.
- مثلث‌ها در LTR در سمت راست آیتم و در RTL در سمت چپ قرار بگیرند؛ جهت نوک و borderهای شفاف با `DirectionRtl` آینه شود. اندازهٔ عمودی مثلث نصف ارتفاع آیتم و عمق آن متناسب با همان ارتفاع باشد.
- عنوان هر nav item به‌صورت متن امن نمایش داده شود؛ `item.name` برای callback استفاده شود و در صورت خالی بودن name، آیتم قابل انتخاب نباشد یا از شناسهٔ پایدار index-based همان instance استفاده کند؛ رفتار نهایی در implementation با استاندارد identity پروژه هماهنگ شود.
- ترتیب آیتم‌ها همان ترتیب آرایهٔ ورودی باشد؛ بر خلاف حلقهٔ Legacy از `length` تا صفر استفاده نشود.
- محاسبهٔ اندازه و رنگ reactive باشد تا تغییر prop یا تغییر `CoreConfig.Settings.SizeName`/`DirectionRtl` نمای ظاهری را به‌روز کند.

| `part_form_title_nav` و `prop_pageNav` | `part-breadcrumb-shadow-navigation` | آرایهٔ itemهای typed با `name` و `title`; نمایش HTML خام حذف شود. |
| `part_form_title_txt` و `prop_pageTitle` | `part-breadcrumb-shadow-title-text` | متن امن، با اندازه و رنگ سیستم. |
| `prop_colorNav` | `Props.prop_colorNav` | رنگ متن و لایهٔ بیرونی triangle. |
| `prop_backgroundColorNav` | `Props.prop_backgroundColorNav` | رنگ زمینه و لایهٔ داخلی triangle. |
| `prop_colorHeader` | `Props.prop_colorHeader` | رنگ عنوان اصلی. |
| `prop_size` و `tools_css.getHeightSize/getFontSize` | `CoreConfig.Settings.SizeName` و `UtilStyle` | اندازه‌های سیستم به جای محاسبهٔ inline و hard-code. |
| `prop_hasIconBack` border conditional | `prop_hasDivider` | جداسازی عنوان حفظ شود؛ دکمهٔ back منتقل نشود. |
| `float`های وابسته به RTL | styles محاسبه‌شده بر اساس `DirectionRtl` | از float خام تا حد ممکن با flex و ترتیب منطقی جایگزین شود، بدون تغییر آرایش نهایی. |
| `:before` و `:after` با border CSS | `UtilShape.Css.Triangle` | تابع شکل عمومی موجود استفاده شود؛ محاسبهٔ CSS مثلث در Component تکرار نشود. |
| `fn_onclickItemNav(event, navName)` | `Methods.SELECT_ITEM` | callback typed شامل event، name و item اصلی. |
| درج `itemNav.html` | text rendering | HTML خام پذیرفته/اجرا نشود؛ API جدید `title` را نمایش دهد. |
| media query ثابت 768px | breakpoint `prop_hideNavigationBelow` با پیش‌فرض 768 | رفتار فعلی قابل تنظیم و تست‌پذیر شود. |

## 8. مثال‌ها و ثبت UI

- `Default`: عنوان نمونه بدون nav؛ separator خاموش.
- `Navigation`: عنوان به‌همراه حداقل دو آیتم nav با `name` و `title` و callback که نام انتخاب‌شده را ثبت/نمایش می‌دهد.
- در تست صفحهٔ component، اندازهٔ عریض و باریک و هر دو جهت RTL/LTR قابل مشاهده باشد؛ جهت از config سیستم خوانده شود و مثال برای نتیجهٔ پایدار صرفاً mock/fixture مشخص داشته باشد.
- نمونهٔ مصرف‌کنندهٔ قدیمی `ComponentPageHeader` در `last/Older/components.js` فقط برای تطبیق بررسی شود؛ اصلاح یا مهاجرت آن در این پلن نیست.

## 9. معیارهای پذیرش

1. کامپوننت مستقل `BreadcrumbShadow` در ComponentManager ثبت و از `UiCategory.UI.Breadcrumb.BreadcrumbShadow(...)` قابل ساخت باشد.
2. عنوان، nav خالی، یک آیتم و چند آیتم بدون خطا و بدون `[object Object]` رندر شوند.
3. در عرض `768px` و کمتر navigation پنهان و در عرض بیشتر قابل مشاهده باشد.
4. هر آیتم nav دو لایهٔ مثلثی داشته باشد؛ رنگ، اندازه و سمت آن در RTL/LTR درست آینه شود.
5. کلیک، Enter و Space روی هر nav item دقیقاً یک بار `SELECT_ITEM` را با `name` و شیء کامل item اجرا کند.
6. title و nav فقط متن امن رندر کنند؛ رشتهٔ HTML به‌عنوان markup تفسیر نشود.
7. تغییر `prop_size`, رنگ‌ها، `DirectionRtl` و separator، رندر را بدون ساختن instance جدید به‌روز کند.
8. metadata ترجمه‌شده، Definition، schemas، methods، examples و barrelها مطابق راهنمای component-create ثبت شوند.
9. `npm run build:app`, typecheck مرتبط و `git diff --check` اجرا شوند؛ خطاهای نامرتبط موجود جداگانه گزارش شوند.

## 10. خارج از محدوده

- انتقال کامل `ComponentPageHeader`، دکمهٔ بازگشت، آیکون‌ها، option list و رفتارهای صفحه.
- تغییر یا اصلاح مصرف‌کننده‌های قدیمی در `last/Older` و ابزارهای Excel/Print.
- سازگاری runtime با HTML خام `itemNav.html` یا handlerهای رشته‌ای.
- ادغام این کامپوننت با `ComponentBreadcrumb` یا `ComponentBreadcrumbWithArrow`.
- تغییر global direction، breakpoint عمومی یا API ماژول Util.Shape.

## 11. نتیجهٔ پیاده‌سازی

- Component مستقل، Definition، Props، Schemas، Methods، Step، Base و کلاس runtime در مسیر پیشنهادی ایجاد شدند.
- دو مثال Title only و Title with navigation ثبت شدند. ComponentManager و callable عمومی `UiCategory.UI.Breadcrumb.BreadcrumbShadow` و گروه UI موجود Breadcrumb به‌روزرسانی شدند.
- ترجمه‌های فارسی و انگلیسی برای component، props، schemaها، method و مثال‌ها اضافه شدند.
- آیتم‌های ناوبری از نوع `{name, title}` هستند؛ مثلث‌های دولایه با `UtilShape.Css.Triangle` تولید می‌شوند؛ جهت از config سیستم می‌آید.
- TypeScript با فیلتر روی فایل‌های جدید خطایی گزارش نکرد. اجرای `npm run build:app` پیش از بارگذاری config با `spawn EPERM` متوقف شد. اجرای typecheck کامل مخزن همچنان خطاهای متعدد و نامرتبط در فایل‌های قدیمی و بخش‌های دیگر دارد؛ برای این Component خطایی از خروجی فیلترشده به دست نیامد.
- `git diff --check` برای تغییرات بررسی‌شده خطای whitespace نداشت.
