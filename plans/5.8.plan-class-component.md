# Plan — Refactor ComponentStructure Runtime Architecture

## 1. هدف

هدف این فاز، تثبیت معماری `ComponentStructure` به‌عنوان **Base Runtime مشترک تمام UI Componentها** است.

معماری نهایی باید این اصل را رعایت کند:

> **Schema فقط ساختار و Metadata را تعریف می‌کند؛ Component مسئول Runtime، Behavior، State و Rendering است.**

در این فاز:

* `SchemaHandlers` حذف می‌شود.
* Rendering مربوط به Schemaها به `ComponentStructure` منتقل می‌شود.
* `ComponentStructure` به یک Base Class واقعی برای Componentهای آینده تبدیل می‌شود.
* `Definition` حفظ می‌شود و بخشی از Metadata قابل استفاده توسط Component Manager خواهد بود.
* سیستم Example به‌صورت Metadata-driven طراحی می‌شود.
* State، Lifecycle و Identity پیشرفته فعلاً پیاده‌سازی نمی‌شوند و برای Phaseهای بعدی Core باقی می‌مانند.

# 9. Rendering پایه ComponentStructure

Rendering مربوط به دو Schema پایه باید وارد خود `ComponentStructure` شود.

## 9.1 COMPONENT

وظیفه:

```text
<component-{name}>
    ↓
classList
styles
RTL
    ↓
STRUCTURE
```

نمونه:

```ts
protected renderComponentSchema(
    context: UiComponents.Basic.Types.ComponentSchemaContext
): CoreReactive.App {

    const rtl =
        CoreConfigs.Settings.DirectionRtl.observable();

    const classList =
        context.data?.classList ??
        new CoreObservable.App([]);

    const styles =
        context.data?.styles ??
        new CoreObservable.App({});

    return CoreReactive.App.component(
        this._COMPONENT_NAME,
        {
            attrs: {
                ...context.attrsDefault
            },

            classBind: [
                classList
            ],

            stylesBind: {
                direction: rtl.mapBoolean("rtl", "ltr"),
                styles
            },

            children: [
                this.executeSchemaPart(
                    Schemas.STRUCTURE.part
                )
            ]
        }
    );
}
```

```ts
protected renderStructureSchema(
    context: UiComponents.Basic.Types.ComponentSchemaContext
): CoreReactive.App {

    const prop_show =
        context.data?.prop_show ??
        new CoreObservable.App(true);

    const prop_structureClass =
        context.data?.prop_structureClass ??
        new CoreObservable.App([]);

    const prop_structureStyles =
        context.data?.prop_structureStyles ??
        new CoreObservable.App({});

    return CoreReactive.App.part(
        "section",
        {

            classBind: [
                prop_structureClass,
                prop_show.mapBoolean(
                    "show",
                    "d-none"
                )
            ],

            attrs: {
                ...context.attrsDefault
            },

            stylesBind: {
                prop_structureStyles
            },

            children: [
                this.renderContentComponent()
            ]

        }
    );
}
```

# 11. Mapping Schema → Runtime

چون Handler حذف شده، `ComponentStructure` باید بتواند Schema پایه را به Runtime behavior متصل کند.

این mapping باید در Runtime انجام شود.

مثلاً:

```ts
protected renderSchemaPart(
    schemaKey: string,
    context: ComponentSchemaContext
): CoreReactive.App {

    switch (schemaKey) {

        case "COMPONENT":
            return this.renderComponentSchema(context);

        case "STRUCTURE":
            return this.renderStructureSchema(context);

        default:
            return this.renderCustomSchemaPart(
                schemaKey,
                context
            );
    }
}
```

نام و API دقیق این متد باید با API واقعی `CoreComponents.App` هماهنگ شود.

هدف معماری مهم‌تر از نام متد است:

```text
Schema Key
    ↓
Component Runtime
    ↓
Rendering Method
```

# 32. اصل معماری نهایی

اصل اصلی این معماری:

```text
Schema
    =
"What exists?"

Component
    =
"How does it behave?"

Definition
    =
"What is this component?"

Example
    =
"How can this component be instantiated/presented?"

Component Manager
    =
"How can I inspect and manipulate this component?"
```

بنابراین:

```text
                    ComponentDefinition
                           │
                           ▼
                     Component Manager
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
        Props           Schemas          Examples
          │                │                │
          └────────────────┼────────────────┘
                           ▼
                   ComponentStructure
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
            State       Methods      Rendering
                           │
                           ▼
                    Component Instance
```

این ساختار اجازه می‌دهد ComponentStructure هم **Base Runtime واقعی** باقی بماند و هم در آینده تبدیل به وابستگی مستقیم Component Manager نشود. Metadata برای Manager قابل خواندن است، Runtime برای خود Component باقی می‌ماند، و Schema هم مجبور نیست نقش نصف Framework را بازی کند.
