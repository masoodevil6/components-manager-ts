# Plan 8.2.3 — Fix executeMethod و CoreEvent Conflict با Message ID

> **پیش‌نیاز:** Plan 8.2.2 (Step Node per Part)
> **هدف:** اصلاح رفتار کلیک آیکون بستن — هر پیام یک ID یکتا داشته باشد

## مشکل

وقتی روی آیکون بستن کلیک می‌شود، **هر دو** مکانیزم اجرا می‌شوند:

1. `CoreEvent.App.request` — به `message.emit` ارسال می‌شود → پیام از `prop_messages` حذف می‌کند (reactive)
2. `this.executeMethod("CLOSE_MESSAGE")` — callback مصرف‌کننده را صدا می‌زند

**مشکل:** `emit` اول اجرا می‌شود و پیام را حذف می‌کند. سپس `executeMethod` با `index` قدیمی (از closure) اجرا می‌شود — ولی لیست تغییر کرده و `index` قدیمی دیگر معتبر نیست.

### ریشه مشکل

۱. **دو مکانیزم همزمان** — هم `emit` (CoreEvent) و هم `executeMethod` (Methods API) اجرا می‌شوند.

۲. **Closure stale** — `extra` در زمان render اولیه capture می‌شود. بعد از re-render (به‌خاطر حذف پیام)، closure قدیمی هنوز `index` قدیمی دارد.

۳. **ترتیب اجرا** — `emit` اول پیام را حذف می‌کند، سپس `executeMethod` با `index` قدیمی اجرا می‌شود.

۴. **index و text هر دو غیرقابل اعتماد** — `index` بعد از re-render تغییر می‌کند، `text` ممکن است تکراری باشد.

## راه‌حل — Message ID یکتا

### مفهوم

هر پیام در زمان render یک **ID یکتا** (random) دریافت می‌کند. این ID در closure capture می‌شود و در کلیک آیکون استفاده می‌شود — هم در `executeMethod` و هم در `CoreEvent.request`.

**مزایا:**
- ID بعد از re-render تغییر نمی‌کند (چون در closure capture شده)
- ID یکتا است (برخلاف `text` که ممکن است تکراری باشد)
- ID مستقل از position در لیست است (برخلاف `index`)

### ساختار Message

```typescript
interface MessageItem {
    id:      string;   // ← یکتا — random
    text:    string;   // ← محتوای پیام
}
```

### تغییر prop_messages

```typescript
// قبل
prop_messages: string[]

// بعد
prop_messages: string[]  // ← مصرف‌کننده همچنان string[] پاس می‌دهد
```

**نکته:** مصرف‌کننده همچنان `string[]` پاس می‌دهد — Component داخلی هر `string` را به `MessageItem` (با id random) تبدیل می‌کند. این حفظ API عمومی است.

### تولید ID در render

```typescript
// در renderMessages — داخل CoreObservable.App.for
(item: string, index: number, context) => {
    const messageId = Math.random().toString(36).slice(2, 11);  // ← یکتا

    return CoreReactive.App.section({
        // ...
        children: [
            CoreReactive.App.b({ children: [item] }),
            this.renderManagerComponent(
                Schemas.ICON.part,
                attrsDefault,
                data,
                { id: messageId, index, messageText: item },  // ← id در extra
            ),
        ],
    });
}
```

### تغییر در CLICK handler

```typescript
CLICK: (event: Event) => {
    event.preventDefault();

    // ۱. اول: executeMethod با id صحیح
    this.executeMethod("CLOSE_MESSAGE", event, {
        MESSAGE_ID:    extra?.id,
        MESSAGE_INDEX: extra?.index,
        MESSAGE_TEXT:  extra?.messageText,
        MESSAGE_TYPE:  prop_type.get(),
    });

    // ۲. بعد: CoreEvent با id برای حذف
    if (this._COMPONENT_STEP) {
        CoreEvent.App.request(
            CoreEvent.requestMap([
                [this._COMPONENT_STEP.message, {
                    action:  "close",
                    id:      extra?.id,      // ← حذف بر اساس id
                    index:   extra?.index,
                    text:    extra?.messageText,
                    type:    prop_type.get(),
                }],
            ]),
            this._COMPONENT_STEP.icon.close,
        );
    }
},
```

### تغییر در emit handler — حذف بر اساس id

```typescript
emit: (request) => {
    const payload = request.payload;

    if (payload?.action === "close") {
        const messageId = payload.id;

        // حذف پیام بر اساس id (نه index، نه text)
        const currentMessages = this.get("prop_messages") as string[];
        if (Array.isArray(currentMessages) && messageId != null) {
            // مشکل: prop_messages همچنان string[] است — id در آن نیست
            // راه‌حل: نگهداری map از id → index در زمان render
        }

        return { value: { closed: true, id: messageId } };
    }

    return { value: null };
},
```

### مشکل: prop_messages همچنان string[] است

`emit` handler به `prop_messages` دسترسی دارد که `string[]` است — `id` در آن نیست. پس چگونه پیام را بر اساس `id` حذف کنیم؟

**راه‌حل:** یک **map داخلی** از `id → index` در Component نگه داریم که در زمان render پر می‌شود.

```typescript
// در ComponentMessages
private _messageIdMap: Map<string, number> = new Map();

// در renderMessages — داخل for
(item: string, index: number, context) => {
    const messageId = Math.random().toString(36).slice(2, 11);
    this._messageIdMap.set(messageId, index);  // ← ثبت id → index

    // ...
}

// در emit handler
emit: (request) => {
    if (payload?.action === "close") {
        const messageId = payload.id;
        const messageIndex = this._messageIdMap.get(messageId);

        if (messageIndex != null) {
            const currentMessages = this.get("prop_messages") as string[];
            const newMessages = currentMessages.filter((_, i) => i !== messageIndex);
            this.set("prop_messages", newMessages);
            this._messageIdMap.delete(messageId);
        }

        return { value: { closed: true, id: messageId } };
    }
    return { value: null };
},
```

**هشدار:** بعد از re-render، `_messageIdMap` باید دوباره پر شود. ولی چون `for` دوباره اجرا می‌شود، map با indexهای جدید پر می‌شود. ولی closure قدیمی هنوز `id` قدیمی دارد — و `_messageIdMap` ممکن است `id` قدیمی را نداشته باشد (چون re-render شده).

**راه‌حل بهتر:** به‌جای map، `id` را به `text` تبدیل کنیم — یعنی هر `id` به یک `text` خاص اشاره کند. ولی این همان مشکل `text` تکراری است.

**راه‌حل نهایی:** `prop_messages` را به `MessageItem[]` تغییر دهیم — ولی این API عمومی را تغییر می‌دهد.

## تصمیم نهایی — prop_messages به MessageItem[]

### تغییر API عمومی

```typescript
// قبل
prop_messages: string[]

// بعد
prop_messages: MessageItem[]    // ← { id, text }
```

مصرف‌کننده می‌تواند:
```typescript
// راه ۱ — پاس دادن MessageItem[]
UiCategory.UI.Simples.Messages({
    prop_messages: [
        { id: "msg-1", text: "Operation completed" },
        { id: "msg-2", text: "Data saved" },
    ],
});

// راه ۲ — پاس دادن string[] (تبدیل خودکار)
UiCategory.UI.Simples.Messages({
    prop_messages: ["Operation completed", "Data saved"],
});
```

**نکته:** برای حفظ API، `prop_messages` هر دو `string[]` و `MessageItem[]` را قبول کند. Component داخلی `string[]` را به `MessageItem[]` (با id random) تبدیل می‌کند.

### پیاده‌سازی

#### Props.ts

```typescript
export interface MessageItem {
    id:   string;
    text: string;
}

// prop_messages — هر دو string[] و MessageItem[] را قبول می‌کند
prop_messages: {
    name:  "prop_messages",
    value: [] as (string | MessageItem)[],
},
```

#### ComponentMessages.ts — renderMessages

```typescript
protected renderMessages(...) {
    const prop_messages = data?.["prop_messages"] ?? this._COMPONENT_PROPS_BIND.prop_messages;

    // نرمال‌سازی: string → MessageItem (با id random)
    const normalizedMessages = prop_messages.map((msg: string | MessageItem) => {
        if (typeof msg === "string") {
            return { id: Math.random().toString(36).slice(2, 11), text: msg };
        }
        return msg;
    });

    // ... استفاده از normalizedMessages در for
}
```

#### emit handler — حذف بر اساس id

```typescript
emit: (request) => {
    if (payload?.action === "close") {
        const messageId = payload.id;

        const currentMessages = this.get("prop_messages") as (string | MessageItem)[];
        if (Array.isArray(currentMessages) && messageId != null) {
            const newMessages = currentMessages.filter(msg => {
                if (typeof msg === "string") return true;  // stringها id ندارند — حذف نمی‌شوند
                return msg.id !== messageId;
            });
            this.set("prop_messages", newMessages);
        }

        return { value: { closed: true, id: messageId } };
    }
    return { value: null };
},
```

## نکات مهم

### چرا id به‌جای index یا text؟

- **index** — بعد از re-render تغییر می‌کند (closure stale)
- **text** — ممکن است تکرانی باشد
- **id** — یکتا، تغییرناپذیر، مستقل از position

### چرا string[] همچنان کار می‌کند؟

برای حفظ API عمومی، `prop_messages` هر دو `string[]` و `MessageItem[]` را قبول می‌کند. Component داخلی `string` را به `MessageItem` (با id random) تبدیل می‌کند.

### چرا executeMethod اول؟

چون `executeMethod` callback مصرف‌کننده است — مصرف‌کننده باید با `id` و `index` صحیح مطلع شود **قبل** از اینکه لیست تغییر کند.

### جداسازی مسئولیت

| مکانیزم | مسئولیت |
|:---|:---|
| `executeMethod` | اطلاع‌رسانی به مصرف‌کننده (callback خارجی) |
| `CoreEvent.emit` | عملیات داخلی Component (حذف پیام از لیست reactive) |
