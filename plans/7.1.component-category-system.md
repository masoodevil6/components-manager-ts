# Plan 7.1 — سیستم Category برای Componentها (مشابه Icon)

## هدف

ایجاد سیستم Category برای Componentها — مشابه سیستم موجود برای Iconها.

این سیستم اجازه می‌دهد:
- Componentها در دسته‌بندی‌های منطقی (basic, inputs, contents, ...) قرار بگیرند
- هر Component به‌صورت callable در دسترس باشد: `UiCategory.UI.Basic.Button(config, methods, events)`
- هر Component `.info` به Definition خودش داشته باشد
- Component Manager بتواند تمام Componentهای ثبت‌شده را کشف کند

### مشکلات فعلی

#### ۱. فقط یک Component ثبت شده

فقط `ComponentStructure` در category `basic` ثبت شده. بقیه categoryها (`contents`, `inputs`, `positions`, `simples`) خالی هستند.

#### ۲. `CreateCategoryComponent` با `ComponentStructure` سازگار نیست

```typescript
// CreateCategoryComponent انتظار دارد:
new ComponentClass(config, methods, events)

// ولی ComponentStructure constructor:
new ComponentStructure(componentName, elId, identity, step)
```

به همین دلیل `as any` استفاده شده:
```typescript
CreateCategoryComponent(
    UIComponents.Lists.ComponentStructure.Definition,
    UIComponents.Lists.ComponentStructure.Component as any  // ← هک
)
```

#### ۳. `CreateCategoryComponent` از `identity` و `step` بی‌خبر است

```typescript
const callable = (config, methods, events) => {
    const instance = new ComponentClass(config, methods, events);
    return instance.getElement();
};
```

این فقط `config, methods, events` را پاس می‌دهد — `identity` و `step` را نه.

#### ۴. `TCategoryComponentTotality` فقط `config, methods, events` می‌گیرد

```typescript
export type TCategoryComponentTotality =
    & ((
        config?:  Record<string, any>,
        methods?: Record<string, any>,
        events?:  Record<string, any>
    ) => HTMLElement)
    & { info: ComponentDefinition }
```

`identity` و `step` در این type نیستند.

## تغییرات لازم

### ۱. به‌روزرسانی `TCategoryComponentTotality`

افزودن `identity` به پارامترهای callable:

```typescript
export type TCategoryComponentTotality =
    & ((
        config?:   Record<string, any>,
        methods?:  Record<string, any>,
        identity?: {
            unique?: any;
            emit?:   any;
            events?: Record<string, any>;
        },
    ) => HTMLElement)
    & {
        info: CoreComponents.ComponentDefinition
    }
```

### ۲. به‌روزرسانی `CreateCategoryComponent`

```typescript
export function MtCreateCategoryComponent(
    definition:      CoreComponents.ComponentDefinition,
    ComponentClass:  new (
        config?:   Record<string, any>,
        methods?:  Record<string, any>,
        identity?: {
            unique?: any;
            emit?:   any;
            events?: Record<string, any>;
        },
    ) => { getElement(): HTMLElement }
): TCategoryComponentTotality {

    const callable = (
        config?:   Record<string, any>,
        methods?:  Record<string, any>,
        identity?: {
            unique?: any;
            emit?:   any;
            events?: Record<string, any>;
        },
    ): HTMLElement => {
        const instance = new ComponentClass(config, methods, identity);
        return instance.getElement();
    };

    return Object.assign(
        callable,
        { info: definition }
    ) as TCategoryComponentTotality;
}
```

### ۳. سازگاری Constructor

برای اینکه `CreateCategoryComponent` کار کند، Constructor Component باید امضای `(config, methods, identity?)` داشته باشد.

این یعنی Componentهای فرزند (مثل `ComponentButton`) باید این امضا را داشته باشند:

```typescript
class ComponentButton extends ComponentButtonBase {
    constructor(
        config:  ButtonPropsType,
        methods: ButtonMethodsType,
        identity?: Partial<ComponentIdentity>,
    ) {
        super("button", null, identity, ButtonStep);
        this.renderComponent(config, methods);
    }
}
```

این امضا با `CreateCategoryComponent` سازگار است.

ولی `ComponentStructure` خودش این امضا را ندارد (چون `componentName` و `elId` نیاز دارد). این درست است — `ComponentStructure` قرار نیست مستقیماً در Category ثبت شود. فقط فرزندها.

### ۴. به‌روزرسانی `ComponentStructureTotality`

فعلاً `ComponentStructure` با `as any` در Category ثبت شده. دو راه‌حل:

**راه‌حل A (توصیه‌شده):** حذف `ComponentStructure` از Category

`ComponentStructure` یک Base Runtime است — قرار نیست مستقیماً توسط مصرف‌کننده استفاده شود. فقط فرزندها (Button, Input, ...) باید در Category ثبت شوند.

```typescript
// module_categories/lists/ui/basic/Definition.ts
export const Definition : UICategories.TCategoryComponentDefinition = {
    id:          "basic",
    name:        Keys.category.components.basic.name,
    description: Keys.category.components.basic.description,
    // components: []  ← خالی — فرزندها در categoryهای خودشان
}
```

**راه‌حل B:** wrapper برای ComponentStructure

اگر واقعاً می‌خواهیم `ComponentStructure` را هم در دسترس بگذاریم:

```typescript
const ComponentStructureCallable = (
    config?:  Record<string, any>,
    methods?: Record<string, any>,
    identity?: { unique?: any; emit?: any; events?: Record<string, any> },
): HTMLElement => {
    return ComponentStructure.component(config, methods, identity ?? {});
};

export const ComponentStructureTotality = Object.assign(
    ComponentStructureCallable,
    { info: UIComponents.Lists.ComponentStructure.Definition }
);
```

## نکات مهم

### چرا `identity` به‌جای `events`؟

در الگوی فعلی، `CreateCategoryComponent` فقط `config, methods, events` می‌گیرد. ولی در معماری جدید:
- `events` بخشی از `identity` است
- `identity` شامل `unique, emit, events` است

پس callable باید `(config, methods, identity?)` بگیرد — نه `(config, methods, events)`.

### چرا `ComponentStructure` مستقیماً در Category ثبت نشود؟

`ComponentStructure` یک Base Runtime است — مثل `IconDefinition` که مستقیماً در Category ثبت نمی‌شود. فقط Componentهای واقعی (Button, Input, ...) باید در Category باشند.

### چرا `step` در Category نیست؟

`step` داخلی Component است — در تعریف کلاس فرزند set می‌شود، نه از بیرون. پس نیازی نیست در Category callable پاس داده شود.
