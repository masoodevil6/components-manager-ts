# Plan 10.1 — ComponentBorder Migration به معماری جدید

> **پیش‌نیاز:** Plan 8.2.7 (SubEvent), Plan 8.2.10 (Component Wrapper Layer), Plan 9.1.3 (Define_ComponentProp)
> **هدف:** مهاجرت `ComponentBorder` از `last/tools/components/ComponentBorder.ts` به معماری جدید (Declarative Layer + Composition با Trait + Examples + Category)

---

## ۱. وضعیت فعلی

`ComponentBorder` در `last/tools/components/ComponentBorder.ts` (1123 خط) یک کامپوننت legacy است که از `ComponentBase` ارث‌بری می‌کند و الگوی قدیمی `GOG_*` / `defineComponentPatterns` / `defineComponentSchema` / `defineComponentMethods` را استفاده می‌کند.

### ۱.۱ ساختار فعلی

| بخش | وضعیت | توضیح |
|:---|:---|:---|
| Props | ❌ legacy | `ComponentBorderProps` با `GOG_ComponentBasicProps_*` + propهای اختصاصی به‌صورت string constants |
| Configs | ❌ legacy | `ComponentBorderConfigs` با `GOG_SetValue<T>` — نوع و default در یکجا |
| Enums | ❌ legacy | `ComponentBorder_ArrowTypes`, `ComponentBorder_BorderTypes` — naming قدیمی |
| Types | ❌ legacy | `GOG_ExtractNameValue` / `GOG_ExtractName` — استخراج نوع قدیمی |
| Base class | ❌ legacy | `ComponentBorderBase extends ComponentBase<...>` — الگوی قدیمی |
| Concrete class | ❌ legacy | `ComponentBorder extends ComponentBorderBase` — constructor قدیمی |
| Schema | ❌ legacy | `defineComponentSchema` با `this._COMPONENT_PATTERN[...]` |
| Methods | ❌ legacy | `defineComponentMethods` با runtime name keys |
| Templates | ❌ legacy | `defineComponentTemplate` — مفهوم حذف‌شده در معماری جدید |
| Rendering | ❌ legacy | `template_render_border` با `ReactiveElement.part` + `Observable.computed` |
| Example | ❌ legacy | `static renderExampleComponent()` — الگوی قدیمی |
| Step | ❌ ندارد | Step Node وجود ندارد |
| dispose | ❌ ندارد | dispose پیاده‌سازی نشده |
| Category | ❌ ندارد | ثبت در Category نیست |
| ComponentManager | ❌ ندارد | ثبت در ComponentManager نیست |
| Language Keys | ❌ ندارد | کلیدهای زبان در `Keys.ts` / `Fa.ts` / `En.ts` نیست |

**نکته مهم:** ComponentBorder یک **utility/wrapper component** است — نه یک کامپوننت مستقل که توسط کاربر نهایی مستقیم استفاده شود. مصرف‌کنندگان اصلی آن سایر Componentها هستند که آن را به‌عنوان wrapper استفاده می‌کنند. در معماری جدید، این الگو باید با `ComponentStructure.create()` یا Trait جایگزین شود — ولی در این مهاجرت، ComponentBorder را به‌عنوان یک Component مستقل با Category registration مهاجرت می‌کنیم تا مصرف‌کنندگان آینده بتوانند از آن استفاده کنند.

الگوی `componentButton` به‌عنوان مرجع اصلی استفاده می‌شود — با تفاوت‌های اختصاصی Border:

### Phase ۶ — `ComponentBorderBase.ts`

الگوی `ComponentButtonBase` با تفاوت‌های Border:

```typescript
import * as CoreComponents   from "@/core_components";
import * as CoreEvent        from "@/core_event";
import {ComponentStructureTrait} from "../../traits/componentStructureTrait";
import {Props,     PropsType}     from "./Props";
import {Schemas,   SchemasType}   from "./Schemas";
import {Methods,   MethodsType}   from "./Methods";
import {Definition}               from "./Definition";
// --------------------------------

export class ComponentBorderBase extends CoreComponents.App<
    PropsType & Record<string, any>,
    SchemasType,
    any,
    MethodsType
> {
    protected _COMPONENT_STEP: CoreEvent.TStepInstance<any> | null = null;

    constructor(
        componentName: string = "border",
        elId: string | null   = null,
        identity?: {
            unique?: CoreEvent.TStepRef | null;
            emit?:   CoreEvent.TEmitHandler | null;
            events?: Record<string, any> | null;
        },
        step?: CoreEvent.TStepInstance<any>,
    ) {
        super(componentName, elId);

        this._COMPONENT_UNIQUE = identity?.unique ?? null;
        this._COMPONENT_EMIT   = identity?.emit ?? null;
        this._COMPONENT_STEP   = step ?? null;

        if (step && identity?.unique && typeof (identity.unique as any).identity === "symbol") {
            CoreEvent.SubEvent(identity.unique as CoreEvent.TStepRef, componentName, step);
        }
    }

    disposeStep(): void {
        if (this._COMPONENT_STEP) {
            CoreEvent.dispose(this._COMPONENT_STEP);
            this._COMPONENT_STEP = null;
        }
    }

    protected _COMPONENT_DEFINITION = Definition;

    protected _COMPONENT_PATTERN = CoreComponents.DefineProp<PropsType & Record<string, any>>({
        ...ComponentStructureTrait.props,
        ...Props,
    } as any);

    protected _COMPONENT_SCHEMA = CoreComponents.DefineSchema<SchemasType, PropsType & Record<string, any>>({
        ...Schemas,
    } as any);

    protected _COMPONENT_METHODS = CoreComponents.DefineMethod<MethodsType, PropsType & Record<string, any>>({
        ...Methods,
    } as any);
}
```

### Phase ۷ — `ComponentBorder.ts`

الگوی `ComponentButton.ts` با تقسیم‌بندی متدهای کوچک و قابل‌توسعه توسط انسان:

```typescript
import * as CoreReactive   from "@/core_reactive";
import * as CoreObservable from "@/core_observable";
import * as CoreConfig     from "@/core_configs";
import * as UtilStyle      from "@/util_styles";
import * as UtilConst      from "@/util_consts";
// --------------------------------
import {ComponentBorderBase}    from "./ComponentBorderBase";
import {createBorderStep}       from "./Step";
import {Schemas}                from "./Schemas";
import {MethodsConfigType}      from "./Methods";
import {ComponentBorder_ArrowTypes} from "./Props";
import {PropsType}              from "./Props";
import {PartAttrDefault}        from "@/core_components";
import {ComponentStructureTrait} from "../../traits/componentStructureTrait";
import {PropsType as StructurePropsType} from "../componentStructure/Props";


export class ComponentBorder extends ComponentBorderBase {

    /* ---------------------------------------------
       Hover State — معادل el.hover قدیمی
       Observable داخلی کلاس — توسط on: {mouseenter/mouseleave} تغذیه می‌شود
    --------------------------------------------- */
    private readonly _HOVER_STATE = new CoreObservable.App<boolean>(false);


    constructor(
        config?:  Partial<StructurePropsType & PropsType>,
        methods?: MethodsConfigType<ComponentBorder>,
        identity?: {
            unique?: any;
            emit?:   any;
            events?: Record<string, any> | null;
        },
    ) {
        const step = createBorderStep();

        super("border", null, identity, step);

        this.renderComponent(
            config as any,
            methods as any,
            identity?.events ?? null,
        );
    }


    /* ---------------------------------------------
       Plan 8.2.7 — Component Disposal
    --------------------------------------------- */
    dispose(): void {
        this.disposeStep();
    }


    /* ---------------------------------------------
       Plan 8.2.10 — renderContentComponent از Trait
    --------------------------------------------- */
    override renderContentComponent(
        attrsDefault: PartAttrDefault,
        data:         Record<string, CoreObservable.App<any>>,
        extra?:       any,
    ): CoreReactive.App {
        return ComponentStructureTrait.renderContent(
            this,
            () => this.executeSchemaPart(Schemas.BORDER.part, {}),
        );
    }


    /* ---------------------------------------------
       renderManagerComponent — Routing
    --------------------------------------------- */
    override renderManagerComponent(
        partName:     string,
        attrsDefault: PartAttrDefault,
        data:         Record<string, CoreObservable.App<any>>,
        extra?:       any,
    ): CoreReactive.App {

        switch (partName) {
            case Schemas.BORDER.part:
                return this.renderBorder(attrsDefault, data, extra);
            default:
                return super.renderContentComponent(attrsDefault, data, extra);
        }
    }


    /* ---------------------------------------------
       renderBorder — رندر Part BORDER اصلی
       فقط ساختار کلی — تمام style‌های computed در متدهای private
    --------------------------------------------- */
    protected renderBorder(
        attrsDefault?: PartAttrDefault,
        data?:         Record<string, CoreObservable.App<any>>,
        extra?:        any,
    ): CoreReactive.App {

        const bind = this._COMPONENT_PROPS_BIND;

        const prop_content                     = data?.["prop_content"]                     ?? bind.prop_content;
        const prop_borderClass                 = data?.["prop_borderClass"]                 ?? bind.prop_borderClass;

                if ((dir && type == ComponentBorder_ArrowTypes.RIGHT) || (!dir && type == ComponentBorder_ArrowTypes.LEFT))

                return null;
            },
            [prop_borderArrowType, prop_borderColor, prop_borderColor_hover, this._HOVER_STATE],
            this.getScope(),
        );
```

**الگوی تقسیم‌بندی متدها (مطابق ComponentButton):**

| دسته | متدها | توضیح |
|:---|:---|:---|
| **Hover State** | `_HOVER_STATE` | Observable داخلی — جایگزین `el.hover` legacy |
| **Render** | `renderBorder()` | فقط ساختار کلی — تمام style‌ها در متدهای private |
| **Arrow CSS** | `getArrowCssCustom()` | استایل ثابت `:after` |
| **Border Radius** | `getStyleBorderTopLeftRadius()`, `...TopRight`, `...BottomLeft`, `...BottomRight` | هر گوشه یک متد مستقل |
| **Border Width** | `getStyleBorderTopWidth()`, `...Right`, `...Bottom`, `...Left` | هر ضلع یک متد مستقل |
| **Colors** | `getStyleBorderColor()`, `getStyleContentColor()`, `getStyleContentBackgroundColor()` | هر رنگ یک متد مستقل با hover logic |
| **Border Style** | `getStyleBorderStyle()`, `getStyleOpacity()` | متدهای مستقل |
| **Arrow CSS Vars** | `getStyleArrowContent()`, `...Left`, `...Right`, `...Top`, `...Bottom`, `...BorderWidth`, `...Transform`, `...BorderColor` | هر CSS variable یک متد مستقل |

**مزایای این الگو:**
- هر متد یک مسئولیت مشخص دارد — قابل تست و تغییر مستقل
- توسعه‌پذیر: اضافه‌کردن style جدید = اضافه‌کردن یک متد private
- خوانایی: `renderBorder()` فقط ساختار کلی را نشان می‌دهد — جزئیات در متدهای private
- سازگار با ComponentButton — همان الگوی `getStyleBtn*`

## ۸. Rollback Strategy

اگر مهاجرت در هر فازی با خطای غیرقابل‌حل مواجه شد:

1. **فازهای ۱-۵ (Declarative):** فایل‌های ایجادشده حذف شوند — هیچ اثر side-effect ندارند.
2. **فاز ۶-۷ (Runtime):** فایل‌های ایجادشده حذف شوند — هیچ وابستگی خارجی ایجاد نشده.
3. **فاز ۸ (Language Keys):** کلیدهای اضافه‌شده از `Keys.ts`, `Fa.ts`, `En.ts` حذف شوند.
4. **فاز ۹-۱۰ (Examples + index):** فایل‌های ایجادشده حذف شوند.
5. **فاز ۱۱-۱۲ (Registration):** registration‌ها revert شوند — تغییرات در فایل‌های موجود undo شوند.

**نکته:** چون این یک Component جدید در مسیر جدید است (نه تغییر در legacy)، rollback ساده است — فقط فایل‌های جدید حذف شوند و تغییرات registration revert شوند.
