# پلن 46.1.0 — ساخت `componentInputJson`

> **وضعیت:** پیاده‌سازی‌شده؛ `npm run build:app` موفق بود  
> **دسته‌بندی:** `UI.Inputs` با شناسهٔ `inputs` و عنوان موجود `Input Components`  
> **مسیر عمومی پیشنهادی:** `UiCategory.UI.Inputs.InputJson(config, methods, identity)`  
> **راهنمای مبنا:** `documents/guides/component-create.md`

## ۱. هدف و محدوده

کامپوننت ترکیبی `ComponentInputJson` ساخته شود. الگوی بیرونی آن از `ComponentInput` گرفته می‌شود: ساختار اصلی، label، form، validation، اتصال props و رویدادها. داخل form، متن خام JSON با `ComponentCodeMirror` ویرایش می‌شود و در صورت معتبر بودن، دادهٔ parse‌شده به‌صورت زنده در `ComponentJsonTree` نمایش داده می‌شود.

این کامپوننت JSON نامعتبر را نباید به‌عنوان دادهٔ معتبر به درخت بدهد. خطای parse باید در رابط کاربری قابل مشاهده باشد و با اصلاح متن، پیش‌نمایش درختی دوباره به‌روز شود.

## ۲. شواهد فعلی و تصمیم‌های معماری

- `ComponentInput` از `ComponentLabelTrait` و `ComponentValidate` استفاده می‌کند و childها را dispose می‌کند؛ همین قرارداد برای والد جدید مبنا است.
- `ComponentCodeMirror` اکنون فقط `HTML` و `JAVASCRIPT` دارد. حالت JSON در آن هنوز وجود ندارد و dependency مربوط به `@codemirror/lang-json` نیز در `package.json` دیده نشد؛ افزودن پشتیبانی JSON جزو کار لازم این پلن است.
- `ComponentJsonTree` ورودی `prop_data` از نوع `JsonValue` می‌گیرد و با تغییر آن درخت را دوباره رندر می‌کند؛ این API برای پیش‌نمایش زنده استفاده شود.
- در سورس فعلی کامپوننت عمومی `ComponentHeader` وجود ندارد. با توجه به اینکه کنترلر `headerPublic` در همین پروژه از `UiCategory.UI.Pages.Header.PageHeader` استفاده می‌کند، بخش header این کامپوننت با `ComponentPageHeader` ساخته می‌شود؛ دکمهٔ back، breadcrumb و menu آن خاموش/خالی می‌مانند و فقط عنوان را نمایش می‌دهد.

### تصمیم دربارهٔ درخت فرم

عبارت «`componentCodeMirror` برای ویرایش JSON و `componentJsonTree` برای نمایش زنده» مبنای ساختار است. بنابراین بخش دوم editor، `ComponentJsonTree` است، نه CodeMirror دوم. `CodeMirrorLanguage.JSON` یعنی CodeMirror اول با حالت زبان JSON تنظیم می‌شود.

```text
COMPONENT
└── STRUCTURE                         از ComponentStructureTrait
    ├── LABEL                         از ComponentLabelTrait
    ├── FORM: part-input-json-form
    │   ├── HEADER: part-input-json-form-header
    │   │   └── ComponentPageHeader   عنوان سربرگ، بدون back، breadcrumb یا menu
    │   └── EDITOR: part-input-json-form-editor
    │       ├── componentCodeMirror   ویرایش متن خام با CodeMirrorLanguage.JSON
    │       ├── part-input-json-error خطای parse، فقط هنگام JSON نامعتبر
    │       └── componentJsonTree     پیش‌نمایش زندهٔ JsonValue معتبر
    └── VALIDATE                      با قرارداد ComponentInput / ComponentValidate
```

`componentCodeMirror` و `componentJsonTree` مالک DOM داخلی خود می‌مانند؛ Schema والد فقط partهای خود `ComponentInputJson` را تعریف می‌کند و مستقیماً منطق render فرزند را در Schema قرار نمی‌دهد.

## ۳. فایل‌های Component

مسیر جدید:

```text
src/framework/module_ui/module_components/lists/componentInputJson/
├── Definition.ts
├── Props.ts
├── Schemas.ts
├── Methods.ts
├── Step.ts
├── ComponentInputJsonBase.ts
├── ComponentInputJson.ts
├── index.ts
└── examples/
    ├── Default.ts
    ├── Nested.ts
    ├── InvalidJson.ts
    └── index.ts
```

`Definition` از `CoreComponents.ComponentDefinition` و شناسهٔ یکتای `component_input_json` استفاده کند. `Base` مطابق راهنما فقط config، definition، props، schemas و methods را ثبت کند. کلاس نهایی سازنده، render، اتصال داده و dispose فرزندان را مدیریت کند. `Step` رویداد تغییر و رخدادهای ورودی موردنیاز را با `CoreEvent` تعریف کند.

## ۴. قرارداد Props

Props با `Define_ComponentProp<T>` تعریف شوند؛ `PropsType` و `PropsConfigType` با helperهای `TypeHelpers` استخراج شوند. Props برچسب از `ComponentLabelTrait` ارث‌برند و دوباره تعریف نشوند.

| Prop پیشنهادی | نوع / پیش‌فرض | کاربرد |
|---|---|---|
| `prop_name` | `string \| null` / `null` | نام فیلد برای سازگاری با الگوی ورودی‌ها |
| `prop_value` | `string` / `"{}"` | متن خام JSON؛ مقدار قابل ویرایش و قابل کنترل والد |
| `prop_isDisable` | `boolean` / `false` | اتصال به `ComponentCodeMirror.prop_isReadOnly` |
| `prop_title` | `string \| null` / `null` | عنوان مورد استفاده در validation، مانند `ComponentInput` |
| props استاندارد validation | مطابق `ComponentInput` | `prop_hasRules`، `prop_isAbsoluteRule`، `prop_listRules` و `prop_msgRules` |
| `prop_editorHeight` | `string \| null` / مقدار اندازهٔ میانه یا مقدار پیش‌فرض مشترک | ارتفاع بخش ویرایش/پیش‌نمایش؛ مقدار نهایی با محدودیت‌های layout هماهنگ شود |
| props منتخب `ComponentJsonTree` | پیش‌فرض‌های خود `ComponentJsonTree` | تنظیم عمق اولیه، جستجو و کنترل‌های نمایش درخت؛ فقط مواردی که برای والد لازم‌اند expose شوند |

تنظیمات عمومی `ComponentCodeMirror` مانند theme و گزینه‌های unrelated به Run به‌صورت پیش‌فرض داخلی بمانند، مگر در پیاده‌سازی شواهدی نشان دهد که برای API والد لازم‌اند. اجرای کد (`prop_canRun`) برای این input فعال نشود.

## ۵. قرارداد داده و رویدادها

- منبع اصلی داده `prop_value` و همواره رشتهٔ خامی است که در CodeMirror ویرایش می‌شود.
- با هر رویداد `CHANGE` از CodeMirror، مقدار خام در prop والد به‌روزرسانی و JSON parse شود.
- در parse موفق، مقدار `JsonValue` به `ComponentJsonTree.prop_data` داده شود و رویداد والد شامل `VALUE`، `JSON` و `IS_VALID: true` باشد.
- در parse ناموفق، متن خام حفظ شود، پیش‌نمایش قبلی پاک شود تا دادهٔ قدیمی به‌اشتباه معتبر جلوه نکند، و خطای parse در `part-input-json-error` نمایش داده شود. رویداد تغییر شامل `VALUE`، `JSON: null` و `IS_VALID: false` باشد.
- مقدار اولیه و تغییرات بیرونی `prop_value` نیز باید از همان مسیر parse عبور کنند تا editor و tree از هم جدا نشوند.
- focus و blur، در صورت پشتیبانی لایهٔ CodeMirror، با قراردادهای معادل ورودی به والد منتقل شوند؛ نام‌گذاری نهایی Methods در `Methods.ts` و `Keys` ثبت شود.
- قواعد `ComponentValidate` روی مقدار خام و کنترل‌شده اجرا شوند. خطای syntax به پیام parse تعلق دارد و جای validation business را نمی‌گیرد.

## ۶. پیاده‌سازی JSON در `ComponentCodeMirror`

تغییرات این بخش فقط برای اضافه‌شدن حالت JSON و بدون تغییر رفتار HTML/JavaScript باشد:

1. افزودن `CodeMirrorLanguage.JSON` به enum و متن‌های منو/عنوان زبان.
2. افزودن dependency مستقیم `@codemirror/lang-json` و به‌روزرسانی lockfile فعال پروژه.
3. توسعهٔ `normalizeLanguage` و `languageExtension` تا JSON به `json()` نگاشت شود؛ مقادیر HTML و JavaScript و اجرای کنونی‌شان حفظ شوند.
4. به‌روزرسانی زبان پیش‌فرض/عنوان نمایشی فقط در مثال‌ها و فراخوانی‌های JSON؛ پیش‌فرض عمومی `ComponentCodeMirror` تغییر نکند.
5. افزودن تست یا بررسی ساخت برای اطمینان از resolve شدن extension جدید و عدم regression دو زبان قبلی.

قابلیت Format/Prettify مستقل از حالت syntax است. این پلن فقط حالت ویرایش JSON را اضافه می‌کند؛ اگر منظور از «json format» دکمهٔ فرمت خودکار نیز باشد، باید API آن جداگانه به محدوده افزوده شود.

## ۷. اتصال اجزا و واکنش‌پذیری

- `ComponentInputJson` از ساختار پایه و الگوی render/dispose در `ComponentInput` پیروی کند.
- `ComponentCodeMirror` با `prop_language: CodeMirrorLanguage.JSON`، مقدار کنترل‌شده و read-only وابسته به `prop_isDisable` ساخته شود.
- دادهٔ parse‌شده مستقیماً به `ComponentJsonTree` داده شود؛ برای JSON نامعتبر tree مقدار قبلی را نگه ندارد.
- تغییر `prop_value` از بیرون باید CodeMirror را به‌روز کند، بدون اینکه callback تغییر به شکل حلقه‌ای دوباره اجرا شود.
- اجزای ساخته‌شده (CodeMirror، JsonTree، header، validator و هر child دیگر) در فهرست childها نگهداری و در `dispose()` آزاد شوند؛ Scope و Step والد نیز dispose شوند.
- اندازه‌گذاری editor و preview در عرض‌های محدود، `minWidth: 0`، `minHeight: 0` و overflow کنترل‌شده داشته باشد تا ارتفاع/عرض داخلی از form بیرون نزند. نسبت دو بخش و رفتار responsive هنگام implementation بر اساس الگوی جاری layout تعیین و در مثال‌ها بررسی شود.

## ۸. ثبت در ComponentManager و UI Category

1. ثبت Definition، Props، Schemas، Methods، Examples و Constructor در `module_components/lists/index.ts` و export عمومی از barrel همان ماژول.
2. ساخت Category Definition و barrel برای `InputJson` زیر مسیر موجود `module_categories/lists/ui/inputs/`.
3. ثبت `InputJson` داخل آرایهٔ `components` در `module_categories/lists/ui/inputs/Definition.ts`؛ در نتیجه در همان دسته‌بندی موجود `Input Components` نمایش داده شود. دسته‌بندی یا زیر‌دستهٔ تازه نساز.
4. export کردن `InputJson` از `module_categories/lists/ui/inputs/index.ts` و barrel بالادستی `ui` تا مسیر عمومی `UiCategory.UI.Inputs.InputJson` در دسترس باشد.
5. افزودن کلیدهای نام، توضیح، props، schemas، methods و examples به `module_categories/languages/Keys.ts` و ترجمه‌های `Fa.ts` و `En.ts`.

## ۹. مثال‌ها

- **Default:** JSON معتبر تو در تو؛ ویرایش در CodeMirror و نمایش هم‌زمان در JsonTree.
- **Nested:** آرایه، object، مقادیر primitive و عمق بیشتر برای نمایش قابلیت‌های `ComponentJsonTree`.
- **Invalid JSON:** syntax نامعتبر، نمایش خطا، حفظ متن قابل ویرایش و بازگشت زندهٔ tree پس از اصلاح.
- در صورت نیاز، مثال مجزا برای حالت read-only و validation اضافه شود؛ نمونه‌ها از callable عمومی `UiCategory.UI.Inputs.InputJson(...)` استفاده کنند و `HTMLElement` برگردانند.

## ۱۰. معیارهای پذیرش و اعتبارسنجی

- کامپوننت از ComponentManager و مسیر عمومی `UiCategory.UI.Inputs.InputJson` resolve شود و در فهرست/فیلتر دسته‌بندی موجود `Input Components` نمایش داده شود.
- DOM شامل یک ویرایشگر CodeMirror در حالت JSON و یک `ComponentJsonTree` برای preview باشد؛ CodeMirror دومی ساخته نشود.
- JSON معتبر با هر تغییر editor در tree منعکس شود؛ JSON نامعتبر پیام خطا نشان دهد و tree دادهٔ قبلی را به‌عنوان نتیجهٔ جدید نمایش ندهد.
- مقدار خام، رویدادهای والد، تغییر prop از بیرون، disabled/read-only، label، validation و dispose مطابق قرارداد تعریف‌شده کار کنند.
- عنوان/ترجمه‌ها در فارسی و انگلیسی موجود باشند و هیچ `[object Object]` در DOM ظاهر نشود.
- HTML و JavaScript در `ComponentCodeMirror` پس از افزودن JSON همچنان کار کنند.
- اعتبارسنجی نهایی: `npm run build:app` و `git diff --check`.

## ۱۱. خارج از محدوده

- تغییر رفتار `ComponentInput` یا `ComponentJsonTree`، جز رفع مانع واقعی اتصال.
- اضافه‌کردن formatter خودکار، schema validation استاندارد JSON Schema، import/export فایل، یا Run برای JSON.
- تبدیل مقدار خام به API جداگانه‌ای که به‌جای رشته object بپذیرد؛ قرارداد اصلی در این نسخه متن JSON است.
- ساخت ComponentHeader عمومی جدید خارج از این پلن است؛ بخش header با کامپوننت موجود `ComponentPageHeader` پیاده می‌شود.
