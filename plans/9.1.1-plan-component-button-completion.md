## ۵. فاز ۴ — به‌روزرسانی ComponentButton.ts (بازسازی Rendering)

**فایل:** `componentButton/ComponentButton.ts`

### ۵.۱. ساختار رندر جدید (مطابق معماری جدید)

```
renderContentComponent()                          ← Trait (موجود)
  └── renderButton()                              ← Part BUTTON (بازنویسی کامل)
        ├── <button> root
        │     ├── className: shadow-sm
        │     ├── classBind: [prop_btnVariant, prop_btnClass]
        │     ├── stylesBind: width, height, backgroundColor(+hover), border, borderRadius(x4)
        │     ├── children: renderTitle() + (اختیاری) renderIcon()
        │     ├── unique/emit از Step
        │     └── on: { click, mouseenter, mouseleave }
        └── semantic color mapping
```

### ۵.۲. Semantic Color Maps (محلی در کلاس — نه Schema)


حالت CUSTOM: مقدار از prop مربوطه خوانده شود.

### ۵.۳. Rendering انیمیشن hover

الگوی Legacy: `el.hover.mapList({true:..., false:...})` — یک قابلیت ReactiveElement قدیمی است. در معماری جدید:

**گزینه A (توصیه‌شده):** از CSS `:hover` استفاده شود:
```typescript
styles: {
    transition: "background-color 200ms ease",
},
// در کلاس‌ها:
// "component-button" + CSS rule: .component-button:hover { ... }
```

**گزینه B:** اگر CoreReactive از `mouseenter/mouseleave` state observable می‌سازد (باید بررسی شود)، از آن استفاده شود.

**تصمیم:** Phase 4 از گزینه A استفاده کند — ساده‌تر، بدون وابستگی به قابلیت‌های حذف‌شده. اگر قابلیت hover-state در CoreReactive موجود باشد (بررسی در Phase 0)، گزینه B اولویت دارد.

### ۵.۴. متدهای رندر جدید

```typescript
protected renderTitle(): CoreReactive.App          // Part BUTTON_TITLE — <b> با رنگ/سایز/کلاس
protected renderIcon(): CoreReactive.App | null    // Part BUTTON_ICON — فقط اگر prop_btnIcon != null
```

children شرطی: اگر `prop_btnIcon.get() != null` → `[renderTitle(), renderIcon()]` وگرنه `[renderTitle()]`.
(الگوی `Observable.conditionWhen` قدیمی — بررسی معادل در CoreReactive — در غیر این صورت بازسازی با App.switchCase یا رندر مجدد)

### ۵.۵. محاسبات سایز (borderRadius, height, line-height)

الگوی Legacy از `AppConfig.get_sizeName()` + `ToolsComponents_BorderRadius` + `Observable.computed` استفاده می‌کرد. در معماری جدید:

- اگر `CoreObservable` در src معادل `AppConfig` observable دارد → استفاده
- وگرنه: مقادیر سایز به‌صورت **string** در prop (برنامه‌نویس خودش پاس می‌دهد مثل `"0.5rem"`) و منطق DEFAULT → در Phase 0 بررسی و تصمیم نهایی
