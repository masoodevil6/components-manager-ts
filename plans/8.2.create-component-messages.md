# Plan 8.2 — ساخت ComponentMessages

## هدف

ساخت اولین Component واقعی با معماری جدید — `ComponentMessages`.

این Component یک لیست از پیام‌ها (success / warning / error / custom) را نمایش می‌دهد، هر پیام قابل بستن است.

---

        super("messages", null, identity, MessagesStep);

        return this.renderMessages();

## دسته‌بندی در UI Category

### پیشنهاد: category جدید `notifications`

`ComponentMessages` در هیچ‌کدام از categoryهای فعلی (`basic`, `simples`, `inputs`, `contents`, `positions`) مناسب نیست.

**دلیل:** Messages یک Component اطلاع‌رسانی است — نه input، نه content ساده، نه position. مفهوم Notifications شامل Messages, Toast, Alert, Notification Banner, Snackbar است.

## نکات مهم

### وابستگی به ComponentIcon

`ComponentMessages` برای آیکون بستن هر پیام از `ComponentIcon` استفاده می‌کند.
`ComponentIcon` در پلن ۸.۱ ساخته شده و قابل استفاده است.

**استفاده:**
```typescript
import {ComponentIcon} from "../componentIcon";

new ComponentIcon(
    {
        prop_icon:      UiIcons.CreateIcon(UiIcons.Src.StatusClose.Definition, { size: 16 }),
        prop_iconClass: ["cursor-pointer"],
        prop_iconStyles: { "inset-inline-end": "5px", "top": "5px" },
    },
    {
        CLICK: { name: "fn_onCloseMessage" },
    },
)
```

### وابستگی به ToolsCss / AppConfig

پیاده‌سازی قدیمی از `ToolsCss.getFontSize` و `AppConfig.get("sizeName")` استفاده می‌کرد.

**راه‌حل:** در معماری جدید، این مقادیر را از `CoreConfigs.Settings` می‌خوانیم (اگر موجود است) یا hardcoded می‌کنیم (برای نسخه اول).

### رنگ‌ها

پیاده‌سازی قدیمی از CSS variables استفاده می‌کرد:
- `var(--successColor1)`, `var(--errorColor1)`, `var(--warningColor1)`

این الگو حفظ می‌شود — تغییر نمی‌کند.
