# 2. هدف

بازطراحی Example System با اهداف زیر:

1. Example برای برنامه‌نویس **قابل‌فهم** باشد — با خواندن فایل بفهمد چه Componentی ساخته و چه چیزی render می‌شود.
2. Example **مستقیم قابل اجرا** باشد — بدون نیاز به دانستن `ExampleRenderer` یا `Component` Constructor.
3. Example **خود-مستندساز** باشد — کد Example خودش نشان بدهد چه propهایی پاس می‌شود و چه behaviorی دارد.
4. Example **Type-Safe** باشد — config/methods بر اساس Props/Methods واقعی Component type-check شود.
5. ComponentManager همچنان بتواند Exampleها را **لیست و discovery** کند (با id, name, description).
6. حذف Exampleهای بی‌معنی برای Base Runtime (مثل `ComponentStructure`).
7. بازنویسی `ClTestsPage` برای استفاده از Exampleهای جدید (به‌جای inline code).

# 4. قرارداد جدید API

Example به‌جای plain data، یک **Factory Function** باشد که مستقیم `HTMLElement` برمی‌گرداند.

## ۴.۱. شکل جدید Example

```ts
export const DefaultExample: ComponentExample = {
    id:          "icon_default",
    name:        Keys.category.components.icon.examples.default.name,
    description: Keys.category.components.icon.examples.default.description,

    render: () => UiCategory.UI.Simples.Icon(
        {
            prop_icon:      UiIcons.CreateIcon(UiIcons.Src.ArrowUp.Definition, { size: 24 }),
            prop_iconTitle: "Arrow Up",
        },
        {},
    ).getElement(),
};
```

برنامه‌نویس با خواندن این فایل:

* می‌بیند چه Componentی ساخته می‌شود (`UiCategory.UI.Simples.Icon`).
* می‌بیند چه propهایی پاس می‌شود (`prop_icon`, `prop_iconTitle`).
* می‌بیند چه methods/eventsای پاس می‌شود (`{}`).
* می‌تواند مستقیم `DefaultExample.render()` را صدا بزند و `HTMLElement` بگیرد.

## ۴.۲. Example با Methodهای واقعی

```ts
export const ClickableExample: ComponentExample = {
    id:          "icon_clickable",
    name:        Keys.category.components.icon.examples.clickable.name,
    description: Keys.category.components.icon.examples.clickable.description,

    render: () => UiCategory.UI.Simples.Icon(
        {
            prop_icon:      UiIcons.CreateIcon(UiIcons.Src.ArrowDown.Definition, { size: 32 }),
            prop_iconTitle: "Click me",
            prop_iconClass: ["cursor-pointer"],
        },
        {
            CLICK: function (event, dataArgs, componentArgs) {
                console.log("[ClickableExample] icon clicked", event, dataArgs, componentArgs);
            },
        },
    ).getElement(),
};
```

برنامه‌نویس می‌بیند:

* چه Methodهایی قابل فراخوانی هستند (`CLICK`).
* امضای callback چگونه است (`event, dataArgs, componentArgs`).
* `this` در callback به Component instance متصل است (طبق Plan 8.1.4).

# 5. Interface جدید

## ۵.۱. `ComponentExample`

```ts
/**
 * Component Example — Factory Function برای نمایش یک Component
 *
 * Example فقط metadata + render callable است.
 * render() مستقیم HTMLElement برمی‌گرداند — بدون نیاز به ExampleRenderer یا Component Constructor.
 *
 * Example به Component وابسته است (چون render() آن Component را می‌سازد).
 * این وابستگی عمدی است — Example بدون Component معنی ندارد.
 *
 * @example
 *   export const DefaultExample: ComponentExample = {
 *       id:          "icon_default",
 *       name:        Keys.category.components.icon.examples.default.name,
 *       description: Keys.category.components.icon.examples.default.description,
 *       render: () => UiCategory.UI.Simples.Icon({ ... }, {}).getElement(),
 *   };
 *
 *   // استفاده:
 *   const el = DefaultExample.render();   // → HTMLElement
 *   document.body.appendChild(el);
 */
export interface ComponentExample {

    /** شناسه یکتای Example (مثلاً "icon_default") */
    id:          string;

    /** کلید ترجمه برای نام نمایشی Example */
    name:        UtilBrands.TranslationKey;

    /** کلید ترجمه برای توضیحات Example */
    description?: UtilBrands.TranslationKey;

    /**
     * Factory Function — ساخت و render Component
     *
     * مستقیم HTMLElement برمی‌گرداند.
     * هر بار صدا زده شدن، یک Instance جدید می‌سازد.
     *
     * @returns HTMLElement نتیجه render
     */
    render:      () => HTMLElement;

}
```

# 7. ComponentManager

## ۷.۱. Registry Entry

`ComponentRegistryEntry.examples` از `Record<string, ComponentExampleDefinition>` به `Record<string, ComponentExample>` تغییر کند.

```ts
export interface ComponentRegistryEntry {
    definition:  ComponentDefinition;
    props?:      Record<string, any>;
    schemas?:    Record<string, any>;
    methods?:    Record<string, any>;
    examples?:   Record<string, ComponentExample>;   // ← تغییر
    constructor?: CoreComponents.ExampleRendererComponentConstructor;
}
```

## ۷.۲. متدهای ComponentManager

`getExamples(id)` و `getExample(id, exampleId)` همچنان کار کنند — فقط type بازگشتی تغییر کند.

```ts
getExamples(id: string): ComponentExample[] {
    const entry = this._registry.get(id);
    if (!entry?.examples) return [];
    return Object.values(entry.examples);
}

getExample(id: string, exampleId: string): ComponentExample | undefined {
    const entry = this._registry.get(id);
    if (!entry?.examples) return undefined;
    return entry.examples[exampleId];
}
```

## ۷.۳. حذف `constructor` از Registry Entry (اختیاری)

`constructor` در Registry Entry فعلی فقط برای `ExampleRenderer` استفاده می‌شد.

با حذف `ExampleRenderer`، `constructor` دیگر لازم نیست — مگر برای استفاده آینده.

**تصمیم:** `constructor` در Registry Entry حفظ شود (برای ComponentManager آینده که ممکن است بخواهد Component را بدون Example instantiate کند). ولی در این Plan از آن استفاده‌ای نمی‌شود.

# 10. بازنویسی ClTestsPage

## ۱۰.۱. هدف

`ClTestsPage` به‌جای inline code دستی، از Exampleهای ثبت‌شده در `ComponentManager` استفاده کند.

## ۱۰.۲. ساختار جدید

```ts
import * as CoreComponents from "@/core_components";
import * as CoreReactive    from "@/core_reactive";
// --------------------------------

export class ClTestsPage implements ITemplate {

    render(query?: Record<string, string>, extra?: Record<string, any>): HTMLElement {

        const sections: CoreReactive.App[] = [];

        // کشف خودکار تمام Componentهای ثبت‌شده در ComponentManager
        const entries = CoreComponents.ComponentManager.list();

        for (const entry of entries) {
            const examples = CoreComponents.ComponentManager.getExamples(entry.definition.id);

            if (examples.length === 0) continue;

            // یک section برای هر Component
            sections.push(
                CoreReactive.App.section({
                    className: ["col-12", "p-2"],
                    children: [
                        `<h5>${entry.definition.name}</h5>`,
                        `<hr/>`,
                        CoreReactive.App.section({
                            className: ["d-flex", "flex-wrap", "gap-3", "p-2"],
                            children: examples.map(example =>
                                CoreReactive.App.section({
                                    className: ["border", "rounded", "p-2"],
                                    children: [
                                        `<h6 class="small text-muted">${example.id}</h6>`,
                                        example.render(),   // ← مستقیم HTMLElement
                                    ],
                                }),
                            ),
                        }),
                    ],
                }),
            );
        }

        return CoreReactive.App.section({
            className: ["row", "p-0", "m-0"],
            children: [
                CoreReactive.App.section({
                    className: ["col-12", "p-2", "m-2"],
                    children: [
                        `<h3>Component Tests</h3>`,
                        `<hr/>`,
                    ],
                }),
                ...sections,
            ],
        }).getElement();
    }

    onLoad(pageElement: HTMLElement): void {
        console.log("[TestsPage] onLoad — page element:", pageElement);
    }

}
```

## ۱۰.۳. مزایا

* **کشف خودکار** — هر Component جدید که در `ComponentManager` ثبت شود و Example داشته باشد، خودش در TestsPage ظاهر می‌شود.
* **بدون کد تکراری** — نیازی به نوشتن دستی هر Example در TestsPage نیست.
* **Single Source of Truth** — Exampleها فقط در پوشه `examples/` هر Component تعریف می‌شوند.

## ۱۰.۴. حذف TestStep و inline logic

`TestStep` و inline `emit`/`events` در `ClTestsPage` فعلی حذف شوند.

دلیل:

* این logic مخصوص تست دستی بود — با Example System جدید، هر Example خودش logic خودش را در `render()` دارد.
* اگر Example نیاز به emit/events دارد، در `render()` خودش تعریف می‌کند.

# 15. ملاحظات

## ۱۵.۱. Serialize شدن

Example جدید قابل serialize شدن برای DB نیست (چون `render()` یک function است).

این یک trade-off عمدی است:

* **قبل:** Example قابل serialize بود ولی نامفهوم و dead code.
* **بعد:** Example قابل serialize نیست ولی قابل‌فهم و در استفاده واقعی.

اگر در آینده نیاز به serialize شد، می‌توان یک `metadata` field اختیاری به Example اضافه کرد (config/methods به‌عنوان snapshot) — ولی این در scope این Plan نیست.

## ۱۵.۲. Example با Identity (unique/emit/events)

اگر Example نیاز به `unique`/`emit`/`events` دارد (مثل تست Workflow)، در `render()` خودش تعریف می‌کند:

```ts
render: () => UiCategory.UI.Simples.Icon(
    { prop_icon: ... },
    {
        CLICK: function (event) {
            this.set("prop_show", false);
        },
    },
    {
        unique: TestStep.icon,
        emit: function (request) {
            this.set("prop_show", false);
            return { value: "icon-response", valid: true };
        },
    },
).getElement(),
```

این کامل‌ترین شکل Example است — همه چیز در یک جا قابل دیدن است.

## ۱۵.۳. Example برای Componentهای آینده (ComponentMessages و غیره)

هر Component جدید باید پوشه `examples/` با حداقل یک `Default.ts` داشته باشد.

الگوی ثابت:

```
componentXxx/
├── examples/
│   ├── Default.ts       # حداقل یک Example
│   ├── <Variant>.ts     # Exampleهای اضافی (اختیاری)
│   └── index.ts         # Registry: { DEFAULT, ... }
```
