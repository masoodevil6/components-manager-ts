# ماژول برندها (Brands Module)

این ماژول وظیفه مدیریت تایپ‌های مربوط به برندها و نگاشت (Mapping) آیکون‌ها به آن‌ها را بر عهده دارد. هدف اصلی این ماژول، ایجاد یک سیستم **Brand-Safe** است که تضمین می‌کند در طول توسعه، کار با برندهای مختلف (مثلاً برندهای تجاری یا گروه‌های خاص) بدون خطا و با استفاده از تایپ‌های دقیق انجام شود.

## 🚀 دسترسی عمومی (Public API)
بر اساس فایل `public.ts` در این ماژول، شما به عنوان زیر-مجموعه از `module_util` به نام مستعار **`Brands`** دسترسی دارید. علاوه بر تایپ‌های برند، این ماژول اکنون شامل یک تابع کلیدی برای ایجاد کلیدهای ترجمه است.

### `Icons` (در اصل `TBrandIcons`)
یک تایپ پیشرفته که اجازه می‌دهد برندهای مختلف را به آیکون‌های مربوط به آن‌ها متصل کنید.

| نوع | توضیحات |
| :--- | :--- |
| `TBrands<T, B>` | یک تایپ ترکیبی که مقادیر اصلی (`T`) را با یک برچسب برند خاص (`B`) ادغام می‌کند. |
| `TBrandIcons` | نگاشتی که در آن هر کلید (نام برند) به یک مقدار آیکون متصل است. |

### `MTCreateTranslationKey`
یک تابع کاربردی (Utility Function) برای ایجاد کلیدهای ترجمه منحصر به فرد (Unique Translation Keys) با استفاده از تایپ‌های `Brand`. این تابع به عنوان پلی بین سیستم زبان‌ها و سیستم برند/دسته‌بندی عمل می‌کند.

| متد | توضیحات |
| :--- | :--- |
| `CreateTranslationKey()` | بازگرداندن یک `Symbol` منحصر به فرد که به عنوان کلید ترجمه در سیستم استفاده می‌شود. |

**نکته معماری:** این تابع به صورت استراتژیک از ماژول `core_languages` به `util_brands` منتقل شده است تا وابستگی چرخه‌ای (Circular Dependency) بین هسته (Core) و رابط کاربری (UI) شکسته شود. چون `util` لایه پایین است، ایمن است که از آن در تمامی لایه‌های دیگر استفاده شود.

## 💡 مثال‌های کاربردی (Usage Examples)

### ۱. ایجاد کلید ترجمه با تایپ‌های برند
به عنوان مثال، فرض کنید می‌خواهید برای دسته‌بندی "آیکون‌ها" (Icons) یک کلید ترجمه ایجاد کنید:

```typescript
import { Brands } from "@/framework/util/module_brands";

// ایجاد یک کلید ترجمه که از تایپ برند استفاده می‌کند
const iconTranslationKey = Brands.MTCreateTranslationKey();

// استفاده در سیستم زبان (به صورت نمونه)
// const translation = languageApp.translate(iconTranslationKey);
```

این تابع تضمین می‌کند که کلیدهای ترجمه شما با تایپ‌های اختصاصی (مثل `TBrandIcons`) ترکیب می‌شوند و از تداخل کلیدها در مقیاس پروژه جلوگیری می‌کند.

### ۲. تعریف ساختار برندها (Branding Types)
اگر می‌خواهید یک مجموعه از برندهای خاص را تعریف کنید تا در سراسر اپلیکیشن از آن‌ها استفاده کنید:

```typescript
import { Brands } from "@/framework/util/module_brands";

// تعریف یک تایپ که شامل نام برند است و یک فیلد اختصاصی برای Brand
type MyBrandSystem = Brands<string, "brand_id">;

const brand: MyBrandSystem = {
    name: "Apple",
    __brand: "brand_id" // این فیلد برای اطمینان از تایپ استفاده می‌شود
};
```

### ۲. نگاشت آیکون‌ها به برندها (Icon Mapping)
استفاد از `Icons` برای ایجاد یک دیکشنری از آیکون‌ها که مستقیماً با نام برندها در ارتباط است:

```typescript
import { Icons } from "@/framework/util/module_brands";

// فرض کنید این ساختار برای نگاشت آیکون‌ها به برندهای شما استفاده می‌شود
const brandIconMap: Icons = {
    "brand_a": "icon_star",
    "brand_b": "icon_heart"
};

// حالا می‌توانید با اطمینان از تایپ، آیکون مربوط به یک برند را دریافت کنید
function getBrandIcon(brandName: keyof typeof brandIconMap) {
    return brandIconMap[brandName];
}
```

## 🛠 ساختار داخلی (Internal Architecture)

* **Type-Driven Design:** این ماژول برخلاف سایر ماژول‌ها، بیشتر بر پایه **TypeScript Types** است تا کلاس‌های اجرایی. هدف آن بهبود تجربه توسعه‌دهنده (DX) از طریق جلوگیری از اشتباهات تایپی در نام برندها است.
* **Generic Branding:** استفاده از Genericهای پیشرفته در `TBrands` اجازه می‌دهد تا هر نوع داده‌ای را به یک "برند" تبدیل کنید بدون اینکه ساختار اصلی داده تغییر کند.
* **Strict Mapping:** با استفاده از `TBrandIcons` تضمین می‌شود که تنها برندهایی که در سیستم تعریف شده‌اند، می‌توانند آیکون داشته باشند.
* **Circular Dependency Solver:** تابع `MTCreateTranslationKey` از این ماژول برای شکستن وابستگی‌های چرخه‌ای بین `core_languages` و `ui_categories` استفاده می‌شود. با جابجایی این تابع به لایه `util` (که هیچ وابستگی خروجی ندارد)، ترتیب بارگذاری ماژول‌ها پایدار و پایدار می‌شود.
